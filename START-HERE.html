快速了解项目状态

核心操作：开一个 director agent 会话，问"当前状态和下一步做什么"。
它会扫描项目文件、判断阶段、告诉你进度和建议。Director 是你的参谋长——任何时候不确定就问它。

日常开发节奏

标准流程："今天有时间推进游戏"

  • 1. 开 director agent，问"当前状态和待做任务"
  • 2. 它告诉你：当前 Slice、哪些任务待完成、建议先做哪个
  • 3. 开对应 agent 窗口，执行任务
  • 4. 做完 → 标记 Done → 还有时间就做下一个
  • 5. 如果本 Slice 任务全部完成 → Director 触发 QA 验收 → 你试玩验证

边界场景处理

做着做着发现设计有问题

比如 Code 实现时发现 Spec 的规则有矛盾或不可行。

→ 标记当前任务为 blocker → 开 Director 会话汇报 → Director 判断是让 Design 修 Spec 还是调整实现方案

想临时换一个任务做

当前任务卡住了或者不想做了，想先做另一个。

→ 看 current-slice.md 的任务表 → 选一个无依赖且状态为 Todo 的 → 直接开窗口做（不需要重新问 Director）

想加一个框架外的新功能

"突然想到一个好点子想加进去"

→ 不要直接做！记到 roadmap.md 的 Backlog → 下一次 Slice 规划时 Director 会评估是否纳入

Slice 做完了但验证不通过

试玩后感觉"不好玩"或"方向不对"。

→ 开 Director 会话 → 它引导你判断：是 Spec 需要修改（局部调整）还是方向需要重新审视（重大回退）

很久没做了，忘了上次做到哪

→ 开 Director agent → "看看当前状态" → 它扫描所有文件重建全景告诉你

感到框架流程有摩擦

"这步好像多余" / "agent 的输出格式不太好用" / "规则互相矛盾"

→ 能 5 分钟修？当场改 + 记到 guides/98-field-notes.md。不能？记一句话到 field-notes → 立刻回到游戏工作。每 3 Slice Director 会集中处理。
