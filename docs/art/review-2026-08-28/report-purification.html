简单几何体 ＝ 占位符，不是可交付给玩家的最终内容

净化点当前的所有世界内实体——三个模块、四个交互点——都在用基本几何形状（六边形 / 正方形 / 三角形 / 圆形） 表达身份。这在开发早期是完全正确的做法：用最少的成本建立可交互的空间逻辑和颜色编码体系。

但几何体只完成了"标识"功能，没有完成"存在"功能。 玩家看到的不是"一台正在运转的净化设备"或"一道撕裂现实的空间裂缝"， 而是"一个蓝色的六边形"和"一个青色的圆点"。 这两者之间的差距，就是原型与成品的差距。

判断标准很简单：如果这个形状被替换成另一种颜色/另一种几何体， 玩家会不会觉得"东西变了"？如果会——说明当前的视觉只承载了编码信息，没有承载物体本身。 如果不会——说明它只是个图标。当前所有实体都属于后者。

以下的每一条建议，都遵循同一个处方：保留几何轮廓作为身份识别（它已经工作了）， 在轮廓之上叠加"物体层"——体积、结构、材质、使用痕迹、运转迹象。

一、三个模块实体：从「形状」到「设备」

三个模块共享同一个问题：纯色填充 + 稍亮描边 = 图标，不是设备。 它们没有体积感、没有结构细节、没有"使用过的痕迹"、没有"正在运转"的迹象。 保留各自的几何轮廓（身份识别已经建立），但要在轮廓内建立可读的物体结构。

1.1 核心（CORE）— 蓝六边形 → 主反应装置 占位
▲ 画面中心的蓝色六边形 — 当前的"核心"
观察 正六边形，#4488cc 纯色填充 + #6699dd 2px 描边，下方 3px 蓝色 HP 条。 完全对称、零纹理、零结构。它是一个二维色块，不是一台设备。
问题 核心是玩家最常交互的对象（分配薪柴的主目标），也是叙事上的"基地大脑"。 但它现在不值得被关心——玩家不会对一块蓝色六边形产生任何情感投射。 更糟的是，它缺少"正在运转"的证据：没有发光核心、没有能量流动、 没有散热、没有振动。一台静止的色块无法传达"勉强维持"这个核心氛围。
方案：六边形基座 + 中央柱体 + 顶部核心 思路：把"平面六边形"变成"俯视的立体装置"——底盘 + 主体 + 发光核心三层结构。
  • 底盘（保留身份）：六边形，直径 ≈ 32px，#2a4a66（比当前暗两级，让它退为"基座"而非主体）
  • 六角加固块：六个角各一个 4×4px 方块，#3a5a76，暗示安装螺栓/配重块
  • 主体柱：底盘内一圈的小六边形或圆柱，直径 ≈ 18px，#4488cc（原主色）， 比底盘亮，形成从边缘向中心凸起的体积感
  • 散热槽：主体上 2-3 条横向暗线（1px，#1a3a56，间距 5px）， 这是"工业感"最廉价也最有效的信号
  • 发光核心：顶面中心 3×3px，#aaddff， alpha 在 0.6↔1.0 之间缓慢脉动（周期 2.5s）— 这是整个场景的"心跳"
  • 能量传导：从核心向六个方向各 1 条极细亮线（#6699dd，alpha 0.12）， 到主体边缘为止。暗示"能量从中心流向底盘"
  • 外接管线：从底盘向 1 个方向（朝向储藏模块）延伸一条 2px 暗灰管线（#3a3d42）， 长度 12-16px。暗示"这些设备是互相连接的系统"，而不是三个孤立的符号
  • HP 受损：核心发光减弱 + 闪烁频率加快；主体出现从边缘向中心的裂纹（用现有的 CRACK_LINE_OFFSETS 逻辑，但加粗到 2px 并延长）

参考信号：Dishonored 的工业科技（几何骨架 + 少量内部线条）· Return of the Obra Dinn 的仪表盘（功能极简但有细节密度）· Alien Isolation 的终端设备（旧、有使用痕迹、在工作）

1.2 储藏（STORAGE）— 橙正方形 → 储物集装箱 占位
▲ 核心右侧的橙色正方形 — 当前的"储藏"
观察 正方形，#cc8844 填充 + #ddaa66 描边，边长 ≈ 28px。 和核心的唯一区别是"六边形 vs 方形"和颜色。同样零结构。
问题 正方形是最缺乏个性的几何体——它读作"按钮""图标""色块"， 几乎不可能读作"一个装东西的容器"。 而"储藏"的语义核心恰恰是容积和可开启。 当前的平面方块完全没有传达这两点。

更隐蔽的问题：橙色 (#cc8844) 是场景中的暖色， 但它没有物理来源。核心的蓝光可以解释为能量， 净化器的 teal 可以解释为污染处理——储藏的橙光来自哪里？ 如果是"指示灯"，那灯在哪里？没有光源的发光会破坏画面的物理可信度。
方案：等轴透视的箱体顶视（顶面 + 正面错位） 思路：用两个错位矩形模拟箱体的顶面 + 正面，建立体积感。这是 2D 顶视游戏表达"容器"最经典的手段。
  • 顶面：正方形 24×24，#cc8844（原主色），位于偏上
  • 正面：矩形 24×10，#aa6622（比顶面暗两级），位于顶面下方，向右错位 4px — 这个错位就是"厚度"的视觉信号
  • 分层线：正面画 1-2 条横线（1px，#883f11），暗示"抽屉 / 隔层 / 堆叠的物品"
  • 锁扣/把手：顶面中央一个 5×5px 方块，#ddaa66， 内部可以有一个更暗的 2×2 点（#553311）作为"锁孔"
  • 指示灯（关键）：顶面右上角一个 3×3px 方块，#e0a848， 慢速闪烁（周期 3s，亮 0.3s）。这是橙色光的物理来源 — 给暖色一个解释
  • 容量可视化：正面可以画一条竖直的"液位线"（1px，#ddaa66）， 其高度绑定当前存储的薪柴量。这让储藏成为唯一一个用视觉反映游戏状态的模块
  • HP 受损：箱体角部出现凹陷（用暗色三角切角）；正面分层线断裂

为什么这样有效：错位矩形 → 立刻读作"有厚度的物体"； 分层线 → 读作"容器"；指示灯 → 给暖色一个理由；液位线 → 让物体参与游戏状态反馈。 四个元素叠加，一个正方形就变成了一个箱子。

1.3 净化器（PURIFIER）— 三角锥台 → 污染处理装置 方向对，需深化
▲ 画面下方的绿色双层三角 — 当前的"净化器"
观察 外层大三角 + 内层小三角嵌套。外层 #1aad96 描边，内层 #0e4a3f 填充。 这是三个模块中唯一有"设计意图"的形状——三角锥台天然带有方向性（尖端向下）和功能联想（漏斗 / 反应堆 / 处理装置）。
肯定 + 三个问题 方向正确：双层嵌套提供了深度感，三角尖端向下的方向性是其他两个模块没有的优势。

问题 1 — 体量失控：双层三角的像素面积明显大于核心六边形， 加上位于画面底部中央（玩家出生点附近），它成为了视觉焦点。 但核心才应该是主角。视觉权重倒置了。

问题 2 — 双层退化：内层填充 #0e4a3f 在 #0d1114 背景上几乎不可见， "双层"效果在正常视距下退化为"一个带描边的三角形"。设计意图没有传达出来。

问题 3 — 静止：它看起来不像"在工作"。 一个净化装置应该有流动感——有什么东西被吸入、被处理、被排出。 当前是完全静态的。
方案：控制体量 + 增强双层 + 加入"工作中"的动效
  • 缩小 15%：让视觉重量低于核心。三角形是强势形状，需要主动压制
  • 内层提亮：从 #0e4a3f → #1a6b5c 或更亮。 "双层"必须在任何距离都可辨，否则这个设计就白做了
  • 三角锚点：外层三角三个角各一个 2×2px 圆点，#2ae6c8。 读作"固定栓"或"能量锚点"，同时强化三角的几何存在感
  • 处理液面（关键动效）：内层三角内有一条水平亮线（#2ae6c8，alpha 0.35）， 在三角内部缓慢上下移动（周期 4s，幅度 ≈ 内层高度的 30%）。 读作"里面在处理液体/能量"。一个 1px 线的移动就能让整个装置"活"起来
  • 排放口：三角尖端处一个 4×5px 的暗色矩形（#0a1a18），带有 1px 亮边。 读作"出口"
  • 排泄粒子：从排放口每隔 ≈1s 下落 1 个 1-2px 的 teal 粒子（#1aad96）， 下落 8-12px 后 alpha 渐隐。极克制——同时最多 2-3 个粒子存在
  • HP 受损：液面移动变得不规则（速度忽快忽慢 + 偶尔停顿）；粒子变得断断续续
三个模块的统一处方 注意上面三个方案共享同一套方法，可以提炼为可复用的规则：
层级作用在三模块中的体现
轮廓层（保留）身份识别 — 已建立，不动六边形 / 方形 / 三角
体积层（新增）从"平面"到"物体"底盘+柱体 / 顶面+正面错位 / 双层嵌套提亮
结构层（新增）工业感 — 廉价高效散热槽 / 分层线 / 三角锚点 / 加固块 / 锁扣
光源层（新增）给颜色一个物理理由核心发光 / 指示灯 / 排放口
动效层（新增）"它在工作" — 从静物到设备核心脉动 / 液位线移动 / 排泄粒子
状态层（强化）HP → 视觉，已有关联但不明显裂纹加粗 / 角部凹陷 / 动效失律

二、四个交互点：从「圆点」到「场所」

2.0 总纲：圆点是可交互物设计中最偷懒的解法 需要重做
▲ 四个交互点：裂隙入口(teal/上) · 防御(紫/左) · 成长(橙/左下) · 加厚(灰白/右上)
观察 四个交互点全部是实心圆 + 描边圆环 + sin 呼吸，只有颜色不同。 半径 7-8px 中心 + 12-14px 外圈。加厚桩例外显示为绿色三角形（与统一语言冲突）。
为什么圆点不成立 (1) 它不告诉你这是什么。 圆点只能靠颜色编码，而颜色需要学习成本。 新玩家看到紫色圆圈不知道那是防御配置、传送门还是陷阱。 好的可交互物应该一眼就能猜出大概功能——门看起来像门，台子看起来像台子。

(2) 它没有尺度感。 所有四个交互点大小和视觉权重相同， 但裂隙入口（进入完整场景）的重要性远高于加厚桩（一次性操作）。 没有层级 = 玩家不知道先去哪。

(3) 它漂浮在空中。 没有阴影、没有与地面的连接、没有物理存在的迹象。 它看起来像一个误入游戏世界的 UI 图标。

(4) 它违背"低信息密度但需要高信息质量"的原则。 圆点是"最少的信息"，但不是"最有效的信息"。 一个精心设计的裂口能同时传达位置、功能、危险度、状态——圆点只能传达位置。
总原则 每个交互点应该是一个"场所"（place），不是一个"标记"（marker）。
• 接地：每个交互点在地面上有投影/基座/痕迹，不是悬空的
• 有体积：即使是扁平的，也要有顶面/侧面/厚度的暗示
• 有功能暗示：形状本身要能让人猜出用途
• 有尺度层级：按重要性分配视觉重量（裂隙 ≫ 防御 ≈ 成长 > 加厚）
• 颜色退为辅助：形状承担主要识别，颜色只做强化（这样色盲玩家也能玩）
2.1 裂隙入口 — 重做为「空间裂缝 / 传送门」 原方案欠考虑，重做
v1 方案的问题（自我修正） 我上一版建议"竖直椭圆形裂口 + 锯齿边缘"，方向偏了—— 那个方案读作物理破损（墙上裂了个洞），太实、太"物质"。 但裂隙入口的本质是空间异常：不是"墙上有个洞"， 而是现实本身被撕开了一个口子，另一边是另一个地方。 这两者的视觉语言完全不同。
正确的设计意图 裂隙入口是玩家从安全区进入危险区的唯一通道。 它必须同时传达三件事：
• "这里是入口" — 明确的、可定位的、有仪式感的
• "另一边不一样" — 透出的是异质空间，不是黑色空洞
• "过去就回不来了（暂时的）" — 有不稳定的、不可逆的暗示

它应该是整个净化点视觉上最引人注目、最超自然、最有分量的东西—— 因为它是通往游戏主体内容（裂隙探索）的门。
方案：垂直空间裂缝（Rift / Portal） 核心视觉概念：一道竖直的、不稳定的现实裂口， 边缘不是平滑椭圆而是"撕裂"的不规则锯齿； 内部不是黑色而是缓慢流动/闪烁的异质色块（透出裂隙世界的一角）； 周围有溢出的光照亮地面。
  • 整体形态：竖直纺锤形 / elongated diamond，宽 ≈ 18-22px，高 ≈ 32-36px。 明显大于现在的小圆点（现在 ≈ 14px 直径）— 它是门，不是标记
  • 撕裂边缘：不是平滑曲线。用 8-12 段短线段拼成不规则轮廓， 左右两侧不对称，有几处"尖刺"向外突出 2-4px。 读作"现实被暴力撕开"，而非"设计好的椭圆门"
  • 内部（关键）：不是纯黑填充。用 2-3 层不同 alpha 的 teal 色块 做缓慢流动（可以用 2 帧交替或极慢的 UV 偏移）：
      · 底层：#0a1a18（近黑，作为"深度"）
      · 中层：#1a6b5c 的不规则斑块，极缓慢形变（周期 6-8s）
      · 高层：2-4 个 1-2px 的亮点 #7fffee，随机位置闪烁（每个亮 0.5-1.5s 后消失，另起一处）
      读作"透过裂缝看到裂隙世界的一角——有东西在那边动"
  • 边缘辉光：沿撕裂轮廓一圈辉光，#2ae6c8， alpha 0.5↔0.8 呼吸（周期 3s，比现在慢、比现在强）
  • 地面溢出光（关键）：裂口底部在地面上投下一片椭圆光斑， 半径 ≈ 24×10px，#1aad96，中心 alpha ≈ 0.15，向外渐隐。 这一条最重要——它让裂缝"接地"了，让它成为场地的一部分， 而不是漂浮的 UI 元素
  • 空间扭曲（可选但强烈推荐）：裂口周围 6-8px 范围内的地面 有轻微的像素偏移/错位（1-2px，向裂缝方向吸引）。 读作"靠近它，空间就开始不正常"。这是"空间异常"最有力的信号
  • 不稳定粒子：每隔 2-4s 从裂口边缘剥离 1 个 1px 亮点， 向外飘 6-10px 后消散。读作"这个裂口在缓慢地、不稳定地存在着"
  • 靠近时：辉光增强、内部流动加速、地面光斑扩大 20%、粒子频率提高。 读作"它在回应你的靠近"

参考信号：Control 的传送门（空间异常感）· Stalker 的空间异常（不稳定 + 危险）· Dark Souls 的雾门（仪式感 + 单向性）· Stranger Things 的逆世界裂缝（撕裂边缘 + 内部异质）

2.2 防御配置点 — 操作台 / 武器架 方向确认 ✓
方案（v1 方向正确，细化执行）
  • 基础形态：扁平梯形台面（上宽 18px / 下宽 14px / 高 8px），俯视角。读作"操作台"
  • 槽位凹槽：台面上 3 个小矩形凹槽（每个 4×3px，#151a1e）， 代表武器/残骸槽位。当前为空时显示为暗坑，装满后显示对应物品的小图标—— 这让防御状态在世界内就可读，不必打开面板
  • 配色：主体金属灰 #2a2d32（保持不变的工业感）， 边缘线紫色 #8866cc — 仅在玩家进入交互半径时亮起 （平时 alpha 0.15，靠近时 0.7）。这样紫色的出现本身就成为一个信号
  • 指示灯：台面一侧 2 个微小指示灯（2×2px，#8866cc），慢闪（周期 2.5s，错相）
  • 接地：台面下方一条 1px 的暗色投影线（宽 20px，alpha 0.25）
  • 有内容时：槽位凹槽内出现小色块（对应装备的残骸），并且台面下方的投影加深
2.3 成长祭坛 — 仪式装置 方向确认 ✓ 强化执行
方案（v1 方向正确，强化"仪式感"） 成长祭坛的语义是永久改变——玩家在这里投入资源，获得不可逆的提升。 这个语义非常适合用仪式/祭坛的视觉语言：古老、庄重、有代价感。
  • 基座：圆形，半径 ≈ 10px，#2a1f1c（暗红棕，暗示"旧材料/有机物"）
  • 仪式纹路：基座表面有同心圆或放射线纹路（1px，#cc8844， alpha 0.10）。这是祭坛最重要的识别信号——圆 + 纹路 = 仪式场所
  • 中央柱：短柱 4×6px，#cc8844， 从基座中心升起。读作"某种被供奉/被改造的东西"
  • 柱顶核心：一个小三角（4×4px），#e0a848， 有极慢的自转（每 20-25 秒一圈）。慢到几乎察觉不到在动—— 但"在动"这件事会被潜意识捕捉到，制造不安感
  • 接地光晕：基座外一圈暖色辉光（半径 14px，#cc8844，alpha 0.08）， 缓慢呼吸。读作"这台装置有自己的能量"
  • 可升级时：柱顶三角亮度提高 + 自转加速到 8s/圈。 让玩家在世界内就能看到"我现在可以升级了"，不必打开面板才发现
  • 升级成功后：一次性动效 — 基座纹路从中心向外亮一遍（0.8s 扫过）， 柱顶三角闪一下白。给不可逆的操作一个仪式性的反馈
2.4 加厚桩 — 最小、最低调 需统一语言
现状问题 当前显示为绿色三角形——既打破了"圆点"的统一语言， 又与净化器（也是三角形）产生形状混淆。 两个不同的东西用同一个形状，这是识别系统的事故。
方案
  • 形态：短粗圆柱俯视 — 椭圆 10×8px + 顶部十字槽（2px 线，#151a1e）。读作"地桩 / 锚栓"
  • 配色：骨灰 #3a3838，暗示"原材料 / 基础构件"，不带任何功能色
  • 尺度：明显小于其他三个交互点（视觉层级：裂隙 ≫ 防御 ≈ 成长 > 加厚）
  • 状态：可加厚时，十字槽内出现微弱的暖色光（#e0a848，alpha 0.4）。 不可加厚时完全是暗的。用"有没有光"表达"能不能用"

三、地面：自然感 = 因果可追溯

3.1 问题：太干净，「勉强维持」只是文字不是视觉 错失的机会
▲ 靠近核心时的地面 — 几乎看不到任何材质差异
观察 地面为均匀暗灰（#1a1c1f ~ #151a1e），带极细微噪声。 在正常视距下噪声融合成"干净的深灰布料"。 看不到石板缝、磨损、污渍、任何材质线索。
为什么重要 净化点的氛围定义是"孤立、微光、功能性、空旷、勉强维持"。 "勉强维持"这四个字需要在视觉上有落脚点，而地面是最佳载体—— 它是场景中面积最大的元素，也是最能承载"时间痕迹"的表面。

当前地面太干净了。它不像一个被长期使用、缺乏维护的空间， 更像一个刚建好的空房间。这直接削弱了整个场景的叙事张力。
3.2 核心方法：自然感 = 因果可追溯
为什么"加装饰"容易失败 玩家的潜意识会问："这个痕迹为什么在这里？"
如果答案是"因为程序随机撒的"，大脑会立刻识别出这是假的—— 即使玩家说不出哪里不对，也会感觉"这个场景很廉价"。

自然 = 每一处痕迹都有一个可追溯的成因， 且这个成因符合物理常识或叙事逻辑。 这是"程序化装饰"和"设计过的环境叙事"之间的分界线。
十条生成规则（可直接转为实现约束）
元素成因锚点（必须有）自然感的技术实现
裂缝 从应力点起源：模块底座边缘（重压）、边界处（张力）、 动线转折点（反复摩擦）、已有裂缝的分叉点。
禁止从空地中央随机起步		 用 Worley/Voronoi 噪声生成骨架（比随机折线自然得多）； 裂缝从起源点最宽、向末端收窄到 0； 主裂缝允许 1-2 条分叉，分叉更细且分叉后主干变细
污渍 有明确源头：模块底部（漏液）、边界（外部渗入）、 裂缝末端（积液）。
禁止无源污渍		 从源头沿重力/坡度方向扩散；边缘用 Perlin 噪声调制使其不规则； 中心浓、边缘渐淡（径向 alpha 曲线）；不是完美圆——有流淌的方向性
足迹/磨损 沿真实动线：出生点 → 核心 → 裂隙入口， 以及核心 ↔ 储藏 ↔ 净化器之间的路径 不是均匀纹理，而是"路径带宽"：路径中线磨损最深（alpha 0.06）， 向两侧渐隐到 0（带宽 12-18px）。高频走过的路段更深
密度分布 —— 关键：用低频噪声调制高频细节的密度。 让某些区域密集、某些区域干净。 均匀分布 = 立即识别为程序化
尺度分层 —— 大裂缝（30-50px，全图 2-3 条）+ 中裂缝（15-30px，5-8 条）+ 细纹（<15px，高频噪声，仅近处可见）。三层叠加而非单一尺度
颜色 —— 比地面暗 1-2 级（#0a0b0c / #101214）。 禁止纯黑、禁止亮色描边。 痕迹应该"被看见"，不应该"跳出来"
与光照交互 —— 高价值：裂缝在玩家灯光经过时显现（侧光产生阴影感）， 离开时隐入黑暗。这让地面成为"被探索"的对象而非静态背景
边界过渡 越靠近安全区边缘，维护越少 边缘 1-2 tile 范围内，污渍/裂缝密度提高 2-3 倍， 出现不规则暗斑（alpha 0.10-0.15）。读作"这边更潮湿/更不稳定/没人管"
总覆盖率 —— 5-8%。记住 art-direction 的"低信息密度"原则—— 目标是"有痕迹"不是"有装饰"。宁少勿多
确定性 —— 用固定 hash（如现有的 mulberry32）绑定种子。 同一局游戏内痕迹不变——玩家会记住"核心左边那条裂缝"， 这种空间记忆是沉浸感的重要来源

  禁止：均匀网格分布 · 等间距重复 · 完美对称 · 无源污渍 · 空地中央起步

四、净化点外部：从「黑墙」到「有东西在外面」

4.1 现状：边界做对了，外部太空了 单调
观察 安全区呈椭圆形，边界有 blob 扰动（不规则起伏，非完美几何椭圆）。 向外快速衰减至 #080a0c 绝对黑暗。 边界上有微弱亮点（可能是 boundary-atmosphere 的粒子）。
肯定 + 问题 边界本身做得不错：椭圆 + blob 扰动读作"自然形成的安全区边缘"， 黑暗过渡速度合适（够快让人不想出去，不至于快到产生硬切）。

问题是外部太空了。 当前外部 ≈ 均匀的纯黑 + 偶尔的微弱粒子。 这浪费了一个巨大的叙事机会：

净化点的核心叙事是"人类最后的立足点，被裂隙包围"。 外部不应该是"什么都没有的黑"——它应该是"有东西在那里，但你看不清"。
art-direction 说"看不清比看清更有效"—— 但前提是得有东西可看不清。纯黑意味着"没有信息"， 而"看不清的东西"意味着"有信息但拒绝给你"。这两者的心理效果天差地别。
设计目标（三条） 1. 外面是"活的" — 有什么东西在那里，在动，在观察
2. 这个边界是"人为撑起来的" — 不是天然的，是设备/仪式维持的，随时可能失效
3. 威胁是渐进的 — 随时间/潮汐推移，外部在逼近

以下 7 个方案按"投入产出比"排序。全部遵循一个铁律：克制—— 每个效果都应该是"偶尔发生"或"极微弱"的。持续演出会毁掉"低信息密度"的氛围， 也会让玩家脱敏。
4.2 七个方案（脑爆）
方案 A — 张力膜：让边界有"被撑起来"的质感
当前边界是"暗色轮廓线"，读作"墙"。把它改成一层有张力的膜：
• 边界不再是静态曲线，而是有极缓慢的波动/涟漪（周期 8-12s，幅度 1-2px）
• 偶尔（每 20-40s）出现局部凸起：某一段边界向外鼓出 3-5px，持续 1-2s 后回弹。 读作"有什么东西从外面顶了一下"
• 膜本身极暗（alpha 0.06-0.12），只有在波动时才被察觉
设计意图：直接传达"这个安全区是撑起来的，不是天然的"——呼应"勉强维持"
方案 B — 侵蚀痕：边界在被慢慢吃掉
安全区内侧边缘的地面有被"啃噬"的痕迹：
• 不规则的缺口啃进安全区（深度 4-10px，长度 15-30px，全图 3-5 处）
• 啃噬边缘的地面材质异常化：轻微结晶感（teal 极暗斑点，alpha 0.05）或褪色
• 越靠近边界，侵蚀越明显（与 3.2 的边界过渡规则叠加）
• 随潮汐/稳定度变化：稳定度降低时，侵蚀痕缓慢扩大
设计意图：让"安全区在缩小"这件事在空间上可读，而非只在 HUD 数字上可读
方案 C — 外部窥视：黑暗中有东西在看
边界外的黑暗中，偶尔出现成组的光点：
• 每 15-30s 出现一次，持续 1.5-2.5s
• 2 个或 4 个一组（成对/成组暗示"眼睛"，但不要画成眼睛的形状—— 保持为无定形光点）
• #2ae6c8 极暗（alpha 0.2-0.35），几乎看不清
• 出现和消失都是渐变的（0.4s 淡入 / 0.4s 淡出），不闪烁
• 位置随机，但总在边界外 8-20px（不近不远，恰好在"看不清"的距离）
设计意图：艺术方向明确禁止"成对眼睛"，但成组出现的光点能触发同样的 心理反应而不违反禁令。这是"看不清比看清更有效"的最佳应用
方案 D — 渗入物：边界在过滤，但过滤不干净
偶尔有细微的 teal 粒子从边界外飘入安全区：
• 每 8-15s 出现 1 个，从边界外侧 10px 处向内飘
• 进入安全区 6-12px 后，开始缓慢旋转/震荡，然后消散（被"过滤"掉了）
• 1px，#1aad96，alpha 0.3 → 0
• 极少数（约 1/10）能飘得更深（20-25px）才消散
设计意图：传达"边界是一个主动工作的过滤系统"——它有用，但不完美。 偶尔飘得深的那一个会制造"这次会不会出事"的紧张感
方案 E — 旧世界残留：曾经有人试图守住这里
边界外侧散落着旧世界的隔离设施残骸：
• 破损的警示带（1px 斜纹短线，褪色的 #b89040）
• 锈蚀的隔离桩（3×6px 小竖条，#3a3838，倾斜 5-15°）
• 褪色的危险标志（4×4px 方块，几乎看不出原来的图案）
• 只出现在边界外 5-15px，且大部分被黑暗吞没（alpha 0.15-0.3）
• 全图 4-7 处，分布不规则
设计意图：这是最有叙事密度的方案——它暗示"曾经有更多人、更完整的防线， 现在只剩这些"。用一个几乎看不见的细节讲完一整段历史。参考 Roadside Picnic / STALKER 的 "前人遗留物"叙事手法
方案 F — 潮汐联动：边界会呼吸，也会紧张
把现有的潮汐系统与边界视觉强绑定：
• 落潮期：膜波动平缓（周期 12s），外部光点极少（每 40s+），无渗入物
• 涨潮期：膜波动加剧（周期 6s，幅度翻倍），外部光点频率提高（每 15s）， 渗入物出现，边缘侵蚀痕略微扩大
• 临界状态（稳定度低）：边界出现局部破口—— 小范围（8-15px 宽）的黑暗侵入安全区，边缘闪烁警告色（#cc3333， alpha 0.3，周期 1.5s）
设计意图：让抽象的"潮汐/稳定度"数值变成看得见的环境状态。 玩家不需要读 HUD 就能感到"现在情况不太好"
方案 G — 声音的视觉化：从外面传来的东西
如果项目有音频系统，可以做一个视觉-听觉联动的极简效果：
• 某些"外部事件"发生时（如显形、外部光点出现）， 边界的对应位置有1-2px 的局部亮度扰动（持续 0.3s）
• 配合极低频的环境音（次声波级别，让人不安但说不出为什么）
设计意图：跨感官的一致性会让"外面有东西"这个暗示变得难以忽视， 即使玩家说不出具体看到了什么。如果音频系统未就绪，此方案可延后
实施建议 不要一次全上。 建议的组合：
第一批（高性价比，成本低）：A 张力膜 + C 外部窥视 — 两个效果就能把"黑墙"变成"有东西的黑暗"
第二批（叙事密度）：E 旧世界残留 + F 潮汐联动 — 让外部有故事、有变化
第三批（锦上添花）：B 侵蚀痕 / D 渗入物 / G 声音联动

铁律：所有效果的默认状态是"不发生"。 它们的价值来自 rarity ——如果外部光点每 3 秒出现一次， 它就从"不安"变成了"装饰"。

五、HUD 与底部提示条

✓ v1 判断已确认 — 以下是执行细化，方向不变。

5.1 右上角 HUD：从 debug overlay 到状态栏 需重构
观察 4 行散列文本直接贴在 canvas 上，无背景、无边框、无分组。 字号/颜色差异极小，四行视觉权重几乎相同。
问题 这是典型的开发者调试信息残留——功能正确，但没有经过"设计"。 无容器 = 遇到亮背景可读性崩溃；无层级 = 玩家每次都要重新扫描全部内容。
方案
  • 背景：background:rgba(15,17,20,0.82); border:1px solid #2a2d32; padding:8px 12px;
  • 分组：1px #2a2d32 线分隔两组 — 上组「资源」（薪柴）／下组「状态」（潮汐 + 下次归来）
  • 层级：薪柴数值 15-16px bold #c89040（最大字号，玩家最关心）； 其余 10-11px #8a8f96
  • 条件显示：「下次归来」默认隐藏（或 opacity 0.4）， 仅当玩家靠近裂隙入口时才完全显示 — 它是"出发前才需要看"的信息
5.2 底部提示条：世界层与 UI 层之间的桥梁 需包装
观察 Tab:存续报告 Esc:记录 裸文字贴在底部，无容器、无动画。
问题 这是玩家与场景交互的主要引导通道，但视觉优先级低到容易被完全忽略。 更关键的是：靠近交互点时它应该切换为该交互点的操作提示， 但这个动态行为在视觉上没有得到强化。
方案
  • 容器：background:rgba(15,17,20,0.88); border:1px solid #2a2d32; padding:5px 16px;
  • 文案层级：按键 [E] 用亮色 #c8cdd4 + 方括号；描述用暗色 #8a8f96；间距 6px
  • 状态切换：无目标时 opacity 0.5（弱化，不抢注意力）； 靠近目标时 opacity 1.0 + 150ms 过渡。 这个过渡本身就是"有东西可交互了"的信号
  • 第二行：靠近模块时显示状态预览（10px #666a70）， 如 HP 60/100 · 混乱抑制 -18%。 这让"要不要现在交互"可以在移动中决策，不必先打开面板
技术工作量极小（纯 CSS + scene.update() 一行逻辑），但它是世界层和 UI 层之间唯一的桥梁。

六、交互面板：从「网页平铺」到「游戏菜单」

6.1 核心诊断：这是网页布局，不是游戏菜单 信息架构需重构
▲ 左：Tab 状态总览 · 右：E+核心 分配面板
先肯定 载体风格选对了。磷光屏 + 扫描线 + CRT vignette + 等宽字体， 与"工业终端监控"的设定完美契合。 四周漏出游戏画面的做法很棒——面板读作"浮在世界上方的透明界面" 而非"遮住世界的全屏菜单"，保持了空间连续性。键印导航（↑↓ 选 / Enter 确认 / Esc 关闭）一致且清晰。
问题不在视觉风格，在信息组织方式。
网页 vs 游戏菜单：本质区别
维度网页式（当前）游戏菜单式（应该）
信息呈现所有内容同时可见，靠眼睛扫描层级递进，一次只显示一层
导航方式滚动 / 扫视 / 搜索方向键 + 焦点，位置即状态
空间组织纵向堆叠，内容多长页面多长固定视口，主区+从区，导航切换内容
焦点无明确焦点，用户自己找始终有一个"当前选中项"，视觉跟随
详情处理和概览混在一起平铺渐进披露：选中后才展开详情
操作 vs 信息混排分离：可操作项有明确焦点，只读信息降为次要
心理模型"阅读一份文档""操作一台设备"

当前面板是"把数据库查询结果显示在屏幕上"—— 信息齐全、排列整齐，但玩家需要自己在大脑里建立层级。 好的游戏菜单应该把层级做在界面上，让玩家的大脑只负责决策。
四条重构原则 1. 主-从结构（Master-Detail） — 一个导航区（有什么）+ 一个详情区（选中的是什么）。 而不是所有内容平铺。
2. 渐进披露（Progressive Disclosure） — 先给"是什么"，选中后才给"细节是什么"。 一屏信息量控制在 7±2 个组块。
3. 焦点驱动（Focus-Driven） — 始终有一个明确的当前选中项， 视觉焦点（高亮/边框/背景）跟随它移动，其余内容降为次要。
4. 状态优先（State over Description） — "能不能用""够不够资源""当前是什么状态"这类决策相关的信息， 优先级高于描述性文字。
6.2 状态总览面板 → 主-从三段式
现状 上半部分密集排列 10+ 个数值/标签（完整度/薪柴值/潮汐/混乱增速/起始混乱/稳定度…）， 下半部分约 40% 是空白 + "尚无残渣"文字。 信息堆在一处，空间浪费在另一处——这是平铺布局的典型症状。
重构方案 
┌──────────────────────────────────────────────┐
│  ⬢ 核心      ▣ 储藏      ▲ 净化器              │  ← 固定模块条
│  70/100      70/100      70/100             │    一眼扫完，不随导航变化
├──────────────┬───────────────────────────────┤
│ ▸ 全局状态   │                               │
│  成长升级     │      [选中分类的内容]          │  ← 左：导航（一次激活一项）
│  工具清单     │                               │  ← 右：详情（跟随导航切换）
│  污染物       │      内容填满这个区域，        │
│  出击记录     │      不留大片空白              │
│               │                               │
├──────────────┴───────────────────────────────┤
│ ↑↓ 选择   Enter 展开   Esc 合上               │  ← 键印
└──────────────────────────────────────────────┘

改变：
  · 顶部三条 = 最需要"一眼扫完"的，固定不动
  · 左侧导航 = 信息分类，玩家知道"有哪几类"（5-6 项）
  · 右侧详情 = 渐进披露，一次只显示一个分类的内容
  · 空间利用率高 — 详情区填满，消除 40% 空白
关键收益：
• 玩家不再需要"扫描 10 个数值找我要的那个"——导航是显式的
• 空白消失——详情区总是被当前分类的内容填满
• 符合"操作一台设备"的心理模型（选频道 → 看读数）
6.3 分配面板 → 单焦点 + 决策闭环
现状 顶部显示核心 HP/效果，中部是操作控件，底部平铺三个模块的对比信息。 问题：三个模块的信息是"平铺"的（都是次要信息）， 而"投入"这个唯一的操作控件没有得到视觉焦点。 玩家的操作目标（投入多少）和决策依据（分配后怎么样）都被淹没在信息里。
重构方案 
┌──────────────────────────────────────────────┐
│   ⬢ 核心   │   储藏    │   净化器              │  ← Tab 式切换
├──────────────────────────────────────────────┤     （不是三个平铺信息块）
│                                              │
│   完整度   ████████░░   70/100              │
│   混乱增速   -21%  →  -27%                  │  ← 主区：当前模块
│                                              │     （只显示一个）
│   ┌────────────────────────────────────┐     │
│   │   投入   [ ◀   12   ▶ ]                │     │  ← 唯一操作控件
│   └────────────────────────────────────┘     │     视觉焦点，框起来
│                                              │
├──────────────────────────────────────────────┤
│  出击预估   混乱抑制 27%  ·  生存 中          │  ← 决策反馈（关键新增）
├──────────────────────────────────────────────┤
│ ←→±1  Shift±5  Enter 注入  Esc 离开           │
└──────────────────────────────────────────────┘

三个关键改变：
  1. 三模块从"平铺三块"改为 tab 切换 — 一次只处理一个决策对象
  2. 「投入」是唯一操作控件，用框+高亮成为明确焦点
  3. 底部加「出击预估」— 让分配决策有即时反馈闭环
为什么"出击预估"是关键： 分配的本质是"我做这个选择，下次出击会怎样"。 当前面板只告诉玩家"这个模块的效果变成 -27%"， 但玩家真正想知道的是"我下次出击能不能活下来"。

加一个综合评估条（混乱抑制率 / 预计生存时间 / 风险等级）， 把"局部数值"翻译成"全局后果"。 这是从"数据界面"到"决策界面"的跃迁。
6.4 跨面板：空状态与文案
两个具体问题 (1) 空状态太消极 — "无可用残骸""尚无残渣"只说了"什么都没有"， 没说"怎么获得"。空状态是展示世界观的好机会，浪费了。
(2) 升级描述偏抽象 — "抵御裂隙隐蚀…""更高效的收割…"是氛围文案， 但玩家在决定"花 8 级薪柴换这个"时需要具体数值。
方案
  • 空状态：虚线轮廓图标（40×40）+ 2 行弱化引导文案， 如「在裂隙中击败敌人可获得残骸」。 不要留纯黑空白——那看起来像渲染错误
  • 升级描述：氛围文案保留（它是世界观的一部分）， 但在下方补一行具体数值， 如 抵御裂隙隐蚀… + 混乱积累 -4%。 氛围和实用性不必二选一
  • 不可达状态：当资源不足时，卡片应进入禁用态 （opacity 0.4 + 边框变暗 + 成本显示为红色）。 当前所有卡片看起来都可交互，但实际一个都买不起——这是误导

七、玩家角色与灯光

✓ v1 判断已确认 — 以下是执行细化。

7.1 暖光存在感可以更强 方向 ✓ 可优化
▲ 靠近核心时的玩家角色 + 暖色灯光
观察 玩家（工业防护人形）周围有微弱暖色光晕，是场景中第三类光源（另两类是模块发光和交互点）。
肯定 + 可改进 肯定：暖光在冷色场景中非常突出，"你是这个世界里唯一的暖色来源" 这个叙事声明在视觉上成立了。

可改进：光晕偏微妙，需要刻意看才注意到。 考虑到这是一个强烈的叙事声明，暖光可以更自信一点—— 不是扩大范围（会影响平衡），而是提高核心区域的亮度和饱和度。

灯尘：静态截图中不可见（可能是帧限制）。 如果运行时也不够明显，需要调整参数。
方案
  • 核心亮度：灯光核心半径内的亮度提高 15-20% （更多 #c4873a 像素达到 alpha 0.4+）
  • 脚底反射（高性价比）：玩家脚下加一个极微弱的暖色圆形渐变 （半径 12px，max alpha 0.08）。 在暗环境中，地面反射能极大增强"光的存在感"—— 因为它证明了光是照在实体上的，而不只是贴在角色身上的贴图
  • 灯尘参数：改为"少而亮"而非"多而弱" — 尺寸增到 2px，发射频率降到每 0.8s 1 个，但初始 alpha 提到 0.5-0.6。 少量高对比粒子比大量低对比粒子更容易被感知
  • 与地面痕迹联动：玩家走过时，暖光会照亮 3.2 节提到的地面裂缝。 这个交互是"免费"的（光照系统已存在）， 但能让地面痕迹从"背景装饰"变成"被探索的对象"

八、优先级排序

按"对玩家第一印象的影响程度"排序，不考虑技术难度。 第一梯队决定玩家是否觉得这是个"做完的游戏"。

第一梯队 — 决定第一印象（不做 = 看起来像原型）
  1. 四个交互点从圆点改为场所（§2）— 最"未完成"的部分。 裂隙入口优先：做成竖直空间裂缝（撕裂边缘 + 内部异质流动 + 地面溢出光）， 它会立刻成为场景的视觉焦点和记忆点。防御/成长按确认的方案，加厚桩改为小地桩
  2. 三个模块从形状变为设备（§1）— 按「轮廓/体积/结构/光源/动效/状态」六层处方执行。 最少成本最高收益的是：储藏的"顶面+正面错位"（立刻有体积）和 核心的"发光核心 + 散热槽"（立刻像设备）
  3. HUD 面板化（§5.1）— 加背景框 + 分组 + 字号层级。 30 分钟工作量，直接消除"debug overlay"感
第二梯队 — 决定沉浸感和可读性
  1. 外部丰富化第一批（§4.2 方案 A + C）— 张力膜 + 外部窥视。 两个低成本效果就能把"黑墙"变成"有东西的黑暗"
  2. 地面加因果痕迹（§3.2）— 严格按十条规则，总覆盖率 5-8%。 "自然"的关键不是加什么，是每处痕迹都有成因
  3. 面板信息架构重构（§6）— 状态面板改主-从三段式； 分配面板改单焦点 + 出击预估。这是从"网页"到"游戏菜单"的转变
  4. 提示条包装（§5.2）— 加容器 + 状态切换动画 + 第二行预览
  5. 玩家脚底反射（§7.1）— 一个渐变就能大幅提升光的存在感
第三梯队 — 锦上添花
  1. 外部第二批（§4.2 方案 E 旧世界残留 + F 潮汐联动）— 让外部有叙事、有变化
  2. 净化器液位动效 + 排泄粒子（§1.3）
  3. 储藏容量液位线（§1.2）— 让物体参与游戏状态反馈
  4. 外部第三批（B 侵蚀痕 / D 渗入物 / G 声音联动）
  5. 面板 CRT 噪声（偶尔像素抖动/scanline 闪烁，需极度克制）
◆ 一句话总结（v2）

净化点的问题不是缺功能，是缺"完成度"。 所有系统都在正确的地方——交互逻辑通了、颜色编码通了、面板功能通了、程序化渲染通了。 但每一件东西都停在了"能用"的最低标准： 形状能识别，但不像物体；信息能看到，但不好用；氛围有底色，但没有细节。

v2 的核心判断比 v1 更锋利：当前所有世界内实体都是占位符。 把六边形变成反应装置、把圆点变成空间裂缝、把平铺面板变成主-从菜单—— 这三件事做完，净化点就从"原型"变成"游戏场景"。

优先级上，裂隙入口的重做应该是第一件事—— 它是通往游戏主体内容的门，也是玩家每次回到净化点都会看到的东西。 一个设计得好的空间裂缝，能把这个场景的完成度整体拉高一个档次。
