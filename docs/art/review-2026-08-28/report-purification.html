⚑ 统领本次审核的核心判断
简单几何体 ＝ 占位符，不是可交付给玩家的最终内容

净化点当前的所有世界内实体——三个模块、四个交互点——都在用基本几何形状（六边形 / 正方形 / 三角形 / 圆形） 表达身份。这在开发早期是完全正确的做法：用最少的成本建立可交互的空间逻辑和颜色编码体系。

但几何体只完成了"标识"功能，没有完成"存在"功能。 玩家看到的不是"一台正在运转的净化设备"或"一道撕裂现实的空间裂缝"， 而是"一个蓝色的六边形"和"一个青色的圆点"。 这两者之间的差距，就是原型与成品的差距。

判断标准很简单：如果这个形状被替换成另一种颜色/另一种几何体， 玩家会不会觉得"东西变了"？如果会——说明当前的视觉只承载了编码信息，没有承载物体本身。 如果不会——说明它只是个图标。当前所有实体都属于后者。

以下的每一条建议，都遵循同一个处方：保留几何轮廓作为身份识别（它已经工作了）， 在轮廓之上叠加"物体层"——体积、结构、材质、使用痕迹、运转迹象。

一、三个模块实体：从「形状」到「设备」

三个模块共享同一个问题：纯色填充 + 稍亮描边 = 图标，不是设备。 它们没有体积感、没有结构细节、没有"使用过的痕迹"、没有"正在运转"的迹象。 保留各自的几何轮廓（身份识别已经建立），但要在轮廓内建立可读的物体结构。

全场景统一视角公约：45° 伪 3D 为什么不是纯俯视：纯俯视（正上方看下去）只能看到顶面， 物体的"高度"完全丢失——一个反应炉和一个井盖在俯视下是一样的。 表现力上限太低，玩家读不出"这是一台立着的机器"。
为什么不是纯侧视：纯侧视（正前方平视）适合横版游戏， 但本作是俯视操作，玩家需要在地图上判断物体的占地位置与相对关系， 侧视会让占地范围失真，也无法表达"绕到它背后"。

45° 伪 3D 的落地约定（本节全部方案图都遵循）：
要素规则作用
顶面俯视可见，但按 y × 0.55 透视压缩既保留占地信息，又给出"从上往下看一点"的角度
侧面自顶面向下拉出高度，前侧亮 / 后侧暗体积感的主要来源——明暗差要拉到 30+ 才读得出来
高度轴竖直向上，物体"立"在地上区分"设备"与"地面标记"
接地底部一道椭圆投影唯一且最低成本的"落地"证据，缺了就浮空
尺度按重要性分配画布（40×56 / 32×44 / 32×40 / 32×36 / 32×32）画布尺寸差异本身就是层级，不只是画得大小不同

这条公约同时约束三个模块 + 三个交互点 + 玩家角色。 它是"所有这些东西属于同一个世界"的技术保证—— 违反它的那个物件，会立刻显得像从别的游戏里抠出来的。

1.1 核心（CORE）— 蓝六边形 → 燃烧薪柴的反应装置 占位
▲ 画面中心的蓝色六边形 — 当前的"核心"
观察 正六边形，#4488cc 纯色填充 + #6699dd 2px 描边，下方 3px 蓝色 HP 条。 完全对称、零纹理、零结构。它是一个二维色块，不是一台设备。
问题 核心是玩家最常交互的对象（分配薪柴的主目标），也是叙事上的"基地大脑"。 但它现在不值得被关心——玩家不会对一块蓝色六边形产生任何情感投射。 更糟的是，它缺少"正在运转"的证据：没有发光核心、没有能量流动、 没有散热、没有振动。一台静止的色块无法传达"勉强维持"这个核心氛围。
三个候选方案 —— 均保留六边形轮廓做身份，差异在内部体量语言 同一形状的三种"存在方式"：A 凸起（设备凸出地面）/ B 塔式（高瘦炉体，火焰自顶部烟囱溢出）/ C 开放式（炉口敞开，火焰直接冒出来）。

设定纠正（本轮最重要的一处）：核心的真相是燃烧薪柴， 而薪柴取自裂隙——也就是污染物本身。所以它必须是 炉 / 反应装置，不是"能量柱"或"控制台"； 光也必须与污染源同源，用 teal 而非原来的蓝色。
一束诡异的 teal 色火焰，本身就是叙事： 玩家一眼就知道烧的不是普通柴火——"我们在用污染维持自己不被污染"， 这句话不用一个字就说清楚了。
A · 炉膛式
六边形底座 + 六棱炉体 + 正面大观察窗（能直接看见里面在烧） + 顶部排气口 + 侧面燃料输入管。
取：观察窗把"燃烧"这个核心真相直接展示出来，信息最直白；45° 下炉体高度清晰可读。
舍：窗口占了正面大半，结构细节被压缩；火焰是静态帧，动效依赖观察窗内的循环动画。
B · 塔式
高瘦炉体 + 三道箍环 + 顶部烟囱（teal 火焰自顶部溢出）+ 底部观察窗 + 侧面燃料管。
取：轮廓最高，"塔"的识别度最强；烟囱火舌是最强的"运转中"信号，远处也看得见。
舍：底部细节被自身遮挡，利用率低；瘦高轮廓在网格中占地小，存在感依赖高度。
C · 开放式
六边形底座 + 敞开的燃烧池 + 三束 teal 火焰 + 顶沿六个固定卡榫 + 燃料输入。
取：最能读"在烧东西"，火焰完全可见；敞开式最贴"勉强维持"的粗粝感，像临时搭的。
舍：火焰最抢眼，可能压过另两个模块；缺少"密封容器"的安全感，与"精密设备"的调性有冲突。
绘制说明 三张均为 32×40 实际像素（比另两模块高——它是"塔"，不是"箱"）、 1:1、透明底、硬边，可直接进游戏；页面按 ~4× 放大显示（pixelated，不插值）。

配色已按设定改为污染源同源：
部位颜色说明
炉体结构#3a3d42 / #2c2e33金属灰，保持工业感，让火焰成为唯一光源
火焰外焰#1a6b5c → #2ae6c8与污染同源的 teal，替代原蓝色 #4488cc
火焰内焰#7fffee → #dffff8白热，只占 1–2px，是"高温"的读数
观察窗玻璃#0e202a极暗衬托，让火焰成为窗内唯一亮点

本轮踩的坑：第一版想用 alpha=0 的矩形当占位， 结果 PIL 的 Draw.rectangle 是直接替换像素而非 alpha 混合， 把刚画好的火焰整个抹成了透明。教训：在 PIL 里"不画"就是别调用，不要用透明矩形占位。

1.2 储藏（STORAGE）— 橙正方形 → SCP 式薪柴收容单元 占位
▲ 核心右侧的橙色正方形 — 当前的"储藏"
观察 正方形，#cc8844 填充 + #ddaa66 描边，边长 ≈ 28px。 和核心的唯一区别是"六边形 vs 方形"和颜色。同样零结构。
问题 正方形是最缺乏个性的几何体——它读作"按钮""图标""色块"， 几乎不可能读作"一个装东西的容器"。 而"储藏"的语义核心恰恰是容积和可开启。 当前的平面方块完全没有传达这两点。

更隐蔽的问题：橙色 (#cc8844) 是场景中的暖色， 但它没有物理来源。核心的蓝光可以解释为能量， 净化器的 teal 可以解释为污染处理——储藏的橙光来自哪里？ 如果是"指示灯"，那灯在哪里？没有光源的发光会破坏画面的物理可信度。
三个候选方案 —— 储藏的语义核心是"容积"，三种截然不同的容器语言 A 封闭箱体（东西藏起来，靠错位表达厚度）/ B 开放货架（东西露出来，物资即信息）/ C 立式收容舱（高舱体，大面积观察窗）。

设定纠正：这里存的不是玩家的装备， 是薪柴——也就是从裂隙带回的污染物。 所以它不该是暗黑like 的宝箱/装备箱，而应该是 SCP 基金会式的收容单元： 厚重、密封、带编号、有警示标识、能透过观察窗看见里面那东西还在。
关键词：收容（containment），不是收纳（storage）。 玩家对它的情绪应该是"这玩意儿被关在里面"，而不是"我的东西放在这里"。
A · 密封罐（横卧）
圆柱罐体 + 正面观察窗（里面是薪柴） + 警示环带 + 顶阀 + 两侧加固肋 + 铆钉。
取：圆润罐体最像"压力容器"，收容感最强；观察窗让内部可见但保持密封。
舍：丢失了方形身份编码；罐体弧面在像素下需要靠箍环破形，否则像色块。
B · 收容箱（方正）
厚重金属箱 + 双侧多重锁扣 + 编号铭牌 + 观察窗 + 底部警示斜纹 + 四角铆钉。
取：最贴 SCP 收容单元——编号、多重锁、警示带三件套齐了；保留方形轮廓，既有编码不用动。
舍：方形与"容器"的读感偏弱，容易看成普通货箱；细节多，依赖描边才不糊。
C · 立式收容舱
高舱体 + 大面积观察窗（分两格） + 顶部六螺栓密封盖 + 侧面加强柱 + 警示带。
取：观察窗最大，内部薪柴的存量变化在世界内直接可读；立式轮廓在三个模块里最独特。
舍：最高，可能压过核心的体量感；密封盖螺栓在 32px 下偏碎。
绘制说明 三张均为 32×36 实际像素、1:1、透明底、硬边，可直接进游戏。

收容感是怎么做出来的（四个信号，缺一不可）：
信号实现心理作用
密封多重锁扣 / 六螺栓顶盖 / 加固肋"打不开"——它是被关住的
编号铭牌上的刻痕（抽象为短竖线）被登记在册，是"项目"不是"箱子"
警示暗黄斜纹 #8a7a3a（不用亮黄）危险，但压得住暗色调
可见观察窗内的 teal 微光看得到里面那东西还在——恐怖感来源

关键取舍：观察窗内的光必须克制。 第一版我画了满窗的 teal，看起来像"整个箱子都在发光"，收容感全失， 变成了能量罐。改小到只透一点之后，"里面有东西被关着"的感觉才出来—— 收容的恐怖在于克制，不在于展示。

1.3 净化器（PURIFIER）— 三角锥台 → 神秘学空气净化器 方向对，需深化
▲ 画面下方的绿色双层三角 — 当前的"净化器"
观察 外层大三角 + 内层小三角嵌套。外层 #1aad96 描边，内层 #0e4a3f 填充。 这是三个模块中唯一有"设计意图"的形状——三角锥台天然带有方向性（尖端向下）和功能联想（漏斗 / 反应堆 / 处理装置）。
肯定 + 三个问题 方向正确：双层嵌套提供了深度感，三角尖端向下的方向性是其他两个模块没有的优势。

问题 1 — 体量失控：双层三角的像素面积明显大于核心六边形， 加上位于画面底部中央（玩家出生点附近），它成为了视觉焦点。 但核心才应该是主角。视觉权重倒置了。

问题 2 — 双层退化：内层填充 #0e4a3f 在 #0d1114 背景上几乎不可见， "双层"效果在正常视距下退化为"一个带描边的三角形"。设计意图没有传达出来。

问题 3 — 静止：它看起来不像"在工作"。 一个净化装置应该有流动感——有什么东西被吸入、被处理、被排出。 当前是完全静态的。
三方案共享的技术规格 —— 三个形态候选见下
  • 控制体量：让视觉重量低于核心。三角形是强势形状，需要主动压制
  • 内层提亮：从 #0e4a3f → #1a6b5c 或更亮。 "双层"必须在任何距离都可辨，否则这个设计就白做了
  • 三角锚点：外层三角三个角各一个 2×2px 圆点，#2ae6c8。 读作"固定栓"或"能量锚点"，同时强化三角的几何存在感
  • 处理液面（关键动效）：内层三角内有一条水平亮线（#2ae6c8，alpha 0.35）， 在三角内部缓慢上下移动（周期 4s，幅度 ≈ 内层高度的 30%）。 读作"里面在处理液体/能量"。一个 1px 线的移动就能让整个装置"活"起来
  • 排放口：三角尖端处一个 4×5px 的暗色矩形（#0a1a18），带有 1px 亮边。 读作"出口"
  • 排泄粒子：从排放口每隔 ≈1s 下落 1 个 1-2px 的 teal 粒子（#1aad96）， 下落 8-12px 后 alpha 渐隐。极克制——同时最多 2-3 个粒子存在
  • HP 受损：液面移动变得不规则（速度忽快忽慢 + 偶尔停顿）；粒子变得断断续续
A · 晶体塔（立式过滤）
六边形基座 + 立柱 + 三层悬浮晶体环（由大到小） + 顶部核心 + 环绕的空气微粒。
取：悬浮环天然带"过滤层"的读感，空气自下吸入、自上排出一眼就懂；动效接口最多（环的转速/亮度＝负载）。
舍：完全丢失三角轮廓，身份编码要重做；悬浮元素需要动画才成立，静帧下略散。
B · 悬浮环装置（同心旋转）
中心轴 + 三道同心悬浮环（断续描边＝旋转虚影） + 三枚悬浮符石 + 被吸入的微粒。
取：最神秘学——同心环＋符石，完全不是工业设备；旋转虚影用静帧就表达了"在转"。
舍：最不像"机器"，与场景的工业基调有张力；圆形与裂隙 C 方案、成长祭坛有轻微撞形。
C · 符文柱（古老石柱）
六边形基座 + 方柱 + 三圈符文带 + 顶部气流口 + 向上排出的气流 + 吸入的微粒。
取：最"古老"，与"神秘学"最贴；方形柱体是唯一保留三角锥台体量感的方案，改动最小。
舍：符文笔画在 32px 下需要简化到抽象符号，细节靠脑补；石质与另两模块的金属感不统一。
绘制说明 · 设定纠正 三张均为 32×44 实际像素（三个模块里最高——它是"塔"）、1:1、透明底、硬边，可直接进游戏。

上一版错在哪：把净化器画成了污水过滤器 （漏斗 / 喷淋 / 液面 / 排放口）。 但它净化的其实是渗透进净化点的微量污染——是气态的、弥漫的东西， 不是一管子污水。正确的比喻是神秘学空气净化器： 吸入空气 → 过滤 → 排出，全程没有"液体"参与。

改对之后的三个共同特征：
特征实现为什么
立式高瘦，不再是"宽底座＋锥台"空气处理是垂直流：下进上出
悬浮/旋转晶体环、同心环、断续描边替代风扇叶片——不用机械语言也能表达"在吸"
微粒周围散布的 teal 小点"空气在流动"的唯一视觉证据，成本极低

微粒是关键：悬浮环本身是静止的（静帧）， 真正让人读出"在换气"的是那些被吸入的小点。 这也是三个方案里最便宜、最有效的一笔—— 十几个像素就把"它在工作"说清楚了。

三个模块的统一处方 注意上面三个方案共享同一套方法，可以提炼为可复用的规则：
层级作用在三模块中的体现
轮廓层（保留）身份识别 — 已建立，不动六边形 / 方形 / 三角
体积层（新增）从"平面"到"物体"底盘+柱体 / 顶面+正面错位 / 双层嵌套提亮
结构层（新增）工业感 — 廉价高效散热槽 / 分层线 / 三角锚点 / 加固块 / 锁扣
光源层（新增）给颜色一个物理理由核心发光 / 指示灯 / 排放口
动效层（新增）"它在工作" — 从静物到设备核心脉动 / 液位线移动 / 排泄粒子
状态层（强化）HP → 视觉，已有关联但不明显裂纹加粗 / 角部凹陷 / 动效失律

二、四个交互点：从「圆点」到「场所」

2.0 总纲：圆点是可交互物设计中最偷懒的解法 需要重做
▲ 四个交互点：裂隙入口(teal/上) · 防御(紫/左) · 成长(橙/左下) · 加厚(灰白/右上)
观察 四个交互点全部是实心圆 + 描边圆环 + sin 呼吸，只有颜色不同。 半径 7-8px 中心 + 12-14px 外圈。加厚桩例外显示为绿色三角形（与统一语言冲突）。
为什么圆点不成立 (1) 它不告诉你这是什么。 圆点只能靠颜色编码，而颜色需要学习成本。 新玩家看到紫色圆圈不知道那是防御配置、传送门还是陷阱。 好的可交互物应该一眼就能猜出大概功能——门看起来像门，台子看起来像台子。

(2) 它没有尺度感。 所有四个交互点大小和视觉权重相同， 但裂隙入口（进入完整场景）的重要性远高于加厚桩（一次性操作）。 没有层级 = 玩家不知道先去哪。

(3) 它漂浮在空中。 没有阴影、没有与地面的连接、没有物理存在的迹象。 它看起来像一个误入游戏世界的 UI 图标。

(4) 它违背"低信息密度但需要高信息质量"的原则。 圆点是"最少的信息"，但不是"最有效的信息"。 一个精心设计的裂口能同时传达位置、功能、危险度、状态——圆点只能传达位置。
总原则 每个交互点应该是一个"场所"（place），不是一个"标记"（marker）。
• 接地：每个交互点在地面上有投影/基座/痕迹，不是悬空的
• 有体积：即使是扁平的，也要有顶面/侧面/厚度的暗示
• 有功能暗示：形状本身要能让人猜出用途
• 有尺度层级：按重要性分配视觉重量（裂隙 ≫ 防御 ≈ 成长 > 加厚）
• 颜色退为辅助：形状承担主要识别，颜色只做强化（这样色盲玩家也能玩）
2.1 裂隙入口 — 空间裂缝（强化：撕裂感 + 空间异常） 原方案欠考虑，重做
v1 方案的问题（自我修正） 我上一版建议"竖直椭圆形裂口 + 锯齿边缘"，方向偏了—— 那个方案读作物理破损（墙上裂了个洞），太实、太"物质"。 但裂隙入口的本质是空间异常：不是"墙上有个洞"， 而是现实本身被撕开了一个口子，另一边是另一个地方。 这两者的视觉语言完全不同。
正确的设计意图 裂隙入口是玩家从安全区进入危险区的唯一通道。 它必须同时传达三件事：
• "这里是入口" — 明确的、可定位的、有仪式感的
• "另一边不一样" — 透出的是异质空间，不是黑色空洞
• "过去就回不来了（暂时的）" — 有不稳定的、不可逆的暗示

它应该是整个净化点视觉上最引人注目、最超自然、最有分量的东西—— 因为它是通往游戏主体内容（裂隙探索）的门。
三个形态候选共用的技术规格（形态见下） 核心视觉概念：一道不稳定的现实裂口， 边缘不是平滑椭圆而是"撕裂"的不规则锯齿； 内部不是黑色而是缓慢流动/闪烁的异质色块（透出裂隙世界的一角）； 周围有溢出的光照亮地面。
  • 尺度（关键）：画布 40×56，裂口本体宽 ≈ 18-22px、高 ≈ 36-42px。 明显大于现在的小圆点（现在 ≈ 14px 直径）— 它是门，不是标记。 光这一个尺寸，就把"裂隙 ≫ 其他交互点"的层级立住了
  • 撕裂边缘：不是平滑曲线。用 8-12 段短线段拼成不规则轮廓， 左右两侧不对称，有几处"尖刺"向外突出 2-4px。 读作"现实被暴力撕开"，而非"设计好的椭圆门"
  • 内部（关键）：不是纯黑填充。用 2-3 层不同 alpha 的 teal 色块 做缓慢流动（可以用 2 帧交替或极慢的 UV 偏移）：
      · 底层：#0a1a18（近黑，作为"深度"）
      · 中层：#1a6b5c 的不规则斑块，极缓慢形变（周期 6-8s）
      · 高层：2-4 个 1-2px 的亮点 #7fffee，随机位置闪烁（每个亮 0.5-1.5s 后消失，另起一处）
      读作"透过裂缝看到裂隙世界的一角——有东西在那边动"
  • 边缘辉光：沿撕裂轮廓一圈辉光，#2ae6c8， alpha 0.5↔0.8 呼吸（周期 3s，比现在慢、比现在强）
  • 地面溢出光（关键）：裂口底部在地面上投下一片椭圆光斑， 半径 ≈ 24×10px，#1aad96，中心 alpha ≈ 0.15，向外渐隐。 这一条最重要——它让裂缝"接地"了，让它成为场地的一部分， 而不是漂浮的 UI 元素
  • 空间扭曲（可选但强烈推荐）：裂口周围 6-8px 范围内的地面 有轻微的像素偏移/错位（1-2px，向裂缝方向吸引）。 读作"靠近它，空间就开始不正常"。这是"空间异常"最有力的信号
  • 不稳定粒子：每隔 2-4s 从裂口边缘剥离 1 个 1px 亮点， 向外飘 6-10px 后消散。读作"这个裂口在缓慢地、不稳定地存在着"
  • 靠近时：辉光增强、内部流动加速、地面光斑扩大 20%、粒子频率提高。 读作"它在回应你的靠近"

参考信号：Control 的传送门（空间异常感）· Stalker 的空间异常（不稳定 + 危险）· Dark Souls 的雾门（仪式感 + 单向性）· Stranger Things 的逆世界裂缝（撕裂边缘 + 内部异质）
A · 垂直撕裂
12 段锯齿边（左右完全不对称）+ 径向深度渐变（边缘暗→中心亮）+ 灼热的撕裂边缘 + 空间拉扯（周围地面被拽向裂缝）+ 剥落碎片 + 地面溢出光。
取：最像"撕开"而非"打开"；边缘是画面最亮处，远处也一眼可辨；空间拉扯让"靠近它空间就不正常"成立。
舍：竖向长条可能被误读为柱子/障碍，需靠辉光与地面光斑强调"可进入"。
B · 多层裂口
现实被撕开三层，由外到内逐层收窄、逐层变亮，每层露出不同的东西；层与层之间有悬浮的剥落薄片。
取："层"是表达"这是空间而非平面"最有效的手法——三层嵌套让厚度一眼可读；信息层次最丰富。
舍：三层轮廓在小尺寸下容易糊成一团；元素最多，需最克制地用色。
C · 空间崩塌
不是"门"，而是这里的空间正在塌进去：不规则核心 + 周围地面碎裂成块 + 碎块正被吸入的坠落轨迹。
取：动态感最强——坠落轨迹让静帧也读作"正在发生"；最不像"设计出来的门"，危险感最足。
舍：形态最"散"，没有明确的轮廓，识别度依赖碎块的排布；不适合做"入口"的隐喻（更像灾害现场）。

绘制说明 · 这一组踩的坑最多 三张均为 40×56 实际像素、1:1、透明底，可直接进游戏 —— 注意它们是四个交互点里唯一用 40×56 画布的， 尺寸差异本身就是"这里最重要"的信号。

坑 3 — 溢出光喧宾夺主：第一版底部光斑又大又亮，比裂缝本体还显眼。 修正：alpha 压到 26/38，面积缩小 —— 光斑是"接地"的证据，不是主体。
2.2 供奉台（原「防御配置点」）— 供奉自裂隙取得的污染物 设定纠正 ⚠ 方向错了，重做
上一版错在哪 我把它当成了「武器架 / 操作台」去设计，画了槽位、弹药箱、炮塔基座。 但在这个游戏里，这里供奉的是从裂隙带回的污染物—— 它是献祭与转化的场所，不是军械库。

方向错了，整组方案作废重画。武器、槽位、支臂这些元素全部拿掉。
新方向 —— 三个形态候选，共用规则先说
  • 尺度：32×32 画布，明显小于裂隙（40×56）、与成长祭坛相当
  • 核心元素：台面/托盘 + 供品 + 符文三件套。 其中供品必须是污染物（teal 发光的晶体／团块）， 这是它区别于"普通桌子"的唯一特征
  • 供品的表现：可悬浮（＝仪式进行中）或置于凹槽（＝已供奉）。 供奉数量直接可见——玩家在世界内就能知道还差几份
  • 符文：刻在台面/基座上，用 teal 或暖色，是"仪式场所"的识别信号
  • 交互高亮：靠近时符文亮起（平时 alpha 0.15），而不是整个台子发光
  • 接地：底部投影。有供品时投影加深
A · 石制供台
六边形厚石台 + 中央供奉凹槽 + 悬浮的供品晶体（teal） + 台面六道放射符文 + 四支脚。
取：悬浮供品＝"仪式正在进行"，动效接口最自然（悬浮高度/辉光＝进度）；六边形与核心的底座语言呼应，像同一批造的。
舍：与核心的六边形有撞形风险，需靠尺寸和供品区分；石头材质与场景工业感略冲突。
B · 金属托盘
浅盘 + 三个供奉位（已供 2 / 空 1） + 两侧把手 + 三支脚。
取：供奉进度在世界内直接可读——一眼看出"还差一份"，这是三个方案里信息最实用的；金属材质与工业基调统一。
舍：最像"普通托盘"，仪式感最弱；空位容易被读成"破损"而非"待供奉"。
C · 立柱祭坛
六边形基座 + 断柱（柱身有裂纹与刻痕）+ 顶部供盘 + 悬浮供品 + 上升的光尘 + 柱侧挂饰。
取：废墟感最强——断柱天然讲述"这里曾经是别的东西"，最贴"勉强维持"；供品悬于断口之上，视觉焦点最集中。
舍：叙事性强但功能性弱，供奉数量不易表达；断柱形态与"可交互"的暗示有冲突（看起来像废墟而非可用的设施）。
绘制说明 三张均为 32×32 实际像素、1:1、透明底、硬边，可直接进游戏。 石材/金属走 concrete / metal 系列，供品统一用污染源同源的 teal （#2ae6c8 / #7fffee）—— 与核心的火焰、储藏的收容物、净化器的过滤环是同一族颜色， 这就把"污染物是这个世界的核心资源"这条设定在视觉上闭环了。

三个方案的真正分歧：供奉是进行中（A 悬浮）、 按份数计（B 三格）还是纪念性的（C 断柱）。 这会决定供奉系统的玩法表达—— 选 A 就做持续型仪式，选 B 就做收集型进度，选 C 就做一次性献祭。
2.3 成长祭坛 → 操作台（复古，非科技） 方向调整 ↻ 从"祭坛"改为"操作台"
方向调整 上一版走的是「石阵 / 骨祭坛 / 机械改造台」，偏"献祭场所"。 但成长的实际操作是玩家在这里做选择、调参数、投入资源—— 它的本质是操作台，不是祭坛。
红线：往操作台靠，但不能太科技、太现代。 不要屏幕、不要机械臂、不要发光面板——那些会让它像"科幻飞船的控制台"， 与本作的粗粝工业＋神秘学调性脱节。
新方向 —— 三个形态候选，共用规则先说
  • 尺度：32×36 画布（比另两个交互点高一点——台面需要高度）
  • 核心元素：可操作的元件——旋钮、拉杆、滑块、齿轮、曲柄。 玩家一眼要看出"这东西能动"，这是它区别于其他台面的唯一特征
  • 材质（关键）：黄铜 / 石头 / 木头 / 暗金属。 禁止：屏幕、发光面板、机械臂、LED 灯条——任何"现代"的东西
  • 可升级时：操作元件的位置/亮度变化（如滑块推到顶、旋钮转到头）， 让"我可以升级了"在世界内可读
  • 升级成功后：一次性动效 — 元件弹回初始位 + 一道暖光扫过台面
A · 黄铜控制台
黄铜台面 + 内嵌板 + 台面三旋钮（带指针） + 正面拉杆滑槽与手柄 + 刻度 + 加固角。
取：操作感最强——旋钮+拉杆+刻度三件套，一眼就知道"这东西是给人拧的"；黄铜是场上唯一的暖色，识别度极高。
舍：蒸汽/炼金调性偏强，可能与其他模块的冷灰调性有点跳；元件多，需靠明度分层才不糊。
B · 石刻操作台
六边形石台 + 内凹台面 + 三条刻痕滑槽（各带一枚滑块） + 台面六道放射符文 + 石基座。
取：最古老、最"神秘学"——石头＋符文，完全不是工业设备；与供奉台的石质语言呼应，像同一套仪式设施。
舍：石刻滑块的操作感弱于旋钮，需要动画辅助才读得出"能推"；与供奉台的石材有撞材质风险。
C · 木质工作台
木台面 + 内嵌板 + 两枚黄铜齿轮 + 正面曲柄（带把手）+ 木纹刻度。
取：手工感最强——木头+齿轮+曲柄，读作"有人在这里手工改造东西"，最贴"成长"的养成语义；材质与场景的破败调性最合。
舍：木头在废墟场景里略显"温暖"，需做旧处理；齿轮在 32px 下只有 8 个齿点，远看会糊。
绘制说明 · 怎么做到"操作台但不科技" 三张均为 32×36 实际像素、1:1、透明底、硬边，可直接进游戏。
手法说明
用机械，不用电子旋钮/拉杆/齿轮/曲柄＝机械传动；不画屏幕、不画发光面板、不画线路
用旧材质黄铜 #8a6a3a / 木 #4a3828 / 石，全部做旧，不反光、不崭新
明度分层台面亮 → 前侧中 → 后侧暗 → 内嵌板最暗，拉开 40+ 的差值，体积才出得来
元件对比旋钮用亮黄铜 #c09a5a、指针用极暗 #2a2018，指针是"能转"的读数

本轮踩的坑：第一版黄铜台面的明度挤在同一档（顶面 66 / 前侧 51 / 后侧 44）， 结果整个台子糊成一块橙色，读不出体积。 把层次拉到 43 / 62 / 90 / 99 / 168 / 192 六档之后， "台面—侧面—内嵌板"的关系才立起来。 复古材质尤其需要明度分层，因为它们本来就缺少强对比的固有色。

2.4 加厚桩 — 并入成长祭坛，暂不单独设计 已合并 ↘
处理决定 加厚桩不再作为独立交互点存在，功能并入成长祭坛（现为操作台）。
原本的推理是"它应该最小、最低调，用 24×24 画布表达层级"。 但现在回看，一个只做"加厚"这一件事的物件，不值得占用一个独立的视觉身份—— 它既加重了玩家的识别负担，又让交互点从四个变成三个时显得突兀。
合并后的落地方式
  • 入口：成长祭坛（操作台）的面板里增加「结构加厚」一项， 与成长升级并列，玩家在同一个地方完成两类投入
  • 世界内反馈：加厚生效后， 净化点边界与模块底座出现"加固"的视觉变化—— 例如底座多出铆钉/支撑件、边界膜变厚。 反馈落在被加厚的那个东西上，而不是新增一个小物件
  • 状态表达：可加厚时，操作台上对应的拉杆推到顶 / 旋钮转到头， 沿用操作台已有的语言，不引入新语汇
  • 好处：识别系统少一个成员（三个交互点 vs 四个）， 玩家的记忆负担下降；同时"加厚"从"去一个地方做一件事"变成"在操作台上多一个选项"， 决策更集中
如果日后要恢复它 需要给它一个独立于成长祭坛的语义—— 例如"临时加固某一段边界"（有位置属性、有持续时间）， 那样它就值得拥有自己的形态与身份了。 在此之前，作为操作台的一个选项存在即可。

三、地面：自然感 = 因果可追溯

3.1 问题：太干净，「勉强维持」只是文字不是视觉 错失的机会
▲ 靠近核心时的地面 — 几乎看不到任何材质差异
观察 地面为均匀暗灰（#1a1c1f ~ #151a1e），带极细微噪声。 在正常视距下噪声融合成"干净的深灰布料"。 看不到石板缝、磨损、污渍、任何材质线索。
为什么重要 净化点的氛围定义是"孤立、微光、功能性、空旷、勉强维持"。 "勉强维持"这四个字需要在视觉上有落脚点，而地面是最佳载体—— 它是场景中面积最大的元素，也是最能承载"时间痕迹"的表面。

当前地面太干净了。它不像一个被长期使用、缺乏维护的空间， 更像一个刚建好的空房间。这直接削弱了整个场景的叙事张力。
3.2 核心方法：自然感 = 因果可追溯
为什么"加装饰"容易失败 玩家的潜意识会问："这个痕迹为什么在这里？"
如果答案是"因为程序随机撒的"，大脑会立刻识别出这是假的—— 即使玩家说不出哪里不对，也会感觉"这个场景很廉价"。

自然 = 每一处痕迹都有一个可追溯的成因， 且这个成因符合物理常识或叙事逻辑。 这是"程序化装饰"和"设计过的环境叙事"之间的分界线。

四、净化点外部：从「黑墙」到「有东西在外面」

4.1 现状：边界做对了，外部太空了 单调
观察 安全区呈椭圆形，边界有 blob 扰动（不规则起伏，非完美几何椭圆）。 向外快速衰减至 #080a0c 绝对黑暗。 边界上有微弱亮点（可能是 boundary-atmosphere 的粒子）。
肯定 + 问题 边界本身做得不错：椭圆 + blob 扰动读作"自然形成的安全区边缘"， 黑暗过渡速度合适（够快让人不想出去，不至于快到产生硬切）。

问题是外部太空了。 当前外部 ≈ 均匀的纯黑 + 偶尔的微弱粒子。 这浪费了一个巨大的叙事机会：

净化点的核心叙事是"人类最后的立足点，被裂隙包围"。 外部不应该是"什么都没有的黑"——它应该是"有东西在那里，但你看不清"。
art-direction 说"看不清比看清更有效"—— 但前提是得有东西可看不清。纯黑意味着"没有信息"， 而"看不清的东西"意味着"有信息但拒绝给你"。这两者的心理效果天差地别。
设计目标（三条） 1. 外面是"活的" — 有什么东西在那里，在动，在观察
2. 这个边界是"人为撑起来的" — 不是天然的，是设备/仪式维持的，随时可能失效
3. 威胁是渐进的 — 随时间/潮汐推移，外部在逼近

以下 7 个方案按"投入产出比"排序。全部遵循一个铁律：克制—— 每个效果都应该是"偶尔发生"或"极微弱"的。持续演出会毁掉"低信息密度"的氛围， 也会让玩家脱敏。
4.2 七个方案（脑爆）
方案 A — 张力膜：让边界有"被撑起来"的质感
当前边界是"暗色轮廓线"，读作"墙"。把它改成一层有张力的膜：
• 边界不再是静态曲线，而是有极缓慢的波动/涟漪（周期 8-12s，幅度 1-2px）
• 偶尔（每 20-40s）出现局部凸起：某一段边界向外鼓出 3-5px，持续 1-2s 后回弹。 读作"有什么东西从外面顶了一下"
• 膜本身极暗（alpha 0.06-0.12），只有在波动时才被察觉
设计意图：直接传达"这个安全区是撑起来的，不是天然的"——呼应"勉强维持"
方案 B — 侵蚀痕：边界在被慢慢吃掉
安全区内侧边缘的地面有被"啃噬"的痕迹：
• 不规则的缺口啃进安全区（深度 4-10px，长度 15-30px，全图 3-5 处）
• 啃噬边缘的地面材质异常化：轻微结晶感（teal 极暗斑点，alpha 0.05）或褪色
• 越靠近边界，侵蚀越明显（与 3.2 的边界过渡规则叠加）
• 随潮汐/稳定度变化：稳定度降低时，侵蚀痕缓慢扩大
设计意图：让"安全区在缩小"这件事在空间上可读，而非只在 HUD 数字上可读
方案 C — 外部窥视：黑暗中有东西在看
边界外的黑暗中，偶尔出现成组的光点：
• 每 15-30s 出现一次，持续 1.5-2.5s
• 2 个或 4 个一组（成对/成组暗示"眼睛"，但不要画成眼睛的形状—— 保持为无定形光点）
• #2ae6c8 极暗（alpha 0.2-0.35），几乎看不清
• 出现和消失都是渐变的（0.4s 淡入 / 0.4s 淡出），不闪烁
• 位置随机，但总在边界外 8-20px（不近不远，恰好在"看不清"的距离）
设计意图：艺术方向明确禁止"成对眼睛"，但成组出现的光点能触发同样的 心理反应而不违反禁令。这是"看不清比看清更有效"的最佳应用
方案 D — 渗入物：边界在过滤，但过滤不干净
偶尔有细微的 teal 粒子从边界外飘入安全区：
• 每 8-15s 出现 1 个，从边界外侧 10px 处向内飘
• 进入安全区 6-12px 后，开始缓慢旋转/震荡，然后消散（被"过滤"掉了）
• 1px，#1aad96，alpha 0.3 → 0
• 极少数（约 1/10）能飘得更深（20-25px）才消散
设计意图：传达"边界是一个主动工作的过滤系统"——它有用，但不完美。 偶尔飘得深的那一个会制造"这次会不会出事"的紧张感
方案 E — 旧世界残留：曾经有人试图守住这里
边界外侧散落着旧世界的隔离设施残骸：
• 破损的警示带（1px 斜纹短线，褪色的 #b89040）
• 锈蚀的隔离桩（3×6px 小竖条，#3a3838，倾斜 5-15°）
• 褪色的危险标志（4×4px 方块，几乎看不出原来的图案）
• 只出现在边界外 5-15px，且大部分被黑暗吞没（alpha 0.15-0.3）
• 全图 4-7 处，分布不规则
设计意图：这是最有叙事密度的方案——它暗示"曾经有更多人、更完整的防线， 现在只剩这些"。用一个几乎看不见的细节讲完一整段历史。参考 Roadside Picnic / STALKER 的 "前人遗留物"叙事手法
方案 F — 潮汐联动：边界会呼吸，也会紧张
把现有的潮汐系统与边界视觉强绑定：
• 落潮期：膜波动平缓（周期 12s），外部光点极少（每 40s+），无渗入物
• 涨潮期：膜波动加剧（周期 6s，幅度翻倍），外部光点频率提高（每 15s）， 渗入物出现，边缘侵蚀痕略微扩大
• 临界状态（稳定度低）：边界出现局部破口—— 小范围（8-15px 宽）的黑暗侵入安全区，边缘闪烁警告色（#cc3333， alpha 0.3，周期 1.5s）
设计意图：让抽象的"潮汐/稳定度"数值变成看得见的环境状态。 玩家不需要读 HUD 就能感到"现在情况不太好"
方案 G — 声音的视觉化：从外面传来的东西
如果项目有音频系统，可以做一个视觉-听觉联动的极简效果：
• 某些"外部事件"发生时（如显形、外部光点出现）， 边界的对应位置有1-2px 的局部亮度扰动（持续 0.3s）
• 配合极低频的环境音（次声波级别，让人不安但说不出为什么）
设计意图：跨感官的一致性会让"外面有东西"这个暗示变得难以忽视， 即使玩家说不出具体看到了什么。如果音频系统未就绪，此方案可延后
实施建议 不要一次全上。 建议的组合：
第一批（高性价比，成本低）：A 张力膜 + C 外部窥视 — 两个效果就能把"黑墙"变成"有东西的黑暗"
第二批（叙事密度）：E 旧世界残留 + F 潮汐联动 — 让外部有故事、有变化
第三批（锦上添花）：B 侵蚀痕 / D 渗入物 / G 声音联动

铁律：所有效果的默认状态是"不发生"。 它们的价值来自 rarity ——如果外部光点每 3 秒出现一次， 它就从"不安"变成了"装饰"。
方向纠正 —— 我上一版理解偏了 上一版把力气全花在了膜与边界的雕琢上（张力膜、侵蚀痕、旧世界残留）。 但边界现在已经做得不错了，它不是重点。

真正的重点是外面那片黑：里面有东西， 但绝对不是任何我们熟悉的东西。 上一版的「旧世界残留」（断裂的墙、管道、警示牌）恰恰是最不该做的方向—— 它把"不可名状"降格成了"废墟"，玩家一看就懂，也就一点都不吓人了。已作废。

正确的参照系是克苏鲁：不是"画一个怪物出来"， 而是让玩家确信那里有东西，却永远看不清它是什么。 恐惧来自两件事——巨大的尺度与看不清， 而不是造型有多精巧。

注意它们的共同点：都不画完整—— 只给一段弧、一个轮廓、几圈涟漪，剩下的交给玩家的想象。

一道横跨画面的弧——某个巨大到看不出全貌的东西的上缘。眼球半径 132px，画面只有 96px 高，玩家永远看不到它的边界；弧线断续、带一点湿润反光，虹膜只是几道几乎不可辨的同心弧。
取：巨物感是最强的氛围杠杆。尺度越大、露得越少，压迫感越强；不画瞳孔、不画睫毛，避免了"一只眼睛"的具象，反而更像"某个器官的一部分"。
舍：含蓄到可能被忽略——需要配合极缓慢的开合/位移才立得住。
乙 · 类人影
一个站立轮廓，但比例是错的：双臂过膝、躯干细长、头部过扁、关节位置不对。无五官、边缘抖动模糊、脚下与地面没有明确接触。
取："像人"这件事本身就是恐怖来源——大脑会先识别成人，再发现哪里不对，这个延迟最不舒服；比例失真比奇形怪状更有效。
舍：过犹不及——如果失真太夸张就变成怪物设计，反而落回"熟悉的东西"。
丙 · 呼喊
六圈向外扩散的声波，但每一圈都被扰动（三重噪声叠加，不是同心圆）；中心是一团边界全糊的暗影，看不出声源是什么；声波之间有几处被"撕开"的裂口。
取：声音的视觉化最省成本也最不安——它暗示"有东西在叫"，却不给出任何形体；不规则波形让"声源非人"这个信息被直觉接收。
舍：需要动画（扩散/淡出）才完整，静帧只能表达一半；波纹太规整会像 UI 特效。

做法说明：全部用"极暗 + 少量形体暗示"实现。 这比纯黑或画清晰的怪物都更有效—— 纯黑等于没做，画清楚反而不吓人。
技术要点：当形体与背景的明度差只有 2–3 时， 靠明度区分会完全失效。巨眼那一版就踩了这个坑： 眼球内部与虚无只差 3，等于隐形。 改用色相区分（眼球偏 teal、虚无偏中性）并加一层体积渐变之后， "那里有个球体"才读得出来。
最后：外部的价值恰恰在于那个"看不清"的距离—— 玩家会用自己的想象填满它，而想象永远比画出来的更可怕。

5.1 右上角 HUD：从 debug overlay 到状态栏 需重构

5.2 底部提示条：世界层与 UI 层之间的桥梁 需包装
观察 Tab:存续报告 Esc:记录 裸文字贴在底部，无容器、无动画。
问题 这是玩家与场景交互的主要引导通道，但视觉优先级低到容易被完全忽略。 更关键的是：靠近交互点时它应该切换为该交互点的操作提示， 但这个动态行为在视觉上没有得到强化。
方案
  • 容器：background:rgba(15,17,20,0.88); border:1px solid #2a2d32; padding:5px 16px;
  • 文案层级：按键 [E] 用亮色 #c8cdd4 + 方括号；描述用暗色 #8a8f96；间距 6px
  • 状态切换：无目标时 opacity 0.5（弱化，不抢注意力）； 靠近目标时 opacity 1.0 + 150ms 过渡。 这个过渡本身就是"有东西可交互了"的信号
  • 第二行：靠近模块时显示状态预览（10px #666a70）， 如 HP 60/100 · 混乱抑制 -18%。 这让"要不要现在交互"可以在移动中决策，不必先打开面板
技术工作量极小（纯 CSS + scene.update() 一行逻辑），但它是世界层和 UI 层之间唯一的桥梁。
实际绘制：提示条与世界对象的关系 下面这张按实际比例画出了提示条（300×46）与它所指的交互点之间的引导线。 这条线就是"世界层 → UI 层"的翻译： 玩家看到的不是一行字，而是"那个东西可以按 E"。

六、交互面板：从「网页平铺」到「游戏菜单」

6.1 核心诊断：这是网页布局，不是游戏菜单 信息架构需重构
▲ 左：Tab 状态总览 · 右：E+核心 分配面板
先肯定 载体风格选对了。磷光屏 + 扫描线 + CRT vignette + 等宽字体， 与"工业终端监控"的设定完美契合。 四周漏出游戏画面的做法很棒——面板读作"浮在世界上方的透明界面" 而非"遮住世界的全屏菜单"，保持了空间连续性。键印导航（↑↓ 选 / Enter 确认 / Esc 关闭）一致且清晰。
问题不在视觉风格，在信息组织方式。
网页 vs 游戏菜单：本质区别
维度网页式（当前）游戏菜单式（应该）
信息呈现所有内容同时可见，靠眼睛扫描层级递进，一次只显示一层
导航方式滚动 / 扫视 / 搜索方向键 + 焦点，位置即状态
空间组织纵向堆叠，内容多长页面多长固定视口，主区+从区，导航切换内容
焦点无明确焦点，用户自己找始终有一个"当前选中项"，视觉跟随
详情处理和概览混在一起平铺渐进披露：选中后才展开详情
操作 vs 信息混排分离：可操作项有明确焦点，只读信息降为次要
心理模型"阅读一份文档""操作一台设备"

当前面板是"把数据库查询结果显示在屏幕上"—— 信息齐全、排列整齐，但玩家需要自己在大脑里建立层级。 好的游戏菜单应该把层级做在界面上，让玩家的大脑只负责决策。
四条重构原则 1. 主-从结构（Master-Detail） — 一个导航区（有什么）+ 一个详情区（选中的是什么）。 而不是所有内容平铺。
2. 渐进披露（Progressive Disclosure） — 先给"是什么"，选中后才给"细节是什么"。 一屏信息量控制在 7±2 个组块。
3. 焦点驱动（Focus-Driven） — 始终有一个明确的当前选中项， 视觉焦点（高亮/边框/背景）跟随它移动，其余内容降为次要。
4. 状态优先（State over Description） — "能不能用""够不够资源""当前是什么状态"这类决策相关的信息， 优先级高于描述性文字。

6.4 跨面板：空状态与文案
两个具体问题 (1) 空状态太消极 — "无可用残骸""尚无残渣"只说了"什么都没有"， 没说"怎么获得"。空状态是展示世界观的好机会，浪费了。
(2) 升级描述偏抽象 — "抵御裂隙隐蚀…""更高效的收割…"是氛围文案， 但玩家在决定"花 8 级薪柴换这个"时需要具体数值。
方案
  • 空状态：虚线轮廓图标（40×40）+ 2 行弱化引导文案， 如「在裂隙中击败敌人可获得残骸」。 不要留纯黑空白——那看起来像渲染错误
  • 升级描述：氛围文案保留（它是世界观的一部分）， 但在下方补一行具体数值， 如 抵御裂隙隐蚀… + 混乱积累 -4%。 氛围和实用性不必二选一
  • 不可达状态：当资源不足时，卡片应进入禁用态 （opacity 0.4 + 边框变暗 + 成本显示为红色）。 当前所有卡片看起来都可交互，但实际一个都买不起——这是误导
实际绘制：空状态该长什么样（520×260） 空状态是最容易被做成"渲染错误"的地方—— 一块纯黑或一句"无数据"，玩家的第一反应是"是不是坏了"。 下面这张是可直接照抄的模板。

三件套缺一不可： ① 这是什么（"暂无污染物"）——斜线填充的占位框表示"这里将来会有东西"； ② 为什么空（"污染物来自裂隙入口，取得战利品后会显示在这里"）—— 把空的原因翻译成下一步的线索； ③ 现在该做什么（"前往裂隙入口"按钮 + 快捷键）—— 给一个可点击的出口，而不是让玩家自己去找。

7.1 暖光存在感可以更强 方向 ✓ 可优化
▲ 靠近核心时的玩家角色 + 暖色灯光
观察 玩家（工业防护人形）周围有微弱暖色光晕，是场景中第三类光源（另两类是模块发光和交互点）。
肯定 + 可改进 肯定：暖光在冷色场景中非常突出，"你是这个世界里唯一的暖色来源" 这个叙事声明在视觉上成立了。

可改进：光晕偏微妙，需要刻意看才注意到。 考虑到这是一个强烈的叙事声明，暖光可以更自信一点—— 不是扩大范围（会影响平衡），而是提高核心区域的亮度和饱和度。

灯尘：静态截图中不可见（可能是帧限制）。 如果运行时也不够明显，需要调整参数。
方案
  • 核心亮度：灯光核心半径内的亮度提高 15-20% （更多 #c4873a 像素达到 alpha 0.4+）
  • 脚底反射（高性价比）：玩家脚下加一个极微弱的暖色圆形渐变 （半径 12px，max alpha 0.08）。 在暗环境中，地面反射能极大增强"光的存在感"—— 因为它证明了光是照在实体上的，而不只是贴在角色身上的贴图
  • 灯尘参数：改为"少而亮"而非"多而弱" — 尺寸增到 2px，发射频率降到每 0.8s 1 个，但初始 alpha 提到 0.5-0.6。 少量高对比粒子比大量低对比粒子更容易被感知
  • 与地面痕迹联动：玩家走过时，暖光会照亮 3.2 节提到的地面裂缝。 这个交互是"免费"的（光照系统已存在）， 但能让地面痕迹从"背景装饰"变成"被探索的对象"
实际绘制：暖光的"存在感"差在哪（480×240 对照） 左＝当前（几乎看不出有光），右＝建议（5 层衰减的光圈，并照亮地面纹理）。 两张图用的是同一个角色、同一片地面，唯一的差别就是光。

建议版本用 70 / 56 / 42 / 30 / 18 五层半径做径向衰减 （alpha 分别 10 / 18 / 28 / 42 / 60）， 边缘用 (1-d/r)^0.6 的曲线让它自然过渡而非生硬圆环。
关键不是"更亮"，而是"照亮了东西"—— 光圈范围内刻意点了地面颗粒，让暖光有东西可照。 光打在纯色地面上是没有存在感的，只有照出纹理，玩家才会意识到"这里有个光源"。
另：与 3.2 节地面裂缝联动后，玩家走过时裂缝会被侧光"显影"， 地面就从背景变成了被探索的对象——这是本章性价比最高的一笔。

放到场景里看：暖光渲染图（480×320） 上面那张是对照示意，说明"差在哪"；这一张是放进实际场景后的效果—— 玩家站在一片废墟地面上，光圈是他唯一的领地，之外全是不知道有什么的黑暗。

① 暖光半径 ≈108px，5 层径向衰减（alpha 26/44/70/104/150， 曲线 (1-d/r)^0.6）避免生硬圆环； ② 光圈内才生成地表细节——颗粒、裂缝、石子。 光打在纯色地面上是没有存在感的，只有照出纹理， 玩家才会意识到"这里有个光源"； ③ 石子的投影方向一致（光来自玩家），这是"光有方向"的读数； ④ 暗角压低画面外围，强化"光是有限的、外面是危险的"； ⑤ 远处模块只被照亮一侧边缘，给出空间纵深。
角色的处理：身体刻意压暗、光源核心提到近白（#fff8e8）。 否则角色会被自己的光池淹没——第一版就犯了这个错， 整个中心糊成一团暖色，分不清哪是角色、哪是光。

八、优先级排序

按"对玩家第一印象的影响程度"排序，不考虑技术难度。 第一梯队决定玩家是否觉得这是个"做完的游戏"。

第一梯队 — 决定第一印象（不做 = 看起来像原型）
  1. 四个交互点从圆点改为场所（§2）— 最"未完成"的部分。 裂隙入口优先：做成竖直空间裂缝（撕裂边缘 + 内部异质流动 + 地面溢出光）， 它会立刻成为场景的视觉焦点和记忆点。防御/成长按确认的方案，加厚桩改为小地桩
  2. 三个模块从形状变为设备（§1）— 按「轮廓/体积/结构/光源/动效/状态」六层处方执行。 最少成本最高收益的是：储藏的"顶面+正面错位"（立刻有体积）和 核心的"发光核心 + 散热槽"（立刻像设备）
  3. HUD 面板化（§5.1）— 加背景框 + 分组 + 字号层级。 30 分钟工作量，直接消除"debug overlay"感
第二梯队 — 决定沉浸感和可读性
  1. 外部丰富化第一批（§4.2 方案 A + C）— 张力膜 + 外部窥视。 两个低成本效果就能把"黑墙"变成"有东西的黑暗"
  2. 地面加因果痕迹（§3.2）— 严格按十条规则，总覆盖率 5-8%。 "自然"的关键不是加什么，是每处痕迹都有成因
  3. 面板信息架构重构（§6）— 状态面板改主-从三段式； 分配面板改单焦点 + 出击预估。这是从"网页"到"游戏菜单"的转变
  4. 提示条包装（§5.2）— 加容器 + 状态切换动画 + 第二行预览
  5. 玩家脚底反射（§7.1）— 一个渐变就能大幅提升光的存在感。 ⚠ 并入迭代 9，不单独派工（见 §7 顶部警告）
第三梯队 — 锦上添花
  1. 外部第二批（§4.2 方案 E 旧世界残留 + F 潮汐联动）— 让外部有叙事、有变化
  2. 净化器液位动效 + 排泄粒子（§1.3）
  3. 储藏容量液位线（§1.2）— 让物体参与游戏状态反馈
  4. 外部第三批（B 侵蚀痕 / D 渗入物 / G 声音联动）
  5. 面板 CRT 噪声（偶尔像素抖动/scanline 闪烁，需极度克制）

◆ 一句话总结（v2.1）

净化点的问题不是缺功能，是缺"完成度"。 所有系统都在正确的地方——交互逻辑通了、颜色编码通了、面板功能通了、程序化渲染通了。 但每一件东西都停在了"能用"的最低标准： 形状能识别，但不像物体；信息能看到，但不好用；氛围有底色，但没有细节。

v2 的核心判断比 v1 更锋利：当前所有世界内实体都是占位符。 把六边形变成反应装置、把圆点变成空间裂缝、把平铺面板变成主-从菜单—— 这三件事做完，净化点就从"原型"变成"游戏场景"。

优先级上，裂隙入口的重做应该是第一件事—— 它是通往游戏主体内容的门，也是玩家每次回到净化点都会看到的东西。 一个设计得好的空间裂缝，能把这个场景的完成度整体拉高一个档次。
