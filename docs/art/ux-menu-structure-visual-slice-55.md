# 主菜单三组空隙与主次（Slice 5.5 视觉合同）

> **给 code 的 px 合同。** 结构三组与游标归属已锁，本文只定整数空隙、字号/色阶、游标占位、Y 累加。不加玻璃/扫描/框/线/凹槽。不把本屏做成 DEC-049 墙机。

机械层已扫。审美待人终审。本 Slice **不标 COMPLETE**。

## 开工闸门（本核填写）

| 项 | 本屏 |
| -- | ---- |
| 载体 | **C 元界面**。玩家尚未进入叙事空间；允许「这是标题」。**不要**做成 DEC-049 墙机 680×468，也不要磷光外壳。 |
| 实现 | Phaser 画布字。`#dom-ui-root` **不适用于**本屏（architecture 已记的例外）。主菜单 camera zoom = 1，不是角锚 HUD。 |

| 本屏不像 | Dashboard / 设置页 / 存档槽浏览器 / 确认对话框链 / 墙机 CRT |

具名参考（与结构合同同一套，学动作不学皮）：

| 游戏 | 锚的动作 | 明确不学 |
| ---- | -------- | -------- |
| Signalis | 标题是身份，下面才是可走的路；空场大字，没有屏壳 | 曲面畸变、扫描吃字、把标题页做成检视仪 |
| FTL | 纪录是读数（上次到哪），入口是另一组动作；层级靠亮度两档灰 | New Game / Continue 软件词、供电格、全息蓝 |
| Into the Breach | 事实写成可分读的节点（表名/值/档位分开） | 精确格子预告、高饱和边框、用线框分区 |

P0（零操作须立刻答上，≤6）：身份（`存续` + 副题）；有纪录时三行读数；动作 1 或 2 行；覆盖确认时警告句替换读数三行。P1/P2 不设。

「哪台机器」：世界外标题字（Courier New，Kit 两档灰）。组分离的物理原因是**空**（行与行之间没有物件），不是框、不是线、不是凹槽。本核不加投影/发光/圆角/脉动/扫描。

复用：Kit §A2 两档灰 `#8a8f96` / `#c8cdd4`；§A3 字号档（标题 28 元界面放大、副题 Body 13、读数 Label 12、动作沿用已在用的 16）。禁止新色、新字号档、新基元。

## 1. 组间空隙 vs 组内行距

逻辑分辨率 **960×640**。基础单位 4px。

**读法：** 组间空必须一眼大于组内行距。当前实现读数末行→动作首行空约 10px，与动作组内行距同级——这是结构失败点。本核把组间空锁到组内空的 4× 量级。

下表「行盒之间空」是意图；**code 用「中心距」列**（Phaser Text `origin.y = 0.5` 的 Y 步进）。不要再发明第三套间距。

| 关系 | 行盒之间空 | 中心距（code） | 常量名 |
| ---- | ---------- | -------------- | ------ |
| 身份组内：标题 ↔ 副题 | 8 | **34** | `ID_INTRA` |
| 读数组内：三行读数之间 | 4 | **20** | `READ_INTRA` |
| 读数组：确认态只有警告 | — | 无组内步进 | （单行，不累加 `READ_INTRA`） |
| 动作组内：两行动作之间 | 8 | **28** | `ACT_INTRA` |
| 组间：身份 ↔ 读数（副题 → 首行读数或警告） | 32 | **48** | `GAP_ID_READ` |
| 组间：读数 ↔ 动作（末行读数或警告 → 首行动作） | 32 | **52** | `GAP_READ_ACT` |
| 组间：无纪录时 身份 ↔ 动作（副题 → 唯一动作） | 40 | **60** | `GAP_ID_ACT` |

约束：

- 组名不上屏。分离只靠上表空隙 + 第 2 节字级。**禁止**分隔线、框、凹槽、玻璃、扫描。
- 三组同一竖轴（身份/读数水平居中；动作左对齐后整块居中，见第 4 节）。必须读成三块，不能读成一条匀进行列。
- 无纪录：不画读数组，不留空表，动作用 `GAP_ID_ACT` 接在副题下。

行盒高度（只用来理解中心距，code 不必再算）：标题 34（28+top6）、副题 17（13+top4）、读数/警告 16（12+top4）、动作 20（16+top4）。CJK top padding 沿用裁切合同；本核 **12px 读数/警告** 补一行：`top: 4`，左右底 0。不要为补偿 origin 再改行距。

## 2. 读数弱 / 动作强（字号 + 色）

失败点：摘要**值** 16 + `#c8cdd4` 与动作行 16 同级，读数会被当成第三种按钮。拉开手段：读数整簇降到 Label 12 + 暗灰；动作保持 16；亮灰只给标题和**已选中动作**。

不引入第三档灰。不用 `#5a5f66` 做字。不用红做警告。

| 文字角色 | fontSize | color | Kit 档 | 出现 |
| -------- | -------- | ----- | ------ | ---- |
| 身份 · 标题 `存续` | **28** | `#c8cdd4` | H1 元界面放大 | 根菜单 + 覆盖确认 |
| 身份 · 副题 | **13** | `#8a8f96` | Body | 根菜单 + 覆盖确认 |
| 读数 · 表名 | **12** | `#8a8f96` | Label | 有纪录三行 |
| 读数 · 值 | **12** | `#8a8f96` | Label | 有纪录三行（**禁止**再 16 / 禁止亮灰） |
| 读数 · 档位 | **12** | `#8a8f96` | Label | 有则画；无则该节点不建 |
| 读数 · 警告句 | **12** | `#8a8f96` | Label | 覆盖确认唯一读数行 |
| 动作 · 静默（未选中） | **16** | `#8a8f96` | 本屏已有动作档，非新档 | 根菜单 + 覆盖确认 |
| 动作 · 已选中 | **16** | `#c8cdd4` | 同档 + 亮灰 | 同时只一行 |

读数行内节点：表名 / 值 / 档位仍分三个 Text，水平间隙 **12**（已有，保持）。禁止 `·` 粘句。整行作为一组水平居中。

覆盖确认：警告用上表「读数 · 警告句」，**不是**动作强。两条动作与根菜单同一套动作规格（16 / 两档灰 / 同一游标规则）。

字体族不变：`"Courier New", monospace`。标题可 `bold`（已有）。读数与动作不加粗。

## 3. 只用留白，不用线

主菜单仍是空场大字：

- 无玻璃、无扫描、无框、无分隔线、无凹槽、无径向发暗
- 组分离 = 第 1 节空隙 + 第 2 节字级
- 底色保持色板深黑（视觉通行证已锁 `#0a0b0d`），本核不改底

## 4. 游标视觉（写死，code 不要猜）

结构已锁：游标只属动作行。读数 / 警告 / 身份禁止 `>` / `▸`。

| 状态 | 前缀 | 字色 | 其它 |
| ---- | ---- | ---- | ---- |
| 已选中 | 左侧 **`▸`**（U+25B8） | `#c8cdd4` | 同时全屏只一枚 `▸` |
| 未选中 | **无可见前缀** | `#8a8f96` | 空位里不得再画 `>` 或第二套符号 |

**占位选 paddingLeft，不用空格。** Courier + CJK 下空格宽 ≠ `▸` 宽，用空格会对不齐。

写死：

```
PREFIX_SLOT_PX = 20
```

- **已选中**：`setText('\u25b8 ' + label)` —— `▸` + **一个** U+0020 + 文案词。`paddingLeft = 0`（top padding 仍 4）。
- **未选中**：`setText(label)`（不要前导空格、不要 `>`）。`paddingLeft = 20`。
- 两行都 `setOrigin(0, 0.5)`，同一 `actionLeftX`：

```
actionLeftX = width/2 - (PREFIX_SLOT_PX + maxLabelWidth) / 2
```

`maxLabelWidth` = 本屏动作文案（不含前缀）在 16px Courier 下的最大宽。根菜单与覆盖确认各自量一次。

结果：切游标时汉字列不动；屏上只有一枚 `▸`。

净化点底栏单行 `>` **本轮不改**（那不是列表游标）。

## 5. 覆盖确认

与根菜单同一套三组，不要第四种画面语言。

```
身份     存续                              28 / #c8cdd4
         边界仍在，光尚未熄                  13 / #8a8f96
         （GAP_ID_READ）
读数     将清除第 {tideNumber} 潮的全部记录   12 / #8a8f96   ← 无游标
         （GAP_READ_ACT）
动作     清除后进入                         16 / #8a8f96   无前缀
         ▸ 沿旧路返回                       16 / #c8cdd4   默认游标
```

警告水平居中（`origin 0.5`），不是动作列。词勿改。不要加「确认」。

## 6. 垂直锚点（960×640）

**沿用现有：标题中心 Y = `round(height / 3)`。** 本轮不改成整块垂直居中（两种锚点并存会让 code 猜）。640 → **TITLE_Y = 213**。身份在根菜单与覆盖确认之间**不要挪**。

Y 为行中心（`origin.y = 0.5`）。水平：身份与读数/警告 `origin.x = 0.5` 于 `width/2`；动作见第 4 节。

## 7. 相关 U（最短核）

- **U1** 载体仍 C。不改挂 `#dom-ui-root`。不做成墙机软件窗。本屏无角锚 HUD。
- **U9** 最小字号 12（Kit 下限）。表名/值/档位分节点。读数与动作靠字号（12 vs 16）+ 有无 `▸` 双通道，不靠第三色。灰度后：身份最大；动作有三角形的那一行是路；读数无前缀且更小。
- **U11** 仍 Courier + 两档灰 + 空场。不引入墙机扫描/玻璃。本屏列表静默不再画 `>`；底栏 `>` 本轮不动（两种记号分工：游标 vs 单行提示）。
- **U12** 仍空场标题页（Signalis 的空）+ 读数/动作分簇（FTL）+ 分节点（ItB）。不像 Dashboard / 设置页 / 确认链 / CRT。

层级可读：组间 32–40 空 vs 组内 4–8 空；读数永不亮灰、永不 16。

## 8. 人该怎么看一帧

逻辑 960×640，有纪录根菜单一帧 + 覆盖确认一帧 + 无纪录一帧（能的话加一帧饱和度 0）。

一眼分开三组，只查这些：

1. **三块，不是一列。** 身份（大标题+紧贴副题）与读数之间的空，明显大于三行读数彼此的空；读数与动作之间的空，明显大于两行动作彼此的空。
2. **读数不是按钮。** 三行（或警告）无 `>` / `▸`，字更小更暗；摘要值不再和选项一样大、一样亮。
3. **动作是路。** 未选中无前缀、暗灰 16；已选中一枚 `▸`、亮灰 16。切上下时汉字列不跳。
4. **确认不是对话框。** 标题还在原处；警告是读数那种小暗字；两条动作与根菜单同一套。
5. **没有线。** 没有框、扫描、玻璃、分隔线。

人否决丑或不像游戏 = 本核不合格。本文件不自称过关。

## 9. 写完自检（skill 1–8）

1. **载体？挂载根？** C。Phaser 画布字，zoom 1。不另起 overlay 根，不改挂 `#dom-ui-root`。
2. **具名参考？不像哪三类？** Signalis 锚空场身份+下面才是路，不学检视仪/扫描；FTL 锚纪录与入口分簇，不学软件词/供电格；Into the Breach 锚分节点，不学格子预告/高饱和边框。本屏不像 Dashboard / 设置页 / 存档浏览器 / 确认对话框链 / 墙机 CRT。
3. **P0？** 身份始终；有纪录才有三行读数；动作 1–2 行；确认态警告替换读数。不操作应能分清「这是什么 / 上次到哪 / 现在走哪」。表名/值/档位分节点。
4. **哪台机器？非平直表现的物理原因？** 世界外标题字。本核**不加**投影/发光/圆角/脉动/扫描/框/线。空隙的原因是组与组之间没有物件。游标 `▸` 是列表位置记号，不是装饰。没有用装饰当理由的条目。
5. **不可用缺口？** 无纪录不灰掉第二项（该项不存在）。覆盖是后果陈述，不是灰按钮。
6. **灰度 / 分节点？** 读数 vs 动作：12 vs 16 + 有无 `▸`。已选中 vs 静默：`▸` 有无 + 亮/暗灰。表名/值/档位分开。警告与动作不同级。
7. **打开方式？阻断？** 进标题即出现。覆盖同时 1 条。Esc 确认→根。不新增阻断。
8. **可见词？键盘？** 不改 DEC-050 词。`↑↓ Enter Esc` 不变。不要「点击/确认/Continue」。

机械层已扫：无圆角、无投影、无玻璃/扫描/框/线、无新色、无新字号档、读数不再 16 亮灰、静默不再画 `>`。**不许写好看 / 像游戏 / PASS。** 机械层已扫；审美待人终审。
