# 工具使用 VFX 规格 + 第 4 槽位视觉判断

## TL;DR

15 种主动工具的效果不是玩家施放的法术，是**玩家身上携带的异源残渣被引爆后，在目标位置/敌人身上短暂打开一个局部"数据覆写窗口"**——工具范围仍用网格对齐矩形块集群（DEC-038），非圆形、非渐变，尺度更小、由玩家触发、寿命更短。不要把 DEC-069 的地面崩坏簇形状套到工具范围上；地面合同见 `docs/art/rift-fragment-surfaces.md`。15 件工具按机制形状归纳为 8 个视觉族群，每族群共享同一套形状/动效语法，差异只来自 `narrative_origin` 决定的色相位置与运动方向（内收/外扩/静止/振荡）。受影响敌人的标示复用已有的"坏像素/感知点"signature——亮度和数量直接绑定该敌人当前的感知倍率，零新增基元；只有纯行为类效果（无感知分量）才追加一个共用的方括号标记。

---

## 约束来源

- 世界观约束（`world.md`）：工具 = 薪柴（异源残渣）的进一步转化物，不是玩家的超能力；"污染是改写不是破坏"；暖色 100% 属于人类侧，工具是污染侧转化物，**不得使用暖色**。
- 美术约束（`art-direction.md` §4.2、§5.2、§13.1）：污染签名仍是「渲染规则崩坏」，不是液体或有机蔓延。**地面**现行是崩坏簇（DEC-069）。**工具 VFX** 仍走 DEC-038 的网格对齐矩形块集群（本文件其余条款不变）。实体污染签名是「坏像素」+比例失调；色彩纪律锁定 L2 污染色谱（teal 光谱内偏移），任何非灰色都要有叙事理由。
- 已验证基线（`docs/design-notes/ui-art-overhaul.md` B3、`purification-module.ts` T6 实现）：三态受损视觉已验证"用 3x3px 方点代替圆形指示灯，避免圆形抗锯齿破坏像素风"——本规格延用同一约束到所有新绘制。

## 任务 A：工具使用 VFX

### A1. 载体决策（第一步）

**载体**：世界内表现（Phaser 层，程序化 Graphics + tween）。

**动作 vs 痕迹**：**世界被改写的痕迹，不是角色施放的动作。**

理由：
1. 玩家 sprite 规格（`ui-art-overhaul.md` B1）已锁定为无个性、无姿态表达——"不表现个性，只表现存在"。给 15 件工具各配一套"施法手势"，等于在玩家身上叠一层从未存在过的表演语言，且极易演变成"发光手势 = 魔法感"，正是 `world.md` 明确禁止的"科幻/魔法感"。
2. 世界观原文：薪柴的否定性是"燃烧释放"，工具是残渣的**进一步转化**——效果的主体是残渣本身在目标处引爆，不是玩家的技能。玩家只是携带者和触发者，不是效果的视觉来源。
3. 工程一致性：现有 8 个占位实现（Slice 4）已经把效果画在目标位置/区域上而不是玩家身上（`fillCircle` at position），15 件延续同一落点方式，改动面最小。

**例外（需明确记录，唯一一个）**：`expand`（膨胀稀释时空）作用对象是玩家自身与现实的耦合关系，效果必须发生在玩家身体上。即便如此仍不做"施法动作"——玩家 sprite 在生效期间本身呈现"数据稀释"（半透明 + 抖动，与污染体坏像素同源手法，只是发生在玩家身上），不是挥手/发光特效。

### A2. 参考锚点（3 个，锚定不同维度）

| 参考游戏 | 锚定什么 |
| -------- | -------- |
| **Into the Breach** | AOE 危险区域的**形状语言**——伤害预告用网格对齐的矩形高亮块，不是圆形光晕。工具范围必须继续用网格对齐的矩形块集群（DEC-038）；圆形只用于判定半径（gameplay 逻辑仍是欧氏距离），不用于渲染。地面污染已改为崩坏簇（DEC-069），不要拿地面簇形状改工具范围。 |
| **Hyper Light Drifter**（已有锚点，扩展维度） | 能力特效的**帧数与质感**——扁平色块 + 极少帧数的硬边闪光，没有柔和渐变/发光泛光/粒子拖尾。本项目已用它锚定环境和粒子表现，这里扩展到"技能触发瞬间"这一新维度：施放瞬间是 2-3 帧的硬边闪光，不是渐变淡入。 |
| **Darkest Dungeon** | 受影响单位的**状态标示克制度**——状态效果靠单位身上的小型固定标记（图标/描边色）表达，不用飘浮气泡、不用粒子云包裹全身。本项目用它锚定"如何标示被工具影响的敌人"：标记要小、要固定在敌人身上的确定位置，不能变成一团特效糊住敌人轮廓（那样反而让"威胁识别"变差，与 `art-direction.md` §5.2 覆盖体的"面积光池预警"逻辑冲突）。 |

**明确不像什么**：不是 MOBA 技能特效（无粒子喷泉、无发光轨迹、无颜色渐变球）；不是 Diablo 类 buff 图标（不在敌人头顶挂一个圆形 buff 图标）；不是任何"魔法阵/施法圈"（无旋转符文、无地面投影贴花）。

### A3. 统一形状/色彩语法（8 个族群的共同底层规则）

在分族群之前先定死不可违反的底层规则，族群差异只在这层规则之上做参数调节（Degree not Kind）：

1. **禁用圆形填充/描边**（`fillCircle`/`strokeCircle`），仅 `echo` 的扩散环例外（见 A5-E，用分段短线拼出多边形近似圆，不用平滑圆弧）。范围/区域一律用网格对齐的矩形块集群渲染；gameplay 判定半径不变（继续用欧氏距离），只是渲染形状从圆改矩形集群。
2. **色彩只能取自 `palette.json` 锁定色**，且必须落在污染色谱（L2）范围内：`contam-cold #1a7a9a` → `contam-deep #0e4a3f` → `contam-mid #1a6b5c` → `contam-core #1aad96` → `contam-glow #2ae6c8` → `contam-bright #3cffd4` → `contam-peak #7fffee` → `contam-ancient #4adf8a` → `contam-white #b0fff5`。**禁止任何暖色**（amber/orange/红/黄/紫/蓝紫等非 teal 谱色），也禁止发明新色值。当前占位实现里的白色（`0xffffff`）、蓝灰（`0x445577`/`0x7799bb`/`0x4488ff`）、橙黄（`0xcc8844`/`0xeebb55`）、暗红（`0x881111`）、紫色（`0x8866cc`/`0xcc55cc`）、近白灰（`0xdadfe0`）**全部违规**，实现时必须替换为下表指定的合法色。
3. **网格块尺寸**统一取 4px / 8px 的倍数，块的位置按 8px 网格取整（不是自由浮点定位），保持"数据错误"的机械感。
4. **强度按稀有度分级**（15 件恰好 5 通用/5 稀有一级/5 稀有二级，按 CSV `rarity` common/fine/rare 三档，非任意划分），只调节块数量/亮度/是否附加二次运动信号，不切换形状语言：

| 稀有度 | 涉及工具（active） | 块数量 | 块尺寸 | 填充 alpha | 二次信号 |
| ------ | ------------------- | ------ | ------ | ---------- | -------- |
| common | solidify / ruminate / retrograde / kindle / stitch | 4-6 | 4-8px | 0.12-0.20 | 无 |
| fine | delay / expand / compress / mirror / echo | 6-10 | 6-10px | 0.16-0.24 | 单一方向运动（见 A5） |
| rare | resonate / overwrite / erode / abyss / combust | 10-16 | 8-12px | 0.20-0.30 | 方向运动 + 敌人标记更明显（描边加粗 1px） |

5. **三阶段统一时序模板**（每个工具在此模板上填具体数值，不改结构）：
   - **施放瞬间**（120-200ms）：起始点（玩家脚下 / 目标敌人位置 / 连线两端点）爆出 2-4 个网格块的"硬边闪光"，2-3 帧内完成，无渐变淡入——闪光本身就是最终形态的缩小版，不是另一套动画。
   - **持续期领域**（= CSV `tool_duration_ms`）：块集群按族群规则呼吸/漂移/振荡，参数见各族群小节。
   - **结束消散**（200-400ms）：**离散跳变，不是连续渐隐**。块数量分 2-4 级台阶式减少（每级间隔 60-100ms），可选一次轻微整体位置跳动（±2px，1 帧），模拟"覆写窗口维持失败时的最后错误抖动"，不用 `ease-out` 平滑 alpha tween。

### A4. 受影响敌人如何标示

**主标示（覆盖所有影响感知的工具，零新增基元）**：敌人已有的"坏像素/感知点"视觉签名（`art-direction.md` §5.2，当前代码里渗透体头部/散点的发光像素）**亮度与数量直接绑定该敌人当前的感知倍率**（`setEnemyPerceptionMultiplier` 的实时值）：

- 倍率降到 0（`solidify` 完全冻结）：坏像素/感知点熄灭到 `#2a2d32`（复用 `purification-module.ts` T6 已验证的"熄灭色"惯例）。
- 倍率降到 0.3-0.7（`erode` -30%、`combust` -50%、`overwrite` -50%）：坏像素亮度按比例调暗（插值到熄灭色）。
- 倍率不变但处于"被压制"状态（`delay` 的升级抑制、`kindle`/`echo` 的困惑/停滞）：坏像素闪烁频率降低（从常规 2-4 帧/秒降到 1 帧/秒），读作"感知迟钝"而非"感知增强"。

这一条规则的好处是零新增视觉基元——只是把已经存在的敌人渲染函数接上一个它此前没读过的实时数值。玩家会自然习得"敌人身上的光点暗了/慢了 = 我的工具在起作用"，且这个语言在 15 件工具里通用，不需要分别学习。

**副标示（仅用于无感知分量的纯行为类效果：`compress` 移动锁定 / `overwrite` 巡逻反转 / `resonate` 眩晕 / `echo` 的停滞部分 / `mirror` 的诱饵重定向）**：敌人脚下追加一个 6x6px 空心方括号标记（四个 2px 角括号，仿 `「 」` 的四角写法，不是圆形描边），颜色取该工具族群指定色，随敌人位置跟随，效果结束同帧移除。这是这一类效果**唯一**新增的绘制基元，15 件里只有上述几件会用到它，且共用同一份绘制代码，不是各画各的。

**残影例外**：`retrograde` 明确要求"即使目标离开视野其位置仍以残影显示"，其标记必须画在视野遮罩（fog，depth 50）**之上**——沿用当前代码已验证的 depth 60 惯例。这是 15 件里唯一需要穿透雾气的标记，其余标记在敌人不可见时不需要继续渲染（正常被 fog 盖住即可）。

### A5. 八个视觉族群 + 逐工具差异表

> 每族群先给共享的三阶段参数，再给族内每件工具的 `narrative_origin` 差异化描述。深度（depth）沿用现有代码惯例：领域/地面效果 depth 10，敌人标记 depth 26（穿透雾气的例外 depth 60），连线 depth 10-12，玩家自身效果 depth 略高于玩家 sprite。

#### 族群 A — 定点凝滞（solidify）

单体、完全停止，晶体锁死的质感。

| 阶段 | 描述 |
| ---- | ---- |
| 施放瞬间 | 目标敌人位置爆出 4-6 个 `contam-cold #1a7a9a` 网格块，快速收拢成一个**棱角分明的多边形描边**（3-5 条折线，不是圆），代表晶格在极短时间内长成 |
| 持续期 | 棱角描边静止不动（冻结=零运动），仅 alpha 极缓慢呼吸（周期 1.5-2s，0.5-0.7 区间）；敌人坏像素按 A4 主标示熄灭 |
| 结束消散 | 棱角描边按 2 级台阶碎裂消失（不是淡出，是"裂开"——块数量瞬降，可加 1 帧位置抖动） |

#### 族群 B — 单体标记（retrograde / overwrite）

作用于单个敌人，改变其行为但不使其停止移动，靠一个跟随标记表达"这个敌人被处理过"。

| 阶段 | retrograde（循环时空） | overwrite（规则覆盖时空，rare） |
| ---- | ---- | ---- |
| 施放瞬间 | 敌人位置一次 `contam-mid #1a6b5c` 菱形硬边闪光（延续现有菱形形状，仅换成合法色） | 敌人位置一次**双重闪击**（2 帧连续闪光，"极快速度重写"）用 `contam-peak #7fffee`，比其他工具的闪光更亮更短（80ms） |
| 持续期 | 菱形标记持续跟随敌人（`contam-mid` 描边）；每 2s 在敌人经过的位置留一个渐隐的方块残影（复用现有 ghost 机制，颜色换成 `#5a5f66`，不是当前的 `0x888888`）；残影与标记均画在 depth 60（穿透雾气） | 施放瞬间闪光过后**无持续视觉**（叙事：现实规则已被静默重写，不需要一直提示）；仅用 A4 副标示的方括号（`contam-peak` 色）跟随敌人 15s，作为"这个仍在生效"的唯一线索 |
| 结束消散 | 菱形标记 2 级台阶收缩消失；已有的 ghost 残影正常按各自寿命淡出，不用额外处理 | 方括号标记消失（无需特殊动效，直接移除即可，因为它本来就很克制） |

#### 族群 C — 领域覆写（delay / erode / compress / combust / kindle）

族内共享"网格块集群覆盖一个圆形判定半径"的渲染方式（A3-1），差异全部来自块的**运动方向**和**色相**：

| 工具 | 稀有度 | narrative_origin | 色相 | 运动信号（族群差异化核心） |
| ---- | ------ | ----------------- | ---- | -------------------------- |
| `delay` | fine | 时间扭曲时空——因果链延展 | `contam-cold #1a7a9a`（L2 定义里"新生/低浓度偏蓝"，恰好是最冷/最蓝的合法色，契合"时间被拉长"的冷感） | 呼吸周期拉长到 2.5-3s（比其他领域慢一倍），代表"这里的时间流速不一样" |
| `erode` | rare | 侵蚀扩张时空——主动向外吞噬 | `contam-mid #1a6b5c` | 块只在**边缘环**（半径的外 20% 环带）持续闪烁增减，中心块保持静止——读作"边界在向外蚕食"，而非整片一起呼吸 |
| `compress` | fine | 重力压缩时空——空间密度趋向无穷大 | `contam-deep #0e4a3f`（最暗，"致密"） | 块持续向中心点缓慢**内收漂移**（每帧位置向锚点插值 1-2px 后归位重生），代表"密度趋向无穷大" |
| `kindle` | common | 燃烧消耗时空——物质在此不断自焚又从灰烬重构 | `contam-ancient #4adf8a`（L2 里唯一带"偏暖绿"的合法色，是这套色谱里能表达"燃烧"而不越界暖色的唯一选择） | 块以**高频不规则闪烁**（0.1-0.2s 随机间隔，非固定周期）快速明灭，代表"不断自焚又重构" |
| `combust` | rare | 焚尽湮灭时空——物质以极高温持续燃烧直到归于虚无 | `contam-ancient #4adf8a`（同 kindle，同一"燃烧"注册色，但下方运动信号完全不同，靠动效区分两者） | 块按**慢速衰减-复燃循环**（单个块 1.5s 内从满 alpha 线性衰减到几乎消失，再突然满血复燃，多个块相位错开）——比 kindle 更沉重、更持久，契合"持续到归于虚无"而不是"快速自焚" |

`kindle`（common）与 `combust`（rare）刻意共用同一色相（都是"燃烧"注册色），仅靠动效节奏区分——这正是"Degree not Kind"要求的：不同强度用同一语言的参数递进，不是换一套语言。

#### 族群 D — 连线贯穿（stitch / resonate）

两点之间的连线效果，靠"缝隙光"语法（`art-direction.md` §4.2："teal 光从 tile 接缝中透出"）表达，不是发光激光线。

| 工具 | narrative_origin | 差异化处理 |
| ---- | ----------------- | ---------- |
| `stitch` | 编织缝合时空——现实碎片被丝线强行缝合为整体 | 主线用 `contam-mid #1a6b5c` 细线（2px），**沿线每 12-16px 加一个垂直短刻线**（4px，模拟缝合针脚），静止不动——"缝合"读作物理上的针脚，不是能量线 |
| `resonate` | 谐振共鸣时空——频率共振覆盖一切（rare） | 主线用 `contam-glow #2ae6c8`，线形不是直线，是**持续的正弦抖动**（振幅 2-3px，频率随 `remainingMs` 变化制造"频率"感），两端点闪烁更亮（`contam-bright`）——"共振"读作物理振动 |

两者共享"两点连线 + 端点小方块标记"的骨架（复用现有代码结构），差异只在线形（直/波动）和刻线细节。

#### 族群 E — 即时脉冲（echo）

族群里的唯一形状例外：一次性向外扩散的环，物理上是"回声波"，保留环形动作但改用分段短线拼出的多边形环（12-16 段折线），不用平滑 `strokeCircle`。

- narrative_origin：回响震荡时空——一切动作在此无限重复回荡不止。
- 施放瞬间即整个效果：环从半径的 15% 在 350ms 内扩张到满半径，色相 `contam-glow #2ae6c8`，分段折线随扩张逐段变暗（模拟"声波衰减"），到达满半径后直接消失（不需要额外的"结束消散"阶段，扩张本身就是收尾）。
- 敌人标示：`echo` 命中的敌人同时触发 A4 副标示方括号（`contam-glow` 色），持续 3s（对应巡逻者困惑/追击者停滞的时长）。

#### 族群 F — 分身诱饵（mirror）

- narrative_origin：镜像对称时空——一切存在产生完美对称的复制体。
- 施放瞬间：玩家当前位置原地出现一次"复制闪烁"——2-3 帧内交替显示玩家轮廓的**镜像反色版**（用 `contam-bright #3cffd4` 描边替代玩家实际颜色，制造"这不是真身"的错位感），随后定格为分身。
- 持续期：分身是一个 18x18px 空心矩形描边（复用现有 `drawMirrorDecoy` 结构，色值从当前的 `0xdadfe0`（不合规）换成 `contam-bright #3cffd4`），alpha 呼吸 0.55-0.85，周期 1.2s。
- 结束消散：被敌人接触"碎裂"时，矩形描边瞬间炸开成 4-6 个网格块并在 150ms 内消失（比标准的 2-4 级台阶更快、更碎），区别于寿命耗尽的正常淡出（正常淡出仍走标准 2 级台阶）。

#### 族群 G — 自身相变（expand）

唯一作用于玩家自身的工具，如 A1 例外条款所述。

- narrative_origin：膨胀稀释时空——物质无限膨胀。
- 施放瞬间：玩家 sprite 边缘像素向外"膨胀溢出"1-2px 后归位（1-2 帧），代表存在被稀释扩散的瞬间。
- 持续期（3s "active" 阶段）：玩家 sprite 整体 alpha 降到 0.5-0.6，且叠加与污染体坏像素同源的抖动（sprite 内 2-3 个像素点随机短暂偏移 1px，频率 4-6 帧/秒）——"玩家自己也短暂读作一个渲染错误对象"，这是唯一允许玩家 sprite 出现"坏像素"手法的场合，且必须在效果结束后完全消失，不能有残留（保持玩家平时"融入环境但不是污染物"的色彩纪律）。
- 结束消散（1s "stiffness" 硬直阶段）：alpha 回升到 1.0 但配一次轻微的"实体化"闪烁（2 帧，contam-cold 描边轮廓一闪即回归玩家正常配色），提示玩家"刚刚结束，硬直中"。

#### 族群 H — 资源/情报（ruminate / abyss）

不产生敌人 debuff，不需要 A4 标示规则。

| 工具 | narrative_origin | 处理 |
| ---- | ----------------- | ---- |
| `ruminate` | 吞噬覆盖时空——通过消化扩张 | 延续现有实现的方向是对的（节点位置一次绿色脉冲），仅需把颜色从 `0x22cc66`（不合规，且绿色在本项目语义里是"稳定度"专用色，与污染谱系冲突）换成 `contam-mid #1a6b5c`；形状从圆改成一个快速收缩的方块（消化 = 被吸入变小，不是膨胀发光） |
| `abyss` | 深渊吞噬时空——光与信息被无底虚空持续吸入（rare） | 施放瞬间：玩家位置一个极短（150ms）的"孔径闭合"效果——4-6 个网格块从外围**向内收缩消失**（呼应"被无底虚空吸入"，是本规格里唯一从一开始就是收缩而非扩散的施放瞬间）。持续期：世界空间不需要额外常驻 VFX（本工具的主要呈现层是 minimap，`showAbyssReveal()` 已有出口）；每个被标记的敌人/节点在小地图上以 `contam-peak #7fffee` 极小方点呈现，方点亮度随 10s 倒计时逐渐衰减（不是恒定亮度突然消失，让玩家感知"信息正在流失"）。结束：方点在最后 1s 加速闪烁 2-3 次后统一移除。 |

### A6. 实现约束（给 code agent）

- 程序化绘制优先：全部用 `Phaser.GameObjects.Graphics` + `fillRect`/`strokeRect`/`lineTo` 组合，不引入位图资产、不使用 `strokeCircle`/`fillCircle`（唯一允许的圆形近似是 `echo` 的分段折线环）。
- 色值全部从 `docs/art/palette.json` 直接取值或在代码里定义为具名常量（如 `CONTAM_COLD = 0x1a7a9a`），**不要保留当前实现里的任何一个不合规色值**——A3-2 已列出全部需替换的色值。
- 块集群渲染建议抽一个共享 helper（如 `drawGlitchBlockField(g, center, radius, blockCount, blockSize, color, alpha, rng)`），15 件里的族群 C（5 件）+ 部分族群 A/F/H 都能复用，避免每个工具各写一套随机块生成逻辑——这是本规格"Degree not Kind"落到代码层面的具体要求。
- A4 的方括号标记和感知点亮度联动同样应各抽一个共享函数，被多个工具调用，不要在每个 `apply*`/`update*` 里各写一份。
- 结束消散的"离散跳变"可以用 `scene.time.delayedCall` 分 2-4 级手动改变块数量/位置来实现，不需要（也不应该）用 `tweens.add` 做连续 alpha 插值——现有 8 个占位实现里大量使用的 `onUpdate` 连续 tween 渐隐写法需要在这次改动里替换掉。
- `retrograde` 的 depth 60（穿透雾气）是唯一特例，其余 14 件的领域/标记效果按现有 depth 惯例（9-26 区间）即可，不需要穿透雾气。

## 任务 B：第 4 槽位面板视觉判断

### 结论：**复用即可，不需要新视觉规格**，但有一处实现层要求需要明确写下来（否则容易被理解成"加一行"而破坏现有比例）。

### 判断过程

面板固定宽度 440px（`loadout-panel.ts`/`defense-panel.ts` 内联样式一致），内边距 20px×2（`.game-panel` padding），`.slot-grid` 当前 `grid-template-columns: repeat(3, 1fr)`、`gap: 6px`。

- 内容可用宽度 ≈ 440 − 40（padding） − 若干像素滚动条 ≈ 390-400px。
- 3 列时单格宽 ≈ (400 − 12) / 3 ≈ 129px；4 列时单格宽 ≈ (400 − 18) / 4 ≈ 95px。降幅约 26%，但 `.slot-cell` 内文字是纵向排列（`flex-direction: column`），不是横向拼接——槽位名称最长为 3 个汉字（如"重力锚"），13px 字号下单行宽度约 40-45px，在 95px 格宽下仍有充裕留白，不会截断或换行。
- `.slot-cell` 的 `.slot-label`（Q/F/被动 或 1/2/3）是 `position:absolute` 左上角标注，不占据横向布局空间，格宽变化不影响它的位置正确性。
- 两个面板的槽位在视觉上本来就是**同构的空白格**（虚线边框，填充后变实线），4 个和 3 个只是同一模式多复制一份，不引入新的视觉关系（没有出现"3 个一组另起一行"的分组语义需求）。

**结论**：单行 4 列在 440px 宽度内可读、不破相，直接把 `grid-template-columns: repeat(3, 1fr)` 改成按实际槽位数量动态生成（如 `repeat(${slots.length}, 1fr)`）即可，这是参数化一个已有组件，不是发明新组件，符合"严格复用"的要求。

**需要明确的实现层要求（写给 code agent，不算新视觉，但容易被漏掉）**：
1. `loadout-panel.ts` 的 `SLOT_LABELS = ['Q', 'F', '被动']` 需要扩到 4 项（3 主动 + 1 被动）。第 3 个主动槽位的按键标签取决于实际键位绑定——**这是键位分配的技术决策，不是视觉决策**，art 不代为决定，但必须提醒 code agent：`SLOT_LABELS` 和实际输入绑定必须一致（`_template-ui.md` U7"输入一致"），不能出现面板写着一个键、实际绑定另一个键。
2. `defense-panel.ts` 的槽位标签是纯数字（`i + 1`），扩到 4 不需要新增任何字符串，天然支持。
3. 两个面板 `for (let i = 0; i < 3; i++)` 的硬编码循环上界要跟着改成读实际槽位数（Task Brief T5 本身已经要求"槽位数量不得硬编码"，这里只是从视觉判断的角度确认：这个改动不会带来任何视觉副作用，可以放心做）。
