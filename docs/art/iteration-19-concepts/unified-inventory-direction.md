# 统一随身物与备行：实施方向与候选属性

## 批准范围与当前边界

用户喜欢 `preparation-inventory-v2.png` 的挂带、器物、暗材质与场景相接的效果，也喜欢 `weapons-and-attacks.png` 的实物外形及握持意图。**库存方案现已获准实施；具体实景画面、交互手感仍需人审。** 原图的双武器、六挂钩、四武器类别与巨大标题不作为当前规则。

库存W1领域/保存、W3共享view/presenter已有实现；场景尚未接入生产，W4搜索/地面物模块显式开关默认关闭，等待出发/结算/中断恢复整链验证和退出规则。此稿描述实现方向，不宣称当前正式游戏已可用。已显式读取 art agent 入口，未读取被用户禁止的旧审美 skill、HOW 或旧 art-direction。固定画布从当前 `src/config/game-config.ts` 与 DOM 根核实为 **960 × 640**；实际文字字体从代码核实为普通中文无衬线。图中文字和放大后的细节不按原尺寸照搬。

最新设计输入：

- 当前仅撬棍一类武器；类型固定攻击方式，候选四品质/十件成品以品质决定主要强度，同档只有小幅重量/抗性取舍；白板朴素，不升级、不增加锤/枪。R2八种功能款及其图稿作废，只保留材料风格。
- 净化点决定一把在手撬棍及既有主动/被动工具；本轮出发后固定。主动仍为 Q/F/G，G 的可用性沿用成长；没有第二把即时切换武器槽。
- 所有携带物共用 **16.0 负重**的实施基准；已装配物也计入。污染物每件 2.0，R4撬棍候选 2.7/3.0/3.3；内部容量160、污染物20、撬棍27/30/33，以十分之一整数求和。负重是质量代价，不是格数、挂钩数或每类单独上限。
- 净化点留存无容量上限。武器和污染物属于同一个可筛选集合；位置可以是随身或留存。装备只是随身物的装配状态，不复制成另一件、不重复计重。
- 裂隙背包管理未装配的收获；已装配物显示并计重，但不能选作抛下对象、换装或转为备用。
- B 打开/收起背包；Tab 保留存续报告；Q/F/G 保留工具；备行的 Shift+Enter 保留出发。
- 翻找揭晓后能放下就直接拿取，只有超载才提示进入附近/随身交换视图（不自动强开背包）。死亡已确认本趟全部随身物丢失（基地保留）；开包不暂停已确认，不能暗示打开就安全。

## 核心画面：打开一卷实际负重，而非开启两个库存系统

沿用认可图的实物语汇：短撬被两道磨旧织带束住；工具扣在小金属环上；收获搁在翻开的暗布衬里。织带是分组和固定的物理理由，不能画成每件物品外面包一张卡。轮廓由暗布、装置阴影与场景一起消失，只有受力边、折边、铆接点和正在看的器物清楚。

**同一份展开的随身卷**贯穿净化点、备行和裂隙背包。变化是可做的事情与物件位置，字体、材料、选中动作、列表尺度和负重位置保持稳定。不是把熟悉的挂带外观分别贴到武器页和污染物页。

净化点左侧保留玩家、真实装置与地面；右侧展开布卷。裂隙仍保留左侧实际世界，玩家位置不由这一视觉提案强行重排；打开背包时世界继续运行（DEC-134）。这里是屏幕空间的物件查看载体，挂当前 960 × 640 的 `#dom-ui-root`，不随世界摄像机 zoom 漂移。不得把概念图的废墟重新生成为一张假净化点背景。

## 固定画布的拟定排版

以下是逻辑像素草案，没有移动端断点，也不把 1536px 概念稿的文字等比例照搬。

### 净化点与备行

- x=0–272 保留实际场景；x=272–938 为展开的物件区域。布卷左缘有少量参差磨损，其余边缘以材质明暗自然收边，避免一圈规整窗口描边。
- x=296，y=44：页名「随身」或「备行」，18px；同一行右侧固定「负重 11 / 16」，数值 12px。计量直接读所有随身实例，筛选后不变化。
- y=86–180：一条装备挂带。左侧约 258px 展示在手撬棍，缩略长形 124–168px，R4同类型保持同一有效长度，不用旧长短款制造不同距离的错觉；右侧安排 Q/F/G 与被动的小挂点，每点约 48px，沿用已解锁数量。不可用的 G 仅表达未开放，不新造三件常开工具规则。
- 装备名用 12px，键位 10px。挂带上是器物主体，背后不堆数值。焦点来到装备时，右侧详情显示同一实例；点击挂带不会生成另一份装备库存。
- y=202：一条低强调文字筛选「全部 / 武器 / 污染物」。这只是同一列表的视图；左边一小段缝线指示当前筛选，不分出两个分页仓库。净化点可在同行最右选择「只看随身」，默认也能看到留存；位置写在物品行的短标签中。
- x=296–684，y=234–534：共享列表，行高 46px，六行完整可见、末端有轻微下一行露头提示。**六行是窗口高度，绝不是六件容量。** 左 52px 放实物缩略图，中间放名字/一句识别，最右显示负重与「随身」「留存」「在手」「Q」等真实状态。
- x=708–922，y=202–550：一个焦点详情面。上方实物图约 116 × 128px，下方名称、角色短句和必要属性。与在手物对照时直接在同一行写旧值→新值；不再并排弹出两张大卡。
- y=570–612：固定操作区。左边列当前有效动作，右边为备行「Shift+Enter 踏入裂隙」。列表滚动不会移动这些操作。净化点普通背包不开出发按钮。

一件可装配留存物被选中时，详情清楚显示替换当前装备后的负重，不把“拿取”当作携出未装物的独立动作；首版只有装配物被带出。随身物换到在手或工具挂点只改变装配状态，不再增加负重。满负重时从留存换装，直接在同一页预览被替换装备交回留存后的重量，显示最终负重，再一次交换；不用先退出装备页、打开储藏、减重、返回原页。

这里的交换是净化点装配动作。出发后不保留这条快捷路径。

### 裂隙的普通背包

外形与负重位置相同，页名为「随身」。上方装备挂带缩短成约 66px 高的只读展示，写「本趟已备好」，不出现换装按钮。既有工具键不借来给背包里的物品赋新槽位；工具的游戏内使用是否被菜单挡住由最终暂停/输入规则决定，不能凭视觉稿偷偷触发。

下方仍是一个「全部 / 武器 / 污染物」共享列表。已装配物在上方只读挂带可被查看，带键位/在手标记；下方战利品列表不重复列出，准备抛下时不能被选入。未装配物有查看与抛下操作。遇见的新撬棍可以和在手物对照，但文案写「回到净化点可装配」，避免展示当前不允许的行为。

普通捡起一件、负重仍允许：物件贴近现有负重位置显示短读数，如「撬棍 +3.0」，负重变为「11 / 16」后消退。无需为一次正常拿取打开整个背包。

### 超载时：附近与随身在同一块布面上

此模式只在拿取会超出负重时出现，也可由玩家再次查看仍在地上的收获进入。**附近物不计入当前负重，只有交易成功的最终状态计入。**

- 继续使用 x=272–938 的物件区域。顶部 y=44 保持总负重位置，显示「14 → 17 / 16　超出 1」；超出以暗赭色文字和明确数值表达，不靠红色闪烁。
- y=86–182 为当前准备拿取物的短详情及对照，复用普通详情内容；装备仅以在手/Q/F/G的紧凑只读条出现，不占两个巨大的长挂带。
- x=296–568、y=222–534 为「附近」；x=594–922 同高为「随身」。两列属于一次交换，标题下分别写「准备拿取 3」和「准备放下 2」，而不是两套容量条。
- 每行均用相同 46px 高度和实物缩略图。附近允许指定本次拿取物；随身允许选中多件未装配物。多选标记像一段翻起的小织带，始终保留物名和重量，不把选择藏在勾选后变色的整行里。
- 选择变化只更新预览：例如「14 − 2 + 3 = 15 / 16」。未选择放下物时，按钮仍在原位置，直接说明「还需腾出 1」，不让按钮消失。
- y=570 固定主要动作「Enter 放下所选 · 拿取」，旁边是「Esc 保持原样」。确认前没有任何物品移动；取消不会先丢物再撤销拿取。失败或世界状态变化时，保持原物归属并在原位置告知，不能只留下重量数值正常但物件不见了。
- 若装备占重但不可抛下，占重数字仍显示；只读装备不能因列表筛选或多选被绕过。负重已由不可卸装备占满时，说明「本趟装备占重，无法再收下」，附近收获保留，不制造禁用按钮循环。

该视图是超载处理，不是重复揭晓：揭晓结果保留，重新打开不再演一次翻找动画或要求再次读条。

## 对照、焦点与大量物品

同一实例 ID 决定选中状态；不得用所在数组索引。物品图像、数值更新、装备标记变化和焦点详情更新都不能重建整个滚动容器。

- 上/下切物品，左右切所在列；Enter 做当前明确主动作，Space 在交换模式勾选/取消放下对象；PageUp/PageDown 翻一屏，Home/End 到首尾。鼠标点击与键盘等价，滚轮只滚指针所在列表；不要求拖动物件才能操作。
- 分类切换保留各自的首条可见实例、像素偏移和焦点实例；回到「全部」时回到离开的位置。物件因为操作离开当前列表时，焦点落在原位置最近一件，不跳顶部。
- 多选交换不自动按重量或选中状态重排；新拾取不把当前列表顶到开头。源列表当前实例仍存在时保持它的位置；更新后若焦点在可见区就不自动滚动。
- 滚动边缘采用细小深色轨迹，只有可见拇指与底部「7–12 / 37」说明剩余内容。页标题、负重、焦点详情和操作区固定，禁止出现整个大面板和内部列表两套滚动条。
- 名称超过一行时保持固定两行上限，在详情完整展开；物重、所在位置、在手/键位标记永不挤掉。R4品质与构造分开标注，缩略图保留钩肩错生、杆身剥层与中空错位的轮廓差异；长度/弯折不能暗示不存在的新攻击方式。
- 极长效果说明在详情内部展开一段，只有确有长文本时出现局部滚动；名称/主要属性/当前动作仍固定。默认详情应能在给定高度内显示，不用空白装饰图把文字挤进滚动条。
- 对照不是所有高数值都标绿。以「品质更高」「伤害 29–35 → 36–44」「重量 3.0 → 2.7」「污染抗性 +2% → 0%」等中性文字表达实际代价；遇见不可直接比较的污染物，只对照作用和次数，不伪造综合战力分。

## 材料、文字与动效

### 材料如何成为界面

认可图的价值是器物有被束住、被摸过的理由。布衬只在清楚的折缝附近有纹理，文字背后的组织更暗、更平；铆点只放在挂带受力处，细锈不撒满背景。暗部允许真实场景轻微透出，但字体背后的等效底色稳定，场景火光不能让一整行字时清时糊。

原物缩略图用像素簇表现铁、旧绑布和哑光扣件；不把展示图的噪点细节硬塞进 32–48px 缩略图。物品侧的微小明暗变化比整行色块更有层次，空白处不画成无数待填格子。

普通中文无衬线贯穿页名、物名、说明：`PingFang SC / Microsoft YaHei / sans-serif`；不用大宋体、斜体或故作古文。标题 18px、物名/主操作 12px、正文 11–12px、键位和位置 10px，正文行高 18px。数值使用同一字体的清楚数字或现有等宽数字；不要把所有名称也变成等宽字。

这里的字号是 960 × 640 提案尺度。正式小样应在真实输出大小检查，不以浏览器放大截图代替。

### 状态与动作

- **静置**：实物低亮，挂带完整可见，行背景几乎融入布衬。
- **正在查看**：物件上缘与名称稍提亮；左侧一段约 12px 的布带折口指向它，不贯穿整行画一条白竖线，不和血条/条目边线相撞。
- **已经装配**：实际挂点呈现物件，列表旁短记「在手」「Q」等。没有额外大光框。
- **准备交换**：翻起的短织带标记，负重预览立即变化；结果尚未落袋，因此物件保持原来的所在列。
- **负重不足**：指出要腾出的量；物件仍可查看和参与对照，不整体灰到读不出是什么。
- **已收好**：短促布带落定，120–160ms；负重更新一次。没有大型成功弹窗。

打开布卷 150–180ms：暗布边缘从所处侧展开 8–12px，物件在其后稍微显现；场景不全黑。切焦点 60–90ms，小幅明度响应，不让列表或详情版式位移。器物图不得每次切换都慢慢旋转。交换时 120ms 的方向性移位仅为确认反馈，物品数据与最终负重一次提交；动画未完也不允许重复交易。

开包不暂停已确认；不设计暂停沙漏、时间停滞颗粒或「安心整理」措辞。

## R4品质与生存属性的展示边界

同类型详情先品质、再伤害区间／污染抗性／重量，攻击范围与节奏归共享家族说明，不在十张详情中堆一排相同数字。同档只比较少0.3重量／少2个百分点抗性，取消旧长短、宽扫、重击、消音与效果对照。

若候选属性获准且真实接入：整备显示最终抗性与已用负重派生的移动变化，细节可展开来源；候选全局抗性上限60%，候选负重半载以后渐降、满载移动−16%。当前不能在生产界面把这些未实现效果写成已生效，也不新增第二容量条。

## 紧凑 HUD

战场仅在已有装备读数附近留一条负重数字；例如「11 / 16」，平时低强调，无完整布卷、三套容量或闪烁警报。到上限时显示「16 / 16」并短暂提亮；新的拾取被挡时才指出差额。不要让负重条比生命、实际危机或场景主体更抢眼。

撬棍常态放低，钩口在手外 2–4 个世界像素仍可辨；肩灯继续是玩家的定位点。基础款只需要铁杆、旧握布和普通磨损。品质款通过污染与侵蚀改写实体造型，抗性则独立用于同品质取舍；攻击包络相同，不凭品质加青绿光或新特效。出手的握点、腰肩前送和回收应共用攻击时钟；世界模型的小样另立制作，不把概念图底部三姿势当生产图集。

## 进入制作前的具体核对

库存方案已获准实施并写入system-field-inventory；领域与view/presenter已有实现，场景未接。此授权不等于视觉人审。R4品质和system-survival-attributes候选仍待用户评审，不能提前展示虚假的有效抗性或移动减速。死亡全丢、背包不停已锁，退出/刷新等待用户明确。

首个小样必须同时装入：一把基础撬棍、一把外形不同的留存撬棍、已装配污染物、未装配污染物、超过六行的混合物件、超载需要放下两件的情境。只放四张漂亮武器图不足以证明这个布局承得住实际库存。

逐项肉眼检查：物件是否有同世界的材料感；1:1下是否读得出名字与重量；装备是否一眼可辨；旧六挂钩/双武器误解是否消失；滚到底后换装/筛选/交换是否还在原处；附近收获是否确实未计重；死亡全丢与开包不暂停是否准确传达。
