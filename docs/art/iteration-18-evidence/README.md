## 批 1：哺乳残余与大号蠕虫

- `beast-directions-*` / `worm-directions-*`：四列为下、左、上、右。九行分三组，每组从上到下为渗透、改写、覆盖。
- `beast-0/1/2-phases-*` / `worm-0/1/2-phases-*`：六列为静止、行走、察觉、蓄势、打击、收势；三行为低、中、高污染。朝右。打击列取最大伸展，收势列取中段。
- `*-walk-*`：八列为一周期八个时刻，三行为低、中、高污染，朝右。
- `native` 为实际像素；`3x` 仅最近邻放大，不能替代正式比例验收。
- `creature-frame-checks.json` 记录当前代码的可复现检查结果。

哺乳大形的代表种子为 `[3, 0, 1]`：低伏长躯、长肢高胯、宽肩厚背。大号蠕虫为 `[4, 0, 3]`：长链拖行、回弯、拱起折叠。每家族当前是三种大形、三档覆盖，即九种结构配置，不把任意种子数当作新的敌人种类。

## 结构与动作设计

哺乳残余保留四个承重点与前后不同的肢体关节。低污染仍读得出前身、后胯与抹去面目的头部；中污染用错位的肩带接替原来的颈部，头颅仍被挤在一侧；高污染的连续胸腹被两列承重弓架替代，中间保留实际空隙，攻击端成为一个开口。三种比例在污染升级后仍影响承重跨度、躯干长度与姿态。

大号蠕虫由连续节链构成。低污染为厚而干燥的节套；中污染让中段外翻，前后尚保留原有节套；高污染将整条链重组为错接的叠片与凹槽，头部被开口取代。三种体轴走向分别是长链、回弯和抬高的折链。它靠沿链传播的压缩与抬节前进，始终无足。

两个家族不使用通用的增肢、放射、随机像素散布或整图拉伸。它们只共享像素栅格化、四向投影、面遮挡与有限级面光，不共享身体布局和运动方程。

攻击相位由游戏的真实战斗时钟提供。模型遵循打击起点最大伸展、打击终点保留 80%、收势从 80% 回到原位的合同；蓄势包含身体压低或节链收拢。原点始终为 `(32, 42)`，碰撞规格为 `20`，画布为 `64×64`。

## 已完成检查与仍需审查

已完成：哺乳 5,184 帧、大号蠕虫 5,760 帧；三种大形、多种子、三档污染、四向和六相；确定性、二值透明度、画布边距、静止/行走首尾与打击/收势衔接。输出的具体边距和像素量见 JSON。

下一步正式场景审查：

1. 灰度与正常灯照下均能区分两家族、三种大形和相邻覆盖档，不能依赖改颜色。
2. 攻击前玩家能从承重变化判断即将出手，出手方向与真实攻击朝向一致；接触范围仍以正式战斗系统为准，不以这张模型图宣称验证。
3. 行走时能读到肢体承重或节链推进，停下后不继续踏步，受击/消亡不出现旧模型。
4. 与已通过的虫、人形同场时，体量和亮部不抢占画面；高污染不能退化成所有家族都长相同放射枝条。
5. 窄走廊和近距离混战中，至少保留攻击端和关键负形的辨认机会。若重叠使其丢失，须联合敌人间距与排序处理，不能靠把模型无限放亮补救。

## 批 2：有机残余与残茎

新增 `remnant-*` / `growth-*`，沿用上面的方向、相位与步行图例。有机残余的大形代表种子为 `[1, 4, 0]`：折叠厚膜、偏悬壳囊、双团共腹。残茎为 `[1, 0, 11]`：束柱、倒伏扇束、断桩。各三个大形、三档覆盖。

有机残余没有头颈、手臂、昆虫足或蠕虫体节。三块厚的承重折面托住主体，重心随折面交替支撑缓慢转移。中档移动左侧承重点，抬高、横移一团主要质量，同时缩窄或下压另一团，用斜向连接造成体腔和重心变化。高档保留整体厚膜包裹，只让错接的内层从斜向夹缝露出，避免与兽的开放承重弓架同形。偏悬壳囊在烤图复核后降低重心、增加侧向悬挑，减少直立人形误读；最终仍需与人形同场验证。

残茎的主体由粗纤维束构成，稀疏长纹沿实体受力方向延伸。中档加粗、侧移并错接一束主干；高档改接全部生长面，仍保留木质端面和共同根座。静止、察觉、蓄势、打击和收势时，根座不平移。上部先向后收紧，再前折打出；行走相才让根束交替抬起承重。模型自身不改变宿主位置；低档 `motion_turn` 的不漂移仍需由实际行为调度保证。

本批检查：有机残余 5,184 帧、残茎 4,608 帧；最终结构/摆扫修正后的最小边距分别为 12、10 像素。前两批四家族合计 20,736 个活动采样帧，具体结果见 JSON。确定性、二值透明度、四向画布边距、循环及攻击/收势衔接检查均已执行。类型检查与正式场景集成验收分开记录，不将烤图当作正式关卡验收。

## 连续休止姿态

四家族的请求均支持可选 `restAmount`（0 活跃，1 休止）。共用栅格器在投影前连续降低离地部分的承重高度，最高收拢为原高度的约 62%；`z≤2` 的接地层保持原位。它不改变模型在地图中的位置或运动状态，由运行时决定何时收拢。

`*-rest-*` 图以三组双列显示三个变体，每组左列活跃、右列完全休止；三行分别是低、中、高覆盖，朝右。附加检查确认四家族 `restAmount=0` 与不传该字段的活动帧逐字节相同，每个变体/覆盖/朝向都存在可见的休止形变，0.25/0.5/0.75/1 四段休止程度在六个动作采样中均满足二值透明与画布边界。

## 批 3：占地门框与街具残骸

本批只替换占地模型；墙体宿主上的门框是另外的结构和渲染入口。

`door-*` 三组为完整框口、断梁单侧框、折叠窄门，代表种子 `[0, 4, 2]`。原有门槛固定，动效作用在独立门扇与错位梁口上。中档增生面挤入原本的开合关系；高档以交错梁、二次反折门扇或不相容的闭合面改写框口。攻击时门扇绕承重点摆出，休止时收回，门框不通过整体缩放模拟呼吸。

`wreckage-*` 三组为压紧柜壳、悬臂长凳、轮架，代表种子 `[3, 1, 0]`。它们保留不同的立面比例、承重跨度与轮状负形。动作分别来自铰接压板、悬臂横板和折叠半轮箍；底座保持固定。检查曾发现覆盖档轮架从后方看不到活动/休止差异，已让上部承重铰点随收拢位移，避免休止信号完全被固定结构遮住。

本批门框 5,760 帧、街具 5,184 帧。**六家族总计 31,680 活动采样帧，另有 5,184 休止程度/相位采样。** 二值透明、确定性、画布边界、休止可见性、活动归零一致性与各动作接缝检查通过。每家族仍为三大形×三档，不把每个方向或动画帧计入敌人种类。

## 攻击定位复核

兽与蠕虫沿承诺方向分别用前身扑出和节链收缩释放表达窄向攻击。有机残余、残茎补充了离地承重体块的扭转：先向一侧压紧蓄势，再横向摆转释放；接地层不参与旋转。街具的压板、横板、轮箍在前伸之外有左右摆扫，门扇本身是铰转动作。所有新攻击保持打击末帧到收势首帧、收势末帧到静止首帧的精确衔接。

`*-front-phases-*` 是各模型正面六相，可与原有朝右六相对照横摆和前伸。实际伤害扇区宽度、前摇时长和命中仍由正式 CSV/战斗系统负责，模型不自行新增攻击规则。

## 循环与快速击发边界复核

扫描现已明确包含 `idle / walk / alert` 的首尾，且在活动、半休止、完全休止下分别核对。六个新家族均为零循环接缝，打击末→收势首、收势末→静止首逐字节相同。另对根任务拥有的虫、人模型做了只读抽样（五种子、三档、四向、这三个循环），未发现首尾差异，未修改其代码。

蓄势末→打击首是从压紧承重到最大伸展的有意快速击发，不能以“首尾完全相同”作为验收。工具记录了每家族该转换的变化像素量与最大像素质心位移，同时要求每个变体/覆盖/朝向都有释放变化。当前最大质心位移：兽 4.358、蠕虫 4.423、有机残余 3.793、残茎 4.106、门框 5.330、街具 4.055 像素。这是模型端测量；运行时是否正确衔接同一组进度仍须独立核验。

## 环境视觉代码有界复核

本次只检查当前 `yi-paint.ts / yi.ts / ding.ts / model-visual.ts / model-animation.ts` 与本批实体模型，不引用历史审美规范。以下是代码层发现，不代替正式场景的最终肉眼验收。

- 墙面预告沿真实危险格向外生长刻痕，攻击时增加粗细和强度；这种与墙接缝相连的短时形变，与本批实体的低饱和材质体块相容，也比常驻发光轮廓更利于读取危险节奏。仍须在地面实际亮度/阴影下检查最初 25% 强度的细线。
- 初次检查发现 `rhythm_sleep` 墙门 `gapHalf` 在休止和活跃时都取 2，实际开口没有变化；窄视亮缝也不受休止 activity 降暗影响。已交根任务修正开口与亮缝的活动对应关系；本文不声称其最终代码已通过。
- 体积污染每 50ms 更新缓慢形变、每帧更新位置与 activity 透明度，有助于保留持续的异常物质感。休止保留 18% 可见度并停止脚底污迹，苏醒逐步恢复，逻辑方向合理；弱透明边缘是否在正式照明下完全消失仍需实景核验。
- 新实体 240ms 的连续收拢与接地固定相容。初次检查发现首个实际休止 pose 会从默认活跃形态缩回，建议初次收到 activity 时直接落到正确休止程度；另发现收势后运行时接回全局静止相位，可能跳入任意呼吸位置。两项均已交根任务检查，未修改其文件。

## 门框侧向体积修正

四向复核发现旧版门框从左右看易退成薄竖片。本次将真实门槛前后深度增加到 18、框体深度增加到 12；门扇从无厚度多边形改成带前后面与封闭侧面的厚板（普通 2.4、改写面 3 个模型单位），铰点贴近框体前侧，活动常态适度微开。没有新增亮边或更改颜色来代替实体质量。三种大形与原点/碰撞合同保持不变。

门框单独重烤了四向、休止和相位证据，单独重新执行 5,760 活动帧及原有接缝/休止检查。新增左右方向站立体块的宽度闸门：只取图像 `y=14…29` 的体块像素，避开门槛，最小宽度要求 12 像素。定向检查使用 `--family=door`，会保留其他家族此前的报告，不重复烤制或覆盖其结论；实际测量见 JSON 的 `minSideBodyWidth`。修正后的当前类型检查通过。
