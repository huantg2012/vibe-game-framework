# 迭代 11 · 界面判断与构图记录

当前共享视觉执行规范只有 `docs/design-notes/ui-art-overhaul.md` A 节（DEC-119）；本文件记录判断过程，不提供第二份字号、色板和尺寸规范。相关UI spec原地维护交互结构。

## 观察

已读项目入口、美术agent定义、vision、world、美术方向、架构挂载约定和现有UI Kit。独立隐藏实机页观察到：设备用完整轮廓、局部亮窗和短暖灯建立身份；HUD把薪柴、潮汐与承压预告压成近似同重的小字。父代理的报告现场记录显示：标题、三模块、分页不足以形成层级，正文拥在上方而中段留空，设备亮窗透过正文，扫描线穿字。

独立隐藏页未成功打开报告；报告诊断来自父代理现场记录与现有status/allocation源码，不冒充独立截图审看。后续须核修改后的实机画面。

## 取舍

- 保留世界已锁的冷灰结构、青绿污染与薪柴暖光；不改设备模型和玩法。
- 文字恢复阅读层级，低保真由材质和有限色阶承担。R0曾使用中文系统黑体与等宽数字分工，此方案已被人否决；R1改为16点阵字贯穿全游戏，以16/32/48整数倍建立层级。
- 正文底面遮住世界干扰，世界从壳外露出；扫描线退到壳边空白，减少持续阅读噪声。
- 报告用模块列表与当前详情建立主从。自身完整度另有明确命名分区；当前装置影响的出击条件紧跟效果，不吸到屏底。
- 分配从现状进入投入，再看注入结果和剩余薪柴。一个投入焦点，减加与实际动作共用状态；不夸大机制里没有的机会成本。
- 空残渣提示只指向真实路径：关闭报告后前往入口。报告内无效的E键不能显示为可执行动作。
- 菜单、准备、结算共享文字与材质阶梯；裂隙HUD控制占屏，优先混乱、生命与工具即时信息，不放大所有字段。

## R1 · 2026-09-06 人否决后的纠正

人肯定交互布局和主菜单左右布局，强烈否决所有UI美术风格与字体。R0不能记录视觉通过。错误是把清晰阅读约等于系统黑体、平整黑板和亮白选择线，世界像素颗粒与残存设备的材质没有进入组件。

保留布局，R1仅纠正真正点阵字体与刻边部件材质：完整像素字形、冷灰机体/暗内腔、标题承梁、底操作座、局部断漆、凹槽键牌和独立的条形读数。正文纹理为零，磨损只在边缘；不把污染青绿包装为现代科技主题。具体数值唯一位于Kit A节。主菜单概念/宣传图由父代理按人指令生成和接入。

本次一轮实现与一轮截图核对，最终人审仍待进行。

## R2 · 全面否决后的重新设计

人明确要求不继承任何此前UX结论。父代理从世界观与场景独立重建轻量界面，正文12px、标题20px、常驻HUD10–11px，实体底板与粗边框取消；供奉/装配重排横槽和两列库存，蜕变七项全显。旧R1并未通过审美，不能作为当前基线。滚动问题已按真实渲染根因修复，不靠样式隐藏。当前规范为UI Kit A节，此处只保留审查事实。


## R3 · HUD锁定后的面板材质微调

用户给予HUD95分PASS、交互80分且布局结构认可。本轮只修改面板背景和标题：暗绿褐半透层、静态细噪点、渐隐边线，标题与正文同族无衬线。art代理已看r3-defense与r3-allocation实景：颗粒未盖字、色层已打破纯色，标题自然，生命条/投入区间隔保留。建议不再加重噪点。最终材质待用户复评；不重开HUD。
