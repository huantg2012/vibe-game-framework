# Slice 5.5 游戏内 UX 审查（art）

审查范围：立项 S1–S15 + 补扫（Esc 记录菜单、裂隙结算、`createCrtPanel`、场景过渡、boot 加载条、窗口失焦层、混乱阈值旁白）。对照世界层（净化点地表/力场、裂隙污染/角色），不只对照 CSS。

**本文件不是新规范。** 不改 Kit、不改 art-direction、不把任何表面标成审美过关。过 U2 反模式机械扫 ≠ 好看 ≠ 读作游戏。

审查时已 Read：`.cursor/skills/in-game-ux/SKILL.md`（开工闸门 + 写完自检）、`like-a-game.md`、`aesthetics.md`，以及 vision / world / art-direction / palette / Kit v2 / ux-references / architecture overlay 根 / `_template-ui.md` U1–U12 / CRT demo。

## 0. 总览（先读）

人原诊断「不像游戏、不成体系」在本轮对照 `src/**` 后，**体系问题仍成立**，不是被 C0–C7 / R3 / R5 / R7 消掉的旧印象。机械层相对 Slice 5 有收口（DOM 挂 `#dom-ui-root`、CRT 默认 680×468、贴顶三槽、裂隙 HUD 迁 DOM、检视 dock、toast 收编、debug 默认关），但视觉上仍是**至少三台机器并排**：

1. **元界面**：Phaser 居中字，画在 `#0a0a0a` 空场上（主菜单、boot）。
2. **净化点墙机**：DOM `.game-panel` 磷光玻璃，teal 扫描线 + 径向发暗，680×468 压在场景中心。
3. **裂隙随身读数**：无扫描线的条/数字角锚 HUD + 仍挂 `document.body` 的小地图。

同族失败的直观信号：安全区的屏比裂隙里的读数**更「污染色、更特效」**（teal 扫描线在净化点墙上），裂隙里反而是扁平条。这和 art-direction §1 / §4「净化点颜色缺席、裂隙才是 teal 入侵」是反着的。人未看实机前，不能把 R7 CRT 当成已解决「成体系」。

CRT demo（`docs/art/demos/menu-crt-*.html`）**不等于**上线：demo 机身仍画 `1px #2a2d32` 边；`src` `.game-panel` 是 `border: none`。demo HUD 是顶条拉满；`src` 是右上 `flex-end` 三槽。下文以 `src` 为准。

## 2. 共享层（S9 `panel-styles.ts` / `createCrtPanel`）

这不是一块独立屏，是所有 B 类终端的外壳。先写它，后面面板只写差异。

### 载体 / 哪台机器

Kit §A0 / art-direction §6.4 / DEC-049：B，净化点墙机磷光屏。字是这台屏打出来的 Courier。`createCrtPanel` 只打 `.game-panel`，占位 680×468、`top:52px; left:140px`。Esc 记录与裂隙结算用内联覆盖，不走这套占位——**同 class、不同占位 = 已经不是同一块玻璃**。

### 布局（680×468 在 960×640）

| 边 | 漏缝 |
| -- | ---- |
| 上 | 52px（贴顶 HUD `top:10px` 理论上能露） |
| 左/右 | 各 140px |
| 下 | 120px |

几何上四周有缝、不盖三槽。占画布约 **71%×73%**，几何中心几乎就是画面中心（屏心约 480, 286；画布心 480, 320）。U6 的「进行中不占中心」对「人已停在装置前」可辩论；视觉上它仍是一块**居中大玻璃**，不是贴墙的监视器，也不是右侧抽屉。无金属壳、无 1px 外框之后，装置身份几乎只靠：扫描线、径向 vignette、Courier、底键印。人未看压在真实净化点地表上的一帧，不能判它是装置还是网页弹层。

`.game-panel-backdrop` 全画布透明可点：功能是挡场景点击，视觉上没有暗罩（符合 §6.4），但也没有「这是墙上的一块屏」的景深。

### 审美机械层（U2）

已扫到的合规：无圆角；`.game-panel` 无 `box-shadow`；无渐变按钮实装（`.action-bar { display:none }`）；滚动走 `.scroll-area` 藏原生条。

仍在的机械问题：

- **扫描线用 `rgba(26,173,150,0.08)`** = `contam-core` 透明。磷光材质 Kit 授权；色谱上这是 L2 污染色铺进净化点每一块墙机。
- **`::before` 径向发暗**：Kit 写成显像管边缘。U2 把无来由 glow 当后台味；这里有物理借口，剂量等人看。
- **死基元还在**：`.action-btn`（uppercase + letter-spacing + teal/红描边）、`.option:hover` / `.item-tile:hover` / `.upgrade-card:hover`。信息通道已键盘化，但 CSS 仍是 web 控件词。
- **`.card-name { font-size:14px }`**：不在 Kit §A3 的 16/13/12。
- **`.panel-title` 默认 12px `#8a8f96`**：Kit H1 是 16px `#c8cdd4`。多数面板标题走默认，分配/冲击自己加粗 16。同一台屏的「屏名」亮度不统一。
- **`.key-hint-bar [id] { cursor: pointer }`**：键印被做成可点网页热区。
- toast `.toast-inline` / `.toast-stamp` 的 `position:fixed`：挂在已 `transform` 的 `#dom-ui-root` 下时，containing block 是根，letterbox 对齐成立。调用方若将来挂到 body，会立刻漂。

### 场景适配

净化点世界层：程序化混凝土地表（`concrete-dark #2c2e33`）、潮汐力场边界、模块工业体、微暖灯。CRT 玻璃 `rgba(15,17,20,0.88)` 吃得进冷灰。**不吃进去的是 teal 扫描线**：净化点「干净 = 颜色缺席」（art-direction §1.2 / world 色彩倾向），墙机却用裂隙主题色做材质。裂隙场景若打开同 class 的结算小屏，又没有这块大玻璃的占位——同族进一步裂。

### 参考锚点

学 Signalis「设备读出 + 扫描线是结构」／Barotrauma「键印在屏上」／FTL「名+量同屏」。不学 Signalis 曲面畸变、Barotrauma 指针、FTL 供电格/全息蓝。明确不像：右侧抽屉、居中卡片、浏览器窗、按钮表单。

无壳体之后，Signalis 那层「这是一台机器」的物理边变薄了。这是 DEC-049 的取舍，不是实现漏画；是否仍锚得住，等人并排看。

### skill 自检 1–8（共享壳）

1. 载体 B；挂 `#dom-ui-root`。暂停/裂隙结算同 class 改居中小块，等于另起占位。
2. Signalis / Barotrauma / FTL（上表）。不像抽屉 / 卡片 / 浏览器窗。
3. 壳本身无 P0；P0 在 HUD。
4. 墙机磷光屏。扫描线/vignette 的物理借口是磷光与显像管边缘；答不出「为什么必须是 teal」则与污染色冲突。
5. 不可用态由各面板写缺口，壳不负责。
6. 灰度后扫描线几乎消失，屏与场景的分离主要靠暗玻璃——无框时更依赖人眼。
7. 走近装置 / Tab / 归来自动。壳不阻断。
8. 壳无文案。底键印由各面板填。

**分级：** P0 成体系（无框大玻璃 + teal 扫描线进净化点 + 同 class 两种占位）。P1 标题字号档与 14px 卡名。P2 死 `.action-btn` / hover 伪类。

## 3. 逐表面

### S1 主菜单（`main-menu-scene.ts`）

**载体 / 机器：** C 元界面，与 Kit §A0 #1 一致。Phaser Text，Courier，画在 `game-config` `#0a0a0a` 上（**不在 palette.json**；近 `deep-black #0a0b0d`）。不是 DOM，不经 `#dom-ui-root`。哪台机器：游戏外的标题字，不是墙机、也不是随身设备。

**布局：** 标题约 1/3 高居中，选项再往下。不挡战场（无战场）。空场 + 居中字列，是典型标题屏，不是装置。

**U2 机械：** 无圆角卡片、无投影、无 HTML 按钮。已选中 `>`→`▸` + 提亮，与 Kit §A5-1 符号语言一致。色：`#c8cdd4` / `#8a8f96` 锁定。字号 28 / 13 / 16，28 是 Kit 允许的元界面放大。

**场景适配：** 主菜单不在净化点也不在裂隙。允许软件感，但仍应属同一世界。标题「存续」、副标题「边界仍在，光尚未熄」吃得进冷峻语调。**选项行不吃：** 实装 `t('menu.newSave')`=「新存档」、`t('menu.loadSave')`=「读取存档」。Kit §A5-1 写的是「进入净化点」「沿旧路返回」（i18n 里 `newGame`/`continue` 仍在，主菜单没用）。玩家第一眼是存档管理器，不是进入据点的仪式。无 CRT、无冷灰地面、无暖灯，和后面净化点墙机跳戏。

**参考：** 学 Signalis 标题克制 / 本项目主菜单「终端箭头」。不学设置页按钮框、Steam 继续游戏大按钮。明确不像 Dashboard / 设置页 /「Prototype Build」启动页。选项文案把参考拉回设置页。

**自检 1–8：**

1. C。Phaser 画布内，非 overlay 根；主菜单 zoom 默认 1，角锚漂移问题不在此屏。
2. Signalis（克制标题）+ 本 Kit 箭头。不像设置页 / 英文原型页 / 电商列表。
3. P0：标题、最多两行选项。无存档摘要（已知）。
4. 元界面标题字。无投影。28px 放大有 Kit 授权。
5. 无档时不显示读取行（诚实缺省）。覆盖确认是第二屏，警告写「将清除第 N 潮的全部记录」。
6. 灰度后仍可靠字与 `▸` 读出选项。
7. 启动进入。覆盖确认 = 第二条阻断；元界面可辩论，仍是确认链。
8. 「新存档 / 读取存档」是软件词；「存续」在世界动机里，未进术语表。键盘 ↑↓ Enter Esc。

**分级：** P0 成体系（第一屏软件存档词 + 与 CRT 世界无视觉血缘）。P1 背景色未入色板。P2 覆盖确认链。

### S2 净化点 HUD（`purification-hud.ts` `#purif-hud`）

**载体 / 机器：** A，与 Kit §A0 #6 / §A5-3 一致。无边框、不套 `.game-panel`。哪台机器：净化点监控装置贴边打出的等宽读数。挂 `#dom-ui-root`，`top:10px; right:12px`。

**布局：** 右上横排三槽 + 可选「再下一轮」。槽间 32px，名/量/档位分节点。不挡画面中心。与 680×468 CRT 的 52px 顶缝对齐意图正确；四槽全开时右上可能挤，须实机看是否与薪柴数字抢行。

**U2 机械：** 无卡片、无投影、无符号菱形/波形/pip（符合人锁 Alt B）。色均落锁定表。字号 12/13。极端档 `hud-critical-pulse` 300ms（装置告警借口）。`text-shadow:0 0 2px rgba(0,0,0,0.8)` Kit 写成可读性暗晕。`COL.barEmpty #1a1e22` **不在 palette.json**（提示条分隔用）——P2 未映射色。

**场景适配：** 冷灰字 + 薪柴暖橙 + 潮汐 teal，吃净化点「暖色只来自资源/人类侧、teal 标潮汐压力」。无扫描线，比墙机 CRT 更「干净」，和「A 类轻、B 类才是屏」的分工一致。潮汐数值用 `contam-core`，与裂隙混乱条同色——跨场景是同一压力色，还是把污染色提前铺进据点，等人看并排。

**参考：** FTL 一槽=名+量贴边；ItB 预告写成事实；Barotrauma 装置自报。不学供电格 / 战棋格 / 整屏仪表。不像 Dashboard / 设置页 / 浏览器 tab。

**自检 1–8：**

1. A；`#dom-ui-root`；不随 camera zoom 漂。
2. FTL / ItB / Barotrauma（上）。不像 tab 栏 / 竖表 / 图标网格。
3. P0：薪柴、潮汐（第 N 潮+相位）、下次归来（目标+档）。消声第四槽按需。≤6。
4. 贴边监控读数。脉动仅极端。暗晕有可读性借口。
5. 无「不可用」槽。
6. 表名/值/档位分节点；灰度可靠词+位置。剧烈/极端另有红字。
7. 常驻。不开面板。
8. 薪柴/潮汐/涨潮潮峰退潮/核心/储藏/轻微中等剧烈极端 在术语表。「下次归来」「再下一轮」不在表内。键盘不操作本层。

**分级：** P1 四槽挤占与潮汐 teal 是否过早入侵（适配）。P2 `#1a1e22`。机械层已扫；审美待人终审。

### S4 供奉（`defense-panel.ts`）

**载体 / 机器：** B，走近供奉。与 §A0 #9 一致。

**布局：** 四列槽 + 库存行 + 固定检视 + 底键。槽内有名、★、减伤、充能、转化、副作用，符合 CRT 分区意图。680×468 内四列文字密度高，副作用一句在槽内换行——实机可能溢，须人看。

**U2：** 无原生 `title`。已选中暖色左边框。空槽写「空 / 可装填」。库存 `tile-disabled` 仍靠 opacity 0.35，缺口在检视 L4「槽位已满」——槽上那一行本身只变淡。稀有度 common 用 `#8a8f96`（为对比度偏离 Kit A2 的 `contam-mid`），fine/rare 用污染亮阶 + ★。hover 仍改边框，键盘有同等已选中。

## 5. 场景适配对照（世界层，不只 CSS）

### 净化点

世界：混凝土程序化地表、冷灰、力场边界、模块工业体、微暖灯、边界外黑暗。氛围「空旷、勉强维持」。

压在上面的 UI：

- A 类三槽：轻，右上，不抢中心。和空旷兼容。
- B 类 CRT：大块发暗玻璃 + teal 扫描线。房间里突然多了一块发亮的冷色矩形。无壳体时，它不像焊在墙上的监视器，像悬浮层。
- 提示条底中：可当成地上的设备字。
- 归来结算 / Tab / 走近：同一块玻璃循环换内容，装置逻辑成立；内容（蜕变卡墙、供奉砖）在语言上分裂。

### 裂隙

世界：暗、碎片色温、teal 数据错误、玩家暖光、有限视野。

压在上面的 UI：

- HUD 条和暖薪柴对色谱。扁平、无坏像素、无扫描线，**比污染世界更干净**——「装备仍在工作」可解释，也可以读成另一套软件。
- 小地图干净雷达窗。
- 超阈 veil 吃渗透，和世界同族。
- Esc 记录、裂隙结算、顶中 toast、body 过渡：把据点壳/网页层盖进裂隙。

### 主菜单

空黑场 `#0a0a0a`。无混凝土、无力场、无 CRT。和两场景都无血缘。元界面允许；要「同一世界」目前只靠 Courier 和两句文案，选项行还把这点拆掉。

## 7. 必须等人看游戏才能判

机械层可以扫；下面这些 **agent 不许代勾**：

1. 无金属壳的 680×468 玻璃压在真实净化点地表上，是墙上的屏还是网页弹层。
2. teal 扫描线剂量：磷光材质 vs 把裂隙涂进据点。
3. 右上三槽在实机 960×640 是否一眼能读、四槽时是否撞 CRT 顶缝。
4. 裂隙 HUD 左上叠条 + 底左工具 + 右下小地图，在有限视野里是否挡威胁、是否「没有 HUD」的旧怨已消。
5. 蜕变 3×2 卡 + ♥ 是否一票否决。
6. 主菜单「存续」空场是否闷/丑/不像这游戏的第一帧。
7. 灰度实机：稀有度、危险、撤离点是否仍可读。
8. 两场景来回切几次：会不会每次都觉得换了一套 UI。
9. 「文字必须看清」（人硬门槛）：12px 磷光 + 扫描线叠字是否仍能读。
10. CRT demo 与 src 无框差：人当初锁的是 demo 观感还是 src 无框。
