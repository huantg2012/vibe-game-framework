### 必须改变的工作方法

上轮根因已由画面和源码确认：对象构造没有完成，表面装饰过早接管；材质主要被表达为颜色替换与统一提亮；角色仅被放进画面，没有成为配色基准；评审关注相对进步而漏掉明显的空白断面。理论解释正确和技术通过都不能证明画面质量。

本轮按**对象怎样建成 → 体积与接合 → 材质的连续明暗/反射 → 少量使用痕迹 → 同场空气**的顺序画。禁止将新反馈逐条转成旧底图上的补丁。若去掉锈斑和划痕后金属就成了蓝纸盒，基础塑造仍失败；若关掉核心光后墙地只剩平底加花纹，不能继续用光晕补救。下层平台外露侧沿与被遮住的转面同样是对象的一部分。

### 世界观、形体与构造

净化点是污染现实中的有限秩序，工业残骸仍在勉强维持功能。启动页原画直接提供本轮的空间与材料目标：破碎建筑从右侧残存墙墩伸向深暗空洞，具有连续依托；厚断面、垂落残构、错位书架与远处碎片构成尺度；木架、书册、旧混凝土、铁机器和微暖炉光让据点有被使用的痕迹。完整构图须给六处功能与原人物留出真实空间，同时保住空洞的压迫和近远层次。

**设定来源边界**：[原始世界规则](world.md#核心设定规则影响机制)定义污染为现实改写、异源模式互相排斥，薪柴用于抵抗本时空污染；核心的既有机制是降低出击混乱增速。原始正文没有规定核心腔内物的物态，也未说它就是薪柴。下述“来自其他Rift世界、被收束约束的污染物”是用户近期明确补全的实体定义；团块的遮蔽、透射与内部密度是本轮认可的表现方向，不反写成早期既有设定。

**核心**置于下层右沿 `[12.8,0,3.4]`，高约4.93m；开放面朝主层与上层地面面积加权几何中心 `[5.45255,0.47473,-0.48510]`，不朝相机或当前角色；朝向由平面几何计算，前场站位随之调整。低阶前场、开放铁冠与有厚度的约束肋形成可朝拜的圣龛，移除遮挡它的前景高书柜。仪式感来自空间停顿、比例与收束关系，不靠贴满符号。其内质是从其他Rift世界收集、被收束和强行约束的污染物。内芯是一团占据空间、内部持续活动、自身向外辐射的污染能量；亮暗表达能量密度、聚集与稀薄，具有体积但没有普通固体的皮。内部涌动、汇聚、撕裂、重新收束，束缚处可见受压关系；能量丝只作内部次级结构，不能替代主体。旧俯视版腔内聚集亮度及壳外溢光是可借回的表达关系。面团、空心细线/薄片、灯泡或规则宝石均不成立。机械壳体承力和约束，能量本身不服从普通固体的表面塑形。

**核心照明（用户明确，已实现于样景，待人审）**：能量体向四周及上下全向辐射，具有整个净化点最大的发光强度，是场景主光源。不能只照前方和地面，也不能用将光源推到正面、背后封死的做法替代全向能量。周边框架的内侧/上缘、两侧与后方可接收区域、邻近建筑和空气都应按真实空间关系受光；距离、朝向与实体遮挡决定各处亮度，允许合理阴影，不等于整圈均匀光环或全场提绿。若壳体结构使核心整体仍只能单向漏光，应调整开口/约束构造，使全向主光的视觉事实成立。

**平台**按薄的铺装面层、承重主体与暴露断面组织。顶面接缝和裂口要有去向；破断处显出厚度变化、粗细骨料、上下层关系、局部承托/连接。不是整圈描亮、不是整块加深色侧面，也不是在断面上贴一排独立小石头。地面的大面保持通行读法，材料变化服从同一块铺装/同一处破断。

**墙体**有承重框架、内退壁龛、施工接缝和连续的墙脚承托。转角的光和暗属于厚度，不用污斑假装凹凸；大块平面也应具有可信的基材和受光，不靠把暗处涂黑藏掉未画内容。

**西侧装置摆放（按追加标注校正）**：供奉`[-3,0,-3.85]`、绕竖轴约32.35°、开口朝画面下方，用户明确确认正确，保留。净化器从前轮`[-1.5,0,3]`/90°改为`[-2.35,0,2.7]`/`atan2(30,-19)`（约122.35°），长轴在画面中近竖直，操作面准确朝画面正右；接受此朝向带来的正面侧视，不再次为展示内腔而改角度。机体、底座、局部光源共享变换，操作点沿新正面计算；底脚13776点全部受平台支撑，距断沿至少约0.065m。当前为艺术样景位置，未迁移到正式游戏。

**机械**区分铸造、压制板与涂层。核心肩体是厚重、圆钝的承力铸体，内侧有装配凹槽；供奉环有连贯的弧面和孔壁厚度；净化器有折边罩壳、真实孔腔及内部筒体。反射随着曲率和表面处理变化，不能所有面同色、所有边同亮或全部变成镀铬。

**核心当前画法**：`energy.ts` 用三维浓缩区与绕行涌流替代线性等相位亮层、贯穿平面暗谷。关键修正是删除包络中的均匀低密度填充：密度只占据实际浓缩团块，让空腔和外轮廓分开；前侧冷浓密区衰减后侧亮流。仅把纹理改成立体噪声仍会读成幕片，不能退回这一中间稿。核心局部中心`[0,2.66,-.44]`、基准半径`[.76,1.10,1.18]`，主体向前后鼓出，保留4.8秒慢扩张/快压缩。7个全向光样本跟随同一中心分布，数量与作用范围保持；静态与动态按底图×透射＋辐射合成。积分后的RGB共用曝光压缩，避免分别截断为大片纯白。整景、实际像素4×近景及峰值均已复核，技术通过不代替本轮艺术人审。

**核心投光可辨识性**：主地面从核心向中心衰减、右坡与平台边沿、右侧残墙形成连续受光关系；炉火和肩灯保留独立色温。核心输出统一乘1.6，使用有限体积源的近场软化`power/(2.2+0.13d²)`，外沿仍由14m支持截断，避免只拉大半径或把近框漂白。3.4m内的空气散射沿相机射线积分、被场景深度及光源到空气的真实遮挡截断，不全屏加绿。`light-core.png`是污染光场中的有效核心贡献，经过无核心并行基色计算保留LDR裁切和玻璃后的实际差值。芯体与环境光共用4.8秒伸缩周期，扩张峰值增加22%；其他污染保留自己的旧节律。查看页“核心照明”只用于同帧开关环境贡献，芯体自发光保持，并按其透射正确合成；正常默认开。

### 角色先行的配色

人物保持暖棕/暖灰工作服、圆顶护帽/单黑面罩、背包及右侧肩灯。`actor.ts` 在据点用同源几何重画约22×41px实尺人物，Rift继续原32×32画布精灵，不能反向替换Rift。以原画为准组织冷暗建筑、旧木架、金属与微暖炉光，各材料保留本色；不要重回遍地土黄，也不要把木材与生活光统一洗成冷灰。用色相、明度、局部对比共同分离人物，不能靠白描边、人物放大或一圈假光圈补救。

普通建筑/机器不默认带绿。污染绿须冷、浑、压抑，避免上版的鲜草绿和糖果薄荷绿；固态污染可呈深墨与灰冷绿层次；核心能量体则由灰绿发光密度、较暗涌动和局部苍白高能区组织，不能把亮度限制在折缝。绿色可在必要处明确出现，但“大胆”不等于大面积鲜艳。当前材料与受光实现见[render.ts](art/demos/purification-last-light/render.ts)；必须与人物、金属、建筑和炉光同屏判断，未获人审不能称锁定色板。

### 2D像素渲染与材料描绘

像素是最终组织形状与边缘的语言，不是限制所有物体只能用三块平色的理由。硬像素边缘、清楚的像素簇与连续受光可以并存。材料的多尺度信息先来自对象本身：断面/接合的大关系、曲面/板层的中尺度转折、局部骨料/加工面的微结构；最后才是磨损和污渍。

当前以[model.ts](art/demos/purification-last-light/model.ts)记录可编辑几何，[environment.ts](art/demos/purification-last-light/environment.ts)和[devices.ts](art/demos/purification-last-light/devices.ts)组织完整环境与六物；[render.ts](art/demos/purification-last-light/render.ts)直接在固定像素网格上计算可见面、材料、局部光源及遮蔽。孔壁、承托、夹件和破断先成为有厚度的对象，再处理受光与微结构。更多三角面、材质参数或光线数量不证明像素画面成立；旧 C 的 `construction-surfaces.ts` 仅保留为被否决版本的历史实现。

光源只分三类：肩灯的淡暖白、炉内橙火、污染的灰绿。各源通过几何遮挡、同一法线/材质响应混合；暗部用低强度漫反射保留材质。所有污染物具有自发光与局部受光，核心最强，六装置和外层污染不同范围；污染材质自身对绿色照明压低响应，避免绿上叠绿变薄荷。空气与源扩散独立且克制。

`motion.ts` 消费三类实际光照贡献，源与接收面采用同一时序；炉火不规则微变、肩灯稳定、污染低频收缩并沿既有材质发生细微侵蚀。外景空气按层流动，约23秒周期中短暂出现被深度遮挡的大形局部；不画眼睛或完整怪物图标。支持暂停、页面隐藏停时、系统减动默认暂停。当前是固定相机的同源光场动画，几何阴影形状已烘焙；不是任意人物移动后的实时阴影或补全隐藏内容的视差层。

被否决 C 版本的复盘仍有效：结构重画后仍像干净机房，大量面材同处中灰，材料只剩连续渐变与细噪点。**本轮必须用完整原画对照检查中尺度像素塑造、边缘显隐、破败场所与生活痕迹**；不能因为结构合理就认为达到成品水平，也不能通过平均加噪点补足。

### 看图时必须回答的问题

1. 第一眼能否读出原人物，以及核心、通行面和背景的主次？是否仍让暖棕人物淹没在相近地面？
2. 不借文字说明，金属、建筑材料、涂层和污染是否有各自的形体与受光？干净面是否也成立？
3. 从顶面看到断面，构造是否连续？孔洞有无内壁，接合有无实际遮挡，厚度是否由可见内容支撑？
4. 正常游戏尺度下是否形成完整的像素绘景，而不是放大后靠碎纹显得有工作量？是否有统一的斑点/网格铺满表面？
5. 与启动页原画并置时，断裂书库、深空、层次和有限暖光的整体效果是否接近？新增六物是否融入同一场所，还是把原画变成装置陈列？
6. 六处操作站位和两条坡道是否有连续空间，人物是否被高物遮没？几何校核结果与未来正式可玩性分别记录，不能混称已经可玩。

这些是需要由实图回答的问题，不能转换为“颜色数量达标”等替代指标。记录具体失败区域并修改，不以“比上一版好”宣布艺术达标。用户尚未认可时始终标记待审。

## 1. 核心视觉原则

### 1.1 视觉统一性原则（Degree not Kind）

**所有视觉变化是同一套语言的参数调节，不是切换语言。**

场景、实体、UI 的视觉表现必须让玩家感到"这些东西属于同一个游戏"。实现方式不是让所有东西长得一样，而是确保底层存在共享的视觉语法：

- **污染的表达方式统一**：实体的"渲染崩坏"和地板上有主的青绿占漆是同一种现象的不同尺度（同一份 ramp）。玩家看到改写体身上的青绿，和看到路上那几滩有主的漆时，应感到这是同一种力量。环境不再要求网格对齐的矩形平涂；接缝漏光可以仍在，不是主签名。地面烤层不再铺不收钱的氛围崩坏簇（DEC-104）
- **浓度递进是连续的**：轻度 → 标准 → 重度之间不切换视觉语言，只调整参数（占漆只数、色相滑动、材质残影）。玩家走入更深区域时体验是渐变加重，不是突然进入另一个画风。年龄不再调氛围簇尺度 / 密度
- **区域差异靠底色色温倾向 + 纹理语法 + 渍色 + 结构共同承担**，不靠改变污染的表达方式。底色只给极弱色温倾向，不强求量化落到不同色板格。可辨的身份主要由渍色、划痕/碎屑语法、污垢幅度、墙偏置（`wall_bv × wall_bias`）、地物尺度与质量语法承担。禁止拿 `wall_body_key` / `wall_rim_key` 当身份（现实现不读这两列）。**为何改写（原「区域差异靠底色色温 + 材质纹理」）：** 色板亮度低于 32 的格子没有暖格，最暗暖格 `#2a2018` 亮度 33；地板像素落在亮度 21–25，噪声扩散之后量化系统性擦掉暖——实测四张启用碎片的可走地板众数塌成 `#1a1e18` / 近黑，户外与旧图书馆的暖减冷几乎重合。原规则与「极度压暗」+「锁死色板」不能同时成立。人授权改本条与 §2.3 规则 6。禁止改用第二层污染色相来「区分区域」。切法见地表说明书身份配方。
- **实体等级差异靠覆盖比例 + 形体完整度区分**，不靠改变"什么是污染"的定义

违反此原则的信号：两个东西放在一起看起来像不同游戏的截图。

### 1.2 光与色的叙事规则

> 本段为旧约定。本轮净化点允许材料本色，颜色职责与世界观表达见[当前美术设计](#current-art-design)，不再以“有颜色即污染”或“干净即无色”作图。

**黑暗是底色，颜色是入侵。**

- 有颜色的地方 = 被污染的地方
- 净化点的"干净"体现为颜色的缺席（冷灰 + 极微弱暖光）
- 裂隙内的"危险"体现为不自然的 cyan-teal 渗出
- 信息层级通过亮度差驱动：越重要/越危险的东西越亮

### 1.2 风格定位

| 维度 | 选择 | 理由 |
| ---- | ---- | ---- |
| 分辨率感 | 32x32 tile，像素可见 | 在像素感和细节表达之间的平衡点；足够空间表达几何污染纹理 |
| 色彩丰度 | 极度受限，近乎单色 + 单色相点缀 | 强化"颜色是入侵"的叙事意义 |
| 细节密度 | 低（留白 > 填充） | "看不清比看清更有效"；减少 AI 生成的不一致性 |
| 对称性 | 污染体几何对称，环境不对称 | 表达"异质秩序 vs 破碎现实" |
| 动态感 | 缓慢、有节奏 | 脉动/呼吸感而非快速运动；压迫而非惊吓 |

### 1.3 为什么选这个风格

- **符合游戏调性**：极暗、低信息密度的画面直接服务于"绝望边缘的紧绷"和"孤独的仪式感"。看不清 = 不安全 = 每一步都是决策。
- **AI 可生成性高**：像素风是当前 AI 图像生成中一致性最好的方向之一。32px 级别的细节量恰好在 AI 能稳定输出的范围内。极暗色调掩盖了 AI 生成中的细微不一致。
- **一致性容易维护**：受限调色板 + 统一后处理管线意味着即使不同批次的 AI 输出略有差异，经过色调映射后仍可归一化。
- **性能友好**：像素风 = 小文件 = Web 加载快。32x32 tile 的 spritesheet 整体体积极小。

### 1.4 视觉禁忌（同 world.md，用于 prompt 排除）

- 不使用：触手、内脏、血浆、虫卵、黏液、有机腐烂
- 不使用：明亮/温暖/高饱和的大面积色块
- 不使用：卡通描边、Q版比例、明快高对比配色
- 不使用：科幻全息 UI 风格（不是高科技文明，是勉强维持的工业残骸）

### 1.5 风格参考

- **Darkwood**：俯视角有限视野的黑暗处理方式；光衰速度；恐惧来自看不见
- **Signalis**：low-fi 像素的恐怖力量；受限色调；工业质感 UI
- **Rain World**：用像素传达"生态系统不关心你"的冷漠感；动画的有机-机械混合感
- **Hyper Light Drifter**：俯视角像素游戏的光照/粒子表现；色彩作为叙事工具

## 2. 色彩体系

### 2.1 四层色彩架构

游戏的色彩不来自单一来源。四个层次共同构成视觉体验，防止"全程暗灰+绿"的单调感：

```
最终画面色彩 = L1(碎片记忆色) + L2(污染色谱) + L3(玩家暖光) + L4(稀有叙事色)
                 区域身份底色      异常的颜色      人类的颜色       情绪标点
```

**设计原理：** 参考 Rain World（区域色温差异）、Hollow Knight（感染色是叠加层不是唯一色）、Hyper Light Drifter（方向感靠区域色建立）。我们的规则"颜色=异常"仍然成立——但"异常"的色彩来源是多元的，且叠加在有微妙色温差异的基底之上。

#### L4：稀有叙事色（情绪标点）

极少出现（整个游戏 5-8 次），出现时冲击力巨大。不固定色值——每次出现都是独特的、属于"旧世界"的颜色残影：
- 褪色照片上的暖黄
- 生锈招牌上依稀可辨的红漆

### 2.3 色彩使用规则

1. **净化点重构采用文首当前设计**：材料保留自身色相，光源暖色集中在有限区域。旧“总体饱和度 < 10%”不再约束本轮。
2. **裂隙场景色彩来自三层叠加**：碎片记忆色（基底色温）+ 污染色谱（有主占漆；接缝漏光可并存、不得长成滩）+ 玩家暖光（随玩家移动）
3. **任何非灰色都必须有叙事理由**：它是碎片残影（L1）、它被污染了（L2）、它是玩家的存在（L3）、或它是旧世界残余（L4）
4. **玩家装备投射微弱暖光**——净化设备在玩家周围 2-3 tile 投射暖色光（warm-dim）。叙事意义：你是这个世界里唯一的暖色来源
5. **同一场景内污染色相不统一**——新生区偏蓝、标准区正 teal、古老区偏暖绿。同一画面内应有 2-3 种色相的污染共存
6. **碎片切换 = 身份层切换**——玩家穿越碎片连接时，应感到这块地方不一样。底色可保留极弱色温倾向，但**不是**可辨身份的主通道（量化在压暗色板里会擦掉暖）。可辨差异来自渍色、划痕方向与碎屑密度、污垢幅度、墙偏置、地物尺度与质量语法。禁止靠 `wall_body_key` / `l1_key` 表达身份。禁止让污染层承担这次切换。**为何改写（原「碎片切换 = 色温切换」）：** 与 §1.1 区域差异条同一死结——烤图上底色色温分不开四张世界。人授权改本条。切法见地表说明书身份配方。
7. **高亮点越少越好**——如果画面中超过 3 个高亮发光点，就削减到最关键的
8. **暖色永远稀缺**——暖色系（amber/orange）在裂隙中仅来自玩家，任何"多出来的暖色"都是叙事事件（L4）。**注**：薪柴世界内实体属**污染侧**（异源残渣，`world.md`），视觉为 teal 余晖（见 §5.3），本不是暖色，不违反本规则；HUD 薪柴计数用 warm-dim 是"玩家资产读数"的 UI 约定，不是世界内光源（见 §6.2 / §13.1）。两处"不一致"实为两个不同上下文的合理表达，单一规则：**裂隙内实体不带暖色，HUD 读数属玩家侧**。**注 2（DEC-110）**：本条约束的是**光源 / 暖意色**；§2.2「残骸材质色」三格（debris-earth / debris-rust / debris-wood）是**世界材料色**——残骸断口的本色，哑不光、不照亮地板、面积小（搜刮堆主体），与薪柴 teal 余晖注同属"不同上下文的合理表达"，不违反本条。

## 3. 技术规格

### 3.1 Tile 系统

| 参数 | 值 | 理由 |
| ---- | -- | ---- |
| Tile 尺寸 | 32x32 px | 像素风和细节表达之间的最佳平衡；AI 生成 32px tile 比 16px 更容易保持一致性；足够表达几何污染纹理 |
| Tileset 排列 | 每行 16 tile（512px 宽） | 标准 spritesheet 宽度，GPU 友好 |
| Tileset 格式 | PNG-8（256色）或 PNG-24 | 像素风不需要太多颜色深度；调色板受限本身就是风格 |
| 画布分辨率 | 960×640 px | Phaser `gameConfig.width/height`；3:2 比例；`pixelArt: true`（nearest-neighbor） |
| 游戏 viewport（逻辑） | ≈ 640×427 px ≈ **20×13 tile** | `camera.setZoom(1.5)` 将物理画布压缩为逻辑视口（DEC-009）；宽恰好 20 tile，高约 13.3 tile（画布 3:2，精确 20×15 不可得） |
| 渲染缩放 | `camera.setZoom(1.5)` + `pixelArt: true`（nearest-neighbor） | zoom 收紧视口实现接近 20 tile 宽的紧张感；`pixelArt: true` 保持像素锐利不模糊 |

### 3.2 Sprite 规格

| 类型 | 尺寸 | 说明 |
| ---- | ---- | ---- |
| 玩家角色 | 32x32（含 padding） | 出击与练习场同一套加厚密像素（DEC-068） |
| 渗透体（低度敌人） | 32x32 | 密像素前倾人形，与玩家画布同等大小；碰撞仍 20 |
| 改写体（中度敌人） | 32x48 | 超出人形比例；横向加质量，不靠再放大画布 |
| 覆盖体（高度敌人） | 48x48 或 64x64 | 完全非人形，几何结构体 |
| 可交互物（小） | 16x16 | 薪柴、消耗品 |
| 可交互物（中） | 32x32 | 撤离点标记 |
| 净化点模块 | 64x64 或 96x96 | 大型功能设备，多状态 |

### 3.3 动画规格

| 动画类型 | 帧数 | 帧率 | 说明 |
| -------- | ---- | ---- | ---- |
| 角色待机 | 4 帧 | 4 fps | 微弱呼吸感（身体微晃） |
| 角色移动 | 4 帧 x 4 方向 | 8 fps | 俯视角四方向行走 |
| 敌人巡逻 | 4 帧 | 4-6 fps | 缓慢、机械、不自然 |
| 敌人警觉 | 2 帧 | 2 fps | 停顿、感知器官亮度变化 |
| 敌人追击 | 4 帧 | 8 fps | 加速、不协调的突进 |
| 污染脉动 | 占漆活层 | 每帧 | 出击与练习场（DEC-070 / DEC-071 技术；DEC-104 改应用）：整图氛围簇呼吸关。活层跟占漆宿主自己走，幅度 5–20%、每帧连续场，禁止 4 张静帧、禁止沿圆周鼓包。地面烤一次。迷雾下亮度等人终审 |
| 光源闪烁 | 3 帧 | 不规则 | 净化点灯光微弱跳动 |
| UI 状态变化 | 即时或 2 帧渐变 | - | 数值变化用直接更新（不花哨） |

**动画原则：**
- 帧数越少越好——像素风的力量在于有限帧的暗示性
- 所有循环动画使用 ping-pong 或无缝循环（无跳跃帧）
- 敌人动画速度随覆盖程度分化：低度（僵硬慢）、中度（不规则速度切换）、高度（匀速滑行如机器）
- 环境动画极缓慢——脉动周期 2-4 秒，不抢注意力

## 4. 区域视觉设计

### 4.1 净化点

> 以下是早期资产需求，不作为 C 重构的画面或资产规格。当前净化点的材质、画法与内外层次统一见[当前美术设计](#current-art-design)。

**氛围关键词：孤立、微光、功能性、空旷、勉强维持**

- **地面**：混凝土板（concrete-dark/mid 交替，偶有裂缝 tile 变体）
- **墙体**：金属板（metal-grey）+ 铆钉/焊缝细节
- **设备/模块**：深灰金属框架，有微弱的功能指示灯（warm-dim 单像素亮点）
- **光照**：1-2 个暖色点光源，光衰极快（3-4 tile 半径有效）
- **边界**：金属栏杆/矮墙过渡到绝对黑暗
- **边界外**：BoundaryAtmosphere 系统渲染（粒子 + 周期性浮现形态）
- **关键识别特征**：几乎无色、有人维护的秩序感、微暖点光

**Tileset 需求：**
- 地面变体：4-6 种（素混凝土、裂纹混凝土、金属板、排水沟盖、连接缝）
- 墙体：直边、内外拐角、T形（金属+铆钉风格）
- 设备/模块：各功能模块视觉（健康/受损/严重受损 三态）
- 光源：可动画的暖光 tile（2-3帧闪烁）
- 边界：栏杆/矮墙 tile + 向黑暗的渐变过渡

### 4.2 裂隙内部

**氛围关键词：窒息、不适、错位、监视感、危险的美感**

**环境污染的视觉签名：渲染崩坏**

环境污染和实体污染是同一种现象的不同尺度表达。实体 = 单个 sprite 的渲染崩坏；环境侧看得见的成片青绿 = 有主占漆（油膜三变体，与敌人四档同一份 ramp）。地面身份靠渍 / 纹理 / 墙结构，不靠污染色相，不靠氛围簇。表现形式：
- **有主占漆（成片青绿的唯一来源）**：油膜三变体钉在贪婪薪柴路径上的可走地板。禁止统一圆球，禁止用网格对齐的矩形平涂当作出击地面的主签名，禁止把氛围崩坏簇加回来（DEC-104）
- **数据泄漏（可并存）**：teal 光仍可从 tile 接缝透出——不是液体在流动，是现实"渲染失败的间隙"。接缝漏光不是主签名，生产不以它代替占漆，也不得长成一滩
- **叠加覆写**：局部区域被"另一组数据"部分覆盖——不属于这里的纹理片段出现

**注意**：污染不是"表面被染色"，也不是"有机脉络蔓延"。签名仍是渲染规则崩坏、与实体同一种现象。环境侧现行合同是有主占漆 + L1 世界，不再要求矩形的网格对齐错误块，也不再铺不收钱的氛围簇。

**污染浓度梯度（degree not kind）**

三级浓度使用**同一视觉语言的连续递进**——同种表达调强度参数，不切换表达方式。色相不写死一组 `CONTAM_*` 套所有岛：从该岛碎片地板/墙 bias 推导 HSV，往青绿轴拉，再按污染年龄偏蓝或偏绿，最后量化到已锁色板。年龄改调占漆只数，不再调氛围簇尺度 / 密度。烤地无主青绿占比走**上限**（防簇偷跑）：新生 ≤ 0.20%、标准 ≤ 0.35%、古老 ≤ 0.50%（占漆宿主不计入此项；数字与切法见地表 HOW）。下限作废。

| 浓度 | 暗色地面占比 | 占漆只数 | 接缝漏光 | 色相滑动 | 乱码 |
|------|-------------|----------|----------|----------|------|
| 轻度 | ~90% | 新生 3–5 | 可省 | 往蓝拉 | 仅单像素异常 |
| 标准 | ~75% | 标准 6–8 | 可并存细线 | 青绿轴中位（仍随该岛 bias） | 无 |
| 重度 | ~50-55% | 古老 9–12 | 可并存 | 往绿拉（`contam-ancient` 须按 §14.4 压饱和，禁止原色铺开） | 有（噪点/乱码纹理） |

- **地面**：碎片记忆色（L1）提供底色色温 + 原有材质残影（砖/土/金属/木）仍可辨认（轻度/标准区）或几乎不可辨（重度区）。有主占漆只经宿主画在已连通的可走地板上，不改碰撞、不拆连通。烤层不再铺氛围簇
- **墙体/障碍**：原始材质轮廓可辨；接缝漏光若画，仍不得挡路
- **光照**：无"正常"光源。成片青绿来自有主占漆；活层跟该宿主自己走（DEC-070 / DEC-071 技术，DEC-104 改应用）。整图氛围簇呼吸关。迷雾下亮度等人终审
- **空间逻辑**：不遵循建筑规则——走廊突然终止于融合物质墙，区域以错误角度接合
- **碎片连接（裂口）**：高亮 tear（白热核心 + teal 边缘），地图中最亮的点，也是决策点

**Tileset 需求：**
- 正常地面变体：4-6 种/碎片类型（各碎片有自己的材质+色温）。连续地面仍走程序化表面（DEC-018），不换回离散 AI tile
- **有主占漆：宿主精灵**，出击与练习场地图课同一套。`bakeGround` 不下氛围簇层。不要再做一套矩形错误 tile 当地面合同，也不要用簇填回
- 缝隙发光层：允许叠加，不是主签名；宽度若画仍分轻/标准/重度，不得用加粗折线冒充占漆
- 乱码：仅重度区；量化后打错点，不是另一块碎片的底色铺上来
- 环境物件：碎片来源的残余物（家具残骸、设备、植被——但随浓度增加越来越不可辨）
- 裂口标记：高亮发光 tile（碎片间连接处，最亮元素）

裂隙地表按碎片类型表驱动，见 `docs/art/rift-fragment-surfaces.md`。晶结 / 溶蚀 / 平涂矩形错误块仅练习场对照，不得进出击。

### 4.3 视野与黑暗

- **视野内**：完全正常渲染（所有色彩/细节可见）
- **视野边缘**：3 级 alpha 渐变，以射程外沿为基准向内切两条等宽渐变带，由内向外递减：
  - 全亮核心 alpha **1.00**（贴身至射程 − 2 tile 处）
  - 中带 alpha **0.60**（固定 1 tile / 32 px 宽）
  - 外带 alpha **0.20**（固定 1 tile / 32 px 宽）
  - 满射程（1.0 R）外沿之外：全黑（void-black）
- **视野外**：void-black 覆盖；非均匀——极微弱像素噪点暗示空间存在（不是空白加载区）
- **远处发光源**：环境中的高亮点（污染核心、裂口）在视野外仍可见极微弱光点（远距离导航辅助）
- **视野形状**：锥形（面朝方向更远）为默认；细节由系统设计 spec 定义
- **混乱值影响**：超阈值后视野边缘出现 teal 噪点渗入 + 视野半径缩小

## 5. 实体视觉设计

### 5.1 玩家角色

怎么画、怎么分层、怎么和敌人对照、练习场怎么验：`docs/art/actor-pixels.md`。审美由人终审。

**出击已接线（DEC-068）。** 裂隙 / 净化点的 `Player` 用 `src/entities/player-sprite-dense.ts` + `player-lamp-aura.ts`。练习场课 `gym.html?lesson=player` 是同一套外形。旧方块人 `player-sprite.ts` 不再驱动 `Player`。

**外形：** 方案 1 加厚工业程序像素 + 方案 3 留下的灯尘。

- **轮廓**：人形偏瘦小，工业防护（面罩 / 背包 / 分腿 / 灯壳体，不是铠甲）。侧影加厚，使体量能与 32×32 渗透体并排
- **色彩**：混凝土灰里略加点暖，与净化点同色系、融入而非突出。灯是唯一高亮。不要青绿、不要把身体裂开当签名
- **面部**：无细节（俯视角 + 面罩）；不表现个性，只表现存在
- **携带暖光**：探照灯投射微弱暖色光（warm-dim #8a5c2a），照亮周围 2-3 tile。裂隙中唯一的暖色来源。灯尘上飘与脚底暖斑叠在密像素上（出击与练习场同一套）
- **受伤表现**：sprite 整体闪烁白色 1-2 帧（不改变颜色，不加红色——保持色彩纪律）
- **方向指示**：朝向靠四向贴图，不旋转 GameObject，不用额外箭头

### 5.2 污染体设计体系

**核心视觉签名：渲染规则崩坏**

污染破坏的不是身体本身，是构成这个像素世界的渲染规则。被污染的实体看起来像"坏掉的 sprite"——不是某种具体的变异（晶体/电路/触手），是**表征本身的失败**。观察者无法命名看到的东西，因为那不是一个"东西"，是渲染错误。

这一签名与"后克苏鲁"设定呼应：在像素世界中，现实的基底就是像素。污染侵蚀基底 = 像素本身出错。"不可名状"体现为"无法归类"。

**实现分层：基底像素（程序绘制）+ 动态效果（代码）**（DEC-066：渗透体 / 改写体不再换 AI 精灵表）

| 层 | 内容 | 来源 | 说明 |
|---|------|------|------|
| 基底层 | 启动时绘制的四向直立像素 + 待机/行走帧 | `infiltrator-sprite.ts` / `rewriter-sprite.ts` | 比例偏移、坏像素、轮廓缺损、前倾猎食、改写体行走裂开/伸缩都画在帧里 |
| 动态层 | 残影、转向滞后剪影、头上指示物、追击 1px 抖动、青绿脱落尘、改写体脚下污斑、木偶顿步 | 实体代码 | 运行时附加。尘往外/往下掉，不是暖灯上飘 |

基底在没有动态效果时就必须读为"有什么不对"。动态层提供"活的恐惧"和记忆点。覆盖体未做；若做，来源另议，不默认套本表。

**与玩家同一密度、相反语言。** 玩家加厚之后，敌人若退回简单多边形会立刻垮。污染体用脱落尘和脚下污斑「吃光」，不要再堆发光，也不要给渗透体面积光。密、能走、有尘仍可能像「会巡逻的像素人」——压迫来自前倾、肢体过长、木偶顿步、质量压在朝向上。

**朝向：** GameObject.rotation 恒为 0。转向靠换贴图。禁止把剪影烘进贴图里转 90° / 180°。

**画布与碰撞：** 渗透体画布 32×32（曾 24×24，相对玩家太小）。碰撞仍 `BODY_SIZE` 20。画布变了只改 `AI.BODY_OFFSET`（32 画布为 `{6,6}`），不要改碰撞边长。改写体保持 32×48，只加横向质量。过程闸门见 `docs/art/actor-pixels.md`。

**三级递进（已验证）**

| 等级 | 轮廓可读性 | 基底静态特征 | 动态增强 | 大小 |
| ---- | ---------- | ------------ | -------- | ---- |
| 渗透体 | 人形清晰可辨（第一眼像人） | 臂过长、肩不对称、家族散点、轮廓缺损、前倾猎食；32×32 密像素 | 木偶步态、迈步脱落尘、转向滞后剪影、头上指示物 | 32×32（碰撞仍 20） |
| 改写体 | 半人半崩坏（需看两眼） | 强不对称、teal 簇 17、肢体偏移副本；32×48 程序像素 | 崩坏侧行走裂开/错位、木偶步态、脱落尘、脚下青绿污斑、残影、1px 抖动 | 32×48 |
| 覆盖体 | 完全非人形 | 抽象几何体、多重偏移叠加形态、全体 teal 自发光、中心核心亮点 | 匀速悬浮滑行、照亮周围地面 | 48-64px |

> **DEC-066**：渗透体与改写体俯视四向 + 步态帧走程序绘制，合同见 `docs/art/rewriter-sprite.md` 与 `src/entities/infiltrator-sprite.ts`。不跑外部生图、不喂管线。不新色相。过程经验（朝向、对照、压迫感、练习场怎么验）：`docs/art/actor-pixels.md`。

**形体设计禁忌：**
- 粗黑描边 + 圆润四肢 = "可爱"，在本游戏中绝对禁止
- 不使用成对"眼睛"——中心亮点/几何感知区替代；感知亮点最多 1 px
- 污染不是有机的（无真触手/黏液/肉质），也不是熟悉的几何（无电路/晶体/蜂窝）
- 污染侧不要暖色；渗透体不要面积光
- 实体形体的压迫感来自：前倾姿态 + 过长肢体 + 关节角度错误 + 比例不适 + 木偶顿步。不是再堆粒子

**覆盖体的光照影响（gameplay 联动）：**
- 覆盖体自发光，在 75% 暗色的裂隙中投射 teal 面积光池
- 玩家远距离先看到光池（"那边有什么在发光"）→ 再辨认光源 → 决策（绕行/面对）
- 区分方式：覆盖体投射的是**面积光**（连续光池），环境青绿是钉在地板上的有主占漆（可加接缝漏光，不是覆盖体那种径向光池，也不是氛围簇地毯）
- 这是威胁预警的视觉系统，不是装饰

**个体差异合法性：**
- 同等级的不同个体可有不同崩坏形态（改写体的"爆发型"vs"溶解型"）
- 基体色温随来源碎片偏移（L1 碎片记忆色影响）——不同碎片里的敌人色温微妙不同

## 6. 界面表现

2026-09-06 人全面否决先前UX，本节原地改写。当前方向是让界面退到世界边缘：常驻HUD无实体底板、10–11px小读数与2px细条；交互正文12px、同族无衬线标题16px，以低饱和灰绿文字在场景渐隐暗场中无框展开。取消此前点阵字体/厚设备壳处方。世界模型、材质和氛围不随UI改写。当前完整设计见 `docs/design-notes/ui-art-overhaul.md` A节；此前UX结论不再作审美输入。R2人审HUD95分PASS并锁定，交互布局已认可；R3材质微调仍被指出外来窗口感；R4核心场景构图获用户明确接受并授权推广。当前六点用真实装置聚焦与旁侧无框操作，字号/配色/已锁HUD保持。详见当前UI Kit。

## 7. 光照与视野的视觉实现

### 7.1 视野渲染

- **视野区域**：完全正常渲染
- **视野边缘**：3 级 alpha 渐变蒙版，**由内向外递减**（以每条光线的最大射程为基准，向内切两条等宽渐变带）：
  - 全亮核心（贴身至射程 − 2×bandWidth）：alpha **1.00**
  - 中带（bandWidth = 32 px / 1 tile 宽）：alpha **0.60**
  - 外带（bandWidth = 32 px / 1 tile 宽）：alpha **0.20**
  - 满射程（**1.0 R**）外沿之外：全黑（void-black #080a0c）
  - 带宽自动收窄保护：`bandWidth = clamp((射程 − 贴身全亮半径) / 2, 0, 32 px)`（环身圈短射程时自动缩窄，不出现负值或分层翻转）
  - **不使用半径百分比切带**：射程随角度变化且受混乱值缩放，百分比模型会把环身方向压成硬边、且调参时需同步换算；固定带宽让"边缘软度"成为稳定的视觉常量
- **视野外**：void-black 覆盖 + 极微弱的噪点纹理（暗示空间存在但不可见）
- **远处发光泄露**：高亮物体（裂口、覆盖体）在视野外 2-3 tile 范围内可见微弱光点

### 7.2 混乱值视觉反馈

| 阶段 | 混乱值范围 | 视觉效果 |
| ---- | ---------- | -------- |
| 安全 | 0-50% | 正常渲染，无额外效果 |
| 警告 | 50-75% | 视野最外圈出现轻微 teal 色相偏移 |
| 危险 | 75-100% | 视野半径缩小约 10%；边缘开始微弱抖动 |
| 超阈值 | >100 | 视野加速缩小至下限；teal 向内渗透加重；全屏 teal 蒙层 + 颗粒噪点随溢出加深；约 2s 一次低频跳变（禁止高频闪烁） |

### 7.3 净化点光照

> 以下为早期实现描述；本轮受控色阶、光影职责与外景层级统一见[当前美术设计](#current-art-design)，不机械继承边界发光线。

- 室内固定暖色点光源（不随玩家移动）
- 视野无限制（或极大范围），但边界外仍为黑暗
- 边界光：安全区边缘有一条 1px 宽的微弱暖色光线标记分界
- 边界外通过 BoundaryAtmosphere 系统处理（不是简单的黑幕）

## 8. 资产来源分类

> 既有来源记录。C 重构采用文首的可编辑分层资产与受控光照，生图不再作为本轮的渲染母版。

本游戏的视觉内容并非全部来自 AI 图片生成。以下明确区分三类来源，避免重复工作或遗漏。

### 8.1 A类：AI 生成静态资产

需要经过完整的 prompt → 生成 → 筛选 → 后处理 管线。这是 art agent 的主要产出对象。

| 内容 | 说明 | 数量预估 |
| ---- | ---- | -------- |
| 裂隙环境 tileset | 地面/墙壁/障碍物的 32x32 像素贴图 | ~40-60 tiles |
| 净化点环境 tileset | 基地地面/墙壁/设备贴图 | ~20-30 tiles |
| 玩家 sprite | 出击已接加厚程序像素 + 灯尘（DEC-068）。AI 精灵表仍是合法后续路径，除非人改口 | ~16-24 帧（若走精灵表） |
| 敌人 sprite（覆盖体） | 未做；来源另议 | — |
| 可交互物 sprite | 薪柴、物品、撤离点图标 | ~10-15 个 |
| 净化点模块外观 | 各模块不同健康状态的 sprite | ~6-10 个 |
| UI 元素 | 按钮纹理、面板背景、状态条填充 | ~15-20 个 |

**总计预估：~110-180 个静态资产文件**（渗透体/改写体已移出 A 类；合并为 atlas 后实际文件数更少）

### 8.2 B类：代码动态生成

完全由程序在运行时渲染，不需要静态图片资产。这是 code agent 的领域。

| 内容 | 技术方案 | 说明 |
| ---- | -------- | ---- |
| 渗透体 / 改写体 | 启动时像素缓冲绘制四向与步态帧 | 成品画面（DEC-066）。指示物、残影、脱落尘、木偶步仍是运行时叠加 |
| 玩家加厚像素 + 灯尘 | 启动时绘制四向密像素 + 运行时暖尘上飘 | 出击 `Player` 与练习场同一套（DEC-068） |
| 视野遮罩 | 自实现 Raycasting + 多边形裁剪 | 核心体验支撑；每帧动态计算 |
| 光照衰减 | 径向渐变渲染（Canvas/WebGL） | 光源周围的明暗梯度 |
| 边界黑暗 + 幽影 | Phaser ParticleEmitter + 低透明度 sprite 周期动画 | 净化点外围氛围系统 |
| 混乱值视觉反馈 | 屏幕后处理（色相偏移/噪点/扭曲） | 超阈值惩罚的视觉层 |
| 空间裂口发光效果 | 叠加式发光渲染 + 粒子 | 碎片连接的地标光效 |
| 敌人感知范围指示 | 程序化绘制半透明扇形/圆形 | debug/gameplay 可见警觉区 |
| 地图拼接布局 | Voronoi + CA 算法输出 tilemap 索引数据 | 决定哪个 tile 放在哪里（非视觉本身） |
| 裂隙地面（L1 + 可选渗缝） | 出击烤一次程序化地表（`putFloorRgb` 只落可走地板） | 不下氛围簇层（DEC-104）。身份靠渍/纹理/结构。晶结/溶蚀/平涂仅练习场对照 |
| 占漆活层 | 出击与练习场：跟占漆宿主自己走，幅度 5–20%、每帧连续场 | 整图氛围簇呼吸关。禁止沿圆周走鼓包、描边星形、4 张静帧、整团透明度冒充呼吸。呼吸层低于视野蒙层（DEC-070 / DEC-071 技术，DEC-104 改应用） |
| HUD 数值/文字 | Phaser Text + Graphics API | 状态条、数值、标签 |

### 8.3 C类：混合型（AI 基础素材 + 代码动态处理）

AI 提供静态基底，代码在运行时叠加效果或切换状态。两个 agent 协作完成。

| 内容 | AI 生成部分 | 代码处理部分 |
| ---- | ----------- | ------------ |
| 污染体发光/脉动 | 无独立 AI sprite（渗透体/改写体已是程序像素） | 代码控制指示物节奏、残影、行走错位 |
| 模块受损状态 | 各状态独立 sprite（3态） | 代码根据 GameState 切换显示 |
| 环境 tile 动态 | 基础 tile 变体 | 连续地面不走 tile 帧切换；成片青绿的呼吸见上表占漆活层 |
| 薪柴闪烁 | 基础 sprite（2帧） | 代码控制帧率和亮度随机性 |
| 边界外浮现形态 | 预模糊的形态 sprite（B类素材） | BoundaryAtmosphere 系统控制淡入/位置/节奏 |
| 撤离点脉动 | 基础 sprite（4帧） | 代码控制脉动速度，接近时加快 |

### 8.4 来源分类的实操意义

- **规划 Slice 任务时**：A 类资产需要在 art agent 提前准备 prompt 和生成时间；B 类直接由 code agent 实现；C 类需要两者协调时序
- **评估工作量时**：A 类静态资产是美术管线的主要工作量（渗透体/改写体已不计入，DEC-066）；B 类和 C 类的代码部分不计入美术工时
- **一致性保障时**：A 类资产的一致性靠本文档第 9 节的管线保障；B 类靠代码中的常量（引用本文档色值）；C 类靠双方对接规格

## 9. AI 生成工作流

> 本节保留既有工具流程，不是 C 重构的制作入口，也不负责决定游戏画风。此次制作依据统一为[当前美术设计](#current-art-design)。

### 9.1 一致性保障策略（优先级递减）

**Layer 1: 固定 Prompt 前缀**

所有同类资产共用风格前缀。正文只描述本资产特有内容，不重复风格描述。

**环境 Tileset 前缀：**
```
Top-down 32x32 pixel art tile, dark low-fi aesthetic, extremely desaturated, heavy shadows, limited palette (cold greys + single cyan-teal accent), visible pixels, retro game tile,
```

**角色/实体 Sprite 前缀：**
```
Top-down pixel art game sprite, 32x32px, dark background, low-fi aesthetic, minimal detail, clear silhouette at small scale, desaturated cold palette with cyan-teal accent glow,
```

**概念/参考图前缀：**
```
Top-down view, pixel art style, low-fi aesthetic, extremely dark ambient lighting, desaturated cold palette, cyan-teal as only saturated color (used for contamination glow), heavy shadows, oppressive atmosphere,
```

**Layer 2: Style Reference 绑定**

- 第一批满意结果成为后续所有生成的风格锚点
- Midjourney：`--sref [URL]` 绑定参考图
- SD/Flux：img2img（denoise 0.5-0.7）或 IP-Adapter 注入风格
- 维护 3-5 张"style anchor"图片集，覆盖各资产类型

**Layer 3: 批量生成 + 筛选**

- 每种 tile/sprite 一次生成 4-8 变体
- 排除标准：色温偏离、细节度不一致、出现有机恶心元素、出现非几何污染
- 保留标准：整体暗度一致、teal 色相一致、像素清晰度一致

**Layer 4: 后处理统一管线**

> **管线输入的铁律**：管线处理的对象是**单块 tile 或单个 sprite 的原始素材图**（一张输入图 = 游戏里的一个原子资产，如一块地面、一段墙、一个敌人）。整场景概念图/效果图（如 `docs/art/demos/rift/` 里的英雄图）**只用于验证美术方向，永远不作为资产喂给管线，也不参与平铺**——把整场景图降采样成 32px 再平铺，只会得到密密麻麻的噪点，不是资产。场景的表现力来自**运行时合成**（多种 tile + 过渡/拼缝 tile + 覆盖层装饰 decal + 光照 + 有限视野），不来自任何单张图。裂隙地面身份是程序化 L1；成片青绿是有主占漆宿主，不要再喂一套矩形错误 tile 或氛围簇给管线当地面合同。

所有正式 AI 视觉资产由构建期离线的 `tools/art-pipeline/` 按 `docs/art/pipeline.*.config.json` 与锁定色板执行以下确定性阶段：
1. **色调映射与饱和度压制**：按本项目色彩约束统一色温、亮度和饱和度。
2. **像素化对齐**：降采样到目标尺寸，并按配置使用最近邻放大或保留目标尺寸。
3. **色板量化**：限制为锁定色板中的颜色。
4. **背景清除与裁切补齐**：sprite 类资产移除背景为透明 PNG，并裁切或补齐为目标尺寸。
5. **机器验收**：程序 Agent 依次运行 `npm run art:postprocess -- --config <配置路径>` 与 `npm run art:verify -- --config <配置路径>`；验证命令退出码为 0 后，仍由人完成最终审美判断。

### 9.2 推荐工具

| 资产类型 | 推荐工具 | 参数建议 |
| -------- | -------- | -------- |
| Tileset | Stable Diffusion (SDXL/Flux) | ControlNet tile mode; 批量 4-8 筛选; seed 固定做变体 |
| 角色/敌人 Sprite | Midjourney v6 / Flux | --sref 绑定; --ar 1:1; --stylize 低值(50-100) |
| 概念参考图 | Midjourney v6 | 探索方向用; 自由度高 |
| UI 图标 | 代码绘制 (Canvas/SVG) 优先 | 几何简单的元素不需要 AI |
| 粒子/特效 | 代码 (Phaser ParticleEmitter) | 动态效果靠代码，不用静态资产 |
| 光照/视野 | 代码 (WebGL shader/mask) | 运行时计算，不用贴图 |

### 9.3 Tileset 生成要求

- 每个 tile 的四边必须可与相邻 tile 无缝接合——生成时使用 seamless/tiling 模式
- 地面变体之间差异要微小（避免重复感但不跳跃；色调/明度差 < 5%）
- 墙体 tile 需有明确边缘（玩家必须快速区分可通行/不可通行）
- 装饰层 tile = 半透明叠加 sprite（放置在地面 tile 之上，非替换）

### 9.4 Sprite 生成要求

- 所有 sprite 在目标尺寸内必须有清晰、可辨识的轮廓
- 动画帧：先生成单帧静态 pose → 确认后再生成/手绘其余帧
- 方向变体：生成正面（朝下）+ 背面（朝上），左右通过 X 轴镜像获得
- 发光部位直接绘制在 sprite 上（不依赖运行时 shader，保持像素风格纯粹性）
- 每个 sprite 的 bounding box 内预留 2-4px padding（避免边缘裁切）

## 13. 整体视觉整合规则（概念验证阶段性总结）

以下规则来自对所有已通过概念（净化点、裂隙、渗透体、改写体、覆盖体）的横向整合评审。这些是**组合到一起时**需要遵守的约束，单独看各自概念图时不一定显现。

### 13.1 色温叙事主轴

```
暖色（amber） = 100% 人类侧        冷色（teal） = 100% 污染侧
净化点灯光                           裂隙环境纹理
玩家携带设备                         污染体发光
薪柴计数（HUD 资产读数）[注]         薪柴实体（世界内实体）
稀有叙事色残影                       覆盖体光池
                                      空间裂口
```

> **[注] 薪柴的双重上下文**：薪柴实体（裂隙内实际物件）属**污染侧**——`world.md` 明确定义为"异源残渣压缩物"，视觉用 teal 余晖（§5.3）。HUD 薪柴计数用 warm-dim 是"玩家资产读数"的 **UI 约定**，属于人类侧界面，不是世界内光源（§6.2）。两处表达不矛盾，因为它们归属不同上下文：一个是世界内实体的色彩，一个是玩家界面的信息读数。规则 8 的"裂隙暖色仅来自玩家"对薪柴实体成立——它用的是 teal，不是暖色。

这条主轴是游戏视觉体验的骨架。任何打破它的设计（如：暖色的敌人、冷色的安全设备）都需要极强的叙事理由。

### 13.2 实体在裂隙中的可见性

渗透体基体色 (#2e2d30) 与裂隙地面暗色 (#0d1114 ~ #1a1c1f) 对比度低——**这是设计意图**（敌人潜伏在黑暗中）。但必须确保：

- 玩家暖光（2-3 tile 范围）照到实体时，实体基体色能被看见
- 实体身上的 teal 散点不被地面有主占漆淹没——**区分方式：实体青绿贴在身体上并随行走脱落；环境青绿是钉在地板上的占漆宿主，不跟甲走。** 二者同一份 ramp（不是两套色），不是氛围簇地毯（DEC-104）
- 动态层（像素飘散、运动）提供额外的运动线索——静止时几乎隐形，动时可察觉
- 渗透体已在 32px 密像素实装并接出击；贴身暖灯下是否仍能从地面里读出来，待人在裂隙里看。本文不代人终审

### 13.3 覆盖体光照与环境的区分

覆盖体自发光投射 teal 面积光池。环境成片青绿是钉在地板上的有主占漆（可加接缝漏光，不是氛围簇地毯）。区分规则：

| 光源 | 形态 | 面积 | 行为 |
|------|------|------|------|
| 环境污染 | 有主占漆钉在可走地板；接缝漏光可并存、不得长成滩 | 按宿主只数，不铺整岛 | 占漆宿主自己呼吸（DEC-070 / DEC-071 技术，DEC-104 改应用）；地面烤一次。整图簇呼吸关。迷雾下亮度等人终审 |
| 覆盖体 | 面积光池、向外径向衰减 | 大（3-4 tile 半径） | 随实体移动 |
| 空间裂口 | 集中高亮点 + 径向衰减 | 中（2 tile 半径） | 固定位置、强度脉动 |

玩家远距离感知到**移动的面积光源** = 覆盖体预警。这是 gameplay 信号，不是视觉装饰。

### 13.4 资产精度对齐

概念图中净化点精度 > 裂隙/实体。实际 32x32 资产制作时：

- 净化点的"细节丰富感"靠**物件密度**实现（多个 sprite 叠加），不靠单个 tile 内细节超标
- 裂隙的"氛围感"靠**色彩/光照系统**实现（代码后处理），不靠 tile 本身复杂
- 所有 tile/sprite 统一在 32x32（或其倍数）像素网格内，无分辨率混用
- 像素渲染风格统一：高细节像素渲染（有机光照渐变、柔和边界），不是硬边传统像素画

### 13.5 空间过渡（净化点 ↔ 裂隙）

玩家从净化点出发进入裂隙时的视觉弧：

```
暖灰工业空间 → 边界渐变（暖光衰减 + 黑暗吞噬） → 极暗冷色空间（teal 从缝隙渗出）
净化点内部        概念7验证区域                         裂隙内部
有秩序、有光      丧失秩序、丧失光                     异质秩序、异质光
```

这个过渡是玩家每次冲击循环的起点体验，需要在概念7（边界外的黑暗）中验证。

## 14. 已知待验证项（移交 Slice 1 美术门禁）

本文档在 2026-07-24 批准锁定，但视觉方向的验证基于 1024px 英雄级概念图。以下五项在概念图阶段**无法验证**，是批准的前提（不是否决项），必须在 Slice 1 的美术门禁中实测确认。若实测结果与本文档冲突，以实测为准并回写本文档。

1. **视角未统一（俯视角可读性）** — 渗透体 / 改写体 ✅ 人已在练习场锁定程序像素（DEC-066）。概念立绘不再当作「还要换成俯视精灵表」的债。覆盖体未做。

2. **32px 尺度 / 细节可读性**
   渗透体 / 改写体已在 32px（改写体 32×48）密像素实装并接出击；玩家加厚像素只在练习场。概念图仍是 1024px 英雄图。坏像素散点、碎片记忆色温差在裂隙视野遮罩下是否还读得见，待人在裂隙里看，本文不代人终审。

3. **俯视角像素路线的表现力（合成测试）—— 最高风险项 ✅ 已验证 PASS（2026-07-31，见 DEC-018）**
   参考图（`docs/art/demos/rift/2026-07-22_192829`）是等距/2.5D 手绘的整场景效果图，只是**氛围目标**，既不是可用资产、也不是一块 tile。要验证的是：纯俯视角像素能否合成出接近参考图的**氛围**（不是纵深/立面）。视角已定不回炉（DEC-007）；平铺重复（网格马赛克）是要攻的靶。

   **验证结果（关键结论，回写自 A-G3 实测）：**
   - **路线成立**：纯俯视角像素 + 有限视野能达到目标氛围（暗、脏、压迫、teal 污染点缀）。参见 `docs/art/demos/rift-synth/scene.s3.png`（实测台，忠实复刻 DEC-016 视野模型）。
   - **破马赛克的正解＝程序化连续表面，不是"多做几种离散 tile"**：A-G3 先按原计划试了"离散 AI tile + 旋转 + decal"五轮——即使做了逐块亮度归一（消棋盘）、随机旋转、降权，AI tile 的显著特征（尤其违反冷色环境规则的暖олив裂纹）仍读作规律重复，马赛克只是从"明暗棋盘"变成"特征重复"。改用**按世界坐标程序化生成整块地面/墙体**后一次成型：连续 = 结构上零接缝零重复，丰富度（脏污/磨损/teal 渗漏）完全可控、确定性、零成本、色板合规，且比 AI tile 更契合程序化地图（DEC-005）与 AI-vibe 像素（DEC-007）两个赌注。**决策见 DEC-018。**
   - **地面配方**（`docs/art/demos/rift-synth/floor.mjs`）：历史小样。当时是多层 value-noise 脏污 + 低频宏观起伏 + 有符号划痕/碎屑 + 稀疏蜿蜒 teal 渗漏裂缝 + flat teal 数据错误块 → 量化到 `palette.json`。**现行出击地面身份是 L1 渍/纹理/结构；成片青绿是有主占漆**，见 `docs/art/rift-fragment-surfaces.md`（DEC-104 覆盖 DEC-069 的氛围簇生产签名）。本节数字仍是 `frag-outdoor` 基线行的材质残影，不是污染主签名。
   - **墙体配方**（`docs/art/demos/rift-synth/scene.mjs`）：基于像素级墙 bitmap 的连续边缘明暗（北侧顶沿高光 / 南侧落影 / 侧沿 AO）→ 墙成连续实体量感，无 32px 分段。
   - **光照配方**（`docs/art/demos/rift-synth/darkwood.mjs`，对齐真实 `VisibilitySystem`）：前向锥 + 环形 + 三段可见度 + 手电光束提亮（**暖心**）+ **视野边缘 teal 冷渗** + 贴身暖灯 + void 颗粒 + 墙体投影遮挡。"暖心冷边"用视野系统本身表达了"人类暖光 vs 污染冷色"的核心张力。
   - **AI 生图的定位收窄**：AI 生图保留给**离散 sprite/道具**（敌人/薪柴/撤离点等有个体身份的对象），**不再用于连续地面/墙体**。`tools/art-pipeline/` 仍是离散 sprite/decal 的处理路径。
   - **落地**：本项以程序化生成器接入 `TilemapRenderer`（实机化在 Part C，基于 DEC-017 的 64×44 真实地图）。原"离散 AI tile 合成测试"流程作废，由 DEC-018 取代。

4. **调性纪律（饱和度上限）**
   重度污染区的 teal 覆盖需设面积上限——经验判断超过画面 40% 会产生视觉疲劳，削弱"颜色是入侵"的叙事力量（此项含宿主与实体，不是烤地闸门）。烤地无主青绿另走上限：新生 ≤ 0.20%、标准 ≤ 0.35%、古老 ≤ 0.50%（占漆宿主不计入；见地表 HOW）。`contam-ancient`（#4adf8a 翠绿）在实装时需经后处理压饱和，不可直接使用原色值。这些上限需在实际场景中标定。

5. **签名一致性（渗透体读感）**
   概念图曾偏向"枯瘦鬼影"。现行实装用密像素前倾猎食 + 坏像素脱落，对齐「渲染崩坏」而非有机鬼怪。裂隙内读感仍待人终审。过程闸门见 `docs/art/actor-pixels.md`。
