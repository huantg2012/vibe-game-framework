# R100：Rift 世界扩展大版本执行合同

**本版本终点：108个经过技术、美术与游戏体验审核、进入正式随机出击池的独立世界，以及整库的运行与体验验收。** 108将“100+”落实为明确排产数；可因实际发现增加任务、拆分迭代或替换世界，不可自行缩减终点。3和6只属于前期检查点，不是可替代的大版本成果。

**当前状态：计划已准备，等待用户敲钟。** 本轮不启动I01测量、游戏代码开发、资产制作、新世界CSV或正式池变更。用户启动后，按此合同持续推进，无需为常规实现、修复、审核和下一轮重复索取启动许可；用户审美决策、范围变更与最终认可按下文单独记录。该计划不意味着已有后台定时任务。

## 1. 版本范围、质量与计数

### 1.1 交付内容

- 可复用的新物质、形体、空间组织与形成过程，支持有身份的世界配方；不为每个世界写专属渲染分支。
- 地面、实体和虚空的共同几何来源，正确支撑碰撞、视线、光照、排序、导航、Host与资源投放。
- CSV驱动的版本世界包、依赖编译、资格工厂、原生Gym审查、失败诊断和发布库。
- 108份完整世界：材料/空间/地标/局部运动/声音/遭遇与搜索关系一起成立；每份能产生多张可玩的地图。
- 正式备行→出击→搜索/遭遇→撤离或死亡→归来、暂停/恢复与连续出击全部接合。
- 有意义的世界出现分布、资源按需装载与释放、旧局兼容、最终资格和交付说明。

本版本是世界模块的成品交付，不等于整款游戏已到发行状态。净化点重构、角色换代、终局、全新货币/成长线、物品四B扩产不因此重开。I28挂起的经济和物品长期平衡不自动解锁；本版本必须验证由新地图引起的收益/风险回归和多趟世界体验，两者范围分开。

当前保持俯视2D、原Rift人物与尺度、基础移动、有限视野、搜撤和纯黑不可照亮空洞。高体量与实体遮挡属于范围；上下重叠可走楼层、运行期改变可走地形的动态拓扑不是首批依赖，若确有必要须提交带成本/影响的范围决策。低饱和、矿物感和荒凉不是输出上限。

### 1.2 什么算一个世界

一份稳定的世界身份包含物质/形体、空间组织、主导形成过程、材料受光、声光与运动节奏、地标及遭遇倾向。种子决定一次地图实例；空间或过程参数变体不会自动增加世界数。

入库最低差异要求：与最相似世界相比，正常游玩视野下至少两项非配色差异成立，其中至少一项改变观察、接近、绕行或撤退的条件。必须再做全库近似簇审查，不能用连续小幅变化拼出108个ID。静帧很不同但玩起来同构、或路线不同但表现像同一世界的内容，都需要重新判断身份。纯氛围变体可保留在原世界内部。

旧五demo保留回归价值；须按本版本重新审核，才可计入108。最终淘汰/合并/失效造成数量不足时必须补齐。不能把失败后备、历史版本、同世界别名或重新发布计作新世界。

### 1.3 四本账

1. **候选/实施数**：内容存在或代码已实现，不代表合格。
2. **当前内部合格数**：实现完成，当前版本技术、美术、体验三审均通过，证据有效。
3. **正式可达数**：内部合格且已接正常随机出击池，入口与恢复有证据。
4. **用户认可范围**：以实际反馈对应的包/家族/批次/版本记录；内部评审不能代签。

看板从worlds记录计算，不手写总数。108正式包＋最终版本验收成立才可标RELEASED；在108候选、108机器通过或108内部合格处都不能关闭大版本。

**I01 0 → I02 3 → I03 6 → I04 12 → I05 20 → I06 36 → I07 52 → I08 52 → I09 72 → I10 92 → I11 108 → I12 108正式交付。**

这是一份覆盖终点的排产，不是精确工期承诺。I01锁技术预算，I03和I05实测内容制作、返工、资格成本后更新排期。若某轮太大，拆成Ixx-B01等有界批次或追加修订轮，保持原终点和缺口，不把困难任务移到“大版本之后”。

- 最小CSV包编译、版本冻结、依赖哈希与资格链从I01/I02即运行，前三/六世界计数前已经过真实准入与恢复验证。I04将该链规模化、增量化并扩到12，不把此前未验证的样板补叫合格；I05形成20世界的完整集合。

**批次上限：** 扩产期单批最多4个世界；未知画法或新增算子单独一批，先成品母版，再做依赖内容。每批必须能在一次受控工作会话内形成可恢复的产物与检查记录；超过上下文/执行能力就拆批，不以ALL作为任务范围。

## 3. 每轮必须完成的工作循环

完整十步及责任在台账 workflow 中维护。以下规定输入、产物和失败处理；技术、美术、体验同轮进行，不设“先把108个做出来，最后统一美化”的路径。

### A. 目标与设计

开工加载当前台账、上轮问题与依赖证据；写清本轮要改变的玩家经验、世界覆盖缺口、数量、范围与不回退的已有优势。每项设计有可观察的差异假设，例如“这组实体让玩家在两次观察之后选绕行方向”，并写反例，不能只写“更有氛围”。

每个候选制作一份短的世界设计卡：改写母题、材料/形体、空间图式、主过程、地标、声光节律、使用的现有遭遇、最相似世界及差异、风险和验收片段。先确定主导因果，再组合细节。

### B. 技术方案

明确数据流与模块所有权、统一几何输出、支撑/碰撞/视线/光照的不同派生语义、内容生成次序、随机支流、保存版本、异常/后备、缓存/资源释放、预算和回滚。高体量必须在路线与投放准入之前进入几何，不能事后贴上障碍。

未来机制在设计稿提出；进入实现时原地更新现行 system-map-generation 等所属spec与architecture，不另造并行“v3 spec”以混淆当前真相。世界包必须绑定算子/算法/资产/内容来源，不只保存一个可变ID。

### C. 美术与视觉方案

由美术与技术美术共同说明“怎样画出目标”，至少包含：

- 大形与中尺度语法、尺度谱、接合/断口/内腔、疏密和负空间。
- 材料与受光关系、色光层级、污染与主体可读性；颜色有表达自由，关键危险不能只靠颜色。
- 像素尺度、轮廓与细节密度、静区；禁止用更多随机噪点冒充材料描绘。
- 真实角色、敌人、交互物与地形的接触/遮挡、移动视口中的构图。
- 局部动态的形态、节律、遮挡和暂停/减动行为；声音母题、远近、安静片段与危险提示的关系。
- 参考的具体作用与明确不借用的部分、可编辑源资产与生产方法、资源成本。

新方法先做包含主要难点的成品尺寸母版，只缩范围，不降低完成度。灰盒用于验证路线，不用于批准画法。概念图或生图可以辅助探索，但整张图不能代替可编辑资产、生成能力和正式实景。直接复用已经获认可且适用的画法，不每轮重新抽卡。

三类对照必须分清：同一视口的前后版本、同材异形/同形异材、原生实景与离线图。最终以正常尺度的游戏画面和连续运动判断。纯艺术表达、吸引力与情绪有独立否决权，不能靠“玩家看得清”代替。

### D. 开发计划与实施

本轮首批开工前写任务包，逐批给出ID、依赖、负责人/文件、输入版本、产物、可运行入口、预计成本档、检查和失败回退。角色职责可以由同一主代理分阶段承担，但产出作者不得成为唯一终审者；并行改动必须明确所有权。

CSV → 编译产物；先完成共用能力，随后制作配方。每个完成的世界进入同一原生Rift运行链，包含正常灯光/视野、角色、遭遇、交互与撤离；禁止用全图亮灯的独立展台冒充入游戏。正常玩家存档与测试存储隔离。

### E. 三项独立审核

**技术审核：** 对照合同与实际调用链，检查支撑/实体/空洞、通行与视线、Host站位、内容预算、确定性、冻结恢复、失败耗尽、暂停/清理、性能及影响闭包。类型或构建通过只是其中一项。

**美术与视觉审核：** 非作者先看产物，不先接受制作说明；记录美术语言、形体体积、材料、色光构图、动效与整体完成度的具体依据。正常行走会暴露的问题不能用精选截图遮盖。声音需要实际审听；工具无法听时明确转交用户，不标已验证。

**游戏体验审核：** 记录真实的“目标→信息→选项→行动→后果”，覆盖瞬间操作、完整出行与多次出行。检查路线选择、暴露/风险、搜取、退路、地标记忆、学习迁移和重复感。保守/冒险的情境比较不能只测是否可达。专家/代理试玩与真实用户反馈分开，不能称为用户研究。

三项分别判定pass / changes-required / pending，不能平均打分抵消。事实冲突先复现，审美分歧并置实帧和依据后由制作负责人提出裁决；用户的明确审美否决优先。

### F. 整改、接入与交付

每项问题有ID、根因类别、严重度/发生条件、影响包、负责人与复验。关键缺陷或关键美术/体验失败使相关包失去资格；共享根因按依赖闭包退回审核。修复后保留原失败证据，再追加当前版本复验。

内部合格可以支持按获准范围继续开发；正式候选小批接入并检查完整循环。人审状态不能被接入操作改为通过。收尾产物必须包含可玩链接、原生实帧/片段、版本/包/种子、技术与体验证据、数量变化、未决事项、下轮首批入口。

本地提交按既有持续授权执行；推送仍按用户指令。完成一个迭代后立刻接续已授权且依赖成立的下一批，不把阶段总结当作整个大版本结束。

## 4. 验证范围与量化预算

### 4.1 现在锁定的硬条件

- 同包/算法版本与种子可复现；继续旧局不静默换身份、重抽或降级。
- 空洞、实体、地面语义一致；合法操作必须有真实身体可达且符合视线的站位。
- 所有正式内容来自版本清单；未知能力拒绝，重试有界；同包后备仍过准入并明确记录。
- 作者自检、独立三审和用户认可分开；验证包含完整原生入口，不只Gym辅助模式。
- 生成失败、超时、拒绝、使用后备和最终成功分别统计；失败样本不能从分母删除。
- 当前共享能力改动使关联证据需要复核；相同包ID不代表旧PASS自动有效。
- 最终不存在未关闭的P0/P1、本版本关键美术或体验阻断；非阻断问题必须有影响说明及处置。

### 4.2 I01必须测量并冻结，不能拖到版本末尾的预算

按明确设备/浏览器/逻辑分辨率分别确定生成与恢复p50/p95/p99、冷/暖缓存、CPU/GPU帧时、内存/纹理峰值、场景切换后的存留趋势、离线每包成本/超时/并发和候选拒绝/后备率。以流畅原生游戏体验为目标；当前没有新构造实测值，不能在计划阶段虚报已达标或编造低端设备结果。

自然分布性能采样与定向恶例资格采样分别报告分母；后者不能混进自然失败率、后备率或耗时分位数。p99样本不足时报告观察最大值/估计与限制，不写尾部性能已通过。I01锁目标与方法，I02新几何实测、I03复核成本；超预算先整改，修订预算必须保留理由及可比证据。

每包资格起始方案：**32个分层普通种子＋至少8个定向混合边界/失败种子＋独立保留种子复核**，不是全低/全高两端替代组合覆盖。每项参数须有实效检查；对高风险算子加样。I01在不降低覆盖目的的前提下，根据运行成本将确切集合、保留比例、超时和抽样依据写入预算记录，在I02内容生产前冻结；后续变更需保留原因和前后可比结果。

每个世界至少两个不同种子的正常视野运行记录；包含一次完整搜取与撤离及一次不同路线/失败或压力状态，不能全为俯瞰导览。复杂形体另查贴边、转角、遮挡前后及动态相位。机器可达性不可替代实际行走。

I05/I08/I12分别安排多趟体验；I01确定连续出击数量、配置与人力，I03/I05校准执行成本。自动选池大样本与真实连续游玩分开，世界出现统计不等于新鲜感通过。最终按完整库抽取、风险与家族覆盖；未覆盖域保留明示，不能结案时才临时缩小样本以求通过。
