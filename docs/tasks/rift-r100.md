# R100：百世界与污染分级大版本执行合同

**本版本终点：108个独立世界，全部覆盖低/中/重污染的324个资格单元，经过技术、美术与游戏体验审核并进入正式等级出击池；等级选择、准备、重度风险回报与整库运行/体验一同验收。** 108将“100+”落实为明确排产数；可因实际发现增加任务、拆分迭代或替换世界，不可自行缩减终点。3和6只属于前期检查点，不是可替代的大版本成果。

**当前状态：计划已准备，等待用户敲钟。** 本轮不启动I01测量、游戏代码开发、资产制作、新世界CSV或正式池变更。用户启动后，按此合同持续推进，无需为常规实现、修复、审核和下一轮重复索取启动许可；用户审美决策、范围变更与最终认可按下文单独记录。该计划不意味着已有后台定时任务。

## 1. 版本范围、质量与计数

### 1.1 交付内容

- 可复用的新物质、形体、空间组织与形成过程，支持有身份的世界配方；不为每个世界写专属渲染分支。
- 地面、实体和虚空的共同几何来源，正确支撑碰撞、视线、光照、排序、导航、Host与资源投放。
- CSV驱动的版本世界包、依赖编译、资格工厂、原生Gym审查、失败诊断和发布库。
- 108份完整世界，每份具备低/中/重三档：材料/空间/地标/局部运动/声音/遭遇与搜索关系一起成立；每级能产生多张可玩的地图。
- 地图等级与世界身份独立；知情选级、有限风险窗口、至少两条有效准备路线、真实可携回的高收益与低中可持续性。重度近崩溃压迫须同时通过艺术与游戏体验审核。
- 正式备行→出击→搜索/遭遇→撤离或死亡→归来、暂停/恢复与连续出击全部接合。
- 有意义的世界出现分布、资源按需装载与释放、旧局兼容、最终资格和交付说明。

本版本是世界模块的成品交付，不等于整款游戏已到发行状态。净化点重构、角色换代、终局、全新货币/成长线、物品四B扩产不因此重开。用户本次已将等级相关准备、供给、风险收益、失败后恢复和多趟选择深度纳入R100必做；不能再用I28挂起来跳过这些验证。不相关的I28全物品长期平衡与四B扩产仍保持挂起，新增独立成长/货币/终局不自动解锁。

当前保持俯视2D、原Rift人物与尺度、基础移动、有限视野、搜撤和纯黑不可照亮空洞。高体量与实体遮挡属于范围；上下重叠可走楼层、运行期改变可走地形的动态拓扑不是首批依赖，若确有必要须提交带成本/影响的范围决策。低饱和、矿物感和荒凉不是输出上限。

### 1.2 双轴与阻断条件

世界身份与地图污染等级分别建模；108×3是324个资格格，不是324个世界。现有污染年龄、实体覆盖档、玩家混乱不能直接改名顶替地图等级。等级生成前冻结，重试/恢复不暗换；旧在途局保持旧合同。三级设计、首选进入/压力/收益方案及反例集中在[设计依据](../design-notes/rift-world-space.md#rift-pollution-grades)，具体机制仍为待实施提案。

专业审美具体标准集中在[art-direction的R100正文](../art-direction.md#rift-r100-standard)：身份与吸引力、空间、材料、色光、运动声景、行动读法、成品一致性；有独立否决权，不以量化总分或技术通过代签。净化点/首页已认可画面不代表Rift自动通过。

**FATAL发布条件：** 同源三级及跨材料美术方法、重度完整出行、108/324资格、自然准备与等级净收益、冻结恢复、正式全库与用户终验六门缺一不可。唯一门清单归JSON的qualityPlan.releaseGates，结果归releaseGateResults；现在结果为空，不伪填通过。

### 1.3 什么算一个世界

一份稳定的世界身份包含物质/形体、空间组织、主导形成过程、材料受光、声光与运动节奏、地标及遭遇倾向。种子决定一次地图实例；空间或过程参数变体不会自动增加世界数。

入库最低差异要求：与最相似世界相比，正常游玩视野下至少两项非配色差异成立，其中至少一项改变观察、接近、绕行或撤退的条件。必须再做全库近似簇审查，不能用连续小幅变化拼出108个ID。静帧很不同但玩起来同构、或路线不同但表现像同一世界的内容，都需要重新判断身份。纯氛围变体可保留在原世界内部。

旧五demo保留回归价值；须按本版本重新审核，才可计入108。最终淘汰/合并/失效造成数量不足时必须补齐。不能把失败后备、历史版本、同世界别名或重新发布计作新世界。

### 1.4 四本账与等级覆盖

1. **候选/实施数**：内容存在或代码已实现，不代表合格。
2. **当前内部合格数**：总体世界身份三审及低/中/重各级三审均通过，当前版本证据有效；同时单列合格等级格数/324。缺一档只能算在制世界。
3. **正式可达数**：内部合格且三级均接正常等级选择/随机世界出击池；单列正式等级格数，入口与恢复有证据。
4. **用户认可范围**：以实际反馈对应的包/家族/批次/版本记录；内部评审不能代签。

看板从worlds记录计算，不手写总数。108正式包/324正式等级格＋六项发布门＋最终版本验收成立才可标RELEASED；在108候选、108机器通过或108内部合格处都不能关闭大版本。

## 3. 每轮必须完成的工作循环

完整十步及责任在台账 workflow 中维护。以下规定输入、产物和失败处理；技术、美术、体验同轮进行，不设“先把108个做出来，最后统一美化”的路径。

### A. 目标与设计

开工加载当前台账、上轮问题与依赖证据；写清本轮要改变的玩家经验、世界覆盖缺口、数量、范围与不回退的已有优势。每项设计有可观察的差异假设，例如“这组实体让玩家在两次观察之后选绕行方向”，并写反例，不能只写“更有氛围”。

每个候选制作一份短的世界设计卡，附三个等级的空间/视听/危险/准备/收益差异与验收矩阵：改写母题、材料/形体、空间图式、主过程、地标、声光节律、使用的现有遭遇、最相似世界及差异、风险和验收片段。先确定主导因果，再组合细节。

### B. 技术方案

明确数据流与模块所有权、统一几何输出、支撑/碰撞/视线/光照的不同派生语义、内容生成次序、随机支流、保存版本、异常/后备、缓存/资源释放、预算和回滚。高体量必须在路线与投放准入之前进入几何，不能事后贴上障碍。

未来机制在设计稿提出；进入实现时原地更新现行 system-map-generation 等所属spec与architecture，不另造并行“v3 spec”以混淆当前真相。世界包必须绑定算子/算法/资产/内容来源，不只保存一个可变ID。

### C. 美术与视觉方案

先执行[集中美术标准](../art-direction.md#rift-r100-standard)。三档的成品完成度相同，差别在改写深入程度和人的处境；重度静帧空间压迫、连续动态/声音和行动代价缺一不可，禁止加绿、压黑、随机碎裂充数。

由美术与技术美术共同说明“怎样画出目标”，至少包含：

- 大形与中尺度语法、尺度谱、接合/断口/内腔、疏密和负空间。
- 材料与受光关系、色光层级、污染与主体可读性；颜色有表达自由，关键危险不能只靠颜色。
- 像素尺度、轮廓与细节密度、静区；禁止用更多随机噪点冒充材料描绘。
- 真实角色、敌人、交互物与地形的接触/遮挡、移动视口中的构图。
- 局部动态的形态、节律、遮挡和暂停/减动行为；声音母题、远近、安静片段与危险提示的关系。
- 参考的具体作用与明确不借用的部分、可编辑源资产与生产方法、资源成本。

新方法先做包含主要难点的成品尺寸母版，只缩范围，不降低完成度。灰盒用于验证路线，不用于批准画法。概念图或生图可以辅助探索，但整张图不能代替可编辑资产、生成能力和正式实景。直接复用已经获认可且适用的画法，不每轮重新抽卡。

三类对照必须分清：同一视口的前后版本、同材异形/同形异材、原生实景与离线图。最终以正常尺度的游戏画面和连续运动判断。纯艺术表达、吸引力与情绪有独立否决权，不能靠“玩家看得清”代替。

### D. 开发计划与实施

本轮首批开工前写任务包，逐批给出ID、依赖、负责人/文件、输入版本、产物、可运行入口、预计成本档、检查和失败回退。角色职责可以由同一主代理分阶段承担，但产出作者不得成为唯一终审者；并行改动必须明确所有权。

CSV → 编译产物；先完成共用能力，随后制作配方。每个完成的世界进入同一原生Rift运行链，包含正常灯光/视野、角色、遭遇、交互与撤离；禁止用全图亮灯的独立展台冒充入游戏。正常玩家存档与测试存储隔离。

### E. 三项独立审核

**技术审核：** 对照合同与实际调用链，检查支撑/实体/空洞、通行与视线、Host站位、内容预算、确定性、冻结恢复、失败耗尽、暂停/清理、性能及影响闭包。类型或构建通过只是其中一项。

**美术与视觉审核：** 非作者先看产物，不先接受制作说明；记录美术语言、形体体积、材料、色光构图、动效与整体完成度的具体依据。正常行走会暴露的问题不能用精选截图遮盖。声音需要实际审听；工具无法听时明确转交用户，不标已验证。

**游戏体验审核：** 另须覆盖知情选级、至少两种准备、同世界三级不同决策、真实消耗/带回净收益、低中维持和重度非必刷；首次预兆到后果和可放弃目标必须可观察。记录真实的“目标→信息→选项→行动→后果”，覆盖瞬间操作、完整出行与多次出行。检查路线选择、暴露/风险、搜取、退路、地标记忆、学习迁移和重复感。保守/冒险的情境比较不能只测是否可达。专家/代理试玩与真实用户反馈分开，不能称为用户研究。

三项分别判定pass / changes-required / pending，不能平均打分抵消。事实冲突先复现，审美分歧并置实帧和依据后由制作负责人提出裁决；用户的明确审美否决优先。

### F. 整改、接入与交付

每项问题有ID、根因类别、严重度/发生条件、影响包、负责人与复验。关键缺陷或关键美术/体验失败使相关包失去资格；共享根因按依赖闭包退回审核。修复后保留原失败证据，再追加当前版本复验。

内部合格可以支持按获准范围继续开发；正式候选小批接入并检查完整循环。人审状态不能被接入操作改为通过。收尾产物必须包含可玩链接、原生实帧/片段、版本/包/种子、技术与体验证据、数量变化、未决事项、下轮首批入口。

本地提交按既有持续授权执行；推送仍按用户指令。完成一个迭代后立刻接续已授权且依赖成立的下一批，不把阶段总结当作整个大版本结束。

## 4. 验证范围与量化预算

### 4.1 现在锁定的硬条件

- 同包/算法版本与种子可复现；继续旧局不静默换身份、重抽或降级。
- 空洞、实体、地面语义一致；合法操作必须有真实身体可达且符合视线的站位。
- 所有正式内容来自版本清单；未知能力拒绝，重试有界；同包后备仍过准入并明确记录。
- 作者自检、独立三审和用户认可分开；验证包含完整原生入口，不只Gym辅助模式。
- 生成失败、超时、拒绝、使用后备和最终成功分别统计；失败样本不能从分母删除。
- 当前共享能力改动使关联证据需要复核；相同包ID不代表旧PASS自动有效。
- 324格逐级准入和证据独立；缺一级撤掉完整世界资格，共享缺陷按影响闭包复验。
- 等级选择与规则/压力/奖励冻结，恢复不能更换承诺；暂停或离线不得推进压力。
- 最终不存在未关闭的P0/P1、本版本关键美术或体验阻断；非阻断问题必须有影响说明及处置。

### 4.2 I01必须测量并冻结，不能拖到版本末尾的预算

按明确设备/浏览器/逻辑分辨率分别确定生成与恢复p50/p95/p99、冷/暖缓存、CPU/GPU帧时、内存/纹理峰值、场景切换后的存留趋势、离线每包成本/超时/并发和候选拒绝/后备率。以流畅原生游戏体验为目标；当前没有新构造实测值，不能在计划阶段虚报已达标或编造低端设备结果。

自然分布性能采样与定向恶例资格采样分别报告分母；后者不能混进自然失败率、后备率或耗时分位数。p99样本不足时报告观察最大值/估计与限制，不写尾部性能已通过。I01锁目标与方法，I02新几何实测、I03压力/分级实测、I04复核成本；超预算先整改，修订预算必须保留理由及可比证据。

每包每级资格起始方案：**32个分层普通种子＋至少8个定向混合边界/失败种子＋独立保留种子复核**，不是全低/全高两端替代组合覆盖。每项参数须有实效检查；对高风险算子加样。I01在不降低覆盖目的的前提下，根据运行成本将确切集合、保留比例、超时和抽样依据写入预算记录，在I02内容生产前冻结；后续变更需保留原因和前后可比结果。

每个世界每个等级至少两个不同种子的正常视野运行记录；包含一次完整搜取与撤离及一次不同路线/失败或压力状态，不能全为俯瞰导览。复杂形体另查贴边、转角、遮挡前后及动态相位。机器可达性不可替代实际行走。

I06/I09/I13/I14分别安排集合、多趟选级、等级经济和最终体验；I01确定连续出击数量、配置与人力，I04/I06校准执行成本。自动选池大样本与真实连续游玩分开，世界出现统计不等于新鲜感通过。最终按完整库抽取、风险与家族覆盖；未覆盖域保留明示，不能结案时才临时缩小样本以求通过。

### 5.2 状态与证据

版本状态：awaiting-start → active；执行中可有waiting-user/paused；全库内审后release-review；全部终验后released。暂停只按用户请求；等待依赖不自动取消大版本。

迭代工作状态：planned / active / in-review / changes-required / verified / closed；当前阶段单独记录。verified指有范围的内部通过，closed须产物、问题、证据及下一步全部登记，不能据此宣称用户认可。各轮gateResults分别引用实际证据；未来完成声明必须绑定版本。

启动/最终授权记录使用{date,evidenceIds,note}，引用真实human证据；不能由代理自行写出用户认可。

启动证据用途为`start-authority`；最终人审须为`final-acceptance`，不能挪用启动消息。发布时`version.releaseManifest:{path,hash,revision}`绑定实际RC清单及SHA-256；发布门结果引用`purpose:release-gate`、相应`gateId`且与RC revision / releaseManifestHash匹配的证据，终验也绑定该RC。当前releaseManifest为null，所有发布结果为空。

每个世界记录id、family、revision、dependencyManifest:{path,hash}、implementation、integration、三审和human状态、evidenceIds、reviewEvidence:{technical,visual,experience,human}、最近邻与差异说明、invalidated。通过项必须指向当前包revision与依赖清单hash相匹配的实际证据，不允许只写三个pass。当前为空，五旧demo没有偷偷转成五个合格包。证据记录id/kind/revision/path/scope/limitations；世界审核证据还绑定worldId和dependencyHash；实际运行再补环境、包/算子/资产哈希、种子、配置和失败记录。审核/校验只能检查记录是否齐全，不能证明审美自动成立。

世界另含grades.low / medium / severe，分别记录三审review、reviewEvidence、integration与invalidated。共用包revision和依赖清单，等级证据显式含grades范围并匹配当前世界/revision/hash；同一份证据可确实覆盖多级，但不可无范围借用。世界总体身份三审有效是资格格共同前提；单级失效撤本格并撤完整世界资格，world失效撤全三级。正式世界还要求world及三级全部production。qualityPlan只存方案与门名称，releaseGateResults的通过需真实版本及证据；其记录完整也不等于机器证明游戏好玩。

每级正式接入另以`integrationEvidence`引用当前world/revision/hash/grade的runtime证据，用途`production-integration`，覆盖`production-entry`和`recovery`；仅改production标签不计正式数。引用同时在world.evidenceIds登记。

完成轮记录`achievement:{revision,qualifiedWorldIds,gradeCases:[{worldId,grade}],evidenceIds}`作为当时达成快照；证据用途`iteration-achievement`，绑定iterationId、revision和由工具`hashAchievement`计算的快照摘要。历史达成与当前有效资格分别显示：后续失效会扣当前数并警告，不抹去真实历史完成，也不让看板无法打开；最终发布仍以当前108/324有效正式数为准。首度结轮缺达成快照或目标不足必须拒绝。

变更共享算子或渲染器后，按依赖标记相关world.invalidated，当前有效计数回落，复验后恢复。删除旧证据或仅改时间戳不能解除失效。文件存在、hash不同/相同与证据审核结论不是同一回事。
