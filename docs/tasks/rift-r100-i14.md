# R100 I14：正式库、连续回归与版本终验

> **TL;DR：** 用户已授权推进I14。沿现有六项发布门，先核有效RC与继承证据，执行新增48趟的分批连续抽样，准备当前浏览器的恢复／性能及可直接体验的视听材料，再完成真实弱设备、实际审听／视觉疲劳与用户总验收。所有未跑、未听、未审项保持pending；技术准备不因最终人审未到而停下，不解锁I28或扩游戏机制。

## 目标、来源与所有权

本轮实现[R100总合同](rift-r100.md)及[唯一台账](../progress/rift-r100.json)的I14退出条件：108个有效正式世界、324个低／中／重资格格、六项发布门及对应RC的用户最终验收全部成立，才可标RELEASED。本轮不是重新设计世界、经济或物件。世界观与核心循环保持：可选污染等级，具体异世界未知；观察、有限停留、真实消耗、带回与净化点维护相互作用。

Design只维护本任务及设计裁决；Code负责冻结、执行器、运行入口和必要实现修复；QA独立核证据／存档／预算与失败；Director负责台账、来源索引、发布门和人审组织。产出作者不独自终审。共享仓库不覆盖他人改动，独立`CLAUDE.md`修改不归本轮。若整改触及游戏内UI或世界像素，须由相应具名角色执行项目skill与原美术规范；本Task Brief不授予新的视觉方向。

- **R100-G-RECOVERY：** 以当前执行环境核等级、压力、回报、已消费工具与旧局承诺；新出发、暂停／失焦、冷续、拒写重试、取消与明确弃局按原合同分开。旧v1／v2及revision1—5保护证据先核有效性，再补实际变化涉及的边界。Chrome154→155是本轮环境变化，旧浏览器结果不能改写成155实测。
- **R100-G-RELEASE：** 汇总正式库、连续回归、尾部／资源、真实弱设备、实际视听与用户总验收；清理本版本P0／P1及关键美术／体验阻断，非阻断项写具体影响和处置。R100-R10仍为发布前实际审听门，不能以工程混音绑定关闭。

六门当前仅为工作分配，未在本任务预填发布PASS。最终每门的`purpose: release-gate`、`gateId`、RC revision与`releaseManifestHash`必须一致；用户最终证据用途为`final-acceptance`，本次“推进I14”的启动授权不是终验。

## 分批执行

### I14-B01：继承证据、候选与可体验入口

**负责人：Code／QA，Director复核；可立即自主完成。** 对实际源／包清单、六门引用、旧证据范围、当前108／324计数及全部未决项做一次绑定检查；整理原失败、原用户认可和未审范围。成果归`docs/qa/artifacts/r100-i14/`，每件记录命令、环境、输入SHA、结论与限制。只读审查可以与运行准备并行，不因人审空缺停工。

核可打开的正式入口、当前Gym和[现有审听页](../qa/interactive/r100-material-listening.html)，提供正常尺度三档、最近邻／最弱项及连续片段的直接入口。审听页的18份原混音属于受控近距离、四提示注入材料；同时准备正常游戏压力、提示和反复进出场景的材料，不能只交声音波形或混音台。使用隔离存储保护用户现有记录；训练给装、无雾、指定世界、回放与正式自然游戏逐项标明。

本批完成只表示“候选和审核材料可复核／可体验”，不表示听过、真人认可或已发布。

### I14-B02：当前环境技术复核与新增连续48趟

**负责人：Code执行、QA核账与连续性、Design解释行动与范围。** 原[I01预算](rift-r100-i01.md#冻结的测量与资格预算-v1)明确要求I14新增至少48趟连续稳定性／选择复核，覆盖三档及六材料家族。Director于本轮开跑前明确保留此要求；这是对324格的抽样，不重跑整库。I10—I12[特定抽查修订](../qa/artifacts/r100-i10-i12/sampling-amendment/root-approved-sampling.json)不默改本轮48；旧自然48与I13的52只作历史继承，不能计入新分母。

Code与QA在运行前冻结简单连续方案：源存档及SHA、主链／独立分支关系、等级顺序、既有公开装备与经营政策、每批边界、暂停／冷续插入点、工具版本、实际浏览器／设备和失败处理。单批最多12趟，至少分四批；每一条主链从真实前次结算与准备继续，不复原消耗、成熟、死亡或欠修。不得新增I13式利润、指定工具回满、每次深搜等经营验收条件，不能为通过稳定性测试注入资源。

**首轮执行合同（2026-10-09，Code／QA交叉后开跑前锁定）：**

- 唯一主链源为[I13 A23真实末态](../qa/artifacts/r100-i13-continuation/a-target-recovery/a-same-run-recovery/i13/browser-storage.json)，现金35、核心51／储藏103／净化器51。精确存档bytes、SHA和公开库存由Code冻结、QA独核，不重新生成同等数值的替代档。
- 四批各12趟，总48；整个序列为`[low, medium, severe] × 16`，每批三档各4。下一批接前批真实末态，不能重置A23。级别使用正常公开选择，目的地仍正常随机；已有重度开放状态保留。
- 执行器只派生已验证B14的有界路线，不混入A定身选靶系统。所有正常可见合法对象可候选；主动Q按公开消声≥5秒、F按公开短冲≥48像素，均先筛单件余次≥2、再真实取得FIFO，无合格物空槽。第三主动清空，真实可用同名黄铜背扣有则装，武器沿既有最高可用公开品质策略。正常每工具最多一次、既有近敌蓄力／出手的紧急短冲仍留真实预算与后果；未出现合法能力窗口不构成稳定性失败，也不能因此签能力作用。
- 复试沿B14已验证规则：每对象初试＋复试最多两次，最少5秒及玩家位移48像素／另一对象完成，再结合正常新观察变化重新走原危险门；最多两个纯公开地形探索目标、18次外层决策、6次成功翻找。保留HP30／混乱120／混乱加已知归途145退出线、接近25秒与宏观42秒上限。经营仍先真实修核心51／储藏100／净化器51，再按既有储备规则支付成长；新获物按取得FIFO供奉，不注入状态。
- 取消仅服务I13单项经济试验的“重度工具资格不足自动降档”及“恢复达标提前停批”；这两项是本轮执行政策变更，不改正式重度开放规则、掉落或成本。本轮缺工具如实空槽，不因结果不利改已定等级。死、空返、欠修均记有效游戏结果并据真实状态继续；不能合法继续或技术故障时停在实际现场定位。正常风险止损不等于样本无效，不为填满48赠装或删失败。
- 前三趟低／中／重各纳入一次正式新入口、压力状态、暂停／失焦及同run冷续检查；实际中断点、输入、时钟差、存档与承诺前后保存。检查不另算出击，其他45趟不冒称都做过同等冷续。
- 性能专项独立串行四例：`hollow-wreckage`、`buried-lamellae`（旧材料提交p95恰3ms）、`felt-wedges`（旧中断）、`white-scarfield`（原未测结构风险例，非已证最差），均重档61.2秒。具体种子／视口／DPR／活动路线随首份执行冻结锁定；不与48自然行程同时占用参考机，不把四例结果填成剩余34世界全过。

上述源档、序列、政策和四个性能对象已明确；工具与执行环境精确清单落盘后再运行。当前没有新增运行结果，RC／1397源文件／108包／307依赖一致性由Code报告，独立QA绑定尚按本轮原件核验。

自然出行仍按正式池随机目的地；等级选择及理由、准备是否实际可用、搜取／空返／死亡、归来与后续状态全部记录。三档和六材料的覆盖表随每批更新，不能取消重抽凑材料、删掉无收获或危险结果；若48自然样本仍有覆盖空白，明确保留，另行事前登记缺失范围的定向复核，与自然分母分开，不能无限随机追齐。技术中断不伪装成游戏死亡；若有真实检查点，先审同局继续及既付费用，原失败保留，不能同局两段充两趟。

冷暖进入、正式首帧、场内移动／压力、暂停失焦与恢复、结束清理及资源变化分别测量。Code／QA按已知最差与变化影响选择有限专项，开跑前固定世界、档位、种子、运行时长和工具；不从并发浏览器推性能结论，性能／资源实测独占。原参考机预算沿用：完整活动采样≥60秒，帧间隔p95≤20ms、p99≤33.4ms、>50ms帧占比≤0.5%；CPU提交p95≤12ms，新增材料提交p95≤3ms；参考机生成与冷恢复p95目标≤5秒、新增主线程连续阻塞不得>50ms。样本不足时报告实际最大值和分母，不伪称p99或全池尾部已证。

资源预算仍归同一原文：10次进出后资源计数稳定，GC后保留内存较初始增长≤10MiB，单世界新增CPU驻留／GPU缓冲估算各≤64MiB；浏览器heap、估算GPU字节和驱动实际内存分别写。旧原生首屏100—117ms长任务与Rift入场阶段分开核，不能以Rift无长任务冒称全网页无卡顿。超预算先定位，不通过放宽门槛、缩原生像素或隐藏压力来变绿。

### I14-B03：真实弱设备与实际视听审核

**Code先完成可携执行包与入口，QA核记录，真人提供实际体验。** 已锁参考机是M4 Pro／14逻辑核／48GiB、逻辑960×640；发布前还须至少另一档较弱真实硬件。原合同没有最低型号。本轮记录实际CPU／GPU／内存／系统／浏览器、DPR、供电／后台条件、冷暖状态与相同来源；CPU降速、模拟网络或改浏览器参数只能另列诊断，不能签作另一台真实弱设备。

先复用B02冻结的代表场景和原预算，准备一份可由实际设备运行、收集报告与复现问题的包。若可访问合适真机则自主执行；若当前连接仅有参考机，所需条件是用户可提供真机执行环境或按已准备入口代跑并返还实际报告。设备是否满足“较弱”按真实规格和记录判断，不要求用户凭空挑一个新产品规格。技术准备和其他独立验证继续，缺设备不提前关闭发布门。

实际审听沿[R100-R10声音处置](../qa/artifacts/r100-i10-i12/final-audio-root-disposition.json)：五个源声音、六材料×三档、关键游戏提示、重复转换，判断材料身份、远近可听性、提示掩蔽、循环接缝、紧张节律与长听疲劳。六个主材配方不是108套声音身份。审阅记录实际聆听者、播放设备／音量、实际时长、具体片段／版本和现象；原合同未锁定“听满几分钟即PASS”，不新增此类阈值。工程播放成功、无削波、静音浏览器或视频截图均不代签听感。

视觉与连续体验使用正常肩灯、角色尺度和完整行动，包含三档压力变化、搜取／受压撤退及归来，查看最近邻、原弱项和未精选内容。记录重复感、噪声／闪动、边界与危险可读性、停顿与转场的一致性；不以静帧总分或录屏数量代替实际疲劳判断。美术与玩法的具体否决按原标准处理，当前已认可画法不因终审另起一套。

### I14-B04：问题闭环、六门绑定与用户总验收

**Director负责收口，各作者修复，QA独立复验。** 每个实际缺陷写根因、严重度、影响包／等级、来源与复验；共享变化使受影响资格失效时按闭包处理，不能沿旧PASS。影响数量不足108／324须补齐当前资格，不能降低目标。原失败保留；无具体原因不扩大随机样本追求好结果。

在提出用户总验收前，先完成已获授权且不依赖用户判断的代码、证据整理、试玩入口、实际问题修复和可复核候选，交出具体RC及其最弱项／已知边界。用户反馈须对应明确版本、实际看／听／玩范围与结论；只看局部、只认可改善或沉默均不能扩大为全版通过。全部六门及最终认可一致后才写`RELEASED`；未满足时维持active／release-review或相应待人条件，不能以Task Brief写完或48趟跑完代替版本交付。
