# 地图与资源生成自动化整改

状态：ACTIVE · 2026-10-21 · DEC-224  
主能力：COH-F011 / F013；关联 F007 / F012 / F015 / F016 / F019 / F044。

## 问题与授权

用户明确否决逐地图适配：地形生成与资源投放必须遵循共享策略、算法自动完成。当前r13是作者布局编译器；三图低档缩图依赖独立坐标CSV，资源依赖worldId固定配额，内容末槽依赖人工认证seed。这些不能作为后续全库生产方式。

本任务整改生成机制，不自动开放其余105世界，也不重做已认可的人物／怪物／光照美术。旧有效在途局按原冻结协议恢复。禁止实机试玩，包括自动操作游戏的浏览器测试；只执行静态、离线生成、规则／恢复检查及构建。

## 必须达到的结果

1. 新生成链只需要世界材料／物体语法、污染档、种子与共享策略；不得要求某world的地块／孔／障碍／资源坐标、数量特批或成功seed名单。
2. 按档位确定探索规模，联合生成地面、真实VOID、实体与通路；保持矩形拼合、自由断缘、错位宽地与次级伸展。不得退回矩形广场、洞穴走廊或成图后补孔。
3. 有效孔约为实体两倍，身体全可达、巨大空白及真实遮蔽路程等原核心约束保留；实际测量，不为使结果通过而重定义计数。
4. 资源预算由实际身体可行面积、通行距离及探索分布计算；位置从实际合法交互席位选择。既检查总预算，也检查大片可探索区域的补给空白；不能把全世界统一“6个”称作自适应。
5. 低档近程燃料可靠，武器不得替换必要燃料；保留盲翻、实际支撑、VOID遮挡、巡逻／危险与一次结算，不移动纯视觉假装移动资源。
6. 生成有明确工作量上限、阶段诊断和失败原因；不依赖离线人工挑seed，不无限搜索，不通过少放内容或偷偷换回旧图完成。
7. 新策略、源模型及版本随配方冻结，同seed可复现；旧r13及更早执行语义不变。三张锁定图只是回归样本，不是算法资格白名单。

### 本批实施中的直接诊断

源部件间距修复已提交；保存夹缝回归由3,178/3,176可站/可达变为4,398/4,398。首份新整图的31,060个身体格全部可达，但空旷与遮蔽覆盖仍拒绝。独立逐格对照进一步发现局部孔栅格使用负数作为空哨兵，误丢负x半边，导致规划与成图不一致；必须先关闭该差异再测下一整图。

初排仍存在另一个策略错误：先放全部实体，且将外岸距离当作内部孔的遮视覆盖。整改改为按真实通行场的未覆盖见证构造孔/实体，完整2H:1S单元内计数，数量受原密度容差约束；不再依赖8,192次整图坐标试挪，不放宽任何验收阈值。原失败证据保留为`connected-first-geometry-rejected.json`。

后续已修正负坐标孔栅格，规划与最终身体／扫掠场逐项一致；源部件及附属relief完整支撑检查通过。三个旧r13冻结存档离线重建的签名、完整布局均保持一致。当前三角覆盖格及有限放置提交`bf5cf3b2`只证明23个新增物件能放置并保持全连通，不代表准入：原severe/24680主案仍有G1空白半径177.66、深域跨度888，正常入口仍为r13。

具体根因是覆盖保证缺失：320间距三角格仅给数量密度，不能替代真实物件的160空白限制；边缘格被邻接排序向内推移形成长空白带，平均源距离免放也不能保证格子远端。接续只针对局部覆盖块的实际空白见证修正构造，不能用换种子、提高全图重试预算或放宽门槛回避。
