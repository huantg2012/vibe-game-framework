# 统一库存、出击装配与裂隙背包

> TL;DR：武器和污染物共享物品身份、存放位置、库存操作和一项负重预算；出击前装好一把撬棍与污染物工具，裂隙内只整理未装配收获。揭晓、取得、丢弃和带回是独立且原子的状态变化。

## 1. 已批准实施范围

用户已锁：只做撬棍家族；不可升级；新游戏白板撬棍；可拾取差异化成品；武器和污染物统一库存；出击装配；裂隙背包统一处理两种拾取对象，携带限制尽量单一。

库存方案已获准进入实施：单负重16、污染物每件2作为实施基准；基地容量不限；首版装备出击期间固定；自动取得可容纳的搜索结果；超重保留实物并在一次界面中交换整理。DEC-138已批准四品质十成品、2.7/3.0/3.3重量、抗性和负重行动初值共同实施，规则正文分别见玩家武器和生存属性spec。

死亡全丢、开包不暂停均已锁定，详见§7。

## 2. 一件物品只有一个身份与归属

统一库存不把污染物改成武器。二者共享物品层，保留各自生命周期：

- Weapon：instanceId、definitionId、来源记录；无等级/经验/升级/耐久字段。
- Contaminant：保持当前id/type/rarity/stage/impactCharges/usesRemaining；残渣供奉、转工具、用尽破碎均沿用同一id，不能转化时再发一件。
- ItemLocation：基地收存、随身、当前裂隙地面、基地供奉中四种互斥归属。销毁后移出活表，记录结算/消费事务。
- EquipmentRef：在手武器和已有主动/被动槽引用随身实例；引用不是额外物品，不能装上就减重或重复占重。
- Source：原拾取节点/生成种子/模板、首次发现runId、是否出发前拥有；用于防重抽、结算与未来场景背景关联，不向玩家暴露技术ID。

基地和裂隙使用同一个库存领域层，界面按位置投影。供奉台、培养藏和入口都是同一库存的操作入口；不得再各存一套数组。供奉中的物品可在库存查询，标出所在装置，不能从库存绕过取下规则直接装出击工具。

现有ContaminantSystem转为污染物生命周期与槽位服务；原实例数组移交唯一库存所有者，不长期保留新旧两套可写副本。ToolSystem绑定的对象与次数变更必须经过统一消费/销毁事件。

## 3. 唯一容量维度：负重

单位用抽象“负重”，不声称真实公斤。界面容量16.0，内部以十分之一整数存储为160；污染物20显示2.0，撬棍27/30/33显示2.7/3.0/3.3。所有比较和交换用整数完成，避免小数累积误差；所有随身武器与污染物逐件求和，含已装配对象；同类各有实例，不能靠堆叠图标绕过重量。

污染物首版统一2，不以稀有度增加惩罚；从残渣转工具仍2，余次降低不减重，用尽破碎才释放2。武器重量由其成品CSV定义。没有格数、长宽拼放、武器专用背负上限、超重后继续慢走、负重升级与额外仓库扩容。

例：基础撬棍3＋基础三个工具6＝出发9/16，剩7可带三件污染物，或一把3重撬棍加两件污染物。成长后的四工具8＋抗污撬棍3.3＝11.3/16，余4.7，仍可带两件污染物。必须以实际CSV重新核算，不把例子当硬编码。

不能主动超过上限；超重时明确显示当前负重、物件重量、还差多少。库存不自行扣混乱或改速度。用户新提出的负重行动方向由system-survival-attributes.md给出公式：半载以前不减速，满载减速16%，只从同一个已提交负重派生，不新增疲劳计量；已接实际玩家速度，UI只读已提交状态，装配预览另标。薪柴继续走现有计数和收益规则，本轮只统一用户点名的两类对象，不趁机重做第三类资源。

基地收存不限容量，以稳定的列表、筛选与分页浏览解决数量问题；首稿“六件收存＋在手/背负”容量提案作废。

## 4. 出击装配：同一页完成准备

入口沿用现有真实场景、装配交互与Shift+Enter出发。新增一个在手武器槽；主动/被动工具槽保留已有成长数量与Q/F/G，选中对象兼容检查下沉到领域层。

建议三块连续信息：左侧人物与在手撬棍/工具挂位；中段共享收存（全部/武器/污染物）；右侧选中物与当前对应装备的比较。上方持续显示“出发负重/上限、可带回余量”；空工具槽合法，不制造“未配满不能出发”。

选武器Enter装在手，旧武器回基地；选已转化污染物装兼容工具槽，残渣只显示用途与去供奉入口，不能出击当技能用。鼠标和键盘走同一事务。选择重武器前先预览装配后的总负重和损失的收获余量，不等出发时才弹错。

首版只携出装配物，不提供无用途的“携出一袋未转化残渣”选项。出发前可随时修改。首版武器与工具在本次裂隙固定，未装战利品只带回；背包详情明确“带回后可装配”。不在首版增加战斗换武器、工具解绑、被动反复开关的额外系统。

在手位不可空着出发。新游戏默认已装基础白板。已有武器的正常存档不会每次白送一把；如果永久删除最后一把，基地提供无收益的基础替补，唯一事务幂等；替补不能售卖/拆解，也不能在裂隙无限召出。

## 5. 裂隙搜寻与取得

武器与污染物都从现有翻堆搜寻进入同一流程：

1. 未搜寻：不提前揭露物件内容；保持E持续1200ms、48px可见距离及现有中断/搜寻声。
2. 揭晓：结果在本节点只生成一次，成为有确定id/模板/属性的地面对象。物品像素轮廓、名称与“重量”短时显现。
3. 容量足够：本节点同批揭晓的武器与污染物能全部容纳时，整批原子移入随身，短促取得反馈并显示新负重；不再要求每捡一件都打开大背包。
4. 容量不足：同批所有武器/污染物均留地（不让数组顺序替玩家选择先拿谁），提示“还差N负重 · E整理”；不自动扔旧物，不吞结果，不重复搜寻。按键必须先释放，避免完成搜寻的E顺带确认另一个动作。
5. 已揭晓再次取得：无需重做1200ms，E按下进行容量校验，够则取得，满则进入附近/随身整理。

批次只有部分可容纳时，附近列表允许逐件取得，或选择一次交换；初次自动收尾不抢占余量。

自动取得仅是玩家完成主动搜寻后的收尾，不恢复走上去触碰就拾取。武器不自动装备；污染物也不自动供奉或变为可用工具。

武器来源首版只做环境搜寻，不同时重做敌人持武与尸体。R4品质掉落表尚待确认，旧八件功能成品权重已清除，不能临时复用；地点背景标签是可扩展接口；普通污染体死亡不随机吐人造武器。节点生成/揭晓/读档的具体抽样时点统一固定，不能通过打开/关闭背包或掉地重捡重抽。

同一翻堆如果包含薪柴与物件，薪柴可按旧规则取得；物件单独遵守重量，不因物件超重撤销已取得薪柴，也不令同节点再次产生薪柴。

## 6. 背包与超重交换

B打开背包；Tab保留存续报告；Q/F/G与R结算返回不复用。工具使用状态、攻击动作和搜索进度不会因开包重置。背包显示负重、已装配条、随身战利品和一个详情；已装配区是同一实例的引用视图，不在战利品区重复呈现。

普通开包时只管理未装战利品，支持丢下。靠近合法地面物件打开时增加“附近”侧；只能显示48px且实际可见的对象，不通过UI看穿墙。已装对象可查看但不卸下、不丢弃，以明确锁标与“本次出击已装配”解释。

满载交换在同一个界面完成：选要取得的附近物件→勾选需要留下的未装收获→即时预览交换后负重→一次确认。可一次留下两件轻污染物来换一把重撬棍，不要求反复关包、丢物、再开包。

交换提交前必须同时验证：目标仍在附近、仍可见、归属未变、全部丢出物都有合法可达落地点、新负重不超限。全部通过才整体提交；任何失败双方原状不变。取消只取消当前交换草稿，不撤销已经明确完成的早先拾取。

默认不勾丢弃物；已有候选与释放重量都由玩家选择，不按品质自动牺牲对象。已勾物在列表与负重条上明确可见；确认写“留下2件，取得精良撬棍”，不写抽象“确定”。Esc先取消交换草稿，再关闭背包；恢复游戏的按键不能穿透为攻击/取物。

地面丢出物保持id、数值、工具余次；在本次裂隙内不因距离消失，能原样捡回。相近多件可共用一个容纳点，附近列表分条列清，不能彼此遮掉交互。离开本次裂隙后未携回物不保存为可回访地图。

长库与焦点：按实例id保留选中项、滚动位置和比较对象；数量变化不整树重建到顶部。删掉当前项后就近选邻项，最后一项删除后落到清晰空态。列表重排必须由显式筛选/排序触发，不在操作中实时跳行。

## 7. 死亡与开包规则已锁定，退出处理待定

### 已确认：死亡丢失全部本趟随身物（2026-09-09，DEC-133）

所有武器/污染物统一处理：带入裂隙的已装配武器和工具、本趟拾获的武器和污染物，在死亡时全部失去，不保留携入装备。净化点收存及未携出的供奉物保留；薪柴沿用本趟死亡损失规则。清理丢失实例、装配引用、工具运行状态与附属计数，不恢复已耗次数或已破碎对象。

此前“保留带入装备、仅丢新收获”的推荐已被用户否决，不作为备选实现。无武器后基础替补的提案仍见§4；它是基地新提供的白板，不是找回死亡丢失的那把，不能恢复任何特殊款或工具。

撤离结算只以最终在包内且合法的实例为准，不以“本趟曾捡过”计数。工具消耗与破碎不当作新收益；重复拾取同一实例只算一件，已丢下的不会出现在带回列表。

### 已确认：开包不暂停（2026-09-09，DEC-134）

打开或整理背包不停止世界：敌人、混乱、战斗、接触伤害、冷却和特效计时继续运行。开包不提供无敌或冻结，关闭也不重置攻击状态。此决定只涉及背包，不自动变更已有Esc暂停菜单规则。

已批准库存交互进入实施：背包占用玩家主动操作，允许通过移动意图快速退出；受击/结算优先关闭并取消未提交交换。附近目标失效要明确显示，不能继续对已经离开的物件交易。具体画面、键鼠手感与长期操作仍待实机验收，不把实施授权写成人审已通过。

### 中途退出与刷新

当前没有裂隙快照，不能暗自宣称可原地续玩。死亡全丢的确认不自动等于确认主动退出或浏览器崩溃也全丢。未完成出击的处理仍待明确；若采用放弃等同死亡，需按本趟全丢结算；若采用恢复，则需另行设计持久化恢复边界。次数消耗/破碎按已提交记录，不能回档免费补满。主动返回标题前明确显示后果。首次武器发现以首次成功揭晓为准：整批揭晓事务保存firstWeaponDiscovered标记，装不下、丢弃或死亡也不重置；开局白板不消耗该标记，单纯生成地图也不消耗。

必须先持久化出发账本，再进入裂隙；物品/工具的归属或次数事务在同一个存档版本中原子更新，后台失焦只作补充，不能依赖退出事件成功写盘。浏览器写入失败时保留当前物品且给出可读提示，不在保存失败后删除地上实例或退出场景。主动工具先校验发动条件与对象有效性，再原子持久化消费，成功后才释放效果；不能先放技能再因写入失败返还次数。持久化失败不发动，输入释放后可重试。结算写盘失败进入保存待重试态，保留当前run快照、显示原因与重试按钮；不重新发放收益/推进潮汐。当前会话可保留已结算结果停留基地，明确“尚未保存”，不能用假成功提示诱导关闭页面；继续下一次出击前必须先成功保存。未结算恢复只执行一次，不重复推进潮汐/冲击；与现有RIFT_EXITED和回基地结算接线统一审计。

不在本轮偷偷增加“崩溃掉全部收藏”或完整地图快照。退出语义须单独明确并展示，不以死亡决策代替。

## 8. 领域事务与持久化接口

领域入口：reveal / take / exchange / drop / prepareEquipment / beginRun / consume / destroy / settleRun。共同先验证后提交，再广播变化；UI不直接splice污染物数组。主动/被动槽兼容、阶段、位置、唯一占位在此校验，不依赖按钮是否隐藏。

存档升级V1→V2：保留旧污染物id、品质、供奉位置、次数、工具槽、成长与防御运行计数；所有未供奉物迁入基地，已有工具引用形成待出发装配；首次迁移补一把白板并记录，重复加载不重复发放。旧档工具组合超负重时保留所有物件，在准备界面提示调整，不静默删除或卸装。

run账本记录runId、begin快照引用、携出id、当前携带/地面归属、已消费/销毁、候选loot身份、最终结算状态。记录引用与必要事务状态，不复制两套可写物品。掉落保存只服务中止归属，不伪装成完整裂隙恢复。

永久弃置发生在基地时用明确长按确认，无自动批量卖低品质；本轮不增加出售或分解奖励。供奉取下、转化和工具破碎均清理归属与引用，特别是ToolSystem缓存/被动和echo附加次数，不能留下“物品没了效果还在”。
