# 阶段1: Ideation（构思）

## 目标

从一个模糊的"我想做一个xxx"变成一份结构清晰、可执行的游戏概念。

**输入**：脑中的粗略想法
**输出**：概念文档（Concept Doc）— 后续所有工作的锚点

---

## Ideation 的子步骤

```
Step 1: 核心体验提取  →  "玩家感受到什么？"
Step 2: 机制探索      →  "用什么玩法制造这种体验？"
Step 3: 参考分析      →  "谁做过类似的？学什么避什么？"
Step 4: 范围界定      →  "Solo+AI能做到什么程度？"
Step 5: 概念定稿      →  输出 Concept Doc
```

---

## Step 1: 核心体验提取

### 你做什么

用你自己的话说出那个让你兴奋的想法，不需要结构化，可以是：
- "我想做一个让人觉得xxx的游戏"
- "我想要xxx的感觉但加上yyy"
- "我玩了xxx觉得如果zzz就更好了"

### AI Agent 做什么

**角色：创意对话伙伴**

AI 的任务不是直接给你一个完整概念，而是通过提问帮你把想法显性化：

- 追问"为什么这个让你兴奋"→ 找到核心情感
- 提出类比"你说的是不是像xxx那种感觉"→ 帮你校准表达
- 拆解"这里面有几层：A体验 + B体验，哪个更核心"→ 找到优先级

### 产出

```markdown
## 核心体验陈述（Core Experience Statement）
[一句话：玩家在游戏中最核心的感受/体验是什么]

## 体验支柱（Experience Pillars）
1. [支柱1]：[说明]
2. [支柱2]：[说明]
3. [支柱3]：[说明]（最多3个）
```

### Prompt 策略

对话开头的引导方式：

```
我有一个游戏想法想跟你讨论。我先把脑中的粗略想法说出来，
请你帮我通过追问来明确核心体验，不要急着给方案，先帮我理清楚"我到底想做什么"。

我的想法是：[你的想法]
```

---

## Step 2: 机制探索

### 你做什么

- 在 AI 给出的机制选项中做选择
- 用"感觉对/不对"来给方向（vibe 本身就是有效反馈）
- 如果脑中有具体机制想法，直接说

### AI Agent 做什么

**角色：系统设计师**

基于 Step 1 的核心体验，AI 发散可能的玩法机制：

- 提供 3-5 种能制造目标体验的机制方向
- 每种给出：核心循环描述 + 为什么能制造目标体验 + 类似游戏参考
- 你选中方向后，AI 进一步细化核心循环

### 产出

```markdown
## 核心循环（Core Loop）
[玩家 做X → 获得Y → 驱动做更多X 的循环]

## 关键机制
1. [机制名]：[工作方式] — 支撑体验支柱[N]
2. [机制名]：[工作方式] — 支撑体验支柱[N]

## 短期循环（Moment-to-Moment）
[每10-30秒玩家在做什么]

## 中期循环（Session Loop）
[每次游玩15-30分钟的节奏]

## 长期循环（Meta Loop）
[是什么让玩家明天还想来]
```

### Prompt 策略

```
基于我们确定的核心体验：[粘贴核心体验陈述]

请提供 3-5 种可能的玩法机制方向。每种需要包含：
1. 核心循环是什么（用 "玩家做X → 获得Y → 驱动Z" 的格式）
2. 为什么这种机制能制造我们要的体验
3. 有什么类似的游戏可以参考

不要给我最终答案，给我选项让我挑。
```

---

## Step 3: 参考分析

### 你做什么

- 提供你自己已知的参考游戏
- 对 AI 找到的参考做判断：哪些确实相关，哪些不是
- 明确"我想学它的xxx，但不要它的yyy"

### AI Agent 做什么

**角色：竞品研究员**

- 基于确定的机制方向，找出 3-5 个核心参考
- 分析每个参考：做得好的 / 做得不好的 / 可以借鉴的具体设计
- 帮助定义差异化："你的游戏和这些相比，独特在哪"

### 产出

```markdown
## 参考图谱

### 核心参考
- [游戏A]：学它的[xxx]，避免它的[yyy]
- [游戏B]：学它的[xxx]，避免它的[yyy]

### 差异化定位
[一句话说清楚：这个游戏和最近似的竞品相比，独特价值是什么]
```

### Prompt 策略

```
我的游戏核心循环是：[粘贴核心循环]
关键机制是：[粘贴关键机制]

请帮我做参考分析：
1. 找 3-5 个机制相近或体验相近的游戏
2. 每个分析：它做得好的 / 它做得不好的 / 我能学的点
3. 帮我找到差异化：我的游戏独特在哪里

我自己想到的参考有：[你的参考]
```

---

## Step 4: 范围界定

### 你做什么

- 诚实评估自己的时间投入（每天/每周几小时）
- 选择 MVP 范围（一定要砍到痛，宁可太少不能太多）
- 确定期望的开发周期

### AI Agent 做什么

**角色：制作人/Producer**

- 基于技术栈（Web游戏）和团队（Solo+AI）评估可行性
- 列出 Must-have / Nice-to-have / Out-of-scope
- 建议 MVP 应该包含什么（刚好能验证核心体验的最小集合）
- 粗略工时估算

### 产出

```markdown
## 范围定义

### MVP（最小可玩产品）
- [功能1] — 验证 [核心体验X]
- [功能2] — 验证 [核心体验Y]
- [共N个功能]

### Nice-to-have（MVP之后）
- [功能列表]

### 明确不做（Out of Scope）
- [排除项列表]

### 预估时间线
- MVP: [X周]
- 完整版: [Y周]
- 假设条件: [每周投入Z小时]
```

### Prompt 策略

```
我的情况：
- 技术栈：Web/浏览器，TypeScript
- 团队：我一个人 + AI辅助开发
- 每周可投入时间：[X小时]
- 编程水平：有经验的程序员
- 美术能力：依赖AI生成

基于我们确定的核心循环和机制，请帮我界定 MVP 范围：
1. 最少需要什么功能才能验证核心体验有趣？（要狠心砍）
2. 什么是 nice-to-have 可以之后加？
3. 什么明确不做？
4. 粗略估算 MVP 需要多久？
```

---

## Step 5: 概念定稿

### 你做什么

- 审核 AI 整合的 Concept Doc
- 修正任何不对的地方
- 最终确认"对，这就是我要做的游戏"

### AI Agent 做什么

**角色：文档整合者**

将 Step 1-4 的所有产出整合为一份结构化的 Concept Doc。

### 产出：Concept Doc 模板

```markdown
# [游戏名/代号]

## 一句话描述（Elevator Pitch）
[一句话让人理解这是个什么游戏]

## 核心体验
[玩家最核心的感受是什么]

## 体验支柱
1. [支柱1]
2. [支柱2]
3. [支柱3]

## 核心循环
[描述 + 简图]

## 关键机制
[列表]

## 目标玩家
[谁会喜欢这个游戏，为什么]

## 参考与差异化
[核心参考 + 独特价值]

## 平台与技术
- 平台：Web浏览器
- 技术栈：[确定的选项]

## MVP 范围
[功能列表]

## 时间线
[里程碑规划]
```

---

## 本阶段的 Agent 配置

在 Ideation 阶段，你不需要多个 Agent。**一个会话足够**，但角色要明确：

| 步骤 | AI 扮演的角色 | 关键行为 |
| ---- | ------------- | -------- |
| Step 1 | 创意对话伙伴 | 追问为主，不给方案 |
| Step 2 | 系统设计师 | 给选项，不做决定 |
| Step 3 | 竞品研究员 | 分析事实，标注观点 |
| Step 4 | 制作人 | 挑战你的scope，帮你砍 |
| Step 5 | 文档整合者 | 结构化汇总，不添加新内容 |

会话可以是连续的（一个长对话走完），也可以分开（每个 Step 一个会话，把前一步的产出粘贴进来）。

---

## 质量门禁：Ideation → Design

通过以下检查才能进入下一阶段：

- [ ] 核心体验能用一句话说清楚
- [ ] 核心循环逻辑自洽（X→Y→Z能循环）
- [ ] 目标玩家明确（不是"所有人"）
- [ ] MVP范围不超过你的时间预算
- [ ] 你自己对这个概念感到兴奋（最重要）

---

## 常见陷阱

| 陷阱 | 症状 | 解药 |
| ---- | ---- | ---- |
| 过早细化 | 还没定核心循环就开始想UI | 强迫自己先写完核心体验陈述 |
| 范围失控 | "再加一个xx也不难" | 回看时间预算，每加一个就砍一个 |
| AI 讨好 | AI说"好主意！"但不挑战你 | 明确要求AI扮演魔鬼代言人 |
| 参考陷阱 | 变成"我要做A+B+C的结合" | 回到体验本身，参考是手段不是目标 |
| 拖延启动 | 无限打磨概念不动手 | Concept Doc完成就停，剩下的原型阶段验证 |
