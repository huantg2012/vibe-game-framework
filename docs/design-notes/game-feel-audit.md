# Game Feel Audit: UX 整改清单

> 背景：Slice 3 系统全部就位后试玩反馈——"东西都有了，放在一起缺'游戏感'"。
> 本文档列出具体问题 + 改进方向 + 优先级建议。决策权属于项目负责人。

---

## 问题分类总览

| 类别 | 问题数 | 核心缺失 |
|------|--------|----------|
| A. 信息不可见 | 5 | 玩家属性/状态无汇总查看入口 |
| B. 物品不可管理 | 3 | 无 inventory 面板，污染物状态不可一览 |
| C. 效果感知缺失 | 4 | 系统作用了但玩家"看不到差别" |
| D. 系统割裂感 | 4 | 各交互点各自为政，缺少整合线索 |
| E. 节奏反馈缺失 | 3 | 循环推进无仪式感，不知道"我在进步" |

---

## A. 信息不可见

### A1. 净化点无"玩家当前状态汇总"

**现状**：净化点没有任何地方显示玩家的永久改造等级、当前 HP 上限、混乱抗性等累积属性。玩家必须走到改造祭坛打开面板才能看到零散信息。

**改进方向**：净化点 HUD 增加一行简明的属性摘要（当前 HP 上限 / 混乱抗性 / 薪柴亲和），或提供一个"状态概览"交互点/面板。

**复杂度**：低  
**体验影响**：高（"我变强了"的感知基础）

---

### A2. 薪柴储备在净化点 HUD 中不可见

**现状**：净化点没有持久的薪柴储备显示。玩家只有在打开分配面板（`allocation-panel`）时才能看到 reserve 数字。但所有决策（修模块/买改造/是否出击）都基于这个数字。

**改进方向**：净化点 HUD 常驻显示薪柴储备数量（与裂隙 HUD 的薪柴位置对应，建立视觉一致性）。

**复杂度**：低  
**体验影响**：高（资源决策的前提信息）

---

### A3. 模块效果无实时显示

**现状**：模块旁只有一个 HP 条。玩家看不到"CORE 当前减混乱 21%"或"STORAGE 当前加成 x1.35"这类生效中的效果数值。必须打开分配面板才能看到。

**改进方向**：模块实体上（或 HUD 中）显示当前生效的效果值（一行文字即可）。

**复杂度**：低  
**体验影响**：中（让模块修复的意义可见）

---

### A4. 潮汐/稳定度信息过于隐晦

**现状**：潮汐信息只有右上角一行 9px 文字"Tide 2 - 涨潮"和一个 80px 宽的绿色稳定度条。没有解释含义，也没有告诉玩家"还差几次出击到下一阶段"。

**改进方向**：①稳定度条旁加百分比数字；②潮汐信息增加"当前冲击强度"提示；③首次看到时给一句说明文本。

**复杂度**：低  
**体验影响**：中（长期目标感知）

---

### A5. 出击前无"当前加成预览"

**现状**：`loadout-panel` 只显示装备了什么工具，不显示本次出击的总修正值（混乱减速、薪柴加成、HP 上限）。玩家不知道"这一趟我比上一趟强在哪里"。

**改进方向**：出击确认面板底部增加"本次出击属性"摘要行：HP / 混乱增速修正 / 薪柴价值修正。

**复杂度**：低  
**体验影响**：高（改造/模块修复的即时回报感）

---

## B. 物品不可管理

### B1. 无独立的 Inventory/收藏面板

**现状**：污染物只有在防御面板（`defense-panel`）和装备面板（`loadout-panel`）的子列表中可见，且只显示对应 stage 的物品。没有一个"我所有的东西"的总览入口。

**改进方向**：新增一个"库存面板"交互点或按键（如 Tab/I），显示所有污染物按 stage 分组（防御中/工具/已碎），含详细属性。

**复杂度**：中  
**体验影响**：高（"物品收集有去处"的基本体验）

---

### B2. 污染物没有效果描述

**现状**：防御面板和装备面板只显示名称+稀有度+剩余次数。没有告诉玩家"固化残渣装备后到底做什么"、"凝锁按 Q 会怎样"。玩家必须凭记忆或试错。

**改进方向**：每个污染物条目增加一行效果简述（tooltip 或内联文本）。参考 `docs/world.md` 的叙事语调约束保持简短。

**复杂度**：低  
**体验影响**：高（无描述 = 玩家无法做有意义的选择）

---

### B3. 污染物转化缺少明确提示

**现状**：当防御 slot 中的污染物充能满 3 次后转化为工具，`contaminantSystem` 触发了事件，但 UI 端没有任何视觉反馈告诉玩家"你的固化残渣已变成凝锁工具"。

**改进方向**：冲击结算面板后（或内嵌在 `impact-result-panel` 中）展示转化结果："固化残渣 -> 凝锁 (工具，x5 次)"。

**复杂度**：低  
**体验影响**：中（循环最满足的一刻被静默跳过）

---

## C. 效果感知缺失

### C1. 改造购买后无即时反馈

**现状**：`growth-panel` 中点击升级后，面板数字更新了，但没有任何确认动画/音效/文本闪烁。"我花了 12 薪柴"但"变强了吗？"的感受缺失。

**改进方向**：升级成功时：① 数字短暂高亮/弹跳；② 面板顶部显示一句效果变化（如"+4% 渗透抗性 -> 当前 8%"）；③ 可选：屏幕边缘短暂闪光。

**复杂度**：低  
**体验影响**：中（成长循环的即时奖励感）

---

### C2. 模块修复后效果变化不可察觉

**现状**：`allocation-panel` 中已经有"修复后效果"预览文字（做得不错），但确认修复后回到场景中，模块视觉上没有变化（HP 条更新了，但效果值在哪里看？）。

**改进方向**：①修复确认后模块短暂发光/颜色变化；②模块实体上常驻显示当前效果值（与 A3 联动）。

**复杂度**：低  
**体验影响**：中

---

### C3. 裂隙内工具使用后缺少"生效"反馈

**现状**：按 Q/F 使用工具后，HUD 的剩余次数更新了，但工具效果本身（凝锁定身敌人/时裂减速/侵蚀领域伤害）是否生效，玩家只能通过观察敌人行为间接判断。

**改进方向**：①使用时在目标位置/角色周围出现短暂的视觉效果（范围指示/着色闪烁）；②HUD 显示一行短暂的状态文本（"凝锁: 3s"）。

**复杂度**：中（需要 per-tool 效果实现）  
**体验影响**：高（工具是"变强"的核心体现）

---

### C4. 裂隙返回净化点后无"收获总结"

**现状**：裂隙结束面板只显示"撤离成功 / 薪柴: N / 峰值混乱: N / 用时: Ns"。但这次出击的完整收获（薪柴、拾取了哪些污染物、击杀数）没有汇总。更重要的是：回到净化点后没有"这些收获怎么用"的引导线索。

**改进方向**：①丰富裂隙结束面板：增加"拾取污染物"列表、击杀数；②到达净化点时，如果薪柴>0，简短提示当前各模块状态和建议行动方向。

**复杂度**：中  
**体验影响**：高（session 闭环感）

---

## D. 系统割裂感

### D1. 净化点交互点之间无导航线索

**现状**：5 个交互点（CORE模块、STORAGE模块、裂隙入口、防御配置、改造祭坛）是 5 个孤立的发光圆/方块。玩家不知道"我该先去哪个"，也不知道"还有哪些我没访问过"。

**改进方向**：①净化点 HUD 增加简明的交互点方位提示（如小箭头或列表）；②首次进入净化点时显示"设施巡视"提示；③交互点在有新内容时（如有新转化工具可装备）给出脉冲或标记。

**复杂度**：中  
**体验影响**：中

---

### D2. "冲击->防御->转化->工具"循环不可视

**现状**：这是游戏最核心的正向循环，但玩家必须自己在脑中拼接。防御面板中的 `impactCharges: 2/3` 这个数字是唯一线索，且没有说明它充满后会怎样。

**改进方向**：①防御面板中的充能条旁加一句 tooltip（"满3次转化为出击工具"）；②冲击结算时明确展示充能进度变化（"固化残渣: 2/3 -> 3/3 -> 已转化!"）。

**复杂度**：低  
**体验影响**：高（核心循环的"啊哈"时刻）

---

### D3. 各面板视觉风格不统一

**现状**：`allocation-panel` 用英文标签 "Confirm/Cancel/Available Kindling"；`defense-panel` 用中文"防御配置/卸下"；`growth-panel` 用混合。面板之间没有统一的信息层级、按钮风格、颜色体系。

**改进方向**：统一所有 DOM 面板的：①语言（全中文或全英文，不混合）；②配色方案（各系统有主题色，但按钮/背景/边框统一）；③信息排布模式（标题/状态/操作区 三段式）。

**复杂度**：低（纯文本/样式修改）  
**体验影响**：中（"一个游戏"而不是"五个工具窗口"）

---

### D4. 净化点与裂隙之间缺少"过渡叙事"

**现状**：出击 = 点确认后瞬间切场景。返回 = 按 R 后瞬间切场景。没有任何过渡画面/文字/动画来标记"你正在穿越裂隙"这个在世界观中重大的事件。

**改进方向**：①极短的过渡屏（0.5-1s 黑屏 + 一句环境文本，如"裂隙坍缩。回到净化点。"）；②出击时可用 fade-out + 裂隙主题色闪烁。

**复杂度**：低  
**体验影响**：中（仪式感，支撑体验支柱 3"孤独的仪式感"）

---

## E. 节奏反馈缺失

### E1. 潮汐阶段转换无提示

**现状**：从 Rise 进入 Crest 或从 Crest 进入 Ebb 时，`tideSystem.advanceCycle()` 更新了状态，但玩家只有下次看 HUD 文字才会注意到变化。"潮峰来了"这个关键节奏点没有任何戏剧性。

**改进方向**：阶段转换时在冲击结算后追加一行高亮文本（"警告: 潮峰期 - 冲击强度将维持在峰值"），或更换边界氛围的颜色/强度。

**复杂度**：低  
**体验影响**：高（潮汐系统的核心价值 = 节奏感，无提示则无节奏）

---

### E2. "首次购买改造"无里程碑感

**现状**：第一次买到改造（从 0 级变 1 级）和后续升级体验完全一样——面板里数字变了。但"我第一次改造了自己"应该是一个重要时刻。

**改进方向**：首次购买任意改造时，触发一个特殊的全屏简短反馈（如边缘闪光 + 一行文字："永久改造已刻入"）。后续升级则用较轻的反馈。

**复杂度**：低  
**体验影响**：中（成长循环的"第一口甜头"）

---

### E3. 稳定度达到里程碑无提示

**现状**：稳定度条从 0% 默默增长到 100%，中间没有任何里程碑反馈（如 25%/50%/75%）。玩家不知道自己"离目标还有多远"。

**改进方向**：稳定度每到达 25% 倍数时给一行简短提示文字；到达 100% 时给一个明确的完成信号。

**复杂度**：低  
**体验影响**：中（长期目标的进度可见性）

---

## "现在做"项目的实现方案方向

### A2: 净化点薪柴常驻显示

**做什么**：在 `PurificationScene` 创建时，像裂隙 HUD 那样在屏幕右上角固定显示 `kindlingReserve` 数字。每次面板关闭后刷新。

**怎么做**：在 `purification-scene.ts` 的 `create()` 中加一个 `Phaser.GameObjects.Text`（scrollFactor 0, depth 100）。用 `gameState.getKindlingReserve()` 取值。在面板关闭回调中调用 update 方法刷新。

---

### A5: 出击属性预览

**做什么**：`loadout-panel` 的确认按钮上方增加一块"本次出击属性"区域。

**怎么做**：在 `loadout-panel.ts` 的 `render()` 末尾（confirm 按钮之前）插入一段 HTML。数据来源：`gameState.getSortieModifiers()` 得到 chaosRateModifier 和 kindlingValueModifier；`growthSystem.getLevel('growth_vitality')` 算出 HP 上限。格式：

```
---
本次出击:
  HP 上限: 130 (基础100 + 改造30)
  混乱增速: x0.82 (核心-12% + 改造-8%)
  薪柴价值: x1.35 (储藏+35%)
---
```

---

### B2: 污染物效果描述

**做什么**：在 defense-panel 和 loadout-panel 中每个污染物名称下方增加一行灰色小字描述效果。

**怎么做**：创建一个 `CONTAMINANT_DESCRIPTIONS` 映射（`Record<ContaminantType, { defense: string; tool: string }>`），遵循 world.md 叙事语调（<15字简述）。示例：

```typescript
solidify: { defense: '冲击时减伤固定值', tool: '凝锁: 定身目标 3s' },
delay:    { defense: '冲击时减伤固定值', tool: '时裂: 大范围减速 4s' },
erode:    { defense: '冲击时减伤固定值', tool: '侵蚀领域: 区域持续伤害' },
```

在 render 中追加一行 `<div style="font-size:10px;color:#666;">...</div>`。

---

### D2: 充能->转化可视化

**做什么**：在 `impact-result-panel` 中，除了显示模块受损信息外，增加防御 slot 的充能进度变化和转化事件。

**怎么做**：
1. 在 `impactSystem.run()` 返回值中追加 `chargeChanges` 数据（每个 slot 的 before/after/transformed 状态）
2. `impact-result-panel` 的 `show()` 接收该数据并在伤害列表下方追加：
   - "Slot 1: 固化残渣 2/3 -> 3/3 [已转化为凝锁!]"
   - "Slot 2: 延时残渣 1/3 -> 2/3"

---

### D3: 面板语言统一

**做什么**：将所有面板中的英文标签替换为中文。

**怎么做**：全局搜索替换：
- `"Confirm"` -> `"确认"`
- `"Cancel"` -> `"取消"`
- `"Available Kindling"` -> `"可用薪柴"`
- `"CORE (Chaos Reduction)"` -> `"核心 (混乱抑制)"`
- `"STORAGE (Kindling Bonus)"` -> `"储藏 (薪柴增幅)"`
- `"HP:"` 保持（或改为 `"完整度:"`）
- `"E - Enter Rift"` -> `"E - 进入裂隙"`
- `"E - Allocate"` -> `"E - 分配"`
- 其他零散英文标签

---

### E1: 潮汐阶段转换提示

**做什么**：当潮汐阶段从 rise->crest 或 crest->ebb 或 tide 递进时，在 impact-result-panel 后追加一个短暂的全屏提示。

**怎么做**：
1. `tideSystem.advanceCycle()` 返回值增加 `phaseChanged?: { from: TidePhase; to: TidePhase; newTide?: number }` 字段
2. `purification-scene.ts` 在调用 `advanceCycle()` 后检查该字段
3. 若有阶段变化，在 impact-result-panel 关闭后显示一个简短 DOM overlay（1.5s 自动消失）：
   - rise -> crest: "潮峰期。冲击强度将维持峰值。"（红色调）
   - crest -> ebb: "退潮。冲击强度逐步降低。"（绿色调）
   - tide 递进: "第 N 潮。压力上升。"（紫色调）

---

## 设计原则提醒

- 以上所有改动的核心约束：**不增加系统复杂度，只增加信息层和反馈层**
- 所有面向玩家文本遵守 `docs/world.md` 叙事语调：冷峻克制、无感叹号、功能描述式
- "决策 > 操作"铁律：展示的信息必须服务于某个决策（不是为了展示而展示）
- indie 规模约束：每项可独立实现、独立验证，不需要连锁改动
