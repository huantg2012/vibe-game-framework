## S1 主菜单

**文件**：`src/scenes/main-menu-scene.ts`（Phaser Text）。i18n：`src/i18n/locales/zh-CN.ts`。

1. **玩家问题**：上次玩到哪、继续回到什么、新纪录毁掉什么。上屏：游戏名「存续」、副题「边界仍在，光尚未熄」、有档时「读取存档」、覆盖文案「将清除第 N 潮的全部记录」。**缺存档摘要** → 「继续会回到什么局面」仍无标签。
2. **P0 ≤6**：两项入口 + 标题，不超。决策信息（潮汐/出击次数/净化%）误留在屏外，等于进了不存在的 P2。
3. **分开展示**：覆盖警告是一句完整陈述，可读。入口标签「新存档」「读取存档」本身是软件复合词。
4. **打开/打断**：进标题场景即出现。无战场。有档时选「新存档」才进二次确认（1 条，符合 IA）。Enter/空格走游标项，**不再静默删档**（IA 旧「最严重」已不成立）。
5. **CRT**：非 S3–S8，无磷光屏合同。
6. **假选择**：无。覆盖确认写明会丢第 N 潮，是真后果。
7. **术语**：已去掉 `COH` / `Prototype Build` / `Continue`。现用「新存档 / 读取存档 / 清除并新建」——「存档」未入术语表，是软件词。i18n 另有未接线的 `menu.newGame`「进入净化点」、`menu.continue`「沿旧路返回」。IA 口径是「继续 / 新的纪录」。Esc 记录菜单里「继续」= 合上菜单，与标题「读取存档」不是同一动作。
8. **分级**：**P1** 无存档摘要；**P2** 入口用软件词、未接已有世界向文案。挂载：Phaser 场景字，不挂 `#dom-ui-root`（architecture 屏幕空间约定的例外，结构层记下）。

## S2 净化点常驻 HUD

**文件**：`src/ui/dom/purification-hud.ts`。挂 `#dom-ui-root`。不套 `.game-panel`（D3/D7）。

1. **玩家问题**：薪柴多少、下次打谁多重何时、整体往哪走、能做什么。薪柴/潮汐/下次归来在贴顶三槽。稳定度不在本层（D7）。「能做什么」在底栏，走近才改写。
2. **P0 ≤6**：三槽（+ 消声第四槽）≤4。决策用的预告在 P1。稳定度未误加回。
3. **分开展示**：三槽表名/值/档位分 span（`薪柴` `12`；`潮汐` `第 N 潮` `涨潮`；`下次归来` `核心` `中等`）。消声时机词是「再下一轮」。无 HUD 上的 ◇/◈/▣/波形/pip/`·`（DEC-047/048）。底栏走近仍是 `◈ 核心` / `▣ 储藏`（合同：本批不改底栏）。裂隙入口细节 `第N次出击 · 强度 x1.6`：**粘句** + 「强度」与结算「冲击」不是同一套词。
4. **打开/打断**：进净化点即出现，无按键。贴顶靠右，不居中。CRT 机身 `top:52px`，HUD `top:10px`，合同上不盖三槽。
5. **CRT**：本表面不是六块之一。六块打开时三槽应仍露在屏顶——壳的 top 值支持这一点；是否真露得出是人眼看的事。
6. **假选择**：无。
7. **术语**：核心/储藏/潮汐三态/四档与术语表及 `SEVERITY_LABEL` 一致。底栏符号不是术语。
8. **分级**：三槽合同 **已落地**（相对 IA 旧「符号网格」）。**P2** 底栏裂隙行粘句与「强度」词。审美/是否像装置 → 人终审。

## S3 分配（注入）

**文件**：`src/ui/dom/allocation-panel.ts`。`createCrtPanel`。

1. **玩家问题**：模块多惨、修好给什么、投 N 值不值、还剩多少、是不是下次挨打的。模块名、完整度条+预览、当前→注入后效果、投入/储备/注入后剩余、机会成本三簇（另一模块完整度 / 蜕变最低 / 是否本模块）均在。**缺** IA 状态文案「完整度已满」「储备 0 · 需要出击」：满或储备 0 时 Enter 无事发生、无缺口陈述。
2. **P0 ≤6**：本屏是唤出终端，P1 项偏多但都是本屏决策用。P2「修复效率来源分解」（基础 4 · 虹吸残渣 x2）**未上屏**，只在有虹吸时标「虹吸增效」。
3. **分开展示**：完整度数字与 `/` 分节点；效果表名与两档数值分开。机会成本三簇分栏。`1薪柴=4完整度` 与「虹吸增效」是粘句。
4. **打开/打断**：走近核心/储藏按 `E`。磷光屏 680×468 居中偏上，四周漏场景。Esc 离开。阻断确认 0（注入即生效并关）。键盘 ←→ / Shift / Home End / Enter 已接。
5. **CRT 分区 vs src**：合同要上（身份）/ 中（投入）/ 下（机会成本）固定区。src 把上述全部放进单个 `.scroll-area`。P1 字段在，**分区合同未覆盖**。库存类溢出时机会成本可能被卷走。
6. **假选择**：无。机会成本是把已有三出口（修这边 / 修那边 / 蜕变）摊开，不是发明权衡。
7. **术语**：「注入」「完整度」「储备」「蜕变最低」；「虹吸增效」不是残渣权威名（CSV 防御名「噬化残渣」类，工具侧才有虹吸词根）。模块效果用「混乱增速 -N%」，与 S5「混乱率 x0.xx」、S6「混乱抗 N%」仍是同一概念三套说法（D4 未收口）。
8. **分级**：**P1** 无「满/储备 0」缺口陈述；CRT 上中下未分区。**P2** 效率分解、粘句换算行。

## S4 供奉

**文件**：`src/ui/dom/defense-panel.ts` + `inspect-dock.ts`。

1. **玩家问题**：四槽装了什么、挡什么、代价、还差几次转化、库存哪件该装。槽上已有：名、★、减伤%、充能 n/3、→ 工具名、还需 N 次、副作用一句。库存行：名、★、类别、减伤%。检视 L1–L5 随游标。空槽检视走 `INSPECT_EMPTY_HTML`「移动光标查看详情」，**不是**合同的 `空 · 可装填`（槽面上有「空/可装填」）。
2. **P0 ≤6**：唤出屏。槽上三行代价/转化是 P1，未推进检视当唯一出处。
3. **分开展示**：槽内减伤表名与 % 分开。检视 L1 `名 ★ · 防御 · 类别`、L3 `减伤 N% · 充能 n/3`、L5 `还需 N 次冲击 → 【工具】：摘要` **朗读会成一句**。
4. **打开/打断**：走近供奉 `E`。Esc 离开。Tab 切区。**结构伤**：仍有看不见的 `actions` 区；Tab 进去后 Enter = 关面板，底栏却始终写「Enter 装填/取下」。阻断确认 0。
5. **CRT 分区 vs src**：合同上=四列槽（固定）、中=库存（可裁切）、下=检视 5–6 行固定。src：槽+库存同在 `.scroll-area`，检视在滚动区外（高度 `min-height:88px`，合同约 110）。**槽区不保证不被卷走**。
6. **假选择 / R1**：没有「装防御或留着当工具」的选项。L5 写自动转化事实。符合 D9「只讲清、不假装纠结」。玩家仍可能把「→ 凝锁」读成当下可点的二选一——那是机制观感，等人试玩，不在本轮改机制。
7. **术语**：防御/工具名走 CSV。类别词来自 CSV（纯减伤/经济收益/…），未入术语表。空态「无可用残渣」；「残渣」未入表。
8. **分级**：**P0** 仍受 L2 截断拖累（「每件做什么」在槽上靠副作用原句 + 截断摘要）。**P1** 隐身 actions 区、检视粘句、CRT 上区不固定。

## S5 踏入裂隙

**文件**：`src/ui/dom/loadout-panel.ts`。

1. **玩家问题**：带哪 4 件、做什么、剩几次、哪个键、出击属性、身上挂什么。槽：键位、CSV 工具名、余量、截断摘要。库存：名、★、主动/被动、余量。三项属性。既有残留行（表名 / 种类 / 数值 / ←来源）。**缺**属性来源分解（P2：核心 vs 渗透抗性）。无工具时「无可用工具」，不是 IA 的「工具来自防御槽的转化」。
2. **P0 ≤6**：决策用的残留已从 toast 提前到本屏 P1。来源分解仍在屏外。
3. **分开展示**：槽内余量表名与数字分开。残留节点大体分开。摘要是截断长句。检视同 S4 粘句。
4. **打开/打断**：走近裂隙入口 `E`。底栏**同时**印「Enter 装/卸/确认」与「Enter 踏入」。合同：踏入只在动作区焦点时。现在两条 Enter 常驻，焦点在槽区时 Enter 卸装，不是踏入。Esc 离开。无「还是算了」主按钮排（`.action-bar { display:none }`）。
5. **CRT 分区 vs src**：合同上槽 / 中上属性 / 中残留 / 中下库存裁切 / 下检视固定。src：槽+属性+残留+库存同卷，检视在外。P1 不固定。
6. **假选择**：踏入 vs 离开是真决定。槽位装不满时没有假权衡（R2 内容密度，不是本屏发明的纠结）。
7. **术语**：工具名与 CSV 一致（IA 旧 D2 本地名表 **已不成立**）。出击三项仍叫「完整度 / 混乱率 / 薪柴值」——「完整度」与模块条同名（S15 类别 4）。
8. **分级**：**P0** 槽摘要仍不是 ≤15 字机制句，验证句 ① 在本屏只答了一半。**P1** 双 Enter、CRT 分区、无转化来源空态。

## S6 存续报告

**文件**：`src/ui/dom/status-panel.ts`。Tab 打开（无其它面板时）。

1. **玩家问题**：整体状态、买过哪些改造、库里什么、在哪阶段。两模块条+效果、四属性、潮汐三节点、稳定度陈述（无条）、改造徽章、库存分组、检视。已碎仍逐条列名（IA 要聚合计数）。
2. **P0 ≤6**：本屏 P1 是模块+属性+潮汐+稳定度。库存是 P2，有检视。

1. **玩家问题**：有哪些、做什么、买得起、买了变什么、满了吗。六卡：名、点阵、当前→下一级（0 级也给出下一级）、费用或「还差 N」、满则「已至上限」。无 `MAX`。

## S8 冲击结算

**文件**：`src/ui/dom/impact-result-panel.ts`。

1. **玩家问题**：多重打谁、防御做了什么、哪件转化、下次背什么、预判对了吗。强度表名+倍率+档位；每模块基础→实际；逐槽挡下/返还等；充能与转化（无感叹号）；本次残留；预告 vs 实际（P2）；潮汐/里程碑并入段。十项披露的主路径已接线。
2. **P0 ≤6**：唤出阻断屏，P1 项多但是本屏唯一职责。预告对照在更暗段，符合 P2。
3. **分开展示**：基础/实际分节点。挡下两行分开。`buildSlotFacts` 的 `equalizationAmount` 文案是 **「HP 均摊」**（英文缩写）。相位并入句「第N潮汐。边界压力上升。」把「第 N 潮」粘成「第N潮汐」。
4. **打开/打断**：归来自动。Enter/Esc 合上，**一条阻断**（D5）。合上后 `showNewToolToast` 是通道 B，不再二次「知道了」。无「知道了」按钮。
