## A. 完整度

### 上屏词

**完整度** = 玩家这条量（出击可损耗）。

| 位置 | 表名 | 数值 | 禁止 |
| ---- | ---- | ---- | ---- |
| 裂隙 HUD | 完整度 | 当前（上限若有则另节点） | `HP`、生命值、状态 |
| 踏入三项 | 完整度 | 出击上限 | 同上 |
| 存续中区 | 完整度 | 出击上限 | 同上；不要加「躯壳」 |
| 蜕变效果行 | 完整度 | `+N` | 不要把卡名改成量名 |

i18n：`hud.health.label` 现为「状态」→ **完整度**。英文 **Integrity**（对齐「未被完全覆盖」）。接线 HUD，禁止继续硬编码 `HP`。

HUD 一行放得下「完整度」三字，**不加「躯壳」**。若 art 核完字宽放不下，升级给人，不要擅自缩回 HP。

### 模块耐久（保持）

模块不是玩家那条量。限定词已经在用，保持：

- 机会成本行：`核心完整度` / `储藏完整度`（表名带限定 + 独立数字）
- 分配条、存续模块框：身份「核心」「储藏」与表名「完整度」分节点；`43/100` 拆成当前、上限两个节点

同屏两处「完整度」靠**身份节点**区分（核心 / 储藏 vs 无模块身份的那一行 = 玩家），不加「躯壳」。

### 「生命强化」

**保留卡名**（仪式名，不是量名）。效果行继续 `完整度 +N`。

0 级风味现为「强化躯壳」→ 改为 **「延缓覆盖」**（不上量名、不含躯壳）。满级/当前→下级格式不变。

### 「HP 均摊」（stitch）

机制不变：冲击伤害算完后，在模块之间把完整度差额的 20% 推向均值。`equalizationAmount` = 转移量。这是**模块**完整度，不是玩家那条。

现实现把效果写成无数字的「HP 均摊」。锁定：

| 节点 | 词 |
| ---- | -- |
| 表名 | 均摊 |
| 数值 | `{equalizationAmount}` |
| 禁止 | HP、生命值、把「完整度均摊」粘成一句无数字的效果词 |

与 scatter 的「伤害均摊」不是同一件事（一个分伤害，一个事后拉平模块完整度）。scatter 维持「伤害均摊」。本轮不改公式。

### 给 code 的替换表（玩家可见）

| 查找（玩家可见） | 换成 | 文件线索 |
| ---------------- | ---- | -------- |
| 裂隙 HUD 标签 `HP` | 完整度 | `rift-hud.ts`；接 `t('hud.health.label')` |
| `hud.health.label`「状态」/ `Status` | 完整度 / Integrity | `zh-CN.ts` / `en.ts` |
| 「HP 均摊」 | 表名「均摊」+ 数值 `equalizationAmount` | `impact-result-panel.ts` `buildSlotFacts` |
| 玩家可见「生命值」「HP」（HUD/结算标签） | 完整度 | Grep `src/ui` `src/scenes` `src/i18n`；**不要**改 F1 调试、注释、内部字段名 `hp`/`maxHealth` |
| 「生命强化」 | **不改** | 只改效果行/风味，见上 |

## B. 主菜单（人授权改内容）

载体 **C**。允许软件感。**禁止**：存档、读取、确认、OK、New Game、Continue、Save。

游戏名 / 副题保持：`存续` / `边界仍在，光尚未熄`。EN：`Enduring` / `The boundary holds. The light has not gone out.`

### 无记录：唯一入口

**进入净化点**  
EN: **Enter the Purification Point**

只这一项。不要灰掉的第二项。不要「新的纪录」（没有旧纪录可覆盖）。接线已有未用的 `menu.newGame`。

### 有记录：默认入口 + 摘要

默认游标：**沿旧路返回**  
EN: **Return by the old path**  
接线已有未用的 `menu.continue`。动作 = `loadExpedition`。

第二项：**新的纪录**  
EN: **Begin a new chronicle**  
动作 = 现 `onSelectNewSave`（有纪录则进覆盖确认）。改 `menu.newSave` 的可见字符串。

### 存档摘要（P1，分节点，禁止粘句）

IA 旧例 `第 N 潮 · 涨潮 · 第 M 次出击 · 净化 X%` **作废**（`·` 粘成一句）。做成与净化点 HUD 潮汐槽同构的独立节点：

| 表名 | 数值 | 档位 | 来源 |
| ---- | ---- | ---- | ---- |
| 潮汐 | 第 N 潮 | 涨潮 / 潮峰 / 退潮 | `tide.tideNumber` + `tide.phase` |
| 出击 | M | （无档位） | `SaveDataV1.cycle`（踏入裂隙时 +1，可为 0） |
| 稳定度 | N% | 未完成 / 已完成 | `stability.progress` + `stability.reached` |

不要上屏「净化%」「净化进度」。长期进度的词是「稳定度」。

摘要只在**有可读纪录**时出现，贴在「沿旧路返回」旁或正上方，不进覆盖确认屏。无纪录不画空摘要。

### code 必须新增的 peek

`peekTideNumber()` 保留（覆盖警告仍用）。禁止 `load()` 进标题。再加无副作用 JSON peek（坏数据 = 与现实现相同：当作无纪录，本轮不新做「记录无法读取」专态）：

| 方法 | 返回 | 字段 |
| ---- | ---- | ---- |
| `peekTidePhase()` | `'rise' \| 'crest' \| 'ebb' \| null` | `data.tide.phase` |
| `peekCycle()` | `number \| null` | `data.cycle` |
| `peekStability()` | `{ progress: number, reached: boolean } \| null` | `data.stability` |

允许收成一个 `peekRecordSummary()`，但四字段都要有。不要 peek 模块 hp / 薪柴 / 库存（本屏不需要）。

相位词与净化点 HUD 同一张表：`rise→涨潮` `crest→潮峰` `ebb→退潮`。EN：Rising / Crest / Ebb。

### 覆盖确认

警告**保留**：`将清除第 {tideNumber} 潮的全部记录`  
EN 保留语义：`This will erase all records of Tide {tideNumber}.`

执行项：`清除并新建` → **清除后进入**  
EN: **Enter after erasure**  
不要「确认」。

另一项：**沿旧路返回**（默认游标，与有纪录根菜单同一字符串）。Esc 回到根菜单。

### 暂停菜单（Esc「记录」）三项

与标题**不是同一套动作**：标题没有「合上」；暂停的「沿旧路返回」会丢掉当前场景（裂隙中 = 结束本次出击）。

| 项 | 中文 | EN | 动作 |
| -- | ---- | -- | ---- |
| 清档 | 新的纪录 | Begin a new chronicle | 有纪录则覆盖确认，否则 `beginNewExpedition` |
| 读档（有纪录才出现） | 沿旧路返回 | Return by the old path | `loadExpedition` |
| 合上菜单（默认游标） | **合上** | **Remain** | `pauseMenu.close()`，场景原样 |

禁止暂停再用「继续」（软件 Continue，且会与标题入口撞车）。标题「沿旧路返回」≠ 暂停「合上」。

覆盖确认警告与标题同一句。键印去掉「选择 · 确认」：

`↑↓ 选中`　`Enter`　`Esc 合上`（覆盖态 Esc = 返回根项）

三个节点分开，不用 `·` 粘。

## C. 其它上屏软件词 / 错名

| 位置 | 现状 | 锁定 |
| ---- | ---- | ---- |
| 裂隙结算拾取列表 | `getToolName` | **`getDefenseName`**（进库存是 `stage: 'defense'`） |
| 裂隙结算被动触发 | `getToolName` | **保持 `getToolName`**（已是工具阶段） |
| 裂隙结算计数标签 | 污染物 | **残渣**（本行计的是本趟拾取件数，不是击杀）。击杀行保持「击杀」 |
| 存续报告空态 | 尚无污染物 | **尚无残渣** |
| 存续分组标题「库存」 | 软件词 | **删掉「库存」**。分组标题：残渣 / 工具 / 已碎。底栏「浏览库存」→ **浏览** |
| 蜕变底栏 | 购买 | **刻入**（薪柴换永久改造；toast「已刻入」已存在）。不要用「注入」（注入 = 薪柴进模块） |
| 失焦层 | 已暂停 / 点击继续 | **已暂停** + **按任意键**。不要「点击」，不要「继续」 |
| 开机 | Loading... | **载入** |
| 裂隙 HUD 薪柴 | `◇ N` 无表名 | 表名 **薪柴** + 数字（`hud.kindling.label` 已有）。不要 ◇ |
| 裂隙结算薪柴行 | 已有表名「薪柴」但仍 `◇ N` | 数字不要 ◇ |
| 检视空态 | 移动光标查看详情 | **空**（S4 槽面已有「空/可装填」则检视跟槽面，不要「详情」） |
| 冲击里程碑 | 净化进度 N%。 | 表名 **稳定度** + 数值 N%（已过半可另节点「已过半」，不要粘进「净化进度」） |
| 暂停键印 | 选择 · 确认 | 见 §B |

「污染物」禁止再上屏。敌人统称是「污染体」；可捡物是「残渣」。不要把计数改成「污染体」（那会变成击杀）。

### 混乱增速：三种写法收成一种（不改机制）

同一出击速率，三处三种说法。数值公式不动，只改可见写法。

**锁定**：表名一律 **混乱增速**。数值一律相对基础 1.0 的百分增减：变慢写 `-N%`，变快写 `+N%`。

| 现状 | 锁定 |
| ---- | ---- |
| S3 `混乱增速 -N%` | 保持（已合规） |
| S5 `混乱率` `x0.xx` | 表名混乱增速；数值 `round((1-rate)*100)` 带符号的 `%` |
| S6 `混乱抗` `N%` | 同上（中区是合计；模块框那行已是混乱增速，保持） |
| 生效中 `混乱增速 x1.5 (5s)` | 表名混乱增速；数值 `+50%`；时长 `5s` 另节点 |

禁止表名：混乱率、混乱抗。禁止玩家可见的裸 `x0.xx` 当这条属性的主写法。

HUD 档位词保持：稳定 / 渗透 / 侵蚀 / 临界（与表名「混乱」分开展示）。「稳定」≠「稳定度」。

## D. 给 code 的验收句（十条）

1. 裂隙 HUD 玩家那条量的表名是「完整度」，不是 HP、生命值、状态。
2. 冲击结算 stitch 行是「均摊」+ 数字，没有 HP。
3. 蜕变卡仍叫「生命强化」；效果行是「完整度 +N」；底栏是「刻入」不是「购买」。
4. 无纪录主菜单只有「进入净化点」；有纪录默认「沿旧路返回」，旁有潮汐 / 出击 / 稳定度三个分开展示的节点，没有「存档」「读取」「Continue」。
5. 覆盖警告仍是「将清除第 N 潮的全部记录」；执行项是「清除后进入」，不是「确认」。
6. Esc 记录菜单三项是「新的纪录」「沿旧路返回」「合上」；默认在「合上」；没有「继续」。
7. 裂隙结算拾取名单是残渣阶段名；计数表名是「残渣」；被动触发才用工具名。
8. 存续空态是「尚无残渣」；没有「污染物」「库存」。
9. 失焦副句是「按任意键」；开机是「载入」；裂隙 HUD 薪柴有表名「薪柴」且无 ◇。
10. 踏入 / 存续 / 分配里这条速率都叫「混乱增速 -N%」或「+N%」，没有「混乱率」「混乱抗」。

玩家仍不应看到：被发现指示；「选防御或选工具」的假按钮。F1 调试内部字段名不在本合同。
