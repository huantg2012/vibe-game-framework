# UX 信息架构：全表面（Slice 5.5）

> **TL;DR**：15 个表面逐一定义"玩家在这里要回答什么问题 → 必须显示什么 → P1/P2/P3 分层 → 游戏语义状态 → 键盘交互"。四处重点：裂隙 HUD 的 P1 信息集、键盘可达的检视层、反馈感知矩阵、术语偏差清单。文末给 U1-U12 结构层自查、结构性风险清单（UX 修不了的问题）、应就地扩写的 spec 清单。

---

## 0. 读法与边界

### 0.1 本文的判断依据

按优先级：`docs/vision.md` 核心体验 → `docs/world.md` 术语表与叙事语调 → 各 `system-*.md` 的规则 → `docs/specs/_template-ui.md` 的 U1-U12。

三根体验支柱决定信息优先级的排序原则：

| 支柱 | 对 IA 的含义 |
| ---- | ------------ |
| 绝望边缘的紧绷 | 资源与威胁必须**常驻**可见，不能靠玩家主动查询。玩家忘记压力 = 支柱失效 |
| 贪婪与撤退的博弈 | 裂隙内每个决策点必须能立刻读到"再多待一会儿的代价"与"现在收手的收益" |
| 孤独的仪式感 | 重复动作（分配、供奉、踏入）要有**结果的重量**，不能做成表单提交后的静默返回 |

### 0.2 优先级分层的定义（本文口径）

| 级别 | 定义 | 预算 |
| ---- | ---- | ---- |
| **P1 常驻可见** | 不按任何键、不走近任何东西就在屏幕上 | **裂隙 ≤6 组、净化点 ≤4 组**。屏幕空间是有限资源，什么都 P1 等于什么都没有 |
| **P2 唤出可见** | 按一个键 / 走近装置 / 键盘游标停在某项上即出现，不需要二级操作 | 无硬上限，但一次唤出的内容要能一屏读完 |
| **P3 深挖查看** | 玩家主动进入某个查看态才可得 | 只放"解释性"信息，不放决策必需信息 |

> **与模板的口径差异（需 Director 知悉）**：`_template-ui.md` 的信息层级表用 P0/P1/P2。本文按 Director 指派用 P1/P2/P3。映射关系：本文 P1 = 模板 P0，本文 P2 = 模板 P1，本文 P3 = 模板 P2。**建议后续把模板改成 P1/P2/P3**——"P0"在软件工程语境里意味着"最高优先级 bug"，与"始终可见"是两码事，实测已经造成过一次误读。

### 0.3 状态命名的强制词表

全项目禁止在 UI 状态命名与文案中出现：`hover / active / disabled / enabled / selected(作为文案) / 提交 / 确认 / 设置 / 物品栏 / 保存成功 / OK`。

统一采用下面这套游戏语义状态名。**"不可用"必须表达缺什么**：

| 状态 | 触发条件 | 文案要求 |
| ---- | -------- | -------- |
| 静默 | 无关联事件 | 默认表现，不占注意力 |
| 可交互 | 玩家进入触发范围 / 该项可被操作 | 显示按键 + 动作 + 该对象的关键读数 |
| 已选中 | 键盘游标停在该项 | 必须与"可交互"视觉可区分（art 层）；被选中项的检视信息**同步填充检视区** |
| 缺 X | 前置条件不满足 | 写出**缺什么、缺多少**：`薪柴不足 · 还差 6`、`槽位已满 · 先取下一件`、`无可指向的目标` |
| 临界 | 濒危阈值 / 下次冲击目标 / 下次冲击即转化 | 必须有除颜色外的第二重编码（形状/符号/位置） |
| 已耗尽 | 次数归零 / 完整度满 | 不是灰掉，是明确陈述：`已耗尽，不可恢复` / `完整度已满` |

### 0.4 键盘是第一公民

**现状最大的系统性缺陷**：`allocation` / `defense` / `loadout` / `growth` / `status` 五个抽屉面板的全部内容操作都只绑定了 `click`，键盘只绑定了 `Escape`。玩家在净化点用 WASD 走路、按 E 开面板，然后**必须放下键盘去摸鼠标**。这一条同时违反 U7 和"仪式感"支柱——它把游戏行为切换成了办公行为。

全项目统一键位契约（所有面板一致，提示的键必须与实际绑定一致）：

| 操作 | 键 | 说明 |
| ---- | -- | ---- |
| 在当前区内移动游标 | `↑ ↓ ← →` | 网格区用四向，列表区用上下 |
| 在区之间切换 | `Tab` | 槽区 ↔ 库存区 ↔ 动作区 |
| 执行主动作 | `Enter` | 装填 / 取下 / 注入 / 购买 / 踏入 |
| 调整数量 | `← →`（±1）/ `Shift + ← →`（±5）/ `Home End`（0 / 最大） | 仅分配面板 |
| 离开 | `Esc` | 全局一致 |
| 存续报告 | `Tab`（在净化点无面板时） | 与面板内的 Tab 不冲突：有面板时 Tab 是切区 |

面板底部固定一行**键位提示条**，列出本面板当前可用的键（内容随焦点区变化）。这是共享样式层必须新增的结构基元（见 S9）。

## 1. 逐表面信息架构

### S1 主菜单

**玩家要回答**：上次我玩到哪了？继续会回到什么局面？重新开始会毁掉什么？

**必须显示**：游戏名、存档摘要、两条入口及其后果。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 游戏名 | — |
| P1 | 存档摘要：`第 N 潮 · 涨潮 · 第 M 次出击 · 净化 X%` | 这是"继续"按钮的真正标签。没有它，"继续"只是一个动词 |
| P1 | 两条入口：继续 / 新的纪录 | 有存档时"继续"是默认游标位置 |
| P2 | 语言、音量（尚未存在；建立时归此层） | — |

**状态**：

| 状态 | 条件 | 表达 |
| ---- | ---- | ---- |
| 无记录 | 无存档 | 只有"新的纪录"一项；不显示灰掉的"继续" |
| 有记录 | 有存档 | "继续"为默认游标位置，附存档摘要 |
| 记录损坏 | 读档失败 | `记录无法读取`，并明说"新的纪录将覆盖它" |
| 覆盖确认 | 有存档且游标在"新的纪录" | **必须二次确认**并写明会丢失什么：`将清除第 N 潮的全部记录` |

**交互**：`↑ ↓` 选择，`Enter` 确认，`Esc` 无操作。

> **现状缺陷（最严重级）**：`main-menu-scene.ts` 把 `keydown-ENTER` 和 `keydown-SPACE` 一律绑到 `startNewExpedition()`，而该函数第一行是 `saveManager.deleteSave()`。**玩家在有存档的主菜单上按一下回车或空格 = 静默删档，无任何确认。** 这不是排版问题，是数据破坏。修复优先级最高。
>
> **术语**：`COH` / `Prototype Build` / `New Expedition` / `Continue` 全部是英文占位与通用软件词，直接违反 U5。这是唯一允许"软件界面感"的表面，但**术语仍然受 world.md 约束**——软件感指的是承认自己在游戏外，不是允许用英文按钮。

### S2 净化点常驻 HUD（含底部提示条）

**载体（U1，已锁定）**：**A 世界内装置**。右上四行是净化点监控装置贴边浮现的常驻读数，无窗口外壳。屏幕空间挂 `architecture.md` 声明的 overlay 根 `#dom-ui-root`。禁止套 `.game-panel`。不是元界面。角锚不得绑在会随 camera zoom 漂移的实现上。

**参考锚点（U12，从 `ux-references.md` 选，不另起）**：

| 游戏名 | 锚的维度（学什么动作） | 明确不学什么 |
| ------ | --------------------- | ------------ |
| FTL: Faster Than Light | 资源槽 = 名称 + 数量同屏、贴边常驻、不靠 hover | 子系统供电格、暂停式全船管理 |
| Into the Breach | 预告把「打谁 / 多重」写成可读事实，与结算同一套词 | 预告 100% 精确不撒谎（本游戏有 `mirror` 谎报与档位模糊） |
| Barotrauma | 装置自己报状态，不是系统对话框 | 整屏潜艇仪表、指针乱转 |

本屏不像：Dashboard / 设置页 / 确认对话框链。

**打开方式**：进入净化点场景即出现，无按键。走近装置时底栏 `#purif-prompt` 改写（**本批不改底栏主交付**，不扩「缺什么」）。进行中不居中弹窗。

**玩家要回答**：我有多少薪柴？下次冲击打谁、多重、什么时候？现在整体在往好还是往坏走？我能做什么、走去哪做？

**现状（与本批合同对齐）**：右上 `#purif-hud` 贴顶横排三槽写明文字（DEC-048）。稳定度**不**在常驻 HUD（DEC-045 D7）。实现若仍是无标签符号或竖表，即为未落地。底栏默认 `Tab:存续报告 │ Esc:记录`，靠近装置时已有 `◈ 核心` / `▣ 储藏`（本批不扩）。

**核心诊断（本批要修的那一层）**：玩家被要求学 ◈=核心、▣=储藏、▮ 格数=档位、◇=薪柴。表名 / 数值 / 档位必须分开展示。布局走 FTL 横槽，不走三列竖表。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 薪柴：表名「薪柴」+ 数字 | 一切决策的预算 |
| P1 | 潮汐：表名「潮汐」+ `第 N 潮` + 相位中文（涨潮 / 潮峰 / 退潮 三态） | 净化点唯一的宏观压力读数。相位必须是字，不靠波形 |
| P1 | 冲击预告：时机「下次归来」+ 目标全称 + 档位中文 | 无 `getForecastDisplay()` 时整行不出现 |
| P2 | 稳定度 | **已不在常驻 HUD**，只在存续报告作状态陈述。本批不加回 |
| P2 | 走近装置时的读数（提示条右段） | 本批不改 |
| P2 | 消声淡预告 | 仅 `getForecastLookahead()` 非空；时机词必须读出「再下一轮」 |
| P3 | 存续报告全文（`Tab`） | — |

**贴顶三槽最终可见结构（art/code 合同，DEC-048）**：

每个槽的表名 / 值 / 档位是**独立可见节点**。禁止合成会被读成复合名词的一句（不合格例：单一文本节点 `下次归来核心中等`、`第2潮涨潮`）。槽间空隙分开三个物件，不是一张表。

| 行 | 表名（独立） | 值（独立） | 档位/相位（独立，若有） | 何时出现 | 读序示例（节点已拆） |
| -- | ------------ | ---------- | ----------------------- | -------- | -------------------- |
| 薪柴 | `薪柴` | 当前储备整数 | — | 始终 | `薪柴`　`12` |
| 潮汐 | `潮汐` | `第 N 潮`（N = `tideNumber`） | `涨潮` / `潮峰` / `退潮` | 始终 | `潮汐`　`第 2 潮`　`涨潮` |
| 预告 | `下次归来` | `核心` 或 `储藏`（全称；CORE / STORAGE） | `轻微` / `中等` / `剧烈` / `极端` | `getForecastDisplay()` 非空 | `下次归来`　`核心`　`中等` |
| 消声淡预告 | `再下一轮`（不得再用「下次归来」） | 同上目标全称 | 同上档位中文 | 仅 `getForecastLookahead()` 非空 | `再下一轮`　`储藏`　`轻微` |

**相位对照**（与存续报告 `phaseLabels` 同一套；禁止发明「满潮」「落潮」）：`rise→涨潮`，`crest→潮峰`，`ebb→退潮`。

**符号规则（结构层；视觉由 art 核 / DEC-048）**：常驻 HUD **不画** `◇`/`◈`/`▣`、波形、pip、间隔号 `·`。底栏走近装置仍可用 `◈ 核心` / `▣ 储藏`（本批不改底栏）。extreme 临界脉动可留在「下次归来」槽。消声槽可更淡、无脉动，但三个文字节点不得省略。

**档位中文（全项目冲击档位，只改展示词）**：选定已上屏的 `SEVERITY_LABEL`（`src/systems/impact-system.ts`）：`light→轻微`，`moderate→中等`，`heavy→剧烈`，`extreme→极端`。理由：S8 结算已用同一份；U5 禁止预告写「中」、结算写「中等」。人口授「轻 / 中 / 重 / 极端」与旧 IA 例句「中」视为口语缩写。HUD **必须 import 这一份**，禁止再手写平行表。S8 本批不改。英文枚举不变。预告仍不报方向（DEC-034）。

**状态**：

| 状态 | 条件 | 表达 |
| ---- | ---- | ---- |
| 静默 | 附近无装置 | 常驻信息 + 一行全局键位 |
| 可交互 | 走近装置 | `[E]` + 装置名 + 该装置的关键读数（现状已有，保留） |
| 缺 X | 走近但无事可做 | 底栏「缺什么」**不是本批主交付**（已登记，不在右上四行范围） |
| 临界 | 模块 <30% / 预告为最高档 | 预告行脉动（可留）+ 档位词「极端」仍必须可见 |

**交互**：`WASD` 移动、`E` 交互、`Tab` 存续报告、`Esc` 打开记录菜单（新存档 / 读取存档 / 继续）。Esc **不得**直接切到标题页——那会让玩家以为已经退出。记录菜单可再按 Esc 或选「继续」关闭，场景原样恢复。在裂隙内选新存档或读取存档都会结束当前出击并进入净化点。

**结构层自检（本批）**：载体 A，挂 `#dom-ui-root`。参考 FTL / Into the Breach / Barotrauma，本屏不像 Dashboard / 设置页 / 确认对话框链。P1 三项（薪柴 / 潮汐 / 预告）零操作可读身份+数值；消声为 P2。表名/值/档位分节点。底栏缺 X 不在本批。打开方式=进入场景。可见词来自 world.md 术语表 + `SEVERITY_LABEL`；不发明相位词。机械层已扫；审美待人终审。

> **对载体的约束**：右上已锁 A + `#dom-ui-root`、不套 `.game-panel`。底栏「缺什么」仍不是本批。

### S3 分配面板（注入）

**玩家要回答**：这个模块现在多惨、修好给我什么？投 N 点差多少、值不值？我还剩多少、别处还要多少？这个模块是下次挨打的那个吗？

**现状**：完整度条 + 预览段 + `-` / `+` 按钮 + 储备行 + 注入。**这个面板的信息是自洽的，问题在于它把决策放在了真空里**——玩家在这里看不到机会成本，而"这次分配的后果是什么"（验证问题 3）恰恰是机会成本问题。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 模块名 + 完整度条（含投入预览段）+ `当前效果 → 注入后效果` | 现状已有 |
| P1 | 投入量 + 剩余储备 | 现状已有 |
| P1 | **机会成本行（新增）**：另一模块的完整度 · 最便宜的未购改造费用 · 本模块是否为下次冲击目标 | 三个数字一行。这是把"注入"从填表变成取舍的唯一结构性手段 |
| P2 | 修复效率的来源分解：`基础 4 · 虹吸残渣 x2 = 8 完整度/薪柴` | 现状用 `(虹吸增效)` 标签做了一半——有标注但没给出基础值，玩家无法验证倍率 |
| P3 | 模块效果的数值上限说明 | — |

**状态**：可交互 / 已选中 / `完整度已满` / `储备 0 · 需要出击` / 临界（本模块是下次冲击目标，面板顶部标注）。

**交互**：`← →` ±1，`Shift + ← →` ±5，`Home` 归零，`End` 拉满，`Enter` 注入，`Esc` 离开。**现状纯鼠标，且一次点击只能 ±1**——修一个 43/100 的模块要点十几次。这是操作成本本身在劝退决策。

### S4 供奉面板（防御槽）

**玩家要回答**：这 4 个槽装了什么、各自替我挡了什么、代价是什么？每个还差几次就转化？库存里哪件更该现在装？装上它，我下次出击会背什么？

**现状**：槽格（名 / 星级 / 充能条 / n/3）+ 库存方块（名 / 星级，说明只在鼠标悬停的原生 tooltip 里）+ 离开。

**核心诊断（三处）**：

1. **副作用完全不可见。** 每一件防御残渣都有副作用（初始混乱 +N / 移速 -X% / 视野 -X% / 储藏减半 / 模块互换……），CSV 里有 `defenseSideEffect` 与 `sideEffectDuration` 两列，UI 一次都没读过。玩家在这里做装备决策，代价却要等到下次出击开始的那一瞬间才以 toast 形式出现。**"防御副作用来自哪"（验证问题 2）的答案缺失，根因就在这一屏。**
2. **减伤数值与类别不可见。** CSV 的 `defenseReduction`（0.15–0.50，三倍以上差距）和 `defenseCategory`（纯减伤 / 经济收益 / 伤害转化 / 模块增益 / 加速催化）都存在且都不显示。玩家分不清 18 件残渣，不是因为它们相似，是因为**区分它们的两个字段从未被渲染过**。
3. **转化去向不可见。** 见下。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 4 个槽：残渣名 · 稀有度 · **减伤%** · 充能 `n/3` | 减伤%是槽位之间唯一的可比标量 |
| P1 | 每个槽第二行：**转化去向** `→ 凝锁 · 还需 2 次` | 见下方专述。这是 Slice 5 遗留验证问题的主战场 |
| P1 | 每个槽第三行：**副作用一句** | 代价与收益必须同屏 |

**转化去向为什么必须在 P1**：一件污染物的两种用途（当防御吃 / 攒成工具用）现在分处两个面板——防御形态在"供奉"，工具形态在"踏入裂隙"。**玩家从来没有机会把它们并排看，所以从来没有机会犹豫。** 把"再挨 2 次冲击 → 变成【凝锁】：冻结最近敌人 4 秒"直接印在防御槽上，是信息架构能为"纠结感"做的全部工作。

> 做完这一步如果仍然不纠结，那就不是界面问题——见结构性风险 R1，那条我认为才是真正的答案。

**状态**：`空 · 可装填` / 已装填 / **临界：下次冲击即转化** / `槽位已满 · 先取下一件`（不是灰掉）。

### S5 踏入裂隙面板（出击装配）

**玩家要回答**：这次带哪 4 件、每件做什么？各剩几次、用完会怎样？哪个键触发哪个？这趟的出击属性是什么？**我身上还挂着什么？**

**现状**：4 个槽（键位 / 名 / xN）+ 库存方块（名 / 星 / xN，说明只在悬停 tooltip）+ 三项属性预览（完整度 / 混乱率 / 薪柴值）+ 踏入 / 还是算了。

**核心诊断（五处）**：

1. **工具名不对。** `loadout-panel.ts` 维护的名表与 CSV 的 `displayNameTool` 只有 4/18 一致，其余 14 条用的是防御侧词根（散射 / 逆行 / 虹吸 / 膨胀 / 共鸣 / 覆写 / 侵蚀 / 燃素……）。同一件工具在"踏入裂隙"叫"散射"、在"存续报告"叫"碎影"。**"我带了什么"这个问题在身份层就答错了。**
2. **工具做什么完全不可见。** 只有鼠标悬停的原生 tooltip，键盘玩家零可得（U7 直接违规）。
3. **本次出击的既有残留不可见。** 上次冲击产生的副作用（初始混乱 +8、移速 -10%……）在这一屏是已知数据，却要等玩家踏进裂隙之后才 toast。**决策信息迟到了一屏。**
4. **主动/被动在库存里不可区分。** 槽位标了"被动"，但库存条目看不出哪件是被动工具，玩家只能靠点击失败来试。
5. **出击属性无来源分解。** `混乱率 x0.70` 的 30% 里有多少来自核心、多少来自渗透抗性改造？这是"改造起作用了吗"（验证问题 2）的直接答案，现状不可得。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 4 个槽：**键位标签** · 工具名（CSV 权威名）· 剩余次数 · **一句能力摘要 ≤15 字** | 摘要是分辨 15 件工具的最小单位 |
| P1 | 库存条目：名 · 稀有度 · **主动/被动** · 剩余次数 | — |
| P1 | 出击属性三项（现状已有） | — |
| P1 | **本次出击的既有残留（新增）**：逐条列出待生效的防御副作用及其来源残渣 | 装配决策必须知道自己开局背着什么 |
| P2 | 检视区（见 S13） | — |
| P2 | 出击属性的来源分解 | `混乱率 x0.70 ← 核心 -18% · 渗透抗性 -12%` |
| P3 | 破碎规则说明 | `次数归零即破碎，不可恢复` |

**状态**：`空 · 可装填` / 已装填 / `此槽只接被动工具` / `库存中无工具 · 工具来自防御槽的转化`（给出去向指引，不是空白）。

**交互**：`Tab` 切区，`↑ ↓ ← →` 移动，`Enter` 装/卸，`Enter`（在动作区）踏入，`Esc` 离开。

### S8 冲击结算面板

**这是"刚才那下发生了什么"的核心表面，也是全项目信息损失最严重的一屏。**

**玩家要回答**：我挨了多重的一下、打了谁？我的防御做了什么、挡下了多少？哪件转化了？我下次出击会背什么？我预判对了吗？

**现状**：标题 `冲击 x1.60` + 每模块伤害条 + 防御充能条 + `…知道了`。

**核心诊断**：`defense-engine.ts` 每次冲击都会算出并返回 `sideEffects` / `kindlingGain` / `stabilityChange` / `expandNullified` / `scatterRedistributed` / `stitchEqualization` / `healOut` / `toolUseGrants` / `moduleSwapTriggered` / `upgradeDiscount` —— **十项结果，一项都没显示。** 玩家看到的只有"我掉了多少血"，看不到"我的防御做了什么"。这直接导致：防御槽的投入无法被感知为收益，于是"当防御吃着"这条路径在体验上是纯亏的（对照结构性风险 R1）。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 冲击强度 + 每模块伤害（**至少两段：基础 → 实际**，让减伤可见） | 只显示最终伤害等于抹掉了防御的全部功劳 |
| P1 | **防御生效清单（新增）**：逐槽一行 = 残渣名 + 它做了什么 | `晶锁残渣 · 挡下 12`、`噬化残渣 · 挡下 9 · 返还 2 薪柴`、`膨胀残渣 · 完全无效化 · 稳定度 -1` |
| P1 | 充能进度 + 转化事件（现状已有） | 转化文案要去掉感叹号（world.md 禁用） |
| P1 | **本次产生的残留（新增）**：`下次出击 初始混乱 +5 ← 噬化残渣` | 让玩家在**做决策的地方**看到代价，而不是在承受代价的地方 |
| P2 | **预告 vs 实际**：`预告 ◈ 核心 中 · 实际 ◈ 核心 中` 或 `预告与实际不符` | 这一行是回溯残渣的预判折扣、镜映残渣的误报机制唯一的表达渠道。没有它，这两件残渣的核心机制对玩家不存在 |
| P3 | 伤害分配的完整计算链 | — |

**状态**：`边界未被突破`（零伤害）/ 有损伤 / **临界：模块归零** / 有转化。

**交互**：`Enter` 或 `Esc` 关闭。**现状只接受 `Esc` 和鼠标点击，按钮却写着"…知道了"**——按钮文案暗示回车，绑定却没有。

> **对载体的约束**：新增的三块内容（防御清单 4 行 + 残留 2-3 行 + 预告对照 1 行）会把这一屏从约 8 行推到约 18 行。这是尺寸下限约束，art 需要知道。

### S9 共享样式层（同一台设备的保证层）

这不是玩家表面，是 U11 的载体。结构层职责是定义**必须复用的结构基元清单**，art 定义它们长什么样。

**现状缺口**：

1. **没有"已选中"状态。** `.slot-cell` / `.item-tile` / `.upgrade-card` 的唯一选中反馈是 `:hover`。键盘游标无处落脚——这是键盘不可用的根本原因，不是"忘了绑键"，是**样式层里根本没有给键盘游标预留状态**。
2. **`.option.disabled` 只变色不说明**（U8）。
3. **没有统一的"缺什么"表达位置**，各面板各自内联。
4. **没有键位提示条基元**，导致每个面板的键位提示各写各的（甚至没有）。

**本轮必须新增的结构基元（结构语义，视觉归 art）**：

| 基元 | 语义 | 出现在 |
| ---- | ---- | ------ |
| `已选中` 态 | 键盘游标所在项 | 所有列表/网格项 |
| 检视区 | 面板底部固定高度区块，内容随游标刷新 | 供奉 / 踏入裂隙 / 存续报告 |
| 代价行 | 统一位置表达"缺什么、缺多少" | 所有可能不可用的项 |
| 键位提示条 | 面板底部固定一行，随焦点区变化 | 全部面板 |
| 来源标注 | 数值旁标"来自 X"（`← 核心`、`← 渗透抗性`） | 属性预览 / 结算 / 残留清单 |
| 临界标记 | 除颜色外的第二重编码 | 濒危模块 / 下次冲击目标 / 即将转化的槽 |

**沿用**：`.game-panel` 框、`.separator`、`.stat-bar`、`.pbar-*`、`.slot-grid`、`.tile-grid`、`.action-bar`。

> Director 在表面清单里点了这一层的两处**视觉**病灶——`.game-panel` 的 `box-shadow: 0 0 12px`（U2 禁投影/发光）与 `.hint` 用 `#5a5f66` 压在 `#0f1114` 上（对比度过低，正是人点名的"文字看不清"）。两条都归 art 的可读性硬规则处置，本文不重复裁定。结构层唯一相关的诉求是：`.hint` 承载的是键位提示，而键位提示在本文里从"可有可无的脚注"升级成了**每个面板必备的基元**——它不能继续是最不可读的那一行。
>
> **待 art 裁定但受结构约束**：净化点 HUD 至今未套 `.game-panel`（backlog 已记）。IA 层的判断是**它不应该套**——常驻 HUD 与唤出面板是两类东西，前者要让位于世界，后者要盖住世界。它们之间的一致性应当来自共用的符号语言与色彩语义，不是共用同一个边框。这是"Degree not Kind"的正确切分点，最终由 art 拍板。

### S10 裂隙 HUD（重点一）

**玩家要回答**（每 10-30 秒循环一次）：

1. 我还能撑多久？
2. 我拿到多少了？
3. 我手上有什么能用、还剩几次？
4. **有没有人在看我？**
5. 撤离点在哪？
6. 我身上现在有什么异常？

**现状**：生命条（60×4，无标签，左上）/ 混乱条（100×4，带 50%·75% 刻度，无标签，顶部居中）/ 薪柴 `◇ N`（右上）/ 工具槽 `[Q] ···`（左下，**圆点表余量，没有工具名字**）/ 撤离提示（靠近时，底部居中）/ 薪柴倍率 `x1.2`（右上）/ 小地图（右下）/ 结算面板（居中）。

**核心诊断**：

- **工具槽没有名字。** 玩家在装配面板选了 4 件工具，进了裂隙之后 HUD 上只剩 `[Q] ···  [F] ··  [被动] ·····`。**"我带了什么"这个问题在裂隙里根本无法回答**——按下 Q 之前不知道会发生什么。这是全项目最直接的一处信息缺失。附带一提，场景层传给 HUD 的 `name` 字段目前是污染物类型 id（`solidify`），不是显示名——即使现在就把它渲染出来，玩家看到的也会是英文 id。
- **被动工具的触发在感知上等于没发生。** 余量圆点确实会减少（三个被动分支都调了 `useTool`，事件链是通的），但"左下角一个圆点悄悄消失"不构成反馈：没有名字、没有闪现、没有文字，而且被动触发的时机恰恰是**什么坏事都没发生**的那一刻——玩家没有任何理由在那一刻去看左下角。三件被动工具对玩家而言是完全静默的。
  （附带的实现细节：`hud.ts` 的槽位匹配用 `slot.name === payload.toolType`，即按类型匹配。同时带两件同类型工具时会扣错槽，属于边缘缺陷，不影响上面的结论。）
- **没有"被发现程度"。** 这是潜行游戏的核心信息，`AISystem` 里有精确的 detection 数值（`SUSPICION_THRESHOLD 0.35` 等），玩家侧零呈现。玩家只能通过敌人身上的表现推断，而敌人在视野外时什么都推断不出来。
- **没有"生效中状态"。** 防御副作用持续整趟出击，但只在开局 toast 三秒；工具的持续效果（侵蚀领域 12 秒、深渊之眼 10 秒且伴随混乱增速 +50%）没有任何剩余时间显示。

**P1 结论（一行）**：

> **生命 · 混乱（含阈值刻度与当前档位）· 薪柴计数 · 工具槽（键位 + 工具名 + 余量）· 生效中状态（副作用 / 工具持续时间 / 混乱惩罚档位）· 被发现程度。**

**P1 明确不含**（下放到结算或净化点）：污染物计数、击杀数、用时、峰值混乱、潮汐与稳定度、出击属性倍率（装配阶段已决策完，裂隙内不可改）。现状把薪柴倍率 `x1.2` 放在 P1 是错的——它整趟不变，且不影响任何裂隙内决策。

**画面占用（逻辑分辨率 640×427，缩放 1.5 于 960×640 画布）**：

| 位置 | 内容 | 约束 |
| ---- | ---- | ---- |
| 左上 | **状态簇**：生命 + 混乱 + 生效中状态 | 建议把混乱条从顶部居中并入左上。两条最相关的"我还能撑多久"分居两角，玩家要扫两次 |
| 右上 | 薪柴计数 | — |
| 左下 | 工具槽（键位 + 名 + 余量） | 必须有名字 |
| 底部居中 | 上下文提示（撤离 / 工具不可用原因） | 仅在有内容时出现 |
| 右下 | 小地图 | — |
| 世界层 | 被发现指示 | 见下 |
| **禁止占用** | **画面中心 ±120×80 逻辑像素**（玩家周围约 4×2.5 tile）、玩家正在移动的朝向前方 | U6 |

**"被发现程度"的方案与范围提示**：

最小方案是屏幕边缘的方向性标记——有敌人的感知正在填充时，对应方向的画面边缘出现一个标记，强度随 detection 上升；进入警戒时改变形态。

> **这条会实质改变潜行手感**（把"猜"变成"看"），因此虽然它不改任何数值、只是把已有的 detection 可视化，我仍把它标为**需人拍板的范围项**，而不是默认纳入。若人认为 Slice 5.5 只做"看得懂"不做"玩法改变"，这条推迟到 Slice 6（第二敌人）一起做——那时潜行轴本来就要重做。

**结算面板（出击结束）**：

现状是 Phaser 居中文本，`ui-art-overhaul.md` 已判定应改 DOM。玩家问题是"这趟值不值"。

- P1：薪柴 / 污染物数 / 击杀 / 峰值混乱 / 用时 / 下一步按键（现状已有）
- P1 **新增**：**这趟拿到的污染物具体是什么**（名 + 稀有度）。现状只报数量。这是"我带了什么"链条的起点——玩家撤离时不知道自己捡到了什么，回到净化点打开供奉面板时也就不知道哪件是新的。
- P2：被动工具本趟触发次数（三件被动工具唯一的事后凭据）

### S11 dev 调试面板

**玩家没有问题要在这里回答——这不是玩家表面。**

**现状**：`debugVisible = true` 默认开启，DEV 构建下常驻左上角，teal 等宽文字，紧贴在生命条附近，密度高、对比强，包含 fps / 视口 tile 数 / 射线耗时 / AI 统计 / 每个敌人的状态与距离。

**这就是人说"裂隙场景显眼的是 dev 调试面板"的直接根因**：它默认开，位置压着玩家 HUD 最重要的角落，且是画面上信息密度最高、文字最多的元素。玩家的 HUD 是几条 4 像素的无标签细线，旁边是一整块密密麻麻的青色文字——注意力当然去了后者。

**结论**：

1. **默认关闭**（`debugVisible = false`），`F1` 打开。
2. **搬离玩家 HUD 的四角**——玩家 HUD 占左上（状态簇）、右上（薪柴）、左下（工具槽）、右下（小地图）、底中（提示）。dev 面板应占**顶部居中偏下的一条**或以半透明覆盖整块，明确"我是临时叠上来的"。
3. **不得使用任何玩家 HUD 的语义色**（薪柴橙 / 混乱青 / 生命红 / 稳定绿）。当前它用的 `#8ad8cc` 正落在污染色谱里，与游戏信息同族。
4. 它的键位提示（`F1 overlay  ESC menu`）留在面板内部，不外溢到画面上。

### S12 小地图

**玩家要回答**：我在哪、探过哪儿？撤离点在哪、离我多远？（深渊之眼生效时）敌人和薪柴在哪？

**现状**：右下角，3px/tile，探索雾，玩家白色圆点（半径 2），撤离点白色圆点（半径 2，发现后），深渊之眼的 teal 方点。

**核心诊断**：**玩家点与撤离点是同色同形同尺寸的白点。** 最关键的两个标记不可区分（U9），玩家只能靠"哪个在动"来分辨——而在你站着不动的时候，这个线索也没了。撤离点是"贪婪与撤退博弈"的锚，它必须一眼可辨。

| 级别 | 信息 | 理由 |
| ---- | ---- | ---- |
| P1 | 地形雾 + 玩家标记（**带朝向**）+ 撤离点标记（**不同形状**，发现后） | 朝向让玩家不必靠试错找回方向 |
| P2 | 深渊之眼的揭示（现状已有，衰减与闪烁的设计是好的） | — |
| P3 | — | 不做全屏大地图。程序化地图（Slice 8）之前地图是固定的，全屏地图无信息增量 |

> **对载体的约束提示**：小地图显示的是玩家角色不可能拥有的俯视信息。若 art 判定它是**世界内装置**，需要一个叙事解释（例如防护面罩的残影投影），且撤离点标记应复用世界里撤离点的视觉符号（垂直裂缝），而不是发明一个新图标。若判定为**元界面**，则它是裂隙场景里唯一的元界面元素，需要与 HUD 其余部分在视觉上明确分层。这个判断我不下结论，但两条路对标记形状的要求不同，art 需要先定。

### S13 物品信息层 / 检视层（重点二）

**玩家要回答**：这件东西是什么？它做什么？数值多少？跟我现在的配置什么关系？它会变成什么？

**现状**：五处 HTML 原生 `title` 属性 tooltip。只能鼠标悬停（U7 直接违规），无分层，内容是 40-80 字的 CSV 长描述整段砸出来（同时违反 world.md 的"详细描述不超过 40 字"）。

**这是回答"我带了什么、每件东西做什么"的主战场，也是当前空缺最大的一块。**

#### 方案：选中即检视

**不做独立的图鉴屏幕。** 15 主动 + 3 被动 + 18 防御型还没到需要独立表面的量级，多一个表面就是多一层深度，与"P1 要克制"同理。

**进入方式**：任何列出条目的表面（供奉 / 踏入裂隙 / 存续报告），键盘游标停在某条目上时，**检视区自动填充**。不需要额外按键——"选中即检视"是"不得只靠悬停可得"的最强解法，因为它让检视成为默认状态而不是额外动作。鼠标悬停填充同一区域（鼠标是二等公民，但不禁止）。

**翻阅方式**：

- `↑ ↓ ← →` 在当前区内移动，`Tab` 切区。
- 库存排序**固定**：阶段（防御 → 工具 → 已耗尽）→ 稀有度（稀有 → 精良 → 普通）→ 类型 id。不随获取时间变化，让肌肉记忆能成立。现状是获取顺序，每次打开位置都不同。

**检视区位置**：面板底部固定高度区块（列表之下、动作栏之上），约 5-6 行。不新开面板 = 不新增表面。

#### 五层信息

| 层 | 内容 | 数据来源 |
| -- | ---- | -------- |
| **L1 身份** | 名称（当前阶段的权威名）· 稀有度 · 阶段 · 类别（防御类别 / 主动·被动） | CSV `displayName*` / `rarity` / `defenseCategory` / `toolType` |
| **L2 它做什么** | **一句 ≤15 字的机制摘要** | **CSV 需新增两列**，见下 |
| **L3 数值** | 减伤% / 使用次数 / 作用范围 / 持续时间 / 充能进度 | CSV `defenseReduction` / `toolUses` / `toolRangePx` / `toolDurationMs`，全部已存在且从未被渲染 |
| **L4 与我的关系** | 代价与冲突：副作用是什么；装上会顶掉谁；触发键是哪个；现在能不能装（不能则**缺什么**） | CSV `defenseSideEffect` / `sideEffectDuration` + 运行时槽位状态 |
| **L5 转化去向** | 防御态：`还需 N 次冲击 → 【工具名】：<L2 摘要>`；工具态：`次数归零即破碎，不可恢复`；来源：`narrativeOrigin` 一句 | CSV + `impactCharges` |

**L5 是纠结感的结构基础**——它是把"当防御吃"和"攒成工具用"两条路径拉到同一屏的唯一机制。

#### L2 需要的数据补充（CSV 扩列）

现有 `descriptionDefense` / `descriptionTool` 是 40-80 字的完整机制说明，适合 L3/L4 的展开，**不适合做条目摘要**。建议给 `data/contaminants.csv` 增加两列：`summaryDefense` / `summaryTool`，硬上限 15 字，遵守 world.md 叙事语调（无人称、陈述事实、无修辞）。

**标杆（4 条，供人确认语感后再批量补完 18×2）**：

| id | summaryDefense | summaryTool |
| -- | -------------- | ----------- |
| `solidify` | `减伤 35%。每 3 次失效一轮。` | `冻结最近敌人 4 秒。` |
| `ruminate` | `减伤 30%。返还 2 薪柴。` | `从空节点回收 1 薪柴。` |
| `scatter` | `伤害均摊至全部模块。` | `被动。怀疑填充减速 30%。` |

>
> **对载体的约束**：检视区需要同屏承载五层结构化文本并随游标即时刷新，强烈倾向 DOM（现有面板已是 DOM）。若 art 有把某个面板改为 Phaser 层的想法，检视区是最大的阻力点。

### S14 瞬时反馈层（重点三）

**现有成员**：拾取闪现（+N，800ms）/ 新工具 toast（顶部 40px，3s）/ 防御副作用 toast（进入裂隙时，多条）/ 潮汐相位通知（全屏）/ 稳定度里程碑通知 / 改造购买闪现（面板内）/ 首次改造全屏覆盖（"已刻入"）/ 混乱阈值提示（3s）/ 模块修复闪现 / **场景过渡**（净化点 ⇄ 裂隙）。

**核心诊断**：**九种反馈，没有统一的通道、位置、时长与并发规约。** 顶部 40px 的 toast 与顶部居中的混乱条争同一块空间；三种"通知"各自定义了自己的全屏覆盖；同时触发多条时互相压盖。更要命的是**阻断链**：玩家从裂隙回到净化点，要依次消解「冲击结算 → 潮汐相位通知 → 稳定度里程碑 → 新工具 toast」。**四次"知道了"。** 这就是"不像游戏"的一个具体来源——仪式感被做成了确认对话框链。

**三级反馈通道（本文定义，所有系统遵守）**：

| 通道 | 定义 | 位置 | 时长 | 并发 |
| ---- | ---- | ---- | ---- | ---- |
| **A · 即时局部** | 就地发生，不用文字 | 事件发生的位置本身 | ≤400ms 出现，≤800ms 消失 | 无限，互不干扰 |
| **B · 事件条** | 一行文字，队列化，不打断 | 屏幕固定一角（**不与 P1 信息重叠**） | 2s，队列最多同时 2 条 | 排队，不压盖 |
| **C · 阻断通知** | 需玩家按键消解 | 居中或面板内 | 直到按键 | **同一时刻只允许 1 条** |

**通道 C 必须稀有。** 建议：一次归来只保留**冲击结算**一个 C。潮汐相位切换与稳定度里程碑**并入冲击结算面板的一个段落**（它们本来就是同一次结算的后果），新工具提示并入结算面板的"转化"段。这样"四次知道了"变成一次。

**反馈感知矩阵**（回答"刚才那下发生了什么"）：

| 事件 | 现状 | 即时 | 事后报告 |
| ---- | ---- | ---- | -------- |
| 主动工具生效 | VFX + 槽位圆点减少 | **A**：VFX（Slice 5 已做）+ 槽位余量变化 + 受影响敌人的标记 | — |
| **主动工具未生效** | **无**（`applyEffect` 返回 false 后静默） | **B**：`无可指向的目标` / `此处无法放置` | — |
| **被动工具触发** | 仅圆点静默减少 | **A**：被动槽闪一次 + **B**：`消声步 · 未被近距发现` | 出击结算：本趟触发 N 次 |
| 工具耗尽破碎 | 无 | **B**：`【凝锁】已耗尽` | 出击结算列出 |
| 拾取薪柴 | +N 闪现 | **A**（已有，保留） | 出击结算 |
| 拾取污染物 | 弱 | **A**：`+【晶锁残渣】` | 出击结算**列出具体条目**（现状只有计数） |
| 混乱越阈值 | 3s 提示 + 视觉调制 | **A + B**（已有，保留） | 出击结算：峰值 |
| **被敌人察觉** | 仅敌人身上 | **A**：方向性边缘标记（**范围待人拍板**） | 出击结算 |
| **防御副作用生效** | 进裂隙时 toast 3s | **B**（开局队列）+ **HUD 状态行常驻整趟** | 冲击结算时已预先披露 |
| **防御减伤生效** | **无** | — | **冲击结算逐槽列出**（主战场） |
| **模块功能互换** | toast | **B** + **核心/储藏的效果标签实际对调并标注"已互换"** | 冲击结算 |
| **改造是否起作用** | **无** | 装配面板的属性来源分解（P2） | 存续报告的改造列表带当前效果 |
| 预告是否准确 | 无 | — | **冲击结算的"预告 vs 实际"行** |
| 污染物转化 | 结算面板 + toast | **A**：结算面板内该槽变化 | 已在结算内 |

**400ms 规则（U10）**：所有 A 通道 ≤400ms 出现；B 通道队列首条 ≤400ms；C 通道由玩家节奏决定，但入场动画 ≤400ms。

**场景过渡（净化点 ⇄ 裂隙）的信息职责**：过渡不只是转场动画，它是两个信息语境之间的交接。结构层要求两条——

- **踏入裂隙时**：过渡期间必须显示"本趟带了什么、背了什么"的一屏摘要（4 个工具槽 + 待生效的副作用）。这是玩家从"装配语境"切换到"操作语境"的最后一次确认机会，也是把 S5 的决策结果**送进玩家短期记忆**的唯一时机——现在这块时间是纯黑屏。
- **撤离归来时**：过渡承接出击结算的结果，交给冲击结算面板。中间不插入任何需要按键的东西（对照通道 C 的唯一性规则）。

视觉表现（"裂隙坍缩"的画面收缩/扭曲）是 art 的活，本条只定义**这段时间必须承载什么信息**。

#### 类别 3 · 术语表欠账（world.md 已补核心/储藏/潮汐三态/冲击四档；其余仍欠）

**最危险的一条**：**"污染物" vs "污染体"**。术语表只定义了"污染体 = 敌人的统称"，而 spec 与 UI 全程使用"污染物 = 玩家收集的残渣"。**一字之差，指两种完全相反的东西**（一个要躲，一个要捡）。这必须在术语表里明确区分，否则任何文案写作都会持续踩坑。

## 3. 结构性风险清单（UX 修不了的问题）

> 这一节的判断标准：如果把界面做到完美，这个问题还在不在？在 → 它是机制问题，回退路径是回 design 重审收益结构，**不得靠 UX 或改 constants 掩盖**。

### R1 · 防御与工具不是二选一，"纠结"在机制上不成立【最重要】

Slice 5 的遗留验证问题是"拿到一件 Fine/Rare 污染物时，玩家是否在'当防御吃着'和'攒成工具用'之间犹豫"。

**按当前规则，这不是一个选择。** 装进防御槽的污染物在积满 3 点冲击计数后**自动、无条件、不可阻止地**转化为工具。所以"装上防御槽"= "先吃 3 次冲击的减伤，然后照样拿到工具"，严格优于"放在库存里不动"（后者永远不会转化）。唯一的代价是副作用。

也就是说：**真正稀缺的是防御槽位（4 个），不是污染物。** 决策只在"库存里的防御态污染物 > 4 件"时才发生，而且那时的决策是"哪 4 件先上"，不是"防御还是工具"。

**信息架构能做的**：把这个事实讲清楚（S4 的 L5 转化去向就是干这个），让玩家至少不再困惑。**信息架构做不到的**：制造本来不存在的取舍。

**若人希望产生真实的犹豫，需要机制层改动**（三条候选，都是 design 的活）：

- (a) 经过防御期的污染物转化后使用次数降低 —— 让"吃减伤"有真实的工具端代价；
- (b) 提供付薪柴强制转化的路径 —— 让"我现在就要这件工具"成为可付费的选项，与"慢慢攒"竞争；
- (c) 副作用强度随稀有度递增 —— 让高价值残渣的防御期成为真实代价，而不是白吃。

### R2 · 早期库存少于槽位时不存在装配决策

4 个防御槽 + 4 个出击槽 = 8 个位置。在玩家累积到 8 件以上可用污染物之前，"带什么"的答案永远是"全都带上"。这是内容密度问题，不是界面问题。

### R3 · 15 件工具在同一张地图、同一种敌人面前没有区分的必要

裂隙地图当前是固定的（`rift-map-data.ts`），敌人只有渗透体一种。**在这种局面里，15 件工具的最优解是稳定的**——玩家会带次数最多的那几件，因为没有需要适配的局面差异。

这可能才是"玩家分不清 15 件工具做什么"的真正根因之一：**不是看不懂，是没有区分的必要。** 无论界面写得多清楚，工具的差异化在第二种敌人（Slice 6）和程序化地图（Slice 8）之前都无法被感知为"选择"。

**结论**：Slice 5.5 的 UX 收敛可以让玩家**读懂** 15 件工具，但不能让玩家**在意**它们的区别。若人在 5.5 之后仍觉得"工具没意思"，那是排期问题不是界面问题。

### R4 · 三件被动工具的收益都是"某件坏事没发生"

碎影（怀疑填充减速）、消声步（免疫近距感知）、寄生引流（击杀返还）——前两件是反事实收益。即使给了反馈（S14 已设计），"刚才那次没被发现是因为它"这个因果链在体感上仍然很弱。UX 能缓解（把不可见的事件变成可见的事件条），不能解决（无法让玩家感受到未发生的危险）。

### R5 · 非空间预告 + 等价防御槽 = 预告没有可执行的应对

DEC-034 把冲击预告改为非空间（目标模块 + 强度档位）。同时防御槽是 4 个等价槽、不分方向。于是"知道下次打核心"这条信息**没有对应的可执行动作**——玩家能做的只有"多修核心"，而这不需要预告也知道该修。

预告的信息价值目前接近零。把它显示得再清楚也无用。**若要让预告有意义，需要机制层给出针对目标模块的应对手段**（例如可指定某个防御槽护住某个模块）。

### R6 · 稳定度 100% 无终局内容，进度条隐喻是空头承诺

`system-growth-tide.md` 规则 23 明确"本 Slice 仅标记 reached = true，不触发终局内容"。进度条这个隐喻承诺终点。在有终局内容之前，把稳定度做成 P1 常驻进度条，是在持续兑现一张空头支票。

**IA 建议**：降到 P2（存续报告内），且在有终局内容之前不使用"进度条"隐喻，改为状态陈述。这是我建议把稳定度移出净化点 HUD 的第二个理由。
