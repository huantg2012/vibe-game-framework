# 裂隙中断恢复与悬海基地往返

用户已选择 **离开续原局，明确放弃才结损**（DEC-158）。这一政策已在悬海连续旅程中实施，采用独立浏览器纪录；默认游戏旧世界尚未接入完整恢复。本文记录取舍和实际边界，机制权威仍是[统一库存](../specs/system-field-inventory.md)。

## 1. 已锁定的玩家规则

- 退出、刷新、崩溃不视为死亡或撤离。恢复最近完整保存的同一趟、同一地点与状态，离线不推进模拟；不重新入场、不补生命/耐久/技能次数，不给归来奖励或供奉进度。
- 暂停、页面隐藏及正常关闭尝试保存完整帧；移动检查点间隔500ms，收益、受伤、装备消耗及终局在当帧提交。崩溃只承认已落盘的完整事实，不能保证尚未提交的动作。
- 暂停菜单明确选择并确认放弃：携入装备和途中收获全部遗失，不给携回薪柴或成功撤离收益；基地收存与供奉物保留。回基地结算一次既有冲击并推进一次潮汐，单独记录为abandon，不伪造战斗死亡。
- 未知版本、损坏或不匹配纪录先停止加载并保留原始字节。不能把不同序号的库存和世界拼合，也不自动用旧备份返还消耗或复活。**目前未提供坏包的可视化抢救/放弃界面**；可读原局可从暂停菜单明确放弃。完全不可读时不能声称仍能救回基地，不能静默新开覆盖。

放弃带来的供奉推进也付出真实基地损伤；基础白板替补降低携入门槛。这种“消耗基地完整度换成熟度”的周转是否适当，仍由四A持续供给验证判断。本轮不改用户接受的规则，不以恢复实现代替经济验证。

## 2. 实施边界

### 同一完整纪录

`SaveDataV2`可携带出发意图或`RiftCheckpoint`，含runId、递增序号、世界/布局/seed、配方和能力签名、校验和及整份基地/库存。物理帧结束、身体位置回写、实际视野和地貌记忆更新之后才捕获。

- 玩家：位置与身体、速度/推退、转向、攻击时序、生命、混乱、受击间隔。
- 敌人：存活集合、生命、感知/调查/追击/巡逻、攻击、控制、路径及随机流；死亡个体不从新生成模板复活。
- 装备/技能：唯一ID、余次、完整持续实例、目标或落点、被动去重。末次清槽后的持续效果仍可恢复。
- 搜寻：纯薪柴、已揭晓与实际拾获分开、所有节点状态、途中读条、留地/取丢和已抽出的ID；不靠只有物件的账本推测薪柴。
- 悬海：真实逻辑时间、改流命中周期、余水、回摆与共享接触间隔；镜头缓动和地形G记忆同存。当前视野R由真实场景重算，G不会透海、造出地面或替代视线。

有限DTO保存决定后续结果的事实，不序列化Phaser/Three、贴图、DOM或音轨。完整准入校验在改live state之前进行；重建地形和能力签名不符即拒绝。校验临时纹理及时销毁。

### 事务与恢复

机制事件帧内同步，使受伤触发的被动进入同一结果；库存观察者、成功提示、声音及结果转场等在完整保存后发布。库存消耗与其产生的命中/技能效果不能各自保存。存储首次失败冻结模拟、保留同一候选字节；手动重试不重抽伤害、不再扣次、不重复发放。加载只使用完整有效纪录；上一份备份不会自动覆盖较新的消耗。

- `departure intent`与beginRun、cycle、冻结入场条件同存，建场景失败不增加第二次cycle。
- `active`恢复同局，不执行基地冲击；正常新入场先同步实际Arcade身体偏移，恢复分支保留已保存的动量。
- `settled && !baseSettled`是终局回执，只进入正式净化点结算；`baseSettled`只读已结基地。基地冲击和预告绑定该run的随机序列，失败重载也不会换攻击目标。
- 终局冻结AI/物理和世界时钟，保留结果展示所需的场景时间。入场暂停和终局暂停分别管理所有权，离场不访问已销毁的物理世界。

核心入口：[完整帧协调](../../src/systems/rift-frame-commit.ts)、[SaveManager](../../src/managers/save-manager.ts)、[悬海准入](../../src/dev/suspended-sea/recovery-validation.ts)、[旅程会话](../../src/dev/suspended-sea/journey-session.ts)。

## 3. 三种入口各自的用途

- `/suspended-sea.html`：两种布局×四种训练配置，独立内存，单趟比较能力；关闭不保留。
- `/suspended-sea-journey.html`：初始白板起步，原净化点备行/供奉/修复与悬海反复往返，同页内存持续；关闭不保留。
- `/suspended-sea-journey.html?resume=1`：同一正式循环，加独立悬海持久纪录和原局恢复。浏览器存储键加`coh-suspended-sea-journey:`前缀，保留原游戏纪录。

目标武器和技能必须亲自翻找获得，再经历真实归来冲击供奉成熟；旅程不调用四配置训练授予，也不允许途中换装或补耐久。未知装备能力在出发前拒绝，不静默卸装。本轮尚不向旧世界随机池注册悬海，不把三条入口混成“正式全游戏已恢复”。

## 4. 实际闭环证据

同一个空白浏览器、正式初始白板、正常键鼠已完成五次搜撤与第六趟真实死亡。原始账本见[操作报告](../qa/iteration-22-playthrough.md)。

1. 第1趟seed19带回优良回声空壳与优良撬棍，在归来冲击之后放入原供奉台，起始进度0。
2. 第2/3趟的真实冲击使空壳0→2→4，成熟为6次；第4趟在原备行槽装配同一ID，合法施放6→5。
3. 优良撬棍在第2/3/4趟冲击后0→1→2→5，成熟为75耐久；第5趟原槽装配、实际战斗75→72。
4. 修复只花实际带回的薪柴，所有阶段保持同ID/来源。第五趟后的基地真实记录为CORE75、STORAGE48、PURIFIER54、薪柴0。
5. 第6趟水伤死亡，携入优良撬棍、空壳及当趟拾获物全损、携回薪柴0；基地12件收存保留，原供奉继续既有冲击进度，未凭空多发基础武器。

四配置16趟两图搜撤及额外近战脱离也已完成。空壳声音响应得到证明，**诱离之后安全翻找的战术收益尚未证实**；两次靠近太早又被追击的失败保留，不再刷到成功为止。空壳的供奉/装配/施放链完成与战术收益是不同结论。

## 5. 验收状态与剩余任务

程序总检查覆盖十组：角色/AI/战斗、五族效果、悬海/镜头/记忆、完整帧事务、run路由、传输、基地随机结算、完整准入、新进程旅程恢复及场景生命周期。纯薪柴、末次持续效果、留地交换、余水接触期限、签名拒绝和终局重复加载都有对应状态断言；不把程序夹具称作真实游玩。

真实浏览器已经验证纯薪柴不重复、原地续玩、存活/击败敌人、生命与耐久、已拾物件ID、活动空壳落点/余次/剩余时间及存储失败冻结。正常主动放弃已验证全携带损失、零收益及结果时钟停住。测试同时发现并修复首次身体偏移、重试按钮继承穿透而不能点击、返基地清理空world，以及入场中放弃的暂停归属。最后两条生命周期、实际重试、主动放弃正常返基地/多次加载及下一次出击真实移动已完成复验，结果统一写入[本轮QA](../qa/iteration-22.md)。原失败录像、错误定位及误用菜单冷却的测试尝试保留。

本轮不是发行验收。音源/混音/生命周期技术检查已做，录音尚未实际审听；用户整体验收仍待进行。旧世界完整恢复、坏包可视化抢救、另一个世界/构筑和能力数据入口仍需后续工作。

**总计划没有跳步：第二世界/构筑与共享能力之后，先做四A连续供给验证，再解锁四B扩产。** 五趟成功和一次死亡仅证明循环接通，不证明正常耗尽、连续失败重组、武器与技能供奉竞争长期可持续。
