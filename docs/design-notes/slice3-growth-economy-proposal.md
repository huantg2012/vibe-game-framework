# Slice 3 设计提案：角色成长 + 长期经济再设计

> **验证问题**：在有成长回路的情况下，压力递增 + 能力递增的动态平衡是否让人想继续？
>
> **核心设计目标**：打破必然下行螺旋，建立"在持续压力下持有希望"的体验。

---

## A. 核心循环重新定义

### A.1 当前循环的问题诊断

当前循环（Slice 1+2）：

```
出击 → 搜刮薪柴(10-14) → 返回 → 分配修复 → 冲击(伤害递增) → 缺口扩大 → 再出击
```

数学上必然崩溃：
- 收入固定：地图总价值 17 薪柴，实际带回 10-14
- 支出递增：BASE_IMPACT_DAMAGE(30) * intensity(1.0→2.5) / REPAIR_PER_KINDLING(4) = 修复成本 7.5→18.75 kindling/cycle
- 交叉点：约 cycle 5-6 时收支持平，之后赤字不断扩大
- 终局：约 cycle 8-10 时两个模块不可维持，游戏进入纯煎熬

这不是"紧绷的边缘"，是"可预见的倒计时"。一旦玩家理解了数学，"希望"就消失了。

### A.2 重新定义的完整循环

```
出击 → 搜刮薪柴 + 积累适应(自动) → 返回净化点
  → 三向分配：模块修复 / 模块强化 / 自身成长 ←← 核心新增决策层
  → 冲击来袭（潮汐节奏，非匀速递增）
  → 成长效果反馈到下次出击效率
  → 净化进度推进（长期目标可视化）
  → 再次出击（带着更强的能力面对更强的压力）
```

### A.3 三个循环维度

| 维度 | 时间尺度 | 驱动力 | 情感 |
| ---- | -------- | ------ | ---- |
| 生存循环 | 单次出击 | 混乱值压力 + 搜刮 | 紧张、贪婪、释放 |
| 维持循环 | 2-3 次出击 | 冲击 + 模块修复 | 焦虑、权衡、勉强 |
| **成长循环** (新) | 5-8 次出击 | 投资 → 回报 | **希望、规划、成就** |

### A.4 压力来源 vs 希望来源

**压力来源**（让玩家觉得"可能撑不住"）：
1. 冲击强度的潮汐上升（现有，调整为非匀速）
2. 每次出击的时间压力/混乱值（现有，不变）
3. 资源的三向争夺（新：成长 vs 修复 vs 强化）

**希望来源**（让玩家觉得"我能行"）：
1. 能力成长可感知（"这次跑得比上次快/远"）
2. 潮汐节奏的回落期（"熬过这波就有喘息"）
3. 进度指标可见（"我在靠近某个目标"）
4. 投资回报可计算（"再投 5 个薪柴到速度，下次能多拿 2 个"）

### A.5 什么阻止了"必然失败"

**三道安全阀**：

1. **潮汐上限**（Tide Cap）：冲击强度不无限递增。每个"潮汐"有明确的峰值和回落。玩家知道"最难就这么难了，我只需要撑住这几轮"。

2. **成长追赶窗口**（Growth Window）：潮汐回落期间，冲击压力减轻，玩家可以将更多薪柴投入成长而非修复。这是追赶曲线的"杠杆时刻"。

3. **能力基线提升**（Capability Floor）：每次成长投资都是永久的。即使当前潮汐很凶猛，玩家的基线能力不会倒退。下一个回落期到来时，玩家比上一个回落期更强。

**关键不等式**（平衡设计的数学锚点）：

```
玩家在潮汐回落期的收入 > 修复成本 + 一次成长投资
玩家在潮汐峰值期的收入 ≈ 修复成本（刚好维持，无余力成长）
玩家的累计成长 > 连续两个潮汐之间的压力差额
```

只要这三条不等式成立，游戏就永远不会进入"必然失败"。

## B. 角色成长系统设计

### B.1 成长资源：薪柴（统一货币）

**设计决策：不引入第二种货币。**

理由：
- `vision.md` 明确指定："薪柴经济：唯一通用货币，同时服务三个出口（净化点各模块防御 + 自身强化）"
- 单一货币最大化"顾此失彼"的纠结感（体验支柱 1+3 的交叉点）
- 简单（indie 一人项目约束）
- 决策权重集中在分配环节而非获取环节

**成长花费薪柴 = 你在用"明天能用来修墙的资源"赌"后天能赚更多"。**

### B.2 成长维度

三条成长轴线，对应三种"我变强了"的感知方式：

#### 轴线 1：出击效率（"我能走得更远"）

| 升级 | 效果 | 初始值 | 成长幅度/级 | 上限 | 世界观解释 |
| ---- | ---- | ------ | ----------- | ---- | ---------- |
| 渗透抗性 | 混乱值基础增速降低 | 0% 减免 | -4%/级 | -20% (5级) | 反复暴露于异源模式后，身体产生微量适应性 |
| 行动效率 | 基础移动速度增加 | 80 px/s | +6 px/s/级 | 110 px/s (5级) | 在异常空间中行动的经验积累 |
| 抗性缓冲 | 混乱值起始安全区扩大(第一阈值提升) | 50 | +5/级 | 70 (4级) | 短期渗透的耐受阈值提升 |

#### 轴线 2：资源效率（"我能赚得更多"）

| 升级 | 效果 | 初始值 | 成长幅度/级 | 上限 | 世界观解释 |
| ---- | ---- | ------ | ----------- | ---- | ---------- |
| 薪柴亲和 | 搜刮节点额外价值 | +0 | +1/级 (对所有档位) | +3 (3级) | 辨识和提取残渣的能力增强 |
| 深度感知 | 进入裂隙时揭示一个随机节点方向 | 无 | 1/2/3个方向提示 | 3级 | 对异源残渣的远程感应力 |
| 模块协同 | 模块效果上限提升 | BARRIER 30% / STORAGE 50% | +5% / +10% per级 | 各3级 | 净化点与守护者之间的共鸣增强 |

#### 轴线 3：生存韧性（"我能承受更多"）

| 升级 | 效果 | 初始值 | 成长幅度/级 | 上限 | 世界观解释 |
| ---- | ---- | ------ | ----------- | ---- | ---------- |
| 生命强化 | 最大生命值增加 | 100 | +15/级 | 160 (4级) | 核心抗性的物理表现增强 |
| 创伤适应 | 受击无敌时间增加 | 400ms | +100ms/级 | 700ms (3级) | 外来攻击的抵御反射加快 |
| 净化共振 | 返回净化点时额外回复模块HP | 0 | +3 hp/级 (每模块) | +9 (3级) | 守护者存在本身对净化点的加固效果 |

### B.3 成长获取方式

**在净化点的"成长界面"中花费薪柴购买升级。**

交互方式：净化点中新增一个交互点（类似现有模块），走近按 E 打开成长面板。面板显示三条轴线的当前等级、下一级效果、费用。

### B.4 成长费用曲线

**递增费用，确保前期成长快、后期成长慢：**

| 级别 | 费用（薪柴） | 累计费用 |
| ---- | ------------ | -------- |
| 1级 | 8 | 8 |
| 2级 | 12 | 20 |
| 3级 | 18 | 38 |
| 4级 | 25 | 63 |
| 5级 | 35 | 98 |

（适用于所有升级项。不同轴线统一费用结构，简化理解成本。）

**关键校准**：
- 1级费用(8) < 一次满载出击收入(10-14)，确保"一次好的出击就能解锁第一个升级"
- 2级费用(12) ≈ 一次满载出击收入，确保"要么修复模块要么成长，不能两全"
- 3级费用(18) > 一次出击收入，确保"需要攒两次才能升级"（推迟满足感）

### B.5 成长曲线与压力的对冲关系

**数学模型**：

设 cycle n 的有效收入为 I(n)，有效支出为 E(n)：

```
I(n) = base_income * (1 + storage_bonus) * (1 + growth_income_bonus(n))
E(n) = impact_damage(n) / REPAIR_PER_KINDLING

其中：
base_income = 实际搜刮量（取决于出击效率成长 → 更快/更远 → 拿更多）
storage_bonus = STORAGE模块当前效果
growth_income_bonus = 薪柴亲和等级效果
impact_damage(n) = BASE_IMPACT_DAMAGE * tide_intensity(n)
```

**渐近分析**：
- 无成长时，I 固定，E 递增 → 必然崩溃
- 有成长时，I 缓慢递增（每次升级 +1-2 kindling/sortie），E 按潮汐波动
- 设计目标：到第 3 个潮汐周期时，玩家的 I 增长率 ≈ E 增长率的平均值
- 到第 5 个潮汐后，E 的增长率趋零（潮汐上限），I 仍可缓慢增长 → 玩家逐渐进入"刚好够"→"稍有余裕"的过渡

**不能让玩家到达"安全状态"的保证**：
- 成长有硬上限（每条轴线 3-5 级封顶）
- 潮汐节奏确保峰值压力始终在"满成长玩家"的能力边缘
- 最终潮汐的峰值设计为：满成长玩家恰好能维持，但没有余裕 → 终极紧绷

### B.6 成长如何改变出击体验

| 成长阶段 | 出击体验变化 | 对应情感 |
| -------- | ------------ | -------- |
| 0级（开局） | 能拿 safe+部分contested，勉强维持 | "活着就好" |
| 1-2级 | 速度/抗性提升，能稳定拿全部contested | "我在进步" |
| 3-4级 | 可以尝试deep节点，偶尔全清 | "我掌控了这里" |
| 5级（满级） | 能稳定拿大部分，但新潮汐的峰值把余裕吃掉 | "更强了但更难了" |

## C. 长期经济平衡

### C.1 潮汐冲击模型（替代匀速递增）

**当前模型**（被替代）：
```
intensity = 1.0 + cycle * 0.15，上限 2.5
```
问题：单调递增，无节奏，无喘息，无希望。

**新模型：潮汐 (Tide)**

```
游戏进程 = Tide 1 → Tide 2 → Tide 3 → ... → Final Tide

每个 Tide 内部结构：
  [涨潮 3-4 cycles] → [潮峰 1-2 cycles] → [退潮 2-3 cycles]
  
intensity 在 Tide 内的变化：
  涨潮：每 cycle +0.20
  潮峰：保持不变
  退潮：每 cycle -0.10
```

**具体数值设计**：

| Tide | 底线 | 峰值 | 涨潮 cycles | 峰值 cycles | 退潮 cycles | 退到 |
| ---- | ---- | ---- | ----------- | ----------- | ----------- | ---- |
| 1 | 1.0 | 1.6 | 3 | 1 | 2 | 1.2 |
| 2 | 1.2 | 2.0 | 4 | 1 | 2 | 1.5 |
| 3 | 1.5 | 2.4 | 4 | 2 | 2 | 1.8 |
| 4 | 1.8 | 2.8 | 4 | 2 | 3 | 2.0 |
| Final | 2.0 | 3.0 | 5 | -- | -- | -- |

总 cycle 数：Tide 1(6) + Tide 2(7) + Tide 3(8) + Tide 4(9) + Final(5+) = 约 35+ cycles。

**每 cycle 对应一次出击**，每次出击 3-4 分钟。总游戏时长约 2-2.5 小时。这符合 `vision.md` 的 Session 级预期（多次 15-30 分钟 session）。

### C.2 潮汐与成长的交互

```
                    Tide 1           Tide 2           Tide 3
Intensity:    ___/‾‾‾\___    ____/‾‾‾‾\____    ______/‾‾‾‾‾‾\
Player Power: ──────/───────────────/─────────────────────/────
                   ↑                ↑                     ↑
              第一次成长投资    稳定多次投资         接近满级
```

- 涨潮期：修复压力增大，成长预算被挤压 → 紧绷
- 峰值期：全部薪柴投入修复，可能还不够 → 最紧绷
- 退潮期：修复压力减轻，可以投资成长 → 希望
- 跨 Tide：因为退潮期投资了成长，新 Tide 的涨潮比上次好应对 → 进步感

**这就是"在明显感受到压力的前提下持有希望"的机制表达。**

### C.3 潮汐预警系统

玩家必须能预见潮汐变化（否则是不可控的随机惩罚）：

- **边界氛围强度**与当前 intensity 正相关（已实现的粒子系统）
- **冲击结果面板**显示：当前 Tide 阶段（涨/峰/退）+ 下次冲击预计强度
- **退潮信号**：连续两次冲击强度下降时，面板文本提示"边界压力趋缓"
- **涨潮警告**：退潮结束后的第一次涨潮冲击，面板文本提示"新一波侵蚀逼近"

### C.4 "游戏进度"的定义

不用"存活轮数"作为进度（那只是耐力计数）。改用：

**净化稳定度 (Purification Stability)**

一个 0-100% 的全局进度指标。规则：
- 每次成功撤离 +2%
- 每次成长升级 +3%
- 每次潮汐峰值被完整度过（无模块归零）+5%
- 每次模块归零 -1%（轻微惩罚，不重挫）

到 100% 时... 游戏进入"终局"（具体终局内容推到更后的 Slice）。

**玩家可见的价值**：这个百分比告诉玩家"你在靠近终点"。即使当前潮汐很难，看到 67% 的进度条会让人想"再撑一下就到了"。

### C.5 经济流速详算

**Tide 1 退潮期（intensity ~1.2）的一个典型 cycle**：

| 项目 | 数量 | 说明 |
| ---- | ---- | ---- |
| 出击收入 | 12 | safe(3) + contested(6) + 部分deep(4) - 未全清 |
| 冲击修复成本 | -9 | 30*1.2/4 ≈ 9 每模块只修复一个 |
| 可用于成长 | 3 | 攒2-3次可以买1级升级(8) |

**Tide 2 涨潮期（intensity ~1.8）的一个典型 cycle**（已有2-3级成长）：

| 项目 | 数量 | 说明 |
| ---- | ---- | ---- |
| 出击收入 | 15 | 成长后效率提升(薪柴亲和+速度+抗性)→能拿更多 |
| 冲击修复成本 | -13.5 | 30*1.8/4 ≈ 13-14，需优先修复重点模块 |
| 可用于成长 | 1-2 | 紧巴巴的，但不是 0 |

**Tide 3 峰值期（intensity ~2.4）（已有4-5级成长）**：

| 项目 | 数量 | 说明 |
| ---- | ---- | ---- |
| 出击收入 | 18 | 接近满成长，效率高 |
| 冲击修复成本 | -18 | 30*2.4/4 = 18，完全吃掉收入 |
| 可用于成长 | 0 | 纯生存模式，只能等退潮 |

**这组数字验证了"边缘感"**：峰值期收支相抵（活在边缘），退潮期有余力（投资希望），涨潮期紧张但可控（成长在帮忙）。

### C.6 如果数值需要调整

**调参优先级**（从最不影响核心体验到最影响）：
1. 潮汐各阶段的 cycle 数（改节奏，不改强度）
2. 成长费用曲线（改投资门槛）
3. 涨潮/退潮的 intensity 步长（改压力斜率）
4. 成长效果的数值（改回报率）
5. BASE_IMPACT_DAMAGE（改绝对压力量级——最后手段）

### C.7 防止"安全状态"的设计保证

即使玩家满级，最终潮汐（Final Tide）的设计保证：
- 峰值 intensity 3.0 → 伤害 90 → 修复成本 22.5/模块
- 满级玩家收入上限约 20-22（成长有天花板）
- 即满级玩家在 Final Tide 峰值期仍然**入不敷出**

这确保了 `vision.md` 的铁律："永远不会到达'安全'的状态。"

### D.3 范围取舍选项（需要用户拍板）

**取舍 1：成长费用来源**

- **方案 A（推荐）**：薪柴直接支付。三向分配：修复 / 强化 / 成长。最贴合 vision.md 的"唯一通用货币"设计。
- 方案 B：薪柴 + 自动累积的"经验"双资源。每次成功撤离自动获得少量经验，升级需要经验等级 + 薪柴。降低了分配纠结感，但减少了"投资成长 = 牺牲当前"的张力。
- 方案 C：纯自动累积（无薪柴成本）。每次出击自动成长。无分配决策，纯手感验证。最小实现量但最无趣。

**取舍 2：潮汐节奏 vs 简化递增**

- **方案 A（推荐）**：完整潮汐模型（涨/峰/退三阶段）。产生节奏感和希望。实现稍复杂（需要 Tide 状态机）。
- 方案 B：分段线性递增（每 5 cycles 停住 2 cycles 不增长作为"喘息"）。简单但缺乏叙事感和"退潮"的明确减压。
- 方案 C：保持匀速递增但调低 INTENSITY_STEP + 提高 MAX_INTENSITY + 成长对冲。最简单实现但没有节奏变化，"希望"完全依赖成长感知。

**取舍 3：进度指标**

- **方案 A（推荐）**：净化稳定度（综合多个行为的进度条）。给出明确"终点"的暗示。需要 UI 空间。
- 方案 B：仅用"已完成的 Tide 数"作为进度（Tide 1/5, Tide 2/5...）。简洁但与游戏行为无直接关联。
- 方案 C：不显示长期进度，仅靠成长等级给出"我在变强"的感知。最小但可能不足以产生"想继续"。

**取舍 4：Slice 3 包含几个成长项**

- **方案 A（推荐）**：3个（每轴1个）。足够验证多轴权衡，不至于选择瘫痪。
- 方案 B：5-6个（每轴2个）。更丰富但实现+平衡工作量翻倍。可能过早引入过多变量。
- 方案 C：1个（仅渗透抗性）。能验证"成长可感知"，但无法验证"多轴分配纠结"。

### D.4 Slice 3 的验证标准

**能验证：**
- "投资成长 vs 修复模块"是否产生和"多拿一个薪柴 vs 撤退"同等级的纠结
- 潮汐的退潮期是否被体验为"希望/喘息"（而非"无聊/空窗"）
- 成长效果是否在 2-3 次出击内可感知（而非"升了级但我感觉不到"）
- 玩家在 15+ cycles 后是否还想继续（对比 Slice 2 的 8-10 cycle 极限）

**预期正面结果：**
- 玩家在退潮期**主动选择少修模块、多投成长**——说明他们相信成长有回报
- 玩家在涨潮期紧张但**不绝望**——说明之前的成长投资在帮忙
- 玩家说出"再撑两轮就退潮了"——说明潮汐节奏被读懂
- 玩家对比早期和后期出击说"现在快/远多了"——说明成长可感知
- 玩家看进度条说"还差一点"——说明长期目标在发力

**不 work 的信号：**

| 现象 | 指向的问题 | 调参方向 |
| ---- | ---------- | -------- |
| 玩家从不投资成长 | 费用太高或当前修复压力太大 | 降低1级费用；拉长退潮期 |
| 玩家全投成长不修模块 | 成长 ROI 太明显 / 模块归零惩罚太轻 | 降低成长效果；加大模块归零的出击debuff |
| 退潮期玩家说"没事干"/"太轻松" | 退潮底线太低 | 提高退潮的底线 intensity |
| 峰值期玩家直接放弃 | 峰值太陡/成长不够追赶 | 降低峰值 / 拉长涨潮给更多准备时间 |
| 进度条推进太快/太慢 | 进度公式不当 | 调整各行为的进度贡献值 |
| 成长感知不到 | 单级效果太小 | 加大单级幅度但降低级数上限（保持总成长量不变） |

## E. 参考分析

### E.1 Darkest Dungeon — 压力与恢复的节奏

**做了什么**：每次远征是一个压力上升过程（Stress系统），远征结束后在小镇恢复（花钱治疗/减压/升级）。但世界不会变强——是英雄变强后去更难的区域。

**可借鉴**：
- "远征后的小镇回合"是天然的投资/恢复窗口 → 对应我们的退潮期
- 压力在远征中单调上升、远征后重置 → 对应我们的混乱值模型（已有）
- 英雄升级花钱且有选择（带谁/练谁） → 对应我们的成长轴线选择

**不借鉴**：
- DD 的成长是"换更强的角色"，我们只有一个角色
- DD 允许失去角色（roguelike式损失），我们不允许永久倒退
- DD 的难度不递增（只是换区），我们的压力在整体上行

### E.2 Hades — 持续成长与可重复体验

**做了什么**：Mirror（永久升级）+ Boon（单局临时能力）。每次失败都推进永久升级和剧情。"失败也是进步"。

**可借鉴**：
- 永久升级的**可感知性**做得极好——每次升级都显著改变体验
- 升级选择给玩家"build 身份感"（我是攻速流/暴击流） → 我们的三轴选择
- 进度条（热度/剧情）给出明确终点感 → 我们的净化稳定度

**不借鉴**：
- Hades 不增加难度（Heat是可选的），我们的压力是强制递增的
- Hades 单局失败=重开，我们是持续进程
- Hades 的临时能力系统太复杂（我们无 boon/perk 系统）

### E.3 FTL — 资源紧缺下的升级决策

**做了什么**：跨 sector 资源紧缺，升级船体/武器是与购买燃料/修复/雇员竞争的。每次升级是一次"赌未来"的决策。

**可借鉴**：
- "用生存资源投资成长"的核心张力 → 完全对应我们的设计
- 升级选择改变应对策略（升护盾 vs 升武器 = 不同 playstyle） → 我们的三轴
- "一次好的 sector 让你有余力升级"的节奏感 → 退潮期
- 最终 Boss 给出明确终点 → 我们的 Final Tide

**不借鉴**：
- FTL 是 roguelike（失败=重开），我们不是
- FTL 的升级是该局限定的，我们的是永久的

### E.4 This War of Mine — "勉强维持"的生存节奏

**做了什么**：夜晚出击搜刮 → 白天消耗（食物/药品/情绪）→ 逐渐建造基地设施（永久）。资源同时服务消耗品+建造两个出口。

**可借鉴**：
- "搜刮回来后在消耗和建造之间权衡" = 我们的"修复 vs 成长"
- 基地设施是永久提升（雨水收集器=持续产出）→ 我们的成长轴线
- 早期极端紧张，中期逐渐稳定但永远有新压力（冬天/突袭） → 我们的潮汐

**不借鉴**：
- TWoM 中后期可以真的稳定下来（成功存活=赢了） → 我们不允许安全状态
- TWoM 的"出击"缺乏我们的时间压力（混乱值）

### E.5 Into the Breach — 完美信息下的优化

**做了什么**：每关完全可见，无随机。成长来自完美执行的奖励。

**可借鉴**：
- "冲击预告"的设计思路（告诉玩家下一波攻击什么方向）→ 我们已有（forecast 准确率 80%）
- 不靠数值碾压解决问题，靠理解系统 → 我们的成长应该是"更多选项"而非"碾压数值"

**不借鉴**：
- ItB 无持续进程，我们需要跨session的成长
- ItB 的"完美信息"与我们的"有限视野"相矛盾

### E.6 综合结论

最接近我们设计的参考组合：
- **经济结构**：FTL（一种资源、多个出口、投资未来 vs 活过当下）
- **节奏模型**：Darkest Dungeon（出击→恢复→出击的呼吸节奏 + 整体递增压力）
- **成长感知**：Hades（每次升级显著改变体验 + 明确的长期进度条）
- **氛围基调**：This War of Mine（勉强维持、投资基建的"活着就是胜利"感）

## F. 实现注意事项

### F.1 对已有系统的影响

| 系统 | 需要的变更 | 复杂度 |
| ---- | ---------- | ------ |
| GameState | 新增：growth levels, tide state, stability progress | 中 |
| ImpactSystem | 重写 intensity 计算（匀速递增 → 潮汐状态机） | 中 |
| ChaosSystem | 接收 growth modifier（渗透抗性） | 低 |
| LootSystem | 接收 growth modifier（薪柴亲和） | 低 |
| Player | 接收 growth modifier（行动效率 → 速度；生命强化 → maxHP） | 低 |
| PurificationScene | 新增成长交互点 + 面板 | 中 |
| 冲击结果面板 | 新增 Tide 阶段显示 + 净化稳定度 | 低 |
| HUD | 新增净化稳定度显示（小型进度条） | 低 |

### F.2 新增系统

| 系统 | 职责 |
| ---- | ---- |
| GrowthSystem | 管理成长等级、计算效果modifier、处理升级请求 |
| TideSystem | 管理潮汐状态机（取代现有的匀速递增逻辑） |
| ProgressTracker | 管理净化稳定度计算 |

### F.3 持久化影响

当前 GameState 是 session-only（页面刷新重置）。Slice 3 的成长系统意味着**玩家需要跨session保留进度**。这需要引入 localStorage 存档，至少保存：
- growth levels
- tide 进度（当前 Tide + cycle within tide）
- stability progress
- module 状态

这是一个架构层面的扩展（roadmap 中的"持久存档"提前了）。**建议 Slice 3 将 localStorage 存档作为 P0 一并实现**——否则一次 2 小时的游戏进程无法跨 session 验证。

### F.4 世界观影响

需要在 `world.md` 中追加的设定：
- 玩家为什么能"成长"：反复暴露于异源模式的副产物——身体产生的不是"免疫"，是"部分适应"。这不违反"覆盖不可逆"规则（玩家不是在治愈自身的污染，是在适应外部的污染模式）。
- 潮汐的叙事理由：本时空的污染不是匀速推进的，而是像潮水一样有周期性的涌退。退潮不意味着"变安全了"，只是"暂时推进速度减缓"。
- 净化稳定度的叙事：净化点边界的结构完整性在玩家持续加固下逐步恢复——不是"扩张"（违规），是"变得更稳定/更难被突破"。

## G. 开放问题（待设计深化时决定）

1. **满级之后怎么办？** 当所有成长到顶后，游戏的"希望"来源从"我还能变强"转变为"我在接近终点"。净化稳定度必须在满级前就开始有意义，否则满级=动力断裂。

2. **程序化地图如何放大成长感知？** 固定地图上，速度+5%的感知很弱。如果地图是程序化的（每次不同），成长效果的感知可能需要更强的UI反馈来补偿。

3. **成长选择是否有重置/重选机制？** 如果玩家选错了成长路径，是否有"洗点"？建议暂时不做——选择的不可逆性增加决策权重，且3个选项不容易"选错"。

4. **多存档支持？** 如果引入持久化，玩家是否需要多个存档槽？vision.md 明确"不做多存档"。单存档+手动删除重开。

5. **Final Tide 的具体内容？** 推到 Slice 5+ 设计。Slice 3 只需要让玩家看到进度在推进。

## H. 总结：为什么这个设计回答了核心问题

> "在有成长回路的情况下，压力递增 + 能力递增的动态平衡是否让人想继续？"

本设计给出"想继续"的三个理由：

1. **短期**：每次投资成长后，下一次出击明显更顺畅（可感知的进步）
2. **中期**：潮汐退潮期是投资窗口，涨潮期是验证窗口（节奏感 = 有呼吸的紧张）
3. **长期**：净化稳定度告诉玩家"你在接近终点"（终点存在 = 希望存在）

如果以上三条中的任何一条在试玩中不成立，那就是调参的信号而非设计方向的问题。设计方向本身的验证条件是：**三条同时成立时，玩家是否表达"想再来一局"**。
