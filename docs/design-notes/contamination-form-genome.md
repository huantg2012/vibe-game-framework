# 污染句法的外形基因谱（诊断 + 方案）

**TL;DR：** 污染句法在纸面与逻辑层是够用的，但美术管线的形状是「基体查表拿一张手写画 → 再刷污染漆」，所以**形体身份的总数等于手写分支数**（甲 15、丙 2–3、丁 3、乙 2，合计约 22）。陈列馆 522 格是这 22 个设计各展示约 24 次。方案是把管线改成三层组合式生成：基体给**骨架语法**、构件库跨基体共享、覆盖深度给**结构违规预算**，污染漆最后才刷。另外修一条独立缺陷：五张世界碎片的污染配色里四张逐字节相同、且整套 ramp 不含青绿。

## 一、诊断（代码级，可复算）

### 1. 覆盖深度在甲身上物理上不可能改剪影

`paintJiaSilhouette(buf, family, variant, facing, d, ink)` 的签名里没有 `coverage`。覆盖度只能走污染漆：`clusterPlan` 把簇从 17 像素加到 32 像素，`punchIntact` 做棋盘挖洞。

量化（`measure:contam-distinct` B 组）：同一只从改写到覆盖，粗占格距离 0.0059–0.0156；灯柱 / 残茎 / 栏柱三个恰好都是 **0.0059**。丙的覆盖度是 `holeChance` 0.30/0.12/0.02、`breathAmp` 0.06/0.12/0.18、半径 0.86/1.00/1.12；丁是 `edgeAlpha` 70/95/120、`coreAlpha` 160/190/220。三张孔谱的覆盖度都是**健康度滑块**，不是疯狂阶梯。

非生物基底更明显是因为灯柱 / 栏柱 / 残茎的剪影本来就都是竖杆——一根竖杆上加几颗青绿点，三档之间无处可差。

### 2. 族内变体只有 3 个手写分支，差异 ±2 像素

`jiaVariantOf` 是 `mix32(seed, substrate) % 3`。三个分支的全部差别：`wide = v===1 ? 2 : 0`（肩宽 ±2px）、`reach = -2`（臂短 2px）、`punchSeam` 一条 1px 竖缝。32 像素画布上是 6% 轮廓变化。

量化（A 组）：16 个随机种子跑同一基体，去重后只有 **3** 个不同剪影，五个基体全是 3/16。种子在甲的外形上几乎没有作用域。

### 3. 丙的基体只选长宽比，不选形状

`substrateShape()` 三个分支里两个都是 `thin: true` 扁带（油膜 1.35×0.28、灰幕 1.52×0.18）。丙实际只有两个形体身份：圆瓣团、扁带（重复两次）。162 格陈列，两个设计。

### 4. 五张世界碎片只改色不改形，且四张的污染配色逐字节相同

`deriveFragmentContamRamp` 实测输出：

| 碎片 | deep | mid | core | glow |
| ---- | ---- | --- | ---- | ---- |
| frag-outdoor | `#3a3d42` | `#3a3838` | `#4a4e55` | `#5a5f66` |
| frag-metro | `#3a3d42` | `#3a3838` | `#4a4e55` | `#5a5f66` |
| frag-library | `#3a3d42` | `#3a3838` | `#4a4e55` | `#5a5f66` |
| frag-residential | `#3a3d42` | `#3a3838` | `#4a4e55` | `#5a5f66` |
| frag-clinic | `#3a3838` | `#0e4a3f` | `#5a5f66` | `#8a8f96` |

**这套 ramp 里一点青绿都没有。** 屏幕上的青绿全部来自事后 `clampCoreTeal` / `snapBright` 把灰色硬钳到三个青绿之一，所以只有 core / glow 两个 accent 是青的；`deep` 和 `mid`（崩坏侧的整个身体、溶散喷点、丙的大部分面积）永远是灰的。

**根因在标度，不在系数。** `rift-fragments.csv` 的 `floor_bv` / `wall_bv` 是 24–30，而 `deriveContamRampCopy` 按 0–255 处理它们。于是 `mapV ≈ 0.10`，`val` 被自己的 `Math.max(0.36, mapV + 0.18)` 下限钉住；唯一还带信息的色相是三个几乎相等的暗通道之间的噪声，往青绿轴只拉 52% 之后，`quantDistinct` 就近落到 `metal-grey`。

同一个标度问题也吃掉了基体残影那条纪律：「按该碎片 L1 混 12–18% 让五种碎片肉眼有色温差」——混的目标色本身接近纯黑（约 rgb(22,26,21)），混完再量化回 36 色板，通常снап 回同一格。

`docs/art/contamination-forms.md` 明写「只换地板 bias、敌人仍用同一组写死 teal = 没做本题」。现在的代码名义上调了 ramp 函数，实际结果正是它禁止的那件事。**这是缺陷，不是取舍。**

### 5. 方法论：「长得不一样」从来没有被验证过

`visualKeyOf` 返回的是参数元组字符串（`portfolio|substrate|coverage|continuity|sense|…`），从不读一个像素。`docs/tasks/iteration-4.md` 的「静帧占格表」是人判断的「哪些字段会改像素」，硬编码在目录里。所以陈列馆的 522 是**被认为**会改像素的参数组合数，不是量出来的形体数。

## 二、三个反转

1. **基体不是「哪张画」，是「用什么零件、按什么规则长」。** 基体给一套构件库 + 一条骨架语法；剪影由种子在语法里长出来。这正是本仓库地图那条已验证的规则（`map-generation-strategy.mdc`：抽风格锚 + 新种子 + 邻域抖动，不搬画廊静帧）。敌人现在犯的，就是那条规则明令禁止的错。
2. **覆盖深度不是浓度旋钮，是结构违规的阶梯。** 疯狂在美术上不是更多漆，是**违反自己的身体规则**：数量违规、对称违规、尺度违规、层级违规（自相似）、朝向违规、拼贴违规、放射化。覆盖度三档 = 违规**预算**三档；同一档抽哪几条由种子决定，所以同基体同覆盖度也疯得不一样。
3. **变体不该是 `% 3`，该是骨架参数的连续采样。** 节数、间距、粗细、倾角、分叉点、不对称量——组合空间上千。

## 三、三层管线（方案）

| 层 | 输入 | 输出 | 谁决定什么 |
| -- | ---- | ---- | ---------- |
| 骨架语法 | 基体 + 种子 + 碎片偏置 | 一组节点（位置 / 尺寸 / 朝向 / 角色） | 基体给语法，种子给采样，碎片给偏置 |
| 构件库 | 节点 | 像素构件：杆 / 梁 / 团 / 座 / 丝 / 碎 / 核 | 构件**跨基体共享**——这是「基因谱」的物质基础 |
| 违规预算 | 覆盖深度 + 种子 | 作用在**骨架**上的违规算子 | 覆盖度给条数，种子抽哪几条 |

污染漆（deep 铺崩坏侧、core 成簇、mid 溶散）**最后才刷**，语言不变，所以它不再是差异的唯一来源。

三条关键性质：

1. 形体身份数从「基体数 × 3」变成「基体数 × 种子空间」。
2. 覆盖度**必然**改剪影，因为它改的是骨架。
3. 碎片可以偏置骨架语法（诊所的杆更细更多、地铁的框更厚），不只是换配色。这才兑现「为不同世界碎片派生出五花八门」。

### 违规算子清单（原型已验证可画）

| 算子 | 违反什么 | 怎么读 |
| ---- | -------- | ------ |
| 数量 | 主构件数量翻倍到三倍 | 茎 3 根变 13 根 |
| 对称 | 一侧构件整体拉长 / 加粗 | 从两侧平衡变单侧崩坏 |
| 层级 | 在某构件上递归长出缩小同族骨架 | 门框上长出小门框 |
| 拼贴 | 挂上另一个基体的签名构件 | 灯柱长出残茎；栏柱顶了门楣 |
| 朝向 | 构件在自己的锚点上转 90° 或反向弯 | 梁竖起来、丝往回长 |
| 尺度 | 某构件放大到压过本体 | 核比杆粗、头比躯干大 |
| 放射 | 线性骨架变放射对称 | **只在覆盖档解锁**——变放射立刻读作「不再是这个世界的物件」，这张牌不能早打 |

预算：渗透 1 条、改写 3 条、覆盖 5 条。

### 违规不得拆散身体（连通纪律）

任何构件必须与其他构件相接；不相接的拉回最近构件（原型里的 `weld`）。这条和地图生成的连通纪律同源：**先保证是一个东西，再谈它有多疯。** 飘着的碎片读作 bug，不读作疯。

### 丙：基体选拓扑，不选长宽比

三个基体应该是三种**拓扑**，不是三种长宽比。旧失败：油膜与灰幕都是 `thin: true` 扁带，塌成同一个身份。覆盖度是拓扑违反自身：

| 基体 | 拓扑 | 覆盖档的拓扑违规 |
| ---- | ---- | ---------------- |
| 菌毯 `fungal_mat` | 团（嵌套瓣） | 子团顶破外沿；中心挖空，团裂成环 |
| 油膜 `oil_film` | **三变体，种子采样（DEC-101）：** 聚珠成滩 / 沾抹拖尾 / 薄滩收边 | 各变体自己的违规：聚并过度 / 抹了一遍又一遍 / 漫出第二滩。禁止用换变体冒充覆盖档 |
| 灰幕 `ash_veil` | 环（带孔覆层） | 环里再嵌环 |

**现行（DEC-101，2026-08-27 人锁定）：油膜 = 聚珠成滩 / 沾抹拖尾 / 薄滩收边三变体，种子采样。** 不进 CSV。每枚油膜污染体用该 form 的渲染种子抽一支，再在该读法里采珠心 / 抹向 / 滩形。抽卡课 A/B/C（树参数 tweak）是历史对照，生产不采样。优化不许换读法（珠 / 抹 / 滩）。

- 菌毯 = 团（嵌套瓣）：实心、连成一坨。
- 油膜 = 三种无机「沾」的读法：聚珠成滩（表面张力收成珠、珠子聚并成滩）；沾抹拖尾（被从簇心抹开的一道，头厚尾薄）；薄滩收边（内部薄到只剩底色，边缘一圈弯月亮线；内部薄但有，与灰幕「环是本体、中空」分开）。
- 灰幕 = 环（带孔覆层）：中空、盖在已有地面上。

丙的呼吸仍走 DEC-070 / DEC-071 那一套整团胀缩，不另写第二套。油膜三变体各有呼吸方式（逐珠相位差 / 沿抹向伸收 / 径向胀缩 + 峰值提亮边缘），「整团」指同一污染体。

**为什么油膜 = 树（2026-08-27 登记；已被 DEC-101 取代，留作历史）：**

当时要三种拓扑，不是三种长宽比。油膜写成树（分支脉络）：油在地面 / 墙上不是实心团，是沿阻力最小路径爬开的细脉；剪影稀疏、能读成线，和菌毯的实心团拉开。覆盖档当时 = 末端互连闭成回路。人先读成菌丝（可接受偏差）；再看太像线不是细脉，抽卡。第二轮从「油膜做污染体基底」原初 idea 重抽得到三支非树读法。人 2026-08-27 19:18 锁定这三支为身份。树方案不再是生产默认。禁止把油膜改回扁带，也禁止加有机细节。

### 污染方言（配色修复）

停止把碎片 bias 当**颜色目标**去量化，改成在色板既有的青绿家族里做**选择器**。原型按 `rift-fragments.csv` 的 `surface_material` 分：土壤偏苔绿、瓷砖偏冷白、金属偏蓝、木头偏暗青、灰泥偏亮青。全部取自 `palette.json` 已有条目，**不加新色**。

真实版本应该是 `rift-fragments.csv` 新增一列污染方言，走项目的 CSV → code 方向；不要在渲染器里写分支。亮核仍只许 `#1aad96` / `#2ae6c8` / `#3cffd4`，亮核仍要克制（原型的做法是整场压到 deep/mid 区间，再撒少量核点）。

## 四、机器闸门：粗占格判别度

把 alpha 掩膜降到 6×8 的占格率再比 L1 距离，配合去重计数。

建议闸门形状（阈值待第一批落地后按实测定）：

1. 同基体同覆盖度取 N 个种子，**去重剪影数必须等于 N**。
2. 相邻覆盖档的粗占格距离必须大于阈值（现状 0.0059 必须判 FAIL）。
3. 跨基体的粗占格距离必须大于阈值。

**不要用 IoU 当闸门。** 这套美术里有大量 1–2 像素宽的杆；两根同样的杆错开 2 像素，IoU 掉到 0.07，机器判「完全不同」，人读「同一根杆」。第一版度量用的是 IoU，A 组和 C 组的结论整个反了（栏柱现状 IoU 0.071 = 判很不同，粗占格 0.0081 = 判几乎相同；后者与人眼一致）。改成粗占格描述子之后每一列都自洽。

### 现状与原型实测

| 指标 | 现状 | 原型 |
| ---- | ---- | ---- |
| 同基体同覆盖度 16 种子，去重剪影数 | 3 / 16（五个基体全是 3） | 16 / 16 |
| 同基体同覆盖度，粗占格距离中位数 | 0.008–0.032 | 0.057–0.187 |
| 改写档到覆盖档，粗占格距离 | 0.0059–0.0156 | 0.031–0.125 |
| 跨五基体粗占格距离中位数 | 0.0413 | 0.1475 |

必须记下的一处例外：有机残影从渗透到改写，现状 0.0892 大于原型 0.0166。原因是现状画布从 32 高变 48 高把整块质量挪了位，不是结构变了。**所以闸门不能只有一个数**——去重计数是那条不会被这类假动作骗到的。

### 纠正 1：「碎片」= 不同世界，不是同一个世界的多块

人的定义：**每一张碎片来自一个不同的世界**，不是同一个世界破碎后的多个片段。`world.md` 与此一致且更明确：

- `world.md:36` 每个时空碎片是一个独立的"被改写区域"，由**不同的外来存在（污染源）各自覆盖**；彼此**互不通信**。
- `world.md:105` 每次进入裂隙 = 进入一个其他时空的碎片。
- `world.md:116` 异时空碎片（**另一个完全被覆盖的时空**的局部片段）

后果：两张碎片看起来像同一个地方，不是打磨问题，是设定层的失败。

### 纠正 2：碎片身份由 L1 承担，污染层不许承担

我曾提议「让污染层承担色相分工（户外偏绿青 / 医院偏白青 / 地铁偏蓝青）」。**这条撤回**，它违反已锁方向：

- `art-direction.md` §TL;DR 四层色彩架构：**碎片记忆色（L1，区域底色温差）** + 污染色谱（L2，**teal 光谱内**偏移）+ 玩家暖光（L3）+ 稀有叙事色（L4）。
- §1.2 规则 3：**区域差异靠底色色温 + 材质纹理区分（L1），不靠改变污染的表达方式。**
- §5.2 规则 6：**碎片切换 = 色温切换。**

所以：碎片身份 = L1 底色色温；污染仍只在 teal 内偏移。污染层的任务只是「读得出是污染」+「与该碎片底色保持对比度下限」，不是替 L1 表达世界身份。

### 纠正 3：污染亮度走「协同但不提亮」

不动 `art-direction.md` 调性、不动 `palette.json`。污染四档与该碎片底色构成关系并保证对比度下限，整体明度与饱和仍在现行调性内（深档暗青绿 `#0e4a3f`，核 `#2ae6c8` 一档）。**色板亮端整只发光那一档不采纳。**（对照样本第三栏仅作参考，不是标准。）

### 新根因：L1 塌陷，与 L2 塌成灰同源

`measure:l1-reach` 实测：色板里**有 4 个暖色暗格**（`#2a2420` lum 37、`#2a1f1c` lum 34、`#2a2018` lum 33、`#24221e` lum 33），最暗的暖格 lum 33。而 CSV 里**所有碎片的 `floor_bv` 是 24–28**。

| 碎片 | `floor_bv` × bias 目标 | 意图色温 | 实际可达第一名 |
| ---- | ---------------------- | -------- | -------------- |
| frag-outdoor | rgb(23,27,21) | OLIVE | `#1a1e18` OLIVE ✓ |
| frag-clinic | rgb(24,26,30) | COOL | `#1a1c1f` / `#151a1e` COOL ✓ |
| frag-metro | rgb(26,21,17) | **WARM** | `#1a1e18` **OLIVE**（前四名里没有暖格） |
| frag-library | rgb(28,22,19) | **WARM** | `#1a1e18` **OLIVE** |
| frag-residential | rgb(30,24,20) | **WARM** | `#1a1e18` OLIVE（暖格 `#2a2018` 排第四，d=216） |

**CSV 的暖色 bias 方向写对了，但 `floor_bv` 比色板最暗的暖格还暗，所以暖色永远到不了。** 三张想做暖世界的碎片全部塌到同一个橄榄格 `#1a1e18`。冷世界能表达是因为色板有 lum 17 / 26 的冷格。

这与污染 ramp 塌成 `metal-grey` 是**同一个错误的两个后果**：把 bias 当颜色目标去无约束量化，而 `bv` 的标度不足以在色板里落到任何有色格。

统一修法原则：**先按偏置定色温组，再在组内取最近色**（允许亮一点也要保住色温），而不是全色板取最近色。这条同时修第一层和第二层，且不动色板、不整体提亮。**I6-0 已收口（DEC-089）：** 采用本条量化策略；否决提高地板亮度与给色板加更暗的暖格。

### 纠正 4：灯柱与栏柱合并；加生物类基底

- **合并**：灯柱 + 栏柱 → 一个「街具残骸」基体，灯柱 / 栏柱 / 标牌杆做变体。理由：它们在原型里共享同一条语法骨干（竖杆 + 底座），差异只有杆数与梁数，48 像素里不够；两个基体名额换一个视觉身份不划算。腾出的名额给生物类。
- **加生物类基底**：虫（多足、横向对称）、哺乳动物（四足、纵向）、大号蠕虫（无足、分节长条）。理由：会走路的甲是玩家最常近距离看的孔谱，而它的合法基体里只有两个是生物；这三条语法的体轴与肢数根本不同，差距远大于灯柱对栏柱。
- **禁忌读法（人已确认，写进 HOW）：基体是被污染的「原物残余」，不是污染的形态本身。** `art-direction.md:344` 的核心是「污染破坏的不是身体本身，是构成这个像素世界的渲染规则」。禁忌（`art-direction.md:66` 触手 / 内脏 / 血浆 / 虫卵 / 黏液 / 有机腐烂；:376 污染不是有机的；`world.md:181` 偏好几何异变 > 生物恶心）禁的是**污染呈有机恶心形态**，不是**原物曾经是动物**。「一头哺乳动物的残余，它的渲染坏了」合法。

人的原话：档位不够就拆档位。

#### 三处被当成天花板的写死分支

| 表面现象 | 实际是什么 | 拆法 |
| -------- | ---------- | ---- |
| 「质量语法只有 3 种，四张世界不够分」 | `masses.ts` 的 `buildMass()` 里三行 if，分派到三个手写格子生成器（`ridgeCells` / `slabCells` / `enclosureCells`）。三者共用同一套参数结构 | 改成参数向量（见下表）。三个现有语法 = 该向量的三个预设 |
| 「渍色只认 3 个键」 | `preview-paint.ts:151–156` 的 `stainRgb` 是三行 if 返回硬编码 RGB | 改成按键查 `palette.json`。36 个条目全部可用 |
| 「划痕方向只有 3 个枚举」 | `masses.ts:820–821` 返回固定角度（0 或 π/2） | 本质是角度分布：主角度 + 离散度两个参数即连续 |

#### 质量语法的参数向量

| 参数 | 现在被写死成 | 拆开后取值 |
| ---- | ------------ | ---------- |
| 错位周期 / 幅度 | 脊「每 4 格移 1」；板片与隔断为 0 | 周期 ∈ {0, 2, 3, 4, 6} × 幅度 ∈ {0, 1, 2} |
| 缺口数 / 位置 | 板片「正中一个」；隔断走 `biteGap` | 数量 ∈ 0..3 × 位置 ∈ {居中, 端部, 随机} |
| 转折数 / 转角 | 隔断「L 形一转」；其余 0 | 转折 ∈ 0..2 × 转角 ∈ {直角, 回折} |
| 末端附件 | 脊 2 格短杵；板片 2×2 墩 | ∈ {无, 短杵, 方墩, 加宽} |
| 次轴宽度 | `Math.min(2, featureWidthTiles)` 夹死 | 放开上限（参数空间；**本轮配方地铁锁 2、不放开钳，见 DEC-095**） |
| 朝向策略 | 每个残块独立随机 | 世界级 ∈ {全随机, 主轴对齐, 正交交替} |

组合空间数百到上千，远超世界张数的需要。

#### 重构的安全证明（机器可核）

三个现有语法必须是该向量的三个预设，且**逐字节复现现在的输出**：

- 脊 = `{turns: 0, jogPeriod: 4, jogAmp: 1, gaps: 0, cap: 'stub'}`
- 板片 = `{turns: 0, jogPeriod: 0, jogAmp: 0, gaps: 1, gapPlacement: 'center', cap: 'pier'}`
- 隔断 = `{turns: 1, jogPeriod: 0, jogAmp: 0, gaps: 1, gapPlacement: 'mid', cap: 'none'}`

这条闸门让重构与内容扩张分开：先证明等价，再加新参数点。

#### 被这条修正消掉的待办

1. **居民区公寓的簇语法「未实现」——消掉。** 它是「转折 0、长度短、数量多、缺口多」的一个参数点，不是缺一个生成器。原 backlog 条目应改写而非保留。
2. **「地物段数不可用」——判断错，但修法比我第一版说的复杂。** 真因在 `masses.ts` 的 `gridWant`：候选摆放点数由 `cap - 4` 一带决定，与 `min` 贴太近时一次摆放失败就整体失败。

   **I6-P 已把公式改成 `min(cap, max(min + 1, cap - 4), max(min, wallBudget / 8))`。这个改动对现有内容是惰性的**（现有段数 12–24 时 `cap - 4 = 20` 仍然胜出），这也是等价快照能逐字节通过的原因之一。**但它没有解开低段数。** 改后实测（旧图书馆，5 个种子）：

   | `min` | `cap` | `gridWant` | 成功率 |
   | ----- | ----- | ---------- | ------ |
   | 8 | 24 | 20 | 5/5 |
   | 8 | 16 | 12 | 5/5 |
   | 10 | 16 | 12 | 5/5 |
   | 8 | 13 | 9 | 4/5 |
   | 10 | 14 | 11 | 4/5 |
   | 8 | 11 | 9 | 2/5 |
   | 6 | 9 | 7 | 0/5 |

   所以我第一版写的「修 `gridWant` 或让 `cap ≥ min + 5` 即可」是错的。实测安全区是 **`gridWant ≥ 12` 且 `gridWant ≥ 1.2 × min`**；低于此偶发失败，`gridWant ≤ 9` 基本不可用。地物段数确实可以当分化轴，但**取值必须落在这个安全区内**，不能任意压低。

   当前身份配方全部在安全区（户外 12–24、医院 14–22、地铁与旧图书馆 10–16、居民区 18–24）。若将来某张世界需要「少而大的残块」（`gridWant < 12`），必须先查 `placeMasses` 里除候选点数之外的失败原因（怀疑与 `maxOpenYard` 的提前 break 有关），不要靠继续调 `gridWant` 硬试。**DEC-096：** 这是摆放成功率诊断，不是验收写死「每张都必须 ≥12 段」。机器验收下限读策划表 `feature_count_min`（地铁 / 图书馆 10–16 合法）。

#### 仍然成立的两条

- **底色色温确实不可用**（色板亮度 < 32 无暖格，量化擦掉暖色）。这一条是色板与压暗纪律的真实冲突，不是写死分支，DEC-093 的换向仍然正确。
- **`wall_body_key` / `wall_rim_key` / `l1_key` / `source_domain` 确实零消费**；`surface_material` 只接脚步音。这些是死数据，要么接线要么删列，不要靠它们表达身份。

#### 纪律（写给后续所有批次）

遇到「档位不够 / 只有 N 种 / 需要补资产」这类结论时，**先去看那个 N 是不是一段手写 if**。本项目已经两次栽在同一处：敌人的 15 张手写剪影、世界的 3 种手写质量语法。判断「需要造新东西」之前必须先证明现有分支已经参数化到底。
