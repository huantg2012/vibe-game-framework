# 裂隙拾取物：读条与翻找（机制设计正文）

**TL;DR：** 薪柴与污染物节点统一为「可翻找对象」：外观不泄露内容物，走近按住 E 读条 1200ms，读条开始发一次 suspicious 级噪音（96px），松开 / 移动 / 攻击 / 工具 / 受击即打断且进度清零；读条完成才揭晓内容物——薪柴走既有右上 +N 通道（teal 余晖世界内揭晓 / warm-dim HUD），残渣走新增 toast-inline 星等通道（teal ramp，与 UI 稀有度色谱同一份）。数据层仍分 `kindlingNodes` / `contaminantNodes` 两个数组，ruminate 与深渊之眼契约按本文改口。无新事件、无 payload 变更。

## 背景与现状真相（代码级，可复算）

- `src/systems/loot-system.ts`：薪柴节点。金色晶体三角 sprite（0x8a6020，12×12——**与 art-direction §5.3 的 teal 余晖不一致，是现状漂移**），Arcade overlap 触碰即拾取，呼吸脉冲 alpha = 可见性 × 呼吸，depth 15。拾取后发 `KINDLING_COLLECTED { amount, total }`。tier 分 safe / contested / deep，价值 1 / 2 / 4。
- `src/systems/contaminant-node-system.ts`：污染物节点。紫色圆球 sprite（0x7722aa 系，12×12——**紫色在 art-direction 无登记，同为漂移**），同样 overlap 拾取，更快脉冲 + 旋转。拾取时按权重 roll 稀有度（60/30/10）与类型，调 `contaminantSystem.acquire`（内部 emit `CONTAMINANT_ACQUIRED`）。
- **现状缺口：污染物拾取没有任何即时 HUD 反馈。** `CONTAMINANT_ACQUIRED` 只被 RiftScene 消费（记入结算清单），rift-hud 不监听。玩家在裂隙里捡到污染物时，屏幕上零反馈（只有世界内 sprite 消失）。人的需求 ③（揭晓动画）正是补这个洞。
- 键位现状：E = 撤离确认（JustDown 边沿触发，触发半径 48px）；Space = 攻击；Q/F/G = 工具；R = 结算后返回。输入读取归 RiftScene。
- `LOOT.PICKUP_RADIUS: 16` 是名义参数——代码里无任何引用（拾取判定实际是 sprite 碰撞体 overlap）。改口后由 `SEARCH_RADIUS` 取代。
- 噪音现成档位（`system-combat` → `AISystem.reportNoise`）：挥击 96px suspicious / 命中 160px alert / 击杀 192px alert。改写体听觉为主：移动听觉 150px、停步 ≤40px 且察觉度封顶 0.20。
- 深渊之眼（rare 工具）：现状只揭示敌人与**薪柴**节点（`getKindlingPositions`，规则 30g），不含污染物节点。
- ruminate（反刍之口）：消费 `contaminantNodes.getCollectedPositions()`（已拾取**污染物**节点位置）。注意 CSV 描述写「空薪柴节点」——与代码消费对象的既有漂移，记录在案，不在本迭代修。
- 死亡路径真相：死亡只清零薪柴（`RunController` lastKindling = 0）；已 acquire 的残渣留在库存，不回滚。

## 人的需求（2026-08-30，逐字三条为一组）

1. 拾取方式调整：触碰拾取 → 需要读条（持续按键）拾取。
2. 拾取物模型调整：两种颜色不同的发光模型 → 统一为需要「开启」「翻找」的对象，玩家不能直接通过外观区分内容物。
3. 拾取物动画调整：因 ①+②，完成拾取后需要动画让玩家感知拾取到的是薪柴还是污染物。

硬性要求：三条涉及视觉效果，统一抽卡——gym 新增抽卡 lesson 展示 3 张卡（每卡 = 读条表现 + 统一翻找对象外观 + 结果揭晓动画的完整组合），人抽完拍板才翻生产默认。**本文只管机制层与信息层；三张卡的表现层设计归合同 + code + art。**

## 十二条决策（T1 职责内拍定，不问人）

### 1. 读条时长：统一 1200ms，不按档、不按内容物

**结论：全部可翻找对象统一 `SEARCH_CHANNEL_MS = 1200`（建议值，待试玩校准）。住 `constants.ts` 的 `LOOT` 段，不走 CSV。**

- 不按内容物分（薪柴 / 残渣不同长度）：读条时长若随内容物变化，时长本身就泄露了内容物——直接违反需求 ②。
- 不按 tier 分（safe / contested / deep 不同长度）：tier 的成本已经由位置定价（规则 20：绕路 + 巡逻窗口），读条时长分档的校准收益小；而统一时长与混乱值「匀速、可预测」的设计纪律同源——玩家必须能脑内估算「翻一个 = 多少秒」，估算成立，纠结才成立。若试玩证明 deep 档翻找太便宜，首选校准旋钮是 deep 的布点环境（巡逻密度），不是读条时长分档。
- 数值依据：BASE_RATE 0.5/s（DEC-024 已落地），一次读条 = 0.6 点混乱；一局 11 个节点全翻 ≈ 6.6 点 ≈ 13 秒等效时间，占全清预算（约 220 s）的 6%——能感知、不主导。1200ms 足够读作「停下来翻找」而不是「点一下」，又不至于 11 次/局变成拖沓。
- 不走 CSV 的理由：这是交互手感常量（与 `PICKUP_RADIUS` / `EXTRACTION.SETTLE_DELAY_MS` 同类），不是策划内容条目（物品 / 敌人 / 技能定义）。策划数据源规则管的是内容条目，不管系统常量。

### 2. 键位：复用 E；同一时刻只有一个交互上下文，近者胜，同距撤离优先

**结论：翻找复用 E 键（按住读条）。不新增键位。**

- 交互习语已建立：撤离按 E、净化点模块按 E、改造祭坛按 E。「对世界里的东西做动作 = E」是本项目唯一交互动词键，新增键位是习语分裂。
- 撤离是「按下即触发」（边沿），翻找是「按住读条」（持续）。同一键两种按法**不靠点按 / 长按区分**——靠上下文：同一时刻只存在一个交互上下文，取距玩家更近者（撤离点触发半径 48px vs 翻找交互半径 48px）；同距（同帧同像素距离）时撤离优先——撤离点位置固定、是全程导航锚点，玩家对它的空间预期更强。
- 提示文案随上下文切换：`[E] 撤离` / `[E] 翻找`，同一时刻只显示一条。玩家在按键前看得见当前上下文是什么——这是防误触的唯一手段（规则 22 的防误触精神在双上下文下的延续）。
- 边界承认：翻找对象落在撤离半径内时，想翻找但站得离撤离点更近的玩家会按出撤离。此风险由「提示先行、文案分明」缓解；布点原则不动（规则 20/21 不在本迭代范围），重叠属低频。写进 spec 边界情况表。

### 3. 打断规则：松开 / 移动 / 攻击 / 主动工具键 / 受击——任一即打断，进度清零

逐条结论：

| 输入 / 事件 | 结论 | 理由 |
| ---- | ---- | ---- |
| 松开 E | 打断，进度清零 | 读条是「按住」语义的本义。保进度会鼓励「蹭一下走开再回来续」，把一次决断拆成多次零成本试探，破坏「停下来翻找」的承诺感 |
| 移动输入 | 打断，进度清零 | 翻找 = 停手停脚的世界内动作；「边翻边退」在幻想与机制上都不成立。不锁移动输入——玩家想动就是放弃翻找，动即断 |
| 攻击输入（Space） | 打断，进度清零 | 被逼近时玩家必须能立刻放弃翻找反击。不锁攻击——任何「想做别的」都读作放弃 |
| 主动工具键（Q/F/G） | 打断，进度清零 | 同上，一致性优先：读条期间任何非 E 动作输入都打断 |
| 受击 | 打断，进度清零 | 「读条期间被抓住」是核心惩罚场景；被打还继续翻说不通 |
| 暂停菜单（Esc） | **冻结保进度**，恢复后继续 | 暂停是元层操作，不是世界内动作；用暂停清进度是惩罚玩家的非战术行为 |

不引入「读条期间锁移动 / 锁攻击」——锁输入与「动即断」在结果上等价，但「动即断」把选择权留给玩家（任何时候都能放弃），锁输入会把玩家按在原地看着敌人走过来，那是挫败不是紧张。

### 4. 读条发声：开始时一次，suspicious 档，96px

**结论：读条开始时经场景层调一次 `reportNoise`（与战斗噪音同一钩子），`SEARCH_NOISE_RADIUS = 96`、`level = 'suspicious'`。读条期间不持续发声；完成与打断不发声。**

- 为什么发声：不发声则读条 = 强制停步 1.2s，而停步对改写体几乎隐形（停步听觉 ≤40px 且封顶 0.20）——翻找反而比走路更安全，读条只剩时间成本，「读条 = 风险决策」不成立。这与 vision 支柱 2「贪婪 vs 撤退」直接挂钩：翻找的代价必须是「时间 + 暴露」两笔，不是只有时间。
- 为什么 suspicious 不 alert：翻找是搜刮的基本动作（11 次/局），每次都 alert 会让听觉敌人成为搜刮的硬禁止而非风险权衡。suspicious 的语义正好——「那边有什么在动」，敌人过来查看一个模糊位置（带 jitter），不是锁定你。
- 为什么 96px：与挥击噪音同级（`NOISE_SWING_RADIUS`）。「翻找的动静 ≈ 挥一下武器」有直觉可读性，且复用现成档位，不发明第三套噪音词汇。
- 为什么只在开始时一次：持续发声 = 持续暴露，1.2s 太狠；「你决定翻的那一刻暴露了位置」决策点清晰。完成时的揭晓是视觉事件，不是听觉事件。
- 风险量级（供校准参考）：敌人从 96px 边缘以巡逻 / 查看速度走到玩家位置约需 1–2 s——读条 1.2s 内敌人不足以贴身，但翻完就要面对一个正在靠近的敌人。这个节奏是设计意图。
- 读条期间玩家的移动状态 = 停步（`isMoving` false）：听觉连续填充通道按停步处理（改写体 ≤40px 封顶 0.20），视觉通道照常——在视锥内翻找照样被看见。翻找 = 停步 1.2s + 一次可疑声响，两个通道的暴露都写清。

### 5. 读条期间混乱值：时间照过、混乱照涨，不加额外脉冲

读条不暂停混乱值（混乱值只在出击结束时 paused，规则 13 不动）。读条**不**加额外混乱脉冲——它不是战斗 / 侦测那样的「制造冲突」行为，它的混乱成本就是时间流逝本身（1.2s × 0.5/s ≈ 0.6 点/次）。与「混乱让时间变货币」一致：读条是把「拾取」从零成本变成明码标价的时间消费，不需要第二笔税。

### 6. 数据契约：生成器仍分开给两个数组；统一的是外观与交互层

**结论：`RiftLayoutData.kindlingNodes` / `contaminantNodes` 两个数组不变，两个系统（LootSystem / ContaminantNodeSystem）分离不变。内容类型在数据层预定；「外观不可区分」是渲染与交互层规则，不是数据层规则。**

- 必须分开的理由：① 分布原则不同（薪柴 8 个按 tier 定价分布 vs 污染物 3 个）；② ruminate 消费已拾取污染物节点位置；③ 深渊之眼揭示契约按类型有语义（见决策 7）；④ 结算面板分别统计（薪柴数 / 残渣具体条目，规则 33）。合并成统一 searchable 数组会把这四处的类型信息全部压没，再在消费端重新推断——纯亏。
- **ruminate 兼容性表态：契约不变。** ruminate 继续消费 `contaminantNodes.getCollectedPositions()`；「已拾取」的语义从「走过即拾取」变为「翻找完成」，位置集合不变，工具行为不变。CSV 描述（「空薪柴节点」）与代码消费（污染物节点）的既有漂移记录在案，不在本迭代修。
- 实现层提示（不归本文钉死）：两个系统可各自保留，交互与外观统一由一个翻找交互层承担；也可合并为一个系统两个节点表。这是 code 的实现自由，spec 只钉契约与行为。

### 7. 深渊之眼：揭示所有敌人 + 所有未拾取可翻找对象，同一菱形标记，不区分类型

**结论：规则 30g 改口——深渊之眼从「揭示敌人与薪柴节点」改为「揭示敌人与全部未拾取可翻找对象（薪柴 + 污染物）」，同一菱形，不区分内容物。**

- 为什么不给工具类型分辨能力：「翻前不可分」是本迭代的核心方向。若 rare 工具能区分类型，它就成了类型探测器——每局翻找博弈被工具预算短路（带着深渊之眼出击 = 跳过需求 ②）。工具的特权是「知道哪里有东西」，不是「知道里面是什么」。
- 工具价值变化（诚实写明，平移不是纯加强）：覆盖面变大（+3 个污染物节点），信息精度变小（不再只标薪柴——跟着菱形走可能翻出残渣）。10 秒全图透视的稀有度定位不变。
- 交接项：`data/contaminants.csv` 深渊之眼的描述文案（「所有敌人和薪柴节点位置」）需同步改口为「敌人与可翻找物」语义。CSV 是策划数据源，本批（design）不碰 CSV 文件——改口文案由 Director 安排（人可编辑 / code 批执行），本文登记缺口。

### 8. 结果揭晓的信息通道：薪柴走既有 +N 通道；残渣走新增 toast-inline 星等通道；揭晓色全部 teal 谱

**揭晓信息集（机制层钉死，三张卡不得增减）：**

| 内容物 | 世界内揭晓动画传达 | HUD 入账通道 | 不给什么 |
| ---- | ---- | ---- | ---- |
| 薪柴 | 「是薪柴」+ 量级感（表现层演绎） | 既有：`KINDLING_COLLECTED` → 右上薪柴计数更新 + `showPickupFlash` +N（warm-dim） | — |
| 残渣 | 「是残渣」+ 稀有度感（表现层演绎） | **新增**：`CONTAMINANT_ACQUIRED` → toast-inline，内容 = `残渣` + 稀有度星等（★/★★/★★★），位置右上资产区（与薪柴 +N 同区不同形） | **不给具体类型名**（固化 / 延时 / 侵蚀……留结算面板与库存，规则 33 已有） |

- 残渣为什么揭晓层给稀有度但不给类型名：稀有度是「这趟翻得值不值」的即时答案（星等一眼可读）；具体类型是构建决策信息，不属于裂隙内的紧绷时刻——现状结算面板已列具体条目（规则 33），库存检视五层已有完整身份（规则 15c）。揭晓瞬间信息量要克制，战斗中可读。
- **新增 HUD 反馈补的是现状缺口**（见「背景与现状真相」）：`CONTAMINANT_ACQUIRED` 事件与 payload 不变，rift-hud 新增监听。toast-inline 是既有通道（`showPickupFlash` / `showPassiveFlash` 同机制），不新造反馈通道类。
- **揭晓色钉死（对任务书默认「污染物紫谱」的偏离，给理由）：**
  - 薪柴：世界内揭晓 = teal 余晖谱（§5.3 薪柴实体色，污染侧异源残渣）；HUD +N = warm-dim（§6.2 玩家资产读数）。两处各司其职，规则 8 暖色稀缺不破。
  - 残渣：**teal ramp——common 暗文字色 / fine contam-core（#1aad96）/ rare contam-bright（#3cffd4），与 UI 层 `RARITY_COLORS` 同一份 ramp。不用紫谱。** 理由四条：① art-direction 的污染色谱 = teal 光谱内偏移，紫色无处登记；② UI 层已锁「无独立紫色类」（ui-art-overhaul A2，defense-panel 注释在案），残渣在面板里全是 teal 谱——揭晓用紫会让同一物件在揭晓瞬间与结算面板两个色相；③ 统一翻找对象消灭紫色节点 sprite 后，紫谱在游戏里绝迹，揭晓用紫等于重新引入一个绝迹色相；④ 薪柴 vs 残渣的揭晓区分**不靠色相**（都 teal 谱），靠通道（右上 +N 数字 vs 残渣 + 星等）、形态（表现层演绎）与星等有无——U9 本就不允许颜色单通道。
- 事件契约判断：**无新事件、无 payload 变更，`interface-changed` 保持 false。** 读条开始 / 进行 / 打断不进事件总线——事件只代表「已发生的事实」，读条是进行中的过程，进度由场景层每帧查询驱动渲染（读条载体是三卡差异点，渲染路径不能钉死在事件上）；读条完成 = 既有 `KINDLING_COLLECTED` / `CONTAMINANT_ACQUIRED`，打断无事实发生（无事件）。

### 9. 可见性：可见才能翻；读条期间视野变化不打断

- 规则 16「拾取不依赖可见性」**改口**：交互提示只在对象当前可见（`getVisibilityAt > 0`）时显示，读条只能在对象可见时开始。理由：提示若无视可见性，提示本身变成探测器（玩家拿提示扫黑暗找节点），直接违反规则 17/19「搜刮靠视野推进」。规则 16 的原始理由是「我明明踩上去了却没捡到」的挫败——读条制下这个预期不存在：黑暗中的对象不可见 = 玩家不知道它存在 = 无挫败。
- 读条期间对象离开视野（如混乱收缩、玩家被击退——等等，击退即受击打断；只剩混乱收缩）**不打断**已开始的读条：翻找是手部动作，开始之后不需要持续视觉。保留规则 16「逻辑与渲染分离」精神中合理的部分。
- 规则 17/19 保留并扩写：统一可翻找对象同样**不是 glow source**，视野外完全不可见。 sprite alpha = 可见性（呼吸 / 脉冲等活层表现归三卡表现层，但 alpha 必须乘可见性这条不动）。

### 辨识度手段（四件叠加成类别身份；类别身份，不是内容物剧透）

1. **剪影：孤立低丘。** 丘体宽 22–24px、高 10–14px，顶缘 2–4 个不规则碎块高点，底缘平（坐在地上）；画布 ≤ 26×18px，origin 底部居中。与地图残块的差异：墙是 ≥1 格宽、4–6 格长的连续体量，带顶沿高光 + 南落影 + 侧 AO；堆是 <1 tile 的孤立小丘，无南落影（不挡光），有自己的底影。与地面装饰（fleck / scratch 烤漆）的差异：那些是 1–2px 无体量地板纹理；堆有三层明度和立体剪影。
2. **构成：碎片材质语言。** 碎块的形体语法随本趟碎片身份（「曾是什么」的残骸），四张启用碎片逐一规定（见下「随图配色」节构成表）：户外 = 圆钝土块石团、医院 = 直边瓷片、地铁 = 长直边锈板片、旧图书馆 = 劈裂木段。构成是「degree not kind」的参数变化——四张碎片的堆共享同一剪影包络与同一四槽明度结构，只换碎块语言；类别身份（可翻找的对象）跨碎片一致。
3. **微动：事件型碎屑滑落（待翻态）。** 每 3–7 秒（节点种子定间隔）一粒 1–2px 碎屑自堆顶缘滑落 2–4px，300ms 淡出；色 = 渍缝格。这是重力事件（向下、单向、偶发），不是自主运动（不整团位移、无朝向变化、无追击节奏）——与敌人的位移语言划清。**禁止整团胀缩 / 透明度呼吸 / 周期脉冲**——那是占漆宿主的活层语言（DEC-070 / DEC-071 应用已锁给占漆宿主），堆用周期呼吸会读作有主的漆。
4. **明度夹心：靠近前的高可读轮廓。** v2（2026-08-30）：底影（均值 10.0）< 地面众数（26.7–34.7）< 堆主体（68–79）< 断口高光（95.7）——堆读作「坐在地上的一坨硬材料」，轮廓可读性来自这道明度阶梯与剪影，**不靠外发光、不靠描边、不靠色相**。（v1 阶梯 16.7 / ≤26.7 / 33.7–36.7 / 56.7 把主体压进地面明度带，人终审判迷彩，已废。）

禁止清单：发光到泄露内容物（堆体零 teal 族色）；UI 图标 / 感叹号 / 屏幕空间标记贴脸；读作敌人（直立、位移、teal）、占漆宿主（贴地板成片青绿、周期呼吸）、普通装饰残块（无体量烤漆）。
