# 供奉台九卡

身份锁见 `docs/design-notes/offering-stand-identity.md`：**一台同时起收容、控制、暴露三种作用的装置。** 不是架子、不是祭坛。

机制不动（`system-growth-tide` CN 组 + `system-purification-impact` 规则 2 / 3 / 40）。本文件只声明九张完整组合，不推荐。

画布 32×32，交互点里最小。相机 **45° 等距**（人拍板，与已锁三台同一套）。8 帧、6fps。锚点 26/32。
生成器 `docs/art/review-2026-08-28/gen/offering_stand_cards.py`（自带 12 条闸门 + 跨卡形体类，退出码非 0 即不合格）。

## 三轮，可分维度换过两次

**第一轮 A / B / C 拆的是收容手段（夹 / 围 / 浇）。人否掉：**「三个卡本质上是同一个方向只是调整了大小，区分度非常低。我还需要其他方向。」

三张确实是同一句形体：`iso_prism` 实心方块 + 前左面 `ragged_band` 开洞，只有块的高矮与表面纹理在换。
手段（夹 / 围 / 浇）在 32×32 的剪影上只值几像素的纹理差，归不出第二个类别。

**第二轮 D / E / F 按体积分布拆，一张一类。** 人看到差异，未抽。

**第三轮 G / H / I 按开口怎么占空间拆**，不落回前四类：

| 卡 | 形体类 | 第一眼的剪影 |
| -- | ------ | ------------ |
| A / B / C | 方块 | 竖立的实心块，开口在前左面 |
| D 举出 | 横向外伸 | 宽底 + 长斜臂 + 末端叉头（Γ） |
| E 抱箍 | 竖向细高 | 细柱贯到顶，中段套箍（工） |
| F 压槽 | 贴地矮宽 | 几乎不往上长，开口朝上（一条） |
| G 拱 | 拱 | 两墩 + 压梁，从当中看过去 |
| H 钳 | 钳 | 两臂朝上岔开，剪影是 Y |
| I 环 | 环 | 整件就是圈，残渣在圈心里 |

九张共用同一份身份锁、同一套色板、同一组闸门。

第三轮开工闸门（分量主导 / 载体平面不变 / 换体量的开口）：

| 卡 | 本质里哪个分量主导 | 于是形体是 |
| -- | ------------------ | ---------- |
| G 拱 | **暴露**——压力从喉里穿过去 | 中间空、两边立、顶上连 |
| H 钳 | **控制**——两臂把它夹死 | 顶上两座峰，丫口朝外 |
| I 环 | **收容**——围成一圈但仍留孔 | 立着的圈，残渣在圈心下沿 |

## 九张共用的画法

| 角色 | 色板名 | hex |
| -- | -- | -- |
| 顶面 | concrete-mid / metal-grey / metal-light | `#3a3d42` / `#4a4e55` / `#5a5f66` |
| 前左面（受光，最大的可见面） | concrete-dark / metal-light | `#2c2e33` / `#5a5f66` |
| 前右面（背光） | frag-clinic / concrete-mid | `#1e2228` / `#3a3d42` |
| 槽沿 | shadow-grey | `#151a1e` |
| 里面那点异源物质 | contam-deep → contam-glow | `#0e4a3f` … `#2ae6c8` |
| 材料 / 磨损 | debris-rust / bone-grey | `#5d483e` / `#3a3838` |
| 极小功能指示 | warm-dim | `#8a5c2a` |

**光向与已锁核心 v6 一致：前左受光、前右背光。** 第一版三张画反了（前右受光），后果是最大的可见面被涂成最暗的——整件读成一坨剪影，在混凝土地上会溶掉。

**开口必须参差、偏竖，不能是横向整齐的亮矩形。** 第一版就是横槽，三张全读成屏幕 / 读数盘。

**青绿只在槽里**，且上方一定被结构盖住。青绿往上冒一次，整件就读成香炉。

**青绿不许是整齐的矩形。** 第二轮实测：D 第一版把青绿劈成两块等大的矩形，整个叉头立刻读成一张朝左的机器脸（两块青绿 = 两只眼）。青绿必须逐行宽度不等、走成一团或一道斜的脉。这条与第一轮「不能是横向整齐的亮矩形」是同一件事的两个方向。

## 机器闸门（生成器内置 12 条 + 一条跨卡）

色板 / 活层只在声明区域 / 单一主体色 < 45% / 材质层 ≥ 3 档各 ≥ 8% / 对混凝土有黑有亮 /
青绿只在装置里（不碰背景）/ **青绿不溢口沿（防香炉）** / 青绿不压全身 < 22% /
**外沿不半数压在暗档**（见下）/ 近黑三色不上外沿 / **45° 顶面是菱形**（顶行 ≤ 5，防被画布切平）/
**45° 外缘不竖直**（斜量 ≥ 3，证明不是正投影）。

### 跨卡：形体类闸门（人这一轮抓回来的那条，已沉淀）

人否掉第一轮不是因为像素，是因为**可分维度选错**。所以每张卡必须声明形体类，机器验证数值真的落在那一类里。两个量：

- `aspect` = 材质包围盒宽 / 高（去接地两行、去近黑地裂）
- `shear` = (上半重心 x − 下半重心 x) / 宽 —— 描述「斜的 / 伸出去的」形体

**为什么不看整件重心：** 抓不到卡 D。长臂往左上伸，底座与配重把它配平了，整件重心仍居中（实测 +0.022），只有上下两半错开才看得出（−0.311）。

| 形体类 | 判据 | 实测 |
| ------ | ---- | ---- |
| 方块 | 0.58 ≤ aspect ≤ 0.90 且 \|shear\| ≤ 0.12 且 mid_runs = 1 且 apex_two < 2 | A 0.69/−0.023 · B 0.65/−0.032 · C 0.71/−0.033 |
| 横伸 | \|shear\| ≥ 0.20 | D 0.77/**−0.311** |
| 竖高 | aspect ≤ 0.56 | E **0.50**/−0.089 |
| 贴地 | aspect ≥ 1.05 | F **1.16**/−0.022 |
| 拱 | mid_runs ≥ 2 且 enclosed = 0 且 arch_open 且 apex_two = 0 | G mid_runs=2 enclosed=0 arch_open |
| 钳 | apex_two ≥ 2 且 enclosed = 0 | H apex_two=3 |
| 环 | enclosed ≥ 20 且 mid_runs ≥ 2 | I enclosed=73 mid_runs=2 |

`mid_runs` = 材质包围盒半高那一行的不透明 x 段数。`apex_two` = 顶上 3 行里有几行是 2 段及以上。`enclosed` = 不与画布边 4 连通的透明格。`arch_open` = 半高处两段之间的缝一直通到包围盒底。

判据先写再画。谎称测试：把 D 或 G / H / I 当成「方块」必须红。

四个体积分布区间仍互斥；第三轮三张靠开口拓扑与它们分开，所以「换了名字没换形体」一定红。已验证会咬人：把 D 谎称成「方块」，闸门立刻红（aspect 0.77 落在方块区间内，但 shear −0.311 超出 ±0.12）。

### 「整件不读成一坨暗剪影」这条改过两次判据

要抓的病没变（卡 C 第一版：最大的可见面就是最暗的那一档）。两次都是**误判**，不是放宽：

| 版本 | 判据 | 为什么废 |
| ---- | ---- | -------- |
| v1 | 外沿众数亮度 ≥ 内部中位数 − 4 | 在**细高 / 骨架式**对象上误报：细柱几乎全是外沿，内部样本少且偏亮，合法的背光面被判成描边（卡 E 实测 dom=46.0 vs 内部中位 60.7） |
| v2 | 外沿众数亮度 ≥ 40 | 判据落在**众数**上，平票时会抖：卡 D 实测 CLINIC 23% 对 METAL 22%，改三颗爪尖就翻红 |
| v3（现行） | 外沿压在 CONC_D 46 以下的比例 < 45% | 不依赖内部构成、不依赖平票。仍抓到了卡 C 的残留问题（46%），修 C 而不是抬阈值 |

描边由「近黑三色不上外沿」单独承担，两条不重叠。

### 第二轮还撞出三个纯技术坑（都已写进生成器注释）

1. **45° 斜梁不能沿垂线逐格打点。** 45° 斜线的单位垂线四舍五入成 (+1,−1)，加上去得到的是**隔一格**的平行线，梁身会漏成一串点。必须填面。
2. **1.6 格进深的 `iso_prism` 会退化。** 侧面不到一像素，只剩一颗顶面浮在空中。这个尺度的小桩 / 耳 / 栓要在屏幕空间画。
3. **挂件的锚点必须从几何算出来，不能钉死行号。** 45° 下抱箍的左右两端不在同一行（左端高、右端低），一改箍的尺寸，钉死行号的耳朵就浮空。
4. 磨损 / 指示灯统一走 `stain()`，只落在已有实体上——一颗漆浮在空中就是噪点。

## 机械层已扫，审美待人终审

九张 12 条闸门 + 形体类闸门全绿。我自己在图上抓到并修掉的剪影误读：D 读成朝左的机器脸（青绿两块矩形 = 两只眼）/ E 读成柱顶顶了个脑袋（图腾、路灯）/ D 的悬腿读成虫腿 / D 的配重箱读成一片黑帆 / F 的螺栓浮在空中 / E 的拧紧耳浮在空中 / G 第一版左墩被宽棱柱吃掉、接地近黑爬出 3 行 / H 第一版顶行 6 像素不像菱形、槽沿用了近黑 / I 第一版内沿用阴影当描边。

**我判断仍偏弱、需要人定夺的地方**（不代勾好看）：

- D 的底座 + 配重 + 斜撑挤在一起，暗部偏糊，看不清是三件东西。
- E 的青绿口是杏仁形，仍沾着「一只眼」那条误读的边。
- F 的顶沿起伏偏多，整件偏「石头 / 土丘」，人造感不如 A / B / C。
- G 的压梁是屏幕空间斜条，和两墩的 45° 棱柱不完全同一套体积语言。
- I 在 32×32 上仍容易被读成一块甜甜圈或舷窗，孔偏心够不够破传送门要人看。
