# 净化点空间重构：封闭双层检修舱

> **TL;DR**：净化点改为能看到上下层和完整外壳的侧视场所。本轮以连续下层主廊、上层操作廊和两端短阶提出具体布局；六功能及既有抗侵蚀规则保持，空间图尚未成为生产场景。

阅读入口：[侧视剖面与动线图](../reading/purification-cutaway.html)。图用于判断空间、边界和功能邻接，不代表最终像素画面、生产碰撞或实测路线时长。

## 1. 决策状态与任务边界

- **用户已明确**：希望净化点类似《死亡细胞》的侧视上下层空间，并且必须是封闭场所，边界是关键。
- **本轮待评审提案**：双层检修舱、主层四功能、上层两功能、两端短阶和免跳跃通行。用户尚未确认这些具体细节。
- 前版 A 残墙工作院、B 错层断崖站、C 剖开的巨械已被新方向取代，仅作为 Git 历史，不再并列为当前候选。
- 改变范围是净化点空间、该场景的移动呈现、装置模型和交互镜头；不是把整款游戏改成横版动作游戏。
- **Rift 继续俯视**：裂隙地图、移动、灯光、遮挡、战斗和角色出击表现不因本提案改变。
- 历史问题仍需解决：膜包圆盘、装饰连线代替空间、六件物体缺少共同安装关系。新视角本身不等于修复这些问题。

## 2. 世界观推导

净化点是一小块尚未被完全改写的区域，需要外来残渣持续维持。封闭建筑为人提供可辨的结构与维护条件，但厚墙不会天然免疫现实改写。设计依据为 [world.md](../world.md) 的核心规则与净化点空间定义。

- 场所应像仍在被使用、修补的残存设施；不能是崭新避难所，也不能只有完全废弃的废墟语言。
- 不解释这座设施原来做什么、由谁制造、为何幸存；这些目前不是已确认的世界事实。
- “检修舱”是本次场景构成的工作名称，不自动新增游戏术语、地名或正史。
- 内部可以有上下两层，但同属一个净化点；不新增房间安全等级、供电链、氧气或扩张系统。
- 修复、供奉与成长仍由原机制驱动，墙体和地形不增加额外资源账本。

## 3. 空间骨架与日常路线

完整顶盖、厚侧墙、后壁和基础围住内部。靠观察者的一面用固定剖切呈现，让玩家看到生活空间；**镜头剖切不等于建筑真的缺了一面墙**。

- **下层主廊**：连续、可左右步行，承载储藏、核心、净化器和裂隙。归来落点靠中央，靠近核心与上楼入口。
- **上层操作廊**：承载蜕变与供奉；两者共享较安静的操作区域，但各有独立腔体、站立面和功能形体。
- **两端短阶**：连通上下层并形成环路。上层处理完供奉，可以从出击侧下楼，无需原路折返。
- 上层不延伸至最右端，裂隙所在端保留较高的封闭空间。该处的空旷来自室内体积，不靠露天断崖。
- 两层之间的楼板、侧壁和大设备构成真实不可穿越体积；上下连通只发生在明确的短阶位置。
- 不加第三层：当前六功能不需要额外一层行走成本，先验证双层是否已经提供足够层次。

### 六功能与载体

- **储藏｜下层归来侧**：低而厚的收存槽，开口、前壁和容量体积清楚；不以散落物数量暗示真实库存。
- **核心｜下层中央**：可辨的独立工作组件，支架接入基础；不能把整栋建筑都称作核心，也不暗示核心供电决定全楼开关。
- **净化器｜下层出击侧**：面向出击端的剥离机构，与裂隙邻接；仍自动影响出击起始状态，不要求玩家先按键净化。
- **裂隙｜最右侧墙地交界**：后壁与地面共同错位的空间伤口。旁边保留可站立的交互面，不画成必须跳入的深坑或整齐传送门。封闭的是建筑外壳，裂隙穿越的是时空；它不要求一条通向本时空墙外的实体走廊。
- **蜕变｜上层内侧**：身体进入位置、支承和改造接触点可读；装置有操作余量，不把玩家塞在墙与面板之间。
- **供奉｜上层靠出击侧**：夹架收容并约束未知包块，受压敞面和观察/操作侧可读；遮护物件身份不等于全封闭罐。此处的暴露是装置的作用关系，不要求凿开外墙。形态不提前泄露供奉完成后的身份或能力。

六件设备必须共同具备安装、承重、维护和操作关系，同时保持不同剪影。楼板、立柱与设备不能组成一排等距商店橱窗。主层设备嵌入后壁工作凹位，连续步行带位于其前侧；实际占位与侧视层级共同定义，不能让角色穿过同一平面内的机身。

### 典型行程

- **立即再出击**：归来落点沿下层主廊走向裂隙，全程不上楼、不逐台打卡。
- **维护后出击**：在下层访问需要维护的模块，再向出击端移动；不因美术布置强制经过其他装置。
- **处理供奉后出击**：从近侧短阶上楼，使用供奉，再从右侧短阶回到出击侧。
- **蜕变后离开**：可就近原路下楼，也可经上层到另一侧；两条路线都不要求跳跃或等待。
- 供奉未必低频，不能用“上层只是偶尔去”回避成本。它必须列入每次归来都使用的压力测试路线。

## 4. 移动与交互提案

- 平层用 A/D 或左右移动。到短阶落点后，W/S 或上下进入并沿阶连续移动；松开可停，反向立即返回。
- 到达楼层落点后自动回到平层移动；上下楼不播放整段不可取消动画，不自动把玩家送到某个装置。
- E 继续负责装置交互；短阶落点与装置操作区分开，避免想上楼却打开面板。
- 不需要跳跃、垂直梯子、升降机、下落穿台或精确落脚。空格不承担本场景必需的新操作。
- 每层安全可走面连续；没有失足扣血、摔落惩罚或随机堵路。楼梯和楼板受损表现不能改变通行图。
- 输入细节须在灰盒中验证，尤其是短阶中途停止、反向、失焦恢复和面板关闭后的输入状态。
- 原成长和操作机制保持；只是按场景上下文解释移动方向，不改变出击中的控制合同。

## 5. 三种边界必须分开

### 物理壳体：限制走动，建立封闭感

顶盖、侧墙、楼板、后壁和基础是可辨的建筑结构。角色不能穿过实体墙和楼板，只能经合法短阶换层。外壳轮廓以承重和构造成立，不再是包围圆形地块的薄膜。

- 观察缝和接缝可以显露外界，但不能让整面外墙读成敞开的舞台背景。
- 靠镜头的墙使用稳定剖切语言；不靠游戏时随机透明或墙体忽隐忽现维持可见性。

### 既有抗侵蚀：维持环境，不是建筑防弹性能

整个可达室内同属现有净化点状态。薪柴、模块完整度和冲击结算继续承担抗侵蚀含义，封闭外墙本身不添加数值防御或永久安全。

- 不新增供电、管线接通、阀门操作或房间净化任务；画出的安装关系不得暗示这些玩法已经存在。
- 不通过成长扩建安全区、解锁新楼层或扩大外壳；投入感由既有装置改造和已发生状态表现。
- 模块受损可以影响自身和附近构件的表现，不产生通行洞、封死短阶、基地持续扣血或新失败条件。

### 外部改写：表达压力，不泄露未获得的信息

外壳之外仍按异质规则运作。外侧物质变形、接缝处局部错位、压力痕迹与少量异常光提示内外冲突；不必再覆盖均匀发光包边。

- 只读取玩家已经获准知晓的已发生状态，例如公开的模块当前完整度、已结算冲击与当前供奉状态。
- 不按未公开的下次目标、强度或随机结果提前点亮对应墙段；场景不能绕过预兆成长的信息门槛。
- 普通环境轻动效不与未来冲击结果对应；“外面在压迫”不等于可以从灯光读出下一次精确事件。

## 6. 镜头、角色与装置画法

- 常态尽量同时读到两层、两端连接和出击端；上下楼不触发骤然竖移或变焦，让完整外壳持续可感。
- 不为塞进全景缩小主角。先收紧布局，再评估小幅带死区的横向跟随；具体范围待灰盒测量。
- 装置操作面朝可读方向，前景梁柱避开操作站位；现有交互聚焦和读数层级继续复用并检查位置。
- 同一主角需补侧视站立、左右行走和阶梯脚步适配；帽子、衣物、工具、灯具、比例与身份保持。
- 现有俯视三分之四精灵不能直接当最终侧视模型，否则容易出现脚部浮空、肩部视角错误和贴纸感。
- Rift 继续使用原俯视表现；侧视补绘不是替换其角色，不顺带改武器、成长外形或出击动画。
- 装置同步改为侧视体量：明确支承、腔体、工作面和维修层次，不把旧顶视精灵旋转或贴到新墙上。
- 美术方向与具体像素规格由 Art 补充；本文没有新增色板或宣称审美通过。

## 7. 参考及架构影响

研究 [《死亡细胞》官方资料](https://deadcells.com/) 的侧视空间阅读与上下层构图。该游戏本身是动作平台游戏；本提案借鉴观看方式，不搬运跳跃、战斗、死亡循环或其随机城堡机制。

原主设计师 [Sébastien Bénard 的关卡设计说明](https://deepnight.net/tutorial/the-level-design-of-dead-cells-a-hybrid-approach/)提出按房间用途设计布局，并用连接关系控制组织。本提案采用“先确定功能与连接，再制作房间”的方法，不据此把净化点改为随机据点。

- **场景运动**：净化点需要能够表达平层与短阶的运动、碰撞和落点；不能将俯视地图只换背景后继续全方向平移。
- **共享角色与输入**：区分场景显示/移动方式与角色身份、属性、库存；场景切换后恢复正确控制，避免 W/S 的基地语义漏入 Rift。
- **镜头与交互**：六锚点改为侧视楼层坐标，操作触发与面板聚焦同步核查；不把上层设备误判为楼下可操作。
- **边界表现**：替换依赖旧椭圆的绘制方式，保持现有结算与公开信息契约；装饰状态不反向修改模拟结果。
- **存档与恢复**：已有玩家权益和在途 Rift 保留；若净化点位置需要迁移，应落到合法主廊站位，不让旧坐标落墙或落空。
- 上述是 Code 需核实的影响清单，不是已落地的架构决定；本轮不修改 architecture.md，不另建重复系统 spec。

## 8. 预算、验证与推进边界

旧净化点的 14×12 格、每格 32 px、速度 80 px/s 仅作为旧基线。新剖面图没有真实尺寸或计时结论，不能据示意比例宣称更快、更短或已经可玩。

1. 先记录现版原速行程，再以同一角色尺度和原速做双层真实碰撞灰盒。
2. 必测“立即再出击 / 核心维护后出击 / 供奉后出击 / 蜕变后出击”，记录路径、时间、转向和额外按键。
3. “常见行程相对现版不增长超过约 20%”仅作待验证预算；供奉路线若超出，应缩短阶梯和操作间距，不能调快角色掩盖问题。
4. 验证无跳跃全点可达、换层只经短阶、上下层交互不串层、楼梯可停可反向、连续来回无等待。
5. 对照初始、受损、修复和已成长状态：通行始终稳定，表现没有新增扣血、供电要求、安全区扩张或未公开预兆。
6. 校验从侧视净化点进入俯视 Rift、归来、继续旧在途局：角色身份、属性、库存、输入及存档权益一致。
7. 用户先判断封闭剖面、层级和六功能邻接；方向确认后做灰盒，再做一段“楼板—设备—人物”的共同美术样板。

本次只交具体设计与阅读图。双层、短阶、模型重绘和运动方案仍待评审；未开始生产替换，也不把图示检查记为游戏运行或审美验收。
