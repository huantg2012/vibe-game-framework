## 短 HOW：先统一观看关系

### 世界绘制：本质、平面与材料

- **本质锁：**有人持续维修的承载空间围住受控活性核心，壳外残体受异质规则挤压和错位。厚板、断墙、深腔均可成立；无宿主的装饰环、薄纸带和通往外部的新功能门不成立。核心保持细高开放内腔、上下约束和接地基础，可强化不对称夹持与活质，不变成封闭电箱、祭坛或可穿门。
- **载体：**磨耗/修补在原 0/32 水平面上；帽边、东墙上沿和前基础的切口属于现有厚实体；外残体为不可走建筑体。核心仍立在原脚底；绘制高度、表面法线和光源位置要随真实画出的形体同步。
- **尺度：**世界底 640×400；原浅透视、原角色大小、双坡连续高程保持。下文世界尺寸均是这张底图的逻辑像素；UI 另用 960×640 overlay 逻辑像素，不能混用。
- **世界六问：**维护者利用混凝土、灰泥、旧胶结和回收金属，工艺够用而不齐；工作面有补平/扫净，断口与接合有磨损；暖光来自真实灯具，青绿来自受控介质和侵入。DEC-180 允许原材自身色相，覆盖旧示例“颜色皆污染”。孤立、微光、功能性、空旷、安静、勉强维持仍是场所气质。

### 统一三级焦点

1. **一级：核心本体与紧贴内腔的光。** 核心拥有最大的局部明暗跨度、最明确的活质亮芯和少量向内受光的结构边。焦点先长在模型上，再传到近处地面/立面。不得靠一团更大的圆光池建立核心地位。
2. **二级：室内工作空间与其余设备。** 两层、双坡、维修材料可辨，地坪变丰富但纹理对比低于设备轮廓；培养藏和净化器仍有原介质与功能光，其峰值和亮面面积退于核心。原人物灯的极小高亮不为竞争焦点而熄灭。
3. **三级：壳外断构与稀疏活动。** 用冷暗大面、深腔与少量受光截面表现重量，亮部局限于朝内/侵入接触侧。外景粒子少、慢、分区，远处更暗。不能让左右残体各自变成一盏与核心同强的灯。

世界建筑仍选现有 `concrete / plane / plaster / ash / recess / shadow`；旧底料/氧化/沉积可用 `oldPlaster / earth / olive / rust`；少量受光断面用 `steel / edge`。核心保留 `deep / teal / live / light`，最亮点可用当前 `pale` 小面积表达内芯；不扩展世界 22 色。外景优先冷铸材与暗青接缝，减少当前与室内灰泥同分量的大片暖褐表皮；这是内外分工，不是“外部原材永远不能有色”的新禁令。

## 可施工范围

### A｜上下地坪：先有施工层，再有使用痕迹

**上层优先。** 在既有 `x≈196–330, y≈156–213` 内组织一处长向约 50–75、短向约 20–35 的成片磨穿/旧修补，与已有施工缝相接。它有完整原涂层、露出的冷铸材、局部重新刮平三个关系；不画成孤立椭圆，不沿四周立暗边。另一处较窄的磨耗接到东坡落点及设备工作区，尺寸、方向与第一处不同。

培养藏、供奉台附近允许局部矿物沉积和回收修补件，必须附在已有接合上；两台脚下不各复制一套圈。原中央大面保留足够连续地坪，但至少一块材料变化在正常 01 直接可见。不是只多三条裂线或在原平色上密撒点。

下层保留 R6 已有储藏工作面及核心—服务沟关系，增加少量有方向的擦磨和开口接缝，顺着真实使用面结束。核心周围的纹理对比低于其本体；主通道、坡口与操作脚底持续可读。两层材料均继承宿主高程/法线，不增加台阶、障碍或悬浮贴块。

### B｜三条齐边：改轮廓与截面，集中做大小不等的断裂

初稿尺度供作者施工，非已经验收的数值：

- **后墙帽**：选 2–3 处不同位置的主豁口，约宽 6–16、深 3–7；其间保留长度不等的完整承载段。至少一处切掉实际外缘并露出侧向断面。
- **东墙上沿**：选 2 处宽 7–14、深 3–6 的断口，避免与后帽等距或同形；一处露粗芯、一处有被扯开的薄表皮。
- **前基础**：选 2–3 处宽 12–24、深 4–9 的破口，从原立面/下外缘撕开，配一块较宽断芯和一段短埋件。沿前沿长直线的整齐亮条须被真实缺失打断。

每一处先画断掉的形状和方向面，再加少量骨料。禁止沿全边均匀锯齿化，也不能保留原直边、只在边内撒碎斑。前基础破口不切穿合法可走顶面；墙帽破口不变新门。缺失像素、断面法线与高度要同步，不能残留不可见遮挡壳或漏光面。维修基础仍仅原薄厚度，不能恢复 R5 厚黑月牙。

### C｜核心：从细高腔体强化为唯一主模型

脚底、基座占地与操作点不动；其余五物主体不动。核心上半允许从当前最高 local `-61` 增至约 `-69～-73`，首稿采用 `-72` 可行；内腔可加宽约 4–6 像素。两侧夹持不等高，顶盖断开，让活质朝上仍受到约束；不额外做整圈门框。

最亮内芯集中在约 local `(0,-46)`，是几格连成的亮核与不等宽活质，不是满腔整片同亮。内缘只留下短的受光反射，外壳用面差承担体积，暗腔仍深。顶肩、压脚、两侧修补表现手工维持的受控装置，基础不随着主体增高而变厚。

光源需跟新的内芯高度对应；近侧框/压脚有明确受光，背光面和内遮蔽继续暗。优先调整核心/次级发光之间的能量、受光位置与亮面积，不扩大照明半径覆盖整屋。少量核心尘粒围绕内芯上方和近处光中活动，结构不呼吸胀缩。完整度变化仍来自真实公开状态：低完整度可减弱/失稳，但核心靠剪影、暗腔与结构对比保持构图中心，不能为了“绝对焦点”在 HP 很低时伪造满功率运转。

**正常 01 验收：**无需看名称先找到核心；它的亮点在模型内部而不是脚底光斑里。培养藏和净化器仍清楚，但不与核心平分主焦点。02 中内腔、夹持和修补仍能分开，不被泛光糊成白团。

### D｜壳外：冷暗厚断体、有限反照与粒子

本轮授权重构壳外设计，不以 R6 现有折段的逐点轮廓为不可改约束。保留室内边界、黑隙与实际侵入接触关系，不拓展可走空间、不虚构新的设施用途。

- 西侧以一块斜断的厚板/残墙为主，明显断头、内侧受光面和背阴厚面共同占体积；至少一段完整大面压住原来连续折带的读法。
- 东侧以较竖的厚壳和一个主要深腔为主，与左侧形体不同；前唇遮住部分洞底，侧壁和下断面不首尾等粗串接。不要复制左右对称门框。
- 远后残构更暗更概括，底前残片少而厚，构图向室内收束。冷灰断面可有真实受光，暗青只留在异质接缝/侵入侧，减少与室内工作皮层相近的暖色大块。
- 光影从朝向、遮蔽及现有接触活层解释；可有局部冷色反照，不能加全屏染色或双侧舞台灯。外面与洞内的亮度差必须在正常镜头可辨。

**粒子初值：**固定小池约 8–14 粒可见上限，分配左右外隙与远后层；单粒 1–2 世界像素，慢漂约 3–8 px/s、寿命约 2–5 s，错开出现。多数为冷灰碎尘，少数暗青沿真实接触段掠过；不整屏随机雪花，不持续喷射，不同步闪烁，不跨进人物/读数/核心腔体。静态纹理一次生成，活动不能每帧重烤大图；具体对象池和更新频率由 Code 决定。

正常 01 应看见厚体和至少局部受光，连续短片应看出活动；只加粒子不改变大形不算完成。粒子及外接触不读取未公开冲击目标，不暗示下一次必然击中哪台装置。

## E｜完整度条：侧置、换色、对玩家避让

**载体：世界内装置的邻近读数。** 它说明正在看的真实设备状态，既不是独立终端，也不是全局仪表盘。行走时的世界条钉设备，可沿用引擎世界层；交互时有标签/数值的屏幕读数仍挂 `#dom-ui-root`，取真实设备/人物投影定位。两者是同一读数的两种观看尺度，交互打开时不重叠显示两套。

**三个既有具名锚点：**《Signalis》沿项目已定的工业功能读数和克制分量，不复制整套科幻控制台；《Darkwood》沿项目的暗处留白和世界优先，不复制其库存；《Hyper Light Drifter》沿本项目既有“小人物与局部视觉信号的主次”参考，不复制高饱霓虹。具体排字/动作以本项目迭代 11 已认可核心与净化器交互为直接基线，参考不是重新换皮理由。

已亲看 `r4-core-committed.png` 与 `r5-purifier.png`，借用实体—读数—旁侧操作的关系；`r4-core-sample.png` 文件本次显示异常占位亮场，不作当前材质证据。当前实景以 R6 图为准，旧截图不代表新位置已通过。

**三问结果（施工依据，非审美代签）：**

1. **审美如何成立：**让状态退居核心腔体之后，采用无光晕的窄规与小读数，以位置和真实数值提供信息；不加底板、边框或颗粒皮肤。是否成立必须看正常/近景以及人物左右两侧实帧。
2. **如何读作游戏：**条随真实设备定位，只随玩家位置做必要避让；长度对应当前完整度，注入时在实体旁更新，返回时还给世界。它不是一列管理卡片。
3. **如何与装置同一世界：**沿现有无框、低分量、功能性读数和 Kit 字体；状态色与青绿能源光分工，读数不发光、不投影成新装置，也不冒充旧墙上的实体显示屏。

### 颜色、形状与状态

- **常态/可交互：**三模块统一取既有 `ui-text-bright #c8cdd4` 的细填充，轨取 `ui-border #2a2d32`，取消世界条现有模块蓝/橙/青绿分色。颜色是无发光的旧骨白与冷灰，不借用薪柴成本色。
- **远离：**沿用当前距离/低值显隐规则和低分量，不新增常驻数字群；不能为改样式改变何时获知状态。
- **低完整度：**沿用已有 `<25%` 危险判定及 `ui-danger #cc3333`，不另造一组机制阈值；空槽/填充长度、近景数值共同传义，不能只靠颜色。
- **修复发生：**数值/填充在 400 ms 内响应真实结算；可保留既有单次确认反馈，不持续闪烁，不让条比核心活质亮面积更大。

### 行走世界条

改为约 **2×24 世界像素的竖向短规**，底到顶填充；在设备视觉左/右边界外留 6–8 世界像素。纵向落在装置侧腰至下部，避开顶肩、腔体与操作脚底。基准位置由实际模型边界确定，不能只套 `baseY + 固定下偏移`。

玩家在右侧优先放左，玩家在左侧优先放右。以**完整人物可见包围盒，包含手持件/灯**外扩约 4–6 世界像素作禁入区；设备、条和玩家均在同一坐标系计算。普通跨中线约 8 像素迟滞避免抖动；若当前条已与人物禁入区相交，应立即换到无冲突侧，不能等待迟滞继续遮人。初次出现选清楚的一侧；不隔几帧来回跳，也不穿过人物或机体滑动。

若两侧候选受邻近设备/坡口约束，在选定侧小范围上下移到清楚位置；不得以提高绘制层级直接盖在人身上作为兜底。位置和颜色同时用于核心、储藏、净化器，不顺带给其余设备新增不存在的 HP。

### 交互近景读数

当前 `.core-integrity` 下置的整组标签/数值/条一并侧置，不能只挪空条。建议约 **104 逻辑 UI 像素宽**、2 px 细横条；“完整度”11 px/18 px，当前值用 Kit 已有 13 px/18 px 等宽体，上限/斜线10 px，必要分两行，保留表名与数值的区分。宽度从原124收至104是为真实设备与既有右侧投入栏之间留出空间，不缩小字体。

读数从设备投影边界外留约 12–16 UI 像素，随玩家投影选择反侧；人物/灯投影外再留约 8 UI 像素，既有投入栏、底部动作与设备标题也是避让区。左右候选必须同时考虑 zoom/letterbox 后实际 bounds；若与操作列冲突，只在侧边上下错开，不移动已认可投入栏或把读数塞回脚下。过渡不穿过人物，变焦结束后位置稳定；关闭/换场景清理跟随更新。

共享语义颜色、条样式和排字复用现有 `panel-styles.ts` / 读数层；需要新增侧置基元就在共享层定义，再由三个分配面板消费，不面板内各写一套。当前成长 UI 的层次、颜色、资格和购买逻辑不在此修改范围。

## 首帧、修正与交付边界

首批实帧须包含正常全景、核心近景、上层两侧、受控损伤全景；完整度另取核心/储藏/净化器的玩家左侧、右侧、临近中线与交互近景。短连续观察覆盖外景/核心活动、条换侧与镜头进入/返回。世界条和近景条都必须看到避让结果，单张“刚好没人”的图不够。

正常尺度依次回答：核心是否先被看到；上层是否确实丰富；三处外沿是否真正断裂；外景是否有厚度与运动且退于室内；条是否换色、侧置、避人。每组留独立 manifest 与来源，不把合成损伤写成自然经历。Code/QA 复用已有高程/法线、缓存重入、公开状态和投影检查，必要检查新增切口及读数禁入区；机械检查不替代美术判断。

**最多两轮有实帧依据的修正。** 优先纠正主焦点/轮廓/遮挡问题，不为凑轮次添加纹理。若新画面只是更吵、泛光更强或外景更亮，本轮未达目标；若关键结果成立且只剩局部制作精度，则明确保留限制并收口。
