# 《那天之后》全游戏补审计划

执行结果见[全游戏补审报告](game-wide-review-2026-09-18.md)，原始证据见[台账](artifacts/game-wide-review-2026-09-18/run-log.md)。两组A/B记录已封存，C/D已对照。六组均已开展取证；供奉成熟后再使用链在出发停滞处截断，死亡后恢复、长期供给与声音仍未验证。下文保留计划定义，范围内未完成的验证不自动算通过。

## 1. 覆盖结论

用户指出上一轮缺少净化点、污染物与武器、角色成长和游戏循环。核对确认：[9月18日评审](rift-world-review-2026-09-18.md)明确只覆盖地图样板；[迭代26验证](iteration-26.md)补了原生搜撤、死亡和部分威胁，但采用隔离训练会话，不包含真实净化点资源分配与跨局成长。二者都不能支持全游戏结论。

旧净化点、武器及污染物迭代存在各自的验收或静态审查，不能概括成“从未审过”。缺的是**当前正式版本在同一套品类标准下的独立复评和跨系统闭环证据**。本次两名已有代理只做文档范围核对，未试玩、未重新审资产、不提供首玩或当前品质结论。

本计划不调整玩法、不重开三维关卡探索、不消耗迭代24/25编号，也不把补审等同于四A持续供给验证完成或四B扩产解锁。

## 2. 版本、入口和信息隔离

- 主对象：当前正式 `/` → 主菜单 → 净化点 → 原2D Rift → 结算 → 净化点 → 再次出行。执行时冻结源码、数据、构建及存档起点，以实际入口核实内容。
- 新地图：`rift-world-play.html` 作为生成材料在正式机制中的独立适配样本；其返回配置、训练库存和部署范围不代表完整游戏循环。当前未进入正式随机池，不能声称已验证其跨局供给。
- 历史三维页、陈列馆与练习场只作 D 阶段诊断工具，不替代正式游玩。
- 使用隔离浏览器存储，保留用户存档；深层状态可用可追溯的存档副本补测，与自然成长分开记录。
- 本文及项目资料只给协调者和 C/D 阶段使用。A 阶段仅提供通用品类协议、正常操作、正式入口和运行说明。
- 首玩职责由未参与被审实现、未读项目细节的审查者承担；现有实现代理只做知情核对。若环境自动注入先验，照实披露，不称严格盲测。

## 3. 六组任务

### G1 · 净化点关卡与准备体验

审可行走空间、六个交互点、地面、力场、装置遮挡、交互面板和状态变化。玩家能否从游戏理解各装置的关系；整备是有意义的仪式还是重复操作负担；返回此处有没有情感价值。

覆盖首次进入、带回收益、低资源、三模块健康/受损/严重受损、修复与投入、潮汐空间变化。UI补测空/满槽、供奉成熟、成长不足/满级、备行装配，以及键鼠切换和取消。美术分别审构图、尺度、材质、人物与装置、动态及声音，不只看健康静帧。

### G2 · 污染物、武器与构筑

“污染物”区分可携异物与污染威胁，避免用敌人外形审查替代道具设计。按活目录审获取、识别、供奉、成熟、装配、使用、次数/耐久与损失。

当前文档列四品质十款撬棍，共用攻击模式；十三族异物各四品质。执行前核对正式数据，不把十款算成十种打法，也不以52组合证明构筑深度。比较攻击距离/时机/命中反馈、重量/抗性/品质取舍，工具目标资格、失败免费与末次效果，以及不同解法、组合、通解和无效选择。

美术单列物件身份连续性、持武动作、特效因果、品质表达和压力下可读性。原角色保持；低饱和不是统一输出要求。

### G3 · 威胁、潜行与战斗

覆盖正式可遇见的感知方式与危险宿主，记录线索、预测、绕行、诱导、应战及失败归因。比较使用与不使用工具的真实机会和代价；“技能触发成功”不能等于“战术收益成立”。

正常视野、混乱、背包不停时的压力、负重和退路共同取证。危险物、可走浅地形、不可照亮的缺失空间分别审读法，不以泄露隐藏地图来修公平性。

### G4 · 角色成长、潮汐与经济

将薪柴、修复、永久成长、模块加厚、防御、供奉槽和携带限制放在同一预算内观察。追踪模块完整度如何影响下趟条件，以及潮峰/退潮、预告和实际冲击是否可理解。

覆盖起步、首次明显成长、资源紧缺或受损、已有积累四类状态。成长是否打开新决策、收益能否感知，还是只在追赶账单；保守与冒险何时各有价值；失败后是否有可理解的恢复路线。当前成长数据涉及混乱抗性、薪柴亲和、生命、主动槽、供奉槽和预告清晰度，不能只审生命数值。

`docs/content/progression.md` 仍是模板，不能当作已完成的整体曲线，也不能据此认定成长机制不存在。实际规则以活 spec、CSV和实现核实；稳定度完成标记不能当成已有完整终局。

### G5 · 完整循环与新手学习

从正式主菜单开始，在同一存档中追踪成功带回、基地处理、再出行，以及一次失败的理解与后续恢复。记录上一趟的资源、知识和能力有没有改变下一趟计划，何时重复劳动压过新判断。

优先追踪三条链：

1. **获得 → 成熟 → 再使用**：翻找揭晓、负重取舍、真实携回、武器/异物竞争供奉槽、冲击、同一实例成熟、备行、下趟发挥、耗尽。观察“捡到不等于立即能用”的学习与等待代价。
2. **资源投入 → 基地状态 → 下趟条件**：同一预算中的修复、成长、加厚和供奉安排，是否通过可见后果改变下一次路线、风险和装备选择。
3. **损失 → 替代打法 → 恢复构筑**：次数耗尽、死亡丢装、低收益或连续失败后，重新得到可用配置需要的出行、薪柴和等待。首次保障与测试赠品单列。

完整循环牵头人交叉核对所有专项，不能以局部操作顺畅、画面精细或物件多推出整体价值。“愿不愿再玩”的专家判断和真实用户证据分别写。

### G6 · 整体视听、交互与连续运行

按协议六轴归类首页、净化点、Rift、角色、敌人、道具、HUD、面板和特效，判断主次语言及场景衔接。美术保持约三分之一专项投入，声音、动作和触发时序分别取证。

声音需实际审听入场、场景过渡、压力与交互的连续变化；不能用播放状态代替听感。覆盖暂停、失焦、结算、继续和跨场景的输入/状态/保存一致性，以及过度依赖单一颜色、声音或细小文字的问题。

当前正式2D退出/刷新恢复需要独立检查。悬海完整原局恢复是历史适配，不能移用其通过记录证明正式随机池恢复已完成。

## 4. 执行顺序与交付

1. **准备**：协调者冻结版本、核对正式内容，建立隔离存档、覆盖台账和证据目录；只给首轮组最小简介。
2. **A 首次体验**：美术组和玩法组独立游玩同一正式版本，封存首次理解及操作；美术归类和循环判断各有结论。
3. **B 定向复核**：首轮后以G1–G6补缺。玩法组牵头成长/经济和多趟循环，美术组跨据点/物件/威胁/界面，技术组交叉核实状态与显示。先形成自然循环，再补深层状态和反例。
4. **C/D 披露与诊断**：公开设计、旧验收、代码、CSV和存档来源。高影响问题最多两轮定向复核；仍不足的保留不确定性，不靠重复截图凑结论。
5. **整合**：输出覆盖记录、六领域判断、独立美术归类、跨系统根因及制作优先级。整改候选明确收益、风险、成本与最小验证实验；不边审边修到被审版本漂移。

分阶段保存原始观察与待办，防止会话压缩遗漏。按实际目录和有理由的等价类抽样，未测武器、品质、能力组合单列。模拟可定位经济风险，不能代替连续实玩，更不能推算人群留存。

报告必须回答：**现阶段最有价值的体验是什么、哪个跨系统瓶颈最妨碍它、下一笔制作投入应放在哪里。** 本轮已形成有限覆盖下的综合判断与建议优先级，不计虚假总分，不取消旧验收；整改尚未实施。
