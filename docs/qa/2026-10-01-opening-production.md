用户认可 `48b700c` 并授权“放到游戏里”。本轮将已认可画面和动效提升到根入口，保持游戏记录、业务与原导航；主功能 COH-F042，关联 F002/F005。

## 实现

- 正式 F 图为 `public/assets/art/menu-refuge-f.png`；两个动效模块原样迁入 `src/art/title-motion.ts`、`title-exterior.ts`。独立联合页通过 re-export 复用同一实现。
- 正式与联合审查页共用 `MainMenuScene` 和 `main-menu.css`。固定 960×640、左侧菜单与右侧庇护所保持获选构图；原潮汐、出击和稳定度摘要保留为分离节点。正式流程调用原 session / MenuEntryTransition，DEV 页继续隔离存储与额外对照按钮，不把样片内存存档带入正式。
- 净化点使用已认可联合资源，原样复制至 `public/assets/last-light/`，正式默认启用 `joint-depth`。角色、导航、站位和坐席数据不变。烘焙历史指纹保持，提升记录单列；旧 A 导出命令增加保护，防止覆盖当前资源。
- `src/main.ts` 在捕获阶段消费失焦恢复键，避免同一次 Enter 同时恢复并开始/确认；DOM 菜单先拦截原生按钮默认行为再忽略重复按键，避免按住 Enter 越过恢复保护。菜单另检查场景活动、暂停、输入和过渡状态；原 DEV 记录/过渡审查按钮已同步为 DOM 键盘事件。

## 正式构建专项

`node tools/qa/check-opening-production.mjs` 在 `http://127.0.0.1:3028/` 的独立 Chromium 上下文运行，消费实际 `dist` 构建，10 项全部通过。[结果与源指纹](artifacts/opening-production/result.json)。

1. 根入口载入 F、唯一动效画布，没有 DEV 控件。
2. 派发浏览器 blur 后时钟冻结；聚焦按钮、Enter 恢复并连续重复按键，只恢复、不启动。
3. 系统减少动态偏好清空动效覆盖层；等待实际画布状态，避免固定短等待误报。
4. 实际“开始”进入已推广净化点，移除标题动效，并写入完整正式存档。
5. 刷新读回该存档，显示“继续”和三行记录摘要。
6. “重新开始”确认默认保留，Esc 取消后存档字节完全一致。
7. 实际“继续”回到净化点；装置、出击、潮汐、成长与薪柴数据保持。
8. 已存在的损坏 JSON 进入覆盖确认，默认选择保留；操作后原字节完全一致。
9. 存储不可读时禁止新建，不静默重置。
10. 正式流程没有请求 `/docs/` 资源，没有页面异常或 HTTP 失败。

主线程另在内置浏览器的独立 `3028` 来源实际点击“开始”、目视核对净化点，并刷新确认“继续”出现；用户原 `3027` 来源存档未重置。正式[首页](artifacts/opening-production/production-title.png)与[入场实景](artifacts/opening-production/production-haven.png)均来自运行中截图。
