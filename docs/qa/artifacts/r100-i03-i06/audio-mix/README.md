## P04结案范围与听感风险

2026-10-04主协调者明确裁决：**P04只关闭下文已修复并复验的声音工程缺陷；实际听感仍未验证，转台账R100-R10，不阻塞本次I03—I06实施结案，但发布前必须完成实际复核。** 这是对非阻断质量风险的明确处置，不是审听通过、用户批准或完整声音质量验收，不据此提高世界／等级资格。其他玩法、美术和技术退出条件并未取消。

实际审听不是本次临时追加条件：最早计划`7cdf86d5`中`docs/tasks/rift-r100.md`第110行已要求“声音需要实际审听；工具无法听时明确转交用户，不标已验证”，现行对应[总任务审核要求](../../../../tasks/rift-r100.md#e-三项独立审核)，并由`docs/art-direction.md`第149、171行延续。用户授权自主完成四轮，没有单独要求每轮等待其亲耳批准；也没有授权虚构听感。下文四项主观问题及全部历史证据保留，在具备实际听音条件后复核，不以更多波形测试代替。

## 发现与修复

1. 全局八声部限制只在 SFX 入口执行；BGM、Ambient 和动态层绕过限制，且 UI 无可抢占对象时允许继续添加。真实浏览器受控测试先出现 13 声部，UI 连续请求后达到 **17**。修复为所有生成声音的入口都经 `spawn` 统一准入；当前 Base 与已播放 UI 受保护，低环境层可让位，低优先请求满额时跳过。
2. 让位不是永久丢失。当前 BGM 有单一待播放目标，Ambient 有去重请求；饱和解除后恢复一次。明确停止、离开场景清除目标，暂停期间不偷播，恢复不复制声部。没有增加声音队列或超过上限的宽限。
3. 七条已有循环存在明显的数字首尾不连续。只在原文件的首尾做 30ms 等功率环形重叠/裁切，段内波形、频率、整体电平不重新设计。Overwriter 的纯音首端在第一次 Vorbis 编码后仍超门，另把同一周期旋转到近零点；没有放宽检查。每条时长缩短 30ms，不是新增声音库。

文件来源固定到 Git `a089bf787b80349533e850485419e3c157b879f4`，生成脚本 [repair.mjs](../../../../../tools/audio-loop-repair/repair.mjs)每次从该原始 OGG 解码，避免叠加处理。七个来源是 Rift base/tension/threat、proximity/alien、enemy idle/overwriter；R100 材料调用的五条 suspended-sea 声音没有替换。OGG/MP3 同步到 assets 和 public，交付 SHA 见 [14 格式实解码报告](loop-browser-delivery/report.json)。

## 实際验证与准确范围

- **18 组最终混音**：六类材料 × 低/中/重；真实 MainMenu 预载资源、真实 AudioManager/WebAudio 总线，逐组录完一个实际材料压力周期 + 暂停/恢复/退出。为了形成可比较压力样本，监听距离固定为零，threat=0.5、proximity=0.3，明确注入敌人警觉、受击、翻找中断、污染阈值提示。这是受控混音台，**不是自然遭遇或完整游玩**。
- 18 组均 0 削波，最大 6 声部，最大总线峰值 **−6.73 dBFS**；每组两个材料事件，无整片实体一起重复响的附加声部；暂停声音均暂停，退出均 0 声部。[最终逐组结果](delivery/report.json)与 [72 条关键提示观测](summary.json)。
- **12 项真实 WebAudio 饱和/所有权检查**：最大 8；敌人警觉与受击可以抢占低层；当前 Base 保留；已有 UI id 不变；环境层被挤出后只恢复一个；八个受保护 UI 暂时阻止 Base，释放后按目标恢复；暂停不创建待播放 Base；stop 可以取消尚未入场的 Base/Ambient；关闭 0 声部。[报告](voices-final/report.json)。为了稳定制造全受保护饱和，其中一段故意把 UI 请求设为循环——这是公开的故障边界夹具，不是正式 UI 行为。
- **14 格式实际 Chrome 解码**：七来源 × OGG/MP3，首尾单样本跳变均不大于同文件内部最大邻样本跳变，峰值<1。44.1kHz 双格式检查另保留；正式游戏同一 48kHz 前后 OGG 总 RMS 变化绝对值≤0.041dB；public/source 文件相同。首尾大跳变例如 同一 48kHz 游戏解码下，Base 0.245935→0.017779、Overwriter 0.350759→0.001232。该指标证明数字不连续被抑制，**不证明耳朵听不见接缝**。
- **掩蔽的有限客观检查**：72 条注入关键提示均观察到对应实际非零声音，而非只调用函数。以解码全文件 RMS × 实际声部增益、与同时声音能量和作宽频估算，最弱的是翻找中断，最低约 **+2.76dB**；其余警觉/受击/阈值高于该值。这个估算忽略相位、瞬态时序与听觉临界频带，不能写成“必然听清”，也不能用来提高全局响度。
- 类型检查、生产 build、既有材料音频 47 项 CPU 合同、43 个既有双格式源非空检查、suspended-sea 12 格式解码检查通过。项目没有独立 lint script。真实 Chrome 启动与播放构成 dev 冒烟；无运行 pageerror。

## 源与失败证据

最终声音使用 `http://127.0.0.1:3085` 冻结副本：[manifest](frozen-delivery/source-snapshot.json)。它沿用 code 稳定的 3084，只补最后 Overwriter 两个 public 文件。最终 AudioManager SHA256 为 `0c1aa43edfdb6e8f5f8e0fc2021f8cb69102f4fb4de0437a584b8891f2f97840`。声部分配测试在 3083，manager 与最终逐字相同，后来只改变 Overwriter 波形拼接点，不能影响声部合同。

修复前 18 组录于 3074，源证据是 [旧正式冻结 manifest](../../r100-i06/final-runtime/frozen/source-snapshot.json)。早期脚本 `sources` 字段读取了工作树，不能拿它证明所访问旧服务的源版本；原报告不改写，以上冻结快照/URL 才是 source-of-truth。前后墙钟帧调度略有不同，不声称逐样本同相位 A/B。

两次在 live 3081 录制的初始尝试因 HMR 导致动态 import 的 AudioManager 与场景实例不一致，`.game` 为空而失败；`after-rejected-hmr/report.json` 保留该失败，未计通过。随后停止用 live 服务做运行录制，使用固定副本。另首次编码 Overwriter OGG 仍超接缝检查，原数据保存在 `loop-browser/rejected-overwriter-codec.json`；近零点旋转后按同一检查通过。没有把这些失败隐藏或改门槛。

## 还需要人耳回答

- 材料摩擦/回落是否像六种实体的物质反应，还是会被听成通用合成噪声。当前六族复用五条材料源，不能宣称六套独立录音。
- 低/中/重的紧张程度是否自然，长时间重复是否疲劳。
- 正常游戏里关键提示是否从环境中分离，尤其能量余量最低的翻找中断；不同设备、低音量时是否仍明确。
- 数字接缝改善后，实际循环过渡是否仍会产生可感知点击或呼吸感。

这些是具体可播放的主观验收点。内部工程缺陷已修复，不能把不可执行的人耳审听伪装成已完成，也不继续为此无限重测波形。

另说明：重跑编码器会改变 OGG 容器 stream serial 与 CRC。六条 OGG 的工作树 SHA 与3085不同，但逐页验证所有 Vorbis packet、lacing、granule 时间和页顺序完全相同；八个其余格式逐字相同。[精确容器等价证据](container-equivalence.json)记录双方 SHA。未改标快照，浏览器声音结论通过这项同一性继承。原14格式报告中的前后 RMS 比较跨44.1/48kHz，仅作诊断；本文与 summary.json 的前后数字改用正式混音台同一48kHz解码。

范围外已知问题：完整49音源扫描还发现旧首页 bgm-menu-void-pad、净化点 bgm-pp-isolation-drone / amb-pp-mechanical-hum 有同类首尾大跳变。本轮没有修改三者；已向根任务报告，不把Rift修复外推为全游戏声音通过。
