# solid + VOID 联合空间增补：独立 QA 契约草案

日期：2026-10-13。任务基线：`99998703743895da7486fdee552f7bed019e64b8`。

本文件是准备执行的反例计划，**没有算法通过结论**。绑定 COH-F007/F011/F013，关联 F006/F012/F015/F044/F052。用户最新要求允许新增真实 VOID；上一轮“原孔不变”只保留为历史批次边界，不限制本算法。正式规则仍归原地更新的 `system-map-generation.md`；阈值待 Design/Code 的 CSV 合同冻结，QA 不自行发明密度、洞数或通道宽度门槛。

## 独立性与证据预算

- 小合成世界验证规则的真假，不烤材质、不生成图库；优先复用 3–4 张几何 fixture 形成 8 类负控及相应正控。
- 使用正式 20px 完整身体、8px 真实支持/VOID、真实投影三角和正式 DDA。不能用视线颜色、名义包围盒、总对象数替代它们。
- 每个断言只记录 fixture ID、输入策略 hash、候选 seed、结果/拒绝原因、前后状态 hash 与关键计数。失败保留必要坐标，不保存所有地图、field 或表面 buffers。
- 旧 r10 基线只存 3 份当前配方 JSON、完整 map hash、patch hash、未翻/已翻四 RGBA hash；旧前一批配方以不可变路径及 hash 复用。运行验收少量具名截图另由主线程组织。
- 验证入口应调用真实候选评估/事务函数；注入只能提供小 fixture、策略预算和明确的失败探针，不能跳过正式几何/部署门。独立测试不得复制生产评分函数作为预期答案。

## 八类高收益契约

### J01：只实体不能抵扣真实遮视缺口

在开阔、无内部 VOID 的可走面放入足够 solid，使真实 solid 距离/净空满足结构目标；选择初始确有遮视缺口的固定区域。

- 预期：结构轴可改善；VOID 遮视轴仍欠缺，不能返回 joint-complete。
- 检查：穿过实体的 DDA 仍可通；对应完整身体路径受阻。把 role 从 solid 改 relief 应取消身体结构收益，而不是仍靠像素/包围盒计入。
- 正控：增加合法真实缺地后，至少取得可达观察位 → 同一有效距离内的遮挡 → 绕端揭露 → 返回遮断见证。它只证明几何能力，仍不代替真实敌人潜行。

### J02：只挖孔删除原可走域不能洗掉分母

对一张大宽面挖去大块原可达地面或把原远端宽面隔离。剩余小岛可能达到 100%“当前可站点可达”，空圆也可能显著缩小。

- 预期：必须按固定原基底 P0 区分仍可达、实体占用、VOID 删除与失联样本。损失样本不计作结构/遮视改善；超过独立损失预算或破坏固定锚点时拒绝，不能借重新计算分母成功。
- 即使损失未超过允许预算，也不能把增加 VOID 自动算作实体结构覆盖：两轴分别记录。
- 正控：合法局部 VOID 可消费明确预算并产生真实遮视；它不需要维持上一轮 VOID mask 相等。

### J03：物理可穿不等于开放碎片

同一 fixture 的两块宽面，先由宽床连接，再用候选 solid/VOID 把连接压成一条仅身体可过的单窄桥；变体为多个宽腔由串联单口连接。

- 预期：即使 20px 图仍 100% 连通，也要拒绝新增的宽核连通退化/瓶颈。按 Design 提议，以基底 `Dclear >= 48px` 的宽核大分量和固定分散锚点保留原连通关系，并分别检查宽核面积/最大分量退化预算。48px 是保守体中心净空，不叫精确门宽。
- 正控：原地图已经存在的窄颈不被当成本轮新增失败；一个新增结构留两条合法宽绕路的候选可通过。
- 机器门仅防已定义的拓扑退化，不代替人判断是否读成房间/走廊。

### J04：新障碍不能损坏关键身体通路和完整部署

一个候选通过点中心连通，却挡住 20px 扫掠；另一候选只保留已部署节点中心，却使 48px 范围内完整合法翻找站位消失；再提供预算/巡路/Host 无法完整部署的合法几何候选。

- 预期：候选被拒绝，不能缩身体、改 LOS、填孔、减敌人/资源/Host 或降低非 safe 的 2400ms 未警觉窗口凑通过。
- 重点重用上一轮负控：实体贴住北边，两个 waypoint 虽在起终点轴线两侧，但实际都绕南边，不得宣称双侧通路。
- 固定锚点只用于比较原空间连通，不应冻结所有玩法投放坐标；最终地形成立后仍由原完整部署流程重布内容。

### J05：关系群不能靠换 ID、重叠或机械平铺充数

重复提交同一真实几何候选但换 group/object ID；将相同群移到已占足迹；再尝试等距同角群排列。

- 预期：几何签名/足迹互斥去重。重复零收益候选不能增加有效组数或改善计数，相邻距离/角度重复防护使用正式策略阈值。
- 正控：相同材料的两个非重叠、实际关系不同且分别补缺的群不应只因 family/profile 相同而全拒绝。
- 不将不同 seed、新 ID、微小不可见坐标抖动当成足以支持“多样性通过”的证据；本轮人工结构多样性仍另审。

### J06：拒绝和异常必须整候选回滚

冻结输入对象与基底快照。顺序运行合法 A、几何合法但内容失败 B、合法 C；另在 B 的实体/孔暂存后抛出可控异常。

- 预期：B 前后已接受状态 hash 相等；B 的实体、VOID、固定样本/宽核缓存、有效组数、收益指标和内容部署不得残留。最终结果应等于从 A 直接评估 C 的结果（除明确的尝试/拒绝日志与计数）。
- 任一候选失败仍消耗一次有限 proposal 预算；不能因为 accepted 数未增加而无限重试同一候选。
- 最终整体准入失败同样不能把“上一个部分候选”静默当完整成果送入正式新局。

### J07：停止原因不能伪装完成

分别验证基底已满足、达到两轴目标、零可行候选、持续零收益、预算耗尽、部分改善后耗尽。另输入负值、NaN/Infinity、非整数预算（按正式 schema 拒绝）。

- 按 Design 正在冻结的结果语义区分 `no-deficit`、`complete`、`partial`、`no-feasible`、`budget-exhausted`。名称可随正式接口调整，但“循环结束”和“目标满足”必须是不同事实。
- 目标未满足时预算为 0，不得完整通过；原来已满足时预算为 0 可以是 no-deficit，不能伪造新增物。
- 每次评估的独立子预算与外层尝试数都有上界，终止后无继续写数据/换世界/换等级。
- 不允许只把共同采样域缩小到一个满足点、丢弃失败区域或筛选成功 seeds 来报告 complete。

### J08：旧 r10 与新策略都必须确定性、冻结自包含

- 当前 HEAD 的三张 medium 基线：相同冻结配方在新版本路由下，完整 map、nodes/patrol、patch、未翻/已翻四 RGBA hash 均保持。复用更早三图三档 9 份旧 r10 配方，不能只覆盖最新三份。
- 在新作者 CSV/新策略启用后再次恢复这些旧身份，仍不得重新补洞/放实体或查询新作者数据；旧 r10 固定路由与未知版本拒绝分别测试。
- 新联合策略的同 seed/同冻结输入连续运行两次，产物与接受/拒绝顺序一致；失败候选路径不能污染下一次调用。若不同 seed 会产生完全相同结果，只说明确定性映射，不因此宣称多样性。
- 修改冻结策略字段而不更新身份校验必须拒绝；跨 worker 序列化后要保留真实增补结果/参数及停止结论。

## 接线后执行顺序

1. 先跑 J01/J02/J03/J05/J07 的小纯函数负控；没有这些门就不要先做全库大图库。
2. 接入候选事务后跑 J04/J06；零收益、回滚和预算上界用确定输入直接观测。
3. 冻结执行器接好后跑 J08 的轻量 hash 回放，再做少量完整三档代表生成。
4. 正式运行另验真实敌人感知与玩家输入。DDA 的“遮断/揭露”、通路和区域指标不可冒充听觉、警觉积累或自然搜撤通过。

Code 拥有实现，Design 拥有目标/预算和状态合同；QA 只在正式接口出现后新增独立测试脚本，不修改生产代码或规格。公共 game-state/evidence 由主线程汇总。
