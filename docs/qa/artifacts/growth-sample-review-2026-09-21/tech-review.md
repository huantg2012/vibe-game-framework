## 结论与范围

**价格、线性资格、购买事务、旧容量迁移和供奉并行收益在本次核查范围内成立。成长抗性的设计承诺与当前消费语义不一致，需要先统一规则。未发现正常购买流程中的新增 P0/P1 接线错误。** 这不是整个成长体验通过，也不覆盖其他审查组发现的 UI 信息旁路。

本任务覆盖 COH-F029，以及 F027/F028/F030/F003/F044/F045 的相关消费链；按已锁定的 22 步、只能购买下一项、供奉 1→4 审查，没有提出重新开放分支。角色为知情技术审查，先查当前代码、数据与活合同，没有把旧评审结论当作观察。方法为静态追踪＋真实领域对象的隔离内存实验；实验直接给予余额、经历事实和等量物件，不代表自然获取，不支持长期平衡、死亡率或好玩结论。

已覆盖：全部路线事务与重载、抗性时间/离散通道差异、供奉容量对应成熟吞吐、当前/旧格式容量迁移、预告冻结/投影的既有回归。部分覆盖：正式 Rift 的生命/亲和/抗性接线与恢复条件，采用代码追踪，浏览器前后对照由主审执行。未覆盖：自然 428 薪柴积累、持续装备供给、长期续局采样、声音、动态美术、真实玩家理解。美术结论由美术审查负责，本技术报告不代签。

## 应保护的已兑现关系

- **购买不是 UI 装饰。** `purchaseGrowth` 在同一保存内处理扣费、等级、稳定度、扩槽库存迁移和预告；只在成功后发事件。新实验按真实路线买完 22 步，每步重载，合计支出 428，余款 572；既有拒写、越步、旧非前缀购买回归本次重跑通过。
- **生命与亲和进入正式消费。** `RiftScene` 将 `100 + 15×生命级` 传给 Combat，并将亲和传给 `LootSearchSystem`；真实薪柴公式为 `max(1, floor((node.value + 亲和级) × 储藏倍率))`。亲和先加后乘，所以满储藏安全堆的最终值是 1/3/4/6，不能承诺每级每堆最终恒增 1。当前显示“基础薪柴”并说明再受储藏增益，符合此事实。见 [rift-scene.ts](../../../../src/scenes/rift-scene.ts#L396)、[loot-search-system.ts](../../../../src/systems/loot-search-system.ts#L636)。
- **同名级数没有被算作新能力。** 生命 4 级是上限 115/130/145/160；亲和 3 级是上述基值；渗透抗性 5 级是时间倍率 0.96/0.92/0.88/0.84/0.80。它们有真实数值差异，但不会新增按键或目标资格。
- **供奉扩容确实提高并行工作量。** 受控放满普通白板，正常冲击后各件积累同步为 1→2→3；容量 1/2/3/4 分别在第三次成熟 1/2/3/4 件，槽随后清空。不是缩短单件周期，也不产生供给。证据中的三次是直接调用成熟结算，未伪称三趟自然出行。
- **预兆是知识层级。** `getForecastReading` 消费已冻结事实：1 级确定强度档、2 级确定目标、3 级公开防御前压力；购买、保存和读取不会重抽。10 组既有回归本次重跑通过。是否有别的 UI 提前公开同一事实需要跨表面审查，领域投影通过不能替代该检查。
- **加厚与多带工具的成本仍真实存在。** 三次加厚提高上限而不回血，净化器按完整度比例计算起始混乱，已通过共享公式预览披露。出击扩容移动被动位置并增加第三主动位，仍只有一个被动位，仍算重量。不能把它们理解为赠送修复或物件。

## T-01 · 成长抗性承诺存在两种不等价解释

**类别：设计／规格／实现语义冲突。严重度 P2；证据把握高。** 所有抗性等级适用；发生频率是恒定的规则差异，不是概率失效。应在下一轮成长规则/数值工作前裁决，但没有证据要求紧急扩大现有效果。

预期依据存在内部冲突：

- [R2 设计路线](../../../design-notes/purification-growth-renewal.md#L45) 把五次购买写成“永久污染抗性增加 4/8/12/16/20 个百分点”。
- [成长活 spec G20](../../../specs/system-growth-tide.md#L236) 写“成长抗性在统一正向混乱通道只计一次”。
- [生存属性 spec](../../../specs/system-survival-attributes.md#L31) 则明确污染抗性按百分点相加、作用时间与离散所有正增；同文又要求旧“混乱增长速度降低”保留时间通道、不能等同新抗性。成长 spec 的旧边界表也保留时间倍率公式。

实际实现与受控结果：

- [RiftScene](../../../../src/scenes/rift-scene.ts#L407) 仅把成长乘入 `chaosRateModifier`；装备/工具抗性通过另一回调提供。[ChaosSystem](../../../../src/systems/chaos-system.ts#L324) 的 `addChaos` 没有消费成长倍率。
- 新档核心 70、无装备抗性时，实际购买到渗透抗性 0/1/2/3/4/5 级，时间增长依次为 **0.395 / 0.3792 / 0.3634 / 0.3476 / 0.3318 / 0.316 每秒**；同样 10 点离散正增在六组中均为 **10**。
- 外部抗性控制为 40% 时，所有成长级的离散正增均为 6；为 60% 时均为 4。时间增长仍额外乘成长倍率。因此它也不是纳入 60% 上限的百分点加法。
- 当前成长 UI 写的是“自然混乱增速 -N%”，准确描述现有实现；没有声称当前画面把所有伤害都减掉。

后果：按 R2 新文字评估战斗/发现/环境承压价值会高估这五笔投资；按当前 UI 和旧时间公式评估则没有这项失效。必须先确定哪种才是产品承诺，才能判断余额、后期 35 薪柴或装备抗性联动是否合理。

竞争解释／可推翻条件：可能只是本轮文案把旧时间减缓误写成新污染抗性。若设计确认保留时间专用语义、同步活合同并维持当前 UI，则不成立“代码漏算”；若确认要百分点统一，则需要实现迁移。不能由本报告代替该决定。

建议与最小验收：先做一次规则裁决，选定唯一术语与公式。随后固定核心状态，对成长 0/1/5 级各测时间、被发现、战斗、场域正增，再测 0/40/60% 其他抗性叠加及在途旧档。保留时间通道方案只需合同一致；统一抗性方案须补总上限与旧在途承诺回归。前者成本小，后者涉及场景、属性、工具资格、存档恢复及数值复核，未估精确工时。

## T-02 · 手工坏档可把物件留在当前容量之外

**类别：存档鲁棒性缺口。严重度 P3；证据把握高；自然发生频率未知。** 仅在手工构造的不一致存档复现，正常 `slotOffering` 会拒绝越界，未找到正常购买、迁移产生此状态的路径。不能写成正常玩家已丢物。

情境：新 `growth.schemaVersion=2`，供奉等级 0、容量 1；在同一内存存档写入一件合法白板，位置和引用均指第 4 槽（索引 3）。通过正式 `saveManager.load()` 加载。

实际：加载返回 true；物件及引用保留，但 `getOfferingItems()` 只投影一槽，看不到该物件；`slotOffering(null, 3)` 返回 incompatible，`discardAtBase` 返回 wrong-location。这件物品不在本轮充能快照里，也无法经正常取回操作释放，直到未来扩到该槽。结果见 `offeringOverflow`。

根因：[SaveManager](../../../../src/managers/save-manager.ts#L83) 验证成长与库存各自的结构；[InventoryStore.loadState](../../../../src/systems/inventory-store.ts#L193) 验证槽引用与位置一致，却没有与该记录迁移后的实际供奉容量核对。不能在默认 3 槽的临时 probe 中直接加死常量，因为合法旧 3/4 槽和新 1～4 槽都要保留。

竞争解释／可推翻条件：这属于无法通过正常入口制造的外部损坏，可以接受为低优先级；若外层已有读档时拒绝此记录的生产路径，则本结论需收窄。当前复现直接调用的是生产 SaveManager。

建议与最小验收：以记录自己的 schema 和等级计算有效容量，在分发现场状态前拒绝超容量的非空引用，并保持原字节可恢复；不截短数组或静默删物。验证新容量 1/2/3/4、合法旧 3/4、空尾槽、非空越界、active/未结算包。小型边界修复，需复用迁移回归；不影响本轮自然体验结论。

## 制作可持续性：当前成立，扩展边界需记录

路线排序、价格、每级数值、经历条件有 CSV 单源，生成器检查唯一覆盖、连续顺序及无跳级，适合在现有六轴范围内调序和调价。不能把此能力泛化为“只填表就能加任何成长”。

- 新能力需要增加 `GrowthUpgradeId`、效果聚合/消费、显示说明及恢复合同，这是合理的机制实现成本，不是已确认缺陷。
- **现有生命/亲和调上限也有跨文件成本。** [rift-recovery-state.ts](../../../../src/systems/rift-recovery-state.ts#L63) 把 `maxHealth` 固定限制 100～160、`kindlingAffinity` 固定限制 0～3；CSV 生成器允许每轴最多 5 级。只把生命第四级效果调高或亲和加到第四级，生成数据/类型可能通过，而新在途快照会被当前 admission 拒绝。当前数据没有越界，属于扩展风险，不是当前出击失败。
- 建议后续改这些 CSV 前，将有效上限从同一策划定义派生，或显式把“新上限出发→保存→重载→继续同局”列为调表验收。无需现在为未知新能力重构通用技能框架。

未上报为玩家缺陷：旧 `loadout-panel.ts` 的“下次踏入”只有模块混乱倍率，但当前正式备行使用新库存面板；没有生产可达性证据，不据此声称当前备行显示错误。存续报告装置页同样按装置语境读取模块效果，是否要总效果读数是新的表达选择。
