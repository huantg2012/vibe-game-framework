## T1 共享能力与表达范围

当前材料和空间确实通过共享参数与数据路径生成。`data/rift-world-spaces.csv` 提供空洞占比、裂口比例、尺度、方向性与聚集；`generateWorldSample` 接收独立 SpaceProfile，几何不按具名世界选择专属形状。`ground-material.ts` 按 strata/crystal/glaze 材料操作分支，再依底材、覆盖、磨损与沉积组合。新增已有能力内的配方主要是数据与验证工作；新物质规律仍需扩能力。

表达范围仍有明确边界：`layout.ts` 的 makeLand 固定使用112×76、16px格及带角向扰动的椭圆外轮廓，随后局部侵蚀并最多12次确定性重试；失败抛错。当前三条世界CSV都用层岩底材，覆盖各不相同；这解释共同基调，不等于架构只能使用层岩底材。完整世界规律、区域身份、语义部署和正式玩法接合，不能从参数数量推定已经具备。

**影响：** 将种子数量误作世界表达范围会导致过早扩大生产，不是已发现的单图故障。**范围/把握：** 当前源码，高；联合参数分布未测。**竞争解释：** 样板有意收窄以比较材料，当前阶段合理。**后续实验：** 在匿名配方和未调优布局中分别控制主形、聚集、静区，验证可见组织关系，不能只验证像素散列变化。

本轮未重复历史大批回归；旧文档的通过数量不属于这次新证据。

## T2 裂口尖端交叉复核

证据：[探针](../corner-probe.mjs)、[原始结果](../corner-probe.json)、[停点](../east-block.png)、[退离后](../east-recover.png)。使用实际浏览器键盘与当前页面移动逻辑；D 阶段读取调试状态和原始shape模块，没有改游戏或传送角色。

样本：crystal-fibre / fracture-fields / 175150，1600×1040、DPR1、150%，关闭视野排除未知区域影响。按玩法代理同类路线从出生点向东、北、东行抵达尖端。

- 当前中心约 **(917.71,817.27)**，九个占地点均合法。
- 东移1px：身体上中探针 `(0,-6)` 进入缺口，collisionAt拒绝。
- 北移1px：上中与右上探针失去支撑。
- 南移1px、东南各1px的候选位置均合法。
- 实际按向南退离，随后向东、向北可正常绕过，复现摩擦与恢复。

`world-study.ts:198` 使用中心、四角、四边中点，范围是上下左右各6px，接近方形占地采样；不能因变量叫radius就按圆形理解。逐轴移动在受挡方向清零速度。`surface.ts`与移动同用worldLandAt/worldWallAt；脚点旁有地面，不保证整块占地平移后仍有支撑。

**裁决：** 可恢复的身体净空/沿边通行读法摩擦，原因有直接证据。未证明地面与碰撞错位、地图断路或永久卡住。算法按定义工作，也不代表体验不需改善。

**范围/把握：** 这一尖端，高；全空间发生率未知。**竞争解释：** 真人连续微调可能更快找到南侧斜向通路，分段自动操作可能放大摩擦。**后续实验：** 在此固定点和新斜边比较脚点、占地及沿边滑动候选，不直接缩小碰撞或加全图轮廓。

## T4 本机有限运行成本

证据：[探针](runtime-probe.mjs)、[原始测量](runtime-probe.json)。Apple M4 Pro、48GiB、Darwin25，Chrome153无头、1600×1040、DPR1，本地Vite开发服务器。两位体验者及根代理角点浏览器均关闭后测量。

测前声明为探索性记录，没有项目给定的平台预算，不作性能验收。初版探针未充分等待PerformanceObserver回调；补齐50ms回调等待后重跑，当前JSON为修正后的有效结果，调用耗时在额外等待之前结束。

- 导航至ready **381.7ms**，捕获一次 **304ms** 主线程长任务；Vite已运行，不是应用冷启动耗时。
- 正常视野下约6秒四向移动，**361个rAF间隔**，中位数/P95约 **16.7ms**，最大约 **16.8ms**，大于33.4ms为0。它是回调间隔，不是输入到显示延迟或长期帧率证明。
- 同种子/空间切三份材料配方，regenerate调用到返回 **342.8 / 317.6 / 302.1ms**，对应长任务 **331 / 303 / 295ms**。
- 页面错误记录为0。

根因：world-study.ts:143的regenerate在一次rAF后同步执行几何、地表烘焙、光场缓存与Canvas上传。它让加载状态有机会出现，但不会自动把重工作分摊到多帧。

**影响：** 当前换图的有限等待；若以后在持续游戏中实时生成，会有节奏风险。**范围/把握：** 一台强设备、一个几何种子、三次重建和短移动；数值可复查，跨设备推广把握低。**竞争解释：** 若正式采用制作期预生成或加载阶段，成本可能可接受；不能单凭0.3秒要求改Worker。**后续：** 先定生成时机与设备预算，再选离线编译、缓存、分块或后台生成。长期内存、低配、组合失败率与制作工时未验证。
