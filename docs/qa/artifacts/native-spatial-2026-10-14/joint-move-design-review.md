# 原生联合生成：有限原子双物件移位评审

2026-10-14 · Design · COH-F011 / F013 / F007。范围：批准合同 §6 的求解器操作选择；本文件不是新 spec。只读现行实现和固定证据，未抽新图、未改 src / CSV / 准入门。

## 结论与证据边界

下一步采用 **有限原子双物件平移**。它针对当前已证实的“移走一个对象就丢掉另一处覆盖，或被另一个对象卡住”的牵制，新增一个最小联合自由度。一次同时试放两个完整对象，比较共同结果；不要求其中任一步单独有利。不增加数量，不改变形状、尺度、方向或板片，不改变 G1–G4、72 次评价 / 60 秒预算。

依据为固定 c39（geometryHash `dec8af0ac04c9412`），详见 [causal-analysis.md](hotspot-c39/causal-analysis.md)、[site-audit.json](hotspot-c39/site-audit.json) 和 [minimum-step.json](hotspot-c39/minimum-step.json)。该候选实际最大空白上界 202.999px、deep 480px、宽域 .581782、最大宽域连通 .999730。最近三个孔的现有有限候选全部合法位都精评后，原位仍为最佳完整 tuple；不是 rough 前 12 漏掉优解。

- 下孔靠近旧热点，旧热点距离降至 105.679px，却在右下岸产生 273.209px 新空白。
- 中左孔仅左移 16px，实际 deep 从 480 增至 1040px：它也承担分隔纵向深空白的职责。
- 大孔南移 16px 被中左孔间隔拦住，南移 64px另有海岸支撑不足；中左孔往东又受母体附属 relief 约束。

这些证据说明单物件贪心的操作域不足，**未证明双物件有解，更未证明现有数量无解**。地图仍未通过。

## 三个方向的取舍

1. **原子双物件平移：本轮实施。** 可以同时填补旧覆盖职责、释放阻挡者；复用现有 footprint、距离场和实际 VOID 宽域缓存，保持原形体和身份。新增的变量只有第二个完整对象的位置，便于反证。
2. **完整 shape 站点交换：暂不实施。** 保留总数，但大孔与小孔互换会同时改变岸支撑、分隔方向、接近空间；最近两个孔同属 small，最近 large 又受岸约束。当前没有“某站点分配错了尺寸类型”的实证。交换即使有效也不能说明根因是交换，而非共同腾挪。
3. **初始分布重排：保留既有 fresh 分支。** 它能跳出这个布局，但已经存在有限 fresh。现在增加一次独立重抽既不能验证已定位牵制，也会把成功归因混入母体、板片、孔大小分配等多变量。本轮不新增重启次数。

## 最小实施合同

### 触发和成本

仅在已有完整 plan 的单物件扫描没有降低完整规划 score 的前两项 `(maximum, sum)`，且实际门仍因空间质量失败时，下一次已有 refinement 使用双物件操作，**替换该次单物件扫描**。均值下降不取消“空间约束停滞”状态。可在 plan 的运行期诊断中记录一次扫描是否停滞；不改冻结配方，不扩大控制器存活/评价次数。

同一不可变 base geometry 只执行一次相同双移位候选集；无改善就交还既有 archive / fresh / 失败流程，不在相同几何上不断换随机流。固定样本可显式调用该操作以验因果，但不能算新生产通过。

建议上限为 **3 个有因对象对，每对至多 16 个共同站位，合计 48 个完整规划 tuple**。前置最多 12 个单移位诊断只计算 footprint / 覆盖损失和阻挡来源，不编译地形，不跑宽域洪泛。总完整 tuple 次数再取 `min(48, 12 × 对象数)`；不可在原本每物件 12 次精评扫描之后无条件追加这 48 次。实际耗时仍须测，评价次数少不等于必在 60 秒内。

### 确定性候选生成

全部从同一 base 同时取样；不把某个试放的临时结果作为下一个试放的世界。

1. 取实际门对应最大标准化违例的见证点：最大空白用 `worstEmptyPoint`，deep 用 `worstDeepPoint`；相同违例按既有固定门顺序。按完整 blocking footprint 到此点的距离选最近 3 个对象 A（H / S 都可），平局按对象稳定 ID。不能只按中心距离、不能只动 H。
2. 每个 A 沿站点到见证点的方向产生 16 / 32 / 64 / 96px 四档位移，坐标对齐现有 8px；零向量、重复坐标去重。此处允许“全局暂时变坏”的中间假设。只有海岸/完整地面支撑已不成立，或同时需释放两个以上其他对象的提案直接排除。
3. 对每个 A 的每个试放站位选一个有因搭档 B：若一个其他对象单独造成间隔或 relief 支撑冲突，选该完整对象作为 B；否则在临时移走 A 后找最大新增覆盖缺口（距离增量为正的场点，按最终距离降序、增量降序、y 升序、x 升序排序），选到该处最近的另一完整 blocking 对象。诊断 deep 时同时保留原 `worstDeepPoint`，最终全域 deep 测量不得省略。若没有新增缺口且没有单一阻挡者，不生成这个有因对象对。每项保存其来源 A 站位、阻挡者或损失点；同一 A 的不同站位可以提出不同搭档，再统一去重截取。
4. 去重后最多保留 3 对：有明确单一阻挡者的对先于覆盖补位对；同类按 A 到原见证点距离、A/B 稳定 ID 排序。不能写入 c39 坐标或世界 ID 特例。
5. 对每对，A 保留上述至多 4 站位，在每个站位重新计算这一对的损失点与共同约束。B 对每个 A 站位产生至多 4 站位：朝新缺口 / 原分隔见证点的 16 / 32 / 64px 位移；第四项在释放阻挡关系时取与 A 相同的平移向量，否则取朝缺口 96px。都对齐 8px、去重；两者不需要移动同样距离。每对的最多 16 组合，按 A 位移档、B 位移档、坐标顺序枚举。

这是有界启发式候选域，不声称穷尽所有双物件解。选择顺序是程序求解预算，不是新增地图内容比例；不得反写为作者形体阈值。

### 共同合法性和比较

- 从阻挡/支撑查询中同时移除 A、B 的旧位置，再将两者完整试放。分别核对海岸与 L−B 支撑、所有未移动对象、两移动对象的双向间隔。仅检查 A 对旧 B 会错误拒绝应当一起腾挪的组合。
- S 的唯一母体及其 attached relief 同步平移，局部接合、尺度、旋转和 ID 不变；不能只动挡路 relief。H 的整个矩形组和对应实际 VOID 缓存一起移动，不能拆孔、造微孔或借外海抵扣覆盖。
- 宽域缓存需一个原子 `evaluatePair` 等价操作：同时扣掉两个旧 mask、加两个新 mask，再测一次；无论成功、失败或异常，都恢复精确原状态。最终择优才共同 commit，禁止半提交。
- 全场距离使用其余对象、A、B 的并集；前两项仍是现有标准化违例的 maximum、sum，均值仅平局排序。旧热点变好或 mean 变好不能单独成为成功理由。无严格前两项改善时返回“该操作域未找到改善”，避免靠微小均值变化制造收敛迹象。
- 只将最佳共同布置产为下一完整 proposal。正式重新编译和测量照常占一次既有几何评价；实际自由断缘可能变化，缓存估计不是准入结果。实际出现更大新空白、deep 合并、H 身份变化或通路断裂均保留失败证据，不以规划分数覆盖。

## 本轮反例验收与停止条件

1. **c39 原因重现及联合改善。** 固定冻结输入、原形体、原数量、原种子，重现上述两个单移位的实际退化；双移位候选必须记录 A/B 旧新站点、阻挡者或损失见证点、完整规划 tuple 和实际全域门。至少一个候选要在真实最大违例 / 合计上优于原 c39，且不能把已过的两项宽域变失败，才能说“本局部牵制得到改善”。若 48 个有界候选没有这一证据，原样报告无改善，不加对象、不继续扩大搜索范围；交还 Director 决定下一操作轴。即使改善，也不能称整图通过。
2. **原子释放与原子拒绝。** 构造 A 到新位时只与 B 旧位冲突、二者新位共同合法的夹具，必须能试评；另构造两个新位互相过近 / 孔侵占随母体移动的 relief 的夹具，必须拒绝。拒绝或异常后 occupancy、sites、wide mask 与原状态完全相同。对象遍历顺序变化不得改变稳定排序后的结果。
3. **覆盖搬家不算修复。** 保留 c39 下孔旧热点 105.679px / 新最大 273.209px 反例，以及中左孔 16px 引起 deep 1040px 反例。若 B 没补住损失，不能以旧热点、均值或宽域通过接纳该对；若规划改善而重新断缘后实际变坏，必须走真实拒绝。

上述定点检查之后才跑一次新的源稳定正式请求，连同全部失败、耗时、真实评价数和完整内容部署记录交付。没有完成图时继续明确标注失败；不得把局部最优、见证点改善或48个候选无解写成地图品质结论。

## 固定 c39 首轮后的候选覆盖审查

2026-10-14 续审。只读取现有 `joint-c39-round1/` 收据与源码、Layout 对原 12 个 A 站位的来源分类；没有新增站位、tuple 评价、地形编译或 fresh 请求。

**结论：首先纠正候选分配失衡，现证据不能判定双物件自由度不足。** 首版“全局 blocker 优先 → 无序对象对去重 → 截取 3 对”的设计让一个主移动对象占了两个名额，另一个已经产生有效因果来源的主对象完全没有获得试评。代码按该排序合同执行，不能把这一结果归咎于实现偏离。

### 本轮实际覆盖了什么

[report.json](joint-c39-round1/report.json) 源稳定，算子约 675.8ms。实际为 **40 个共同站位、18 个合法精评**，不是 48 个合法双物件状态，更不是任意双移位全域穷尽。无共同状态改善，selected entries 为空，原图保留；没有把规划拒绝当成实际新图结果。

- `hole-4 → hole-0`：8 个共同站位，2 个合法。其余主要是两个移动孔仍过近，部分也碰固定 upper-clamp。合法项 deep 规划代理仍为 1056px。
- `hole-0 → upper-clamp`：16 个共同站位，0 合法；母体连同附属 relief 的完整支撑不成立，不能拆 relief 来迁就。
- `hole-0 → subordinate-13`：16 个共同站位，全部合法；仍不能在规划代理上切断 1056px 深区。

所有合法项的最大标准化违例至少 1.357，原规划值为 .262；没有准入改善。详细拒因见 [rejection-classification.json](joint-c39-round1/rejection-classification.json)。这些非选中共同状态没有重新编译为完整实际地形，1056px 应明确称规划代理；实际保留的 c39 deep 仍为 480px。

### 被截掉的有因来源与反向来源

[pair-source-classification.json](joint-c39-round1/pair-source-classification.json) 保留了原枚举的 12 个 A 站位及 10 个成立的 cause；这里只重新核对已存在来源，没有探测新坐标。

1. 中左 `hole-0` 的 16 / 32px 源站位失守点为 (964,1116)，最近补位者为 subordinate-13；64 / 96px 失守点为 (956,1116)，最近补位者为 upper-clamp。因此它提供两个不同对象对。
2. 下方 `hole-1` 的四档源站位均已提供 `hole-1 → subordinate-13`，损失点 (948,1468)。该方向正对应已实证的“下孔西移，右下岸丢覆盖”。它不是无 cause、不是岸拒、不是共同评价后失败，而是排序截断前已经生成、随后作为第 4 个无序对被删除。
3. 大孔 `hole-4` 的 16 / 32px 是 `hole-4 → hole-0` 单阻挡来源；64 / 96px 原岸支撑失败。blocker 全局优先让这一对先占一个槽。

原排序的规划 footprint 距离为 hole-0 191.846、hole-1 194.487、hole-4 282px；与实际断缘后的两个近孔先后略有差异，但三个 A 都已入选。主要缺口发生在选出 A 之后的对象对截断，不能误写成“下孔不是最近三个”。

**本例没有丢失 `hole-0 → hole-4` 反向因果：该方向原先根本未生成。** 无序 pair 去重一般会把 A→B、B→A 当同一来源，尽管它们的主见证点/修补向量不同；这是需要澄清的契约语义风险，不是本次已发生失败的根因。不能为补方向而凭空生成反向 cause。

### 最小纠正：先分给主对象机会，再在其内部选搭档

本条替代上文“确定性候选生成”第 4 步的全局截取方式；其他步骤、位移档和预算保持。

- 仍只使用同样最近的 3 个主对象 A、同样已经定义的四档站位与 cause 规则。为每个有 cause 的 A 保留 **1 个有向操作槽**；按既有 A 距离 / 稳定 ID 顺序分配。一个 A 不得在另一个有 cause 的 A 获得首槽前占第二槽。
- 每个 A 的槽内沿原有“blocker 先于 coverage、搭档稳定 ID”顺序选择第一项有向 cause 组 A→B，不借失败结果挑新搭档。仍最多 3 槽、每槽至多 16 个共同站位、全次不超过 48；**本轮不回填未用槽，不把剩余额度滚给已占槽的 A**，保持一个可反驳的分配改动。
- 去重键为有向 `(A ID, B ID)`，保留来源方向；只有两个方向本来都由 cause 规则产生时，才可各占其主对象自己的一个槽。最终完全相同的两个对象新站位依然全局去重，不能靠方向重复计数。没有反向来源就不构造。
- 这一纠正将恢复原先已生成而未得到名额的 `hole-1 → subordinate-13` 机会；不增加第五档位移、不扩大物件数、不增总共同站位上限、不放松实际门，也不更换双移位操作轴。

这不是宣称下孔那一对会成功，而是让一次“最近三个原因对象”的有界试验确实覆盖三个来源。首轮无改善结论继续成立，仅限定为实际被选的三对。**调整后的候选分配尚未执行；没有新改善结果。**

### 修正本身如何验证

先用已有来源列表做纯选择检查：三个有 cause 的 A 各至多一槽；hole-1 来源不得再被 hole-0 的第二搭档挤掉；同一来源集顺序变化不影响稳定结果；无反向 cause 不凭空新增。再由 Director 授权 Code / QA 对原 c39 做一次替换后的同上限定点评价，完整保留旧收据。

若纠正后的三个来源均获得额度仍没有实际改善，可以报告“这个固定方向生成器下、这批均衡分配的有界双移位未解决”；仍不能推出全部双物件位移、shape 交换或当前计数数学无解。任何下一操作轴都应依据新的具体失败原因决定，不能只由试位数量驱动。

## 补位距离与修复目标的必要条件审查

2026-10-14 再续审。Director 批准的一次均衡选择评价已经结束，见 [joint-c39-balanced-round1/report.json](joint-c39-balanced-round1/report.json)：源稳定、约 633.2ms，40 个共同站位 / 14 个合法精评；恢复的 `hole-1 → subordinate-13` 为 16 个共同站位 / 12 个合法，其最佳规划 `(maximum,sum)` 为 `(.375378,.553949)`，仍劣于原 `(.262147,.440718)`。没有提交新布置，实际图仍是 c39。

本次只对两份既存收据中的坐标、原 12 个 A 站位来源点和 c39 已冻结的 footprint 求点到三角形距离。重建的是原 `planningObject` 的同 seed 20261012 blocking footprint；没有生成新站位，没有调用完整 tuple、宽域测量或地形编译。以下不是新的通过图。

### 1. 恢复的下孔配对：四档 B 位置确实都没有补位能力

对原已存在损失点 `q=(948,1468)`，subordinate-13 原 footprint 距离为 **310.820px**。均衡收据内四个 B 站位到此点分别为：

- `(1216,1224)`：299.546px；
- `(1200,1240)`：277.008px；
- `(1176,1256)`：249.503px；
- `(1152,1280)`：215.870px。

最远一项实际位移 96.333px。任何固定 footprint 平移都满足 `d(q, B+Δ) ≥ max(0, d(q,B) − |Δ|)`，因此仅由位移长度就能给出该项 **214.487px** 的距离下界。达到名义 112px 至少需要 198.820px 平移；按 deep 场点误差 `4√2`，达到保守中心距离 `112−4√2≈106.343px` 至少需要 204.477px。即便不读取已产生的 B 位置，只用四档名义上限 96px 加 8px 坐标对齐的最大误差，也能证明最短剩余距离下界 209.163px，大于 112。

更强的有限域证明直接对应本轮 tuple：A 四个原位移后到 q 分别为 **209.057 / 220.057 / 255.705 / 284.522px**；除 A/B 之外所有固定对象到 q 最近也有 **430.010px**。于是这 16 个组合不管如何搭配，此点的最终最近结构距离都不可能低于 **209.057px**。对现行规划 cover 目标 `160−8=152px`，单这一点就给出 `209.057/152−1=.375378` 的最大违例下界，恰好等于收据中的最好值。

这条反证精确解释了本轮为何无改善：**虽然分配机会恢复了，原定的 B 四站位不能履行这一损失点的补位职责。** 这不是两个对象在连续合法位置上一定无解，也不能直接把原计算中的规划点结论写成实际新地形门结果。

### 2. 不能把首轮全部失败都归因于位移太短

对大孔 `hole-4 → hole-0`，损失点 `(844,708)` 到旧 B 为 274.192px。首轮已列 B 位置最长位移 68.352px，必要距离下界 205.840px；两个合法的同向腾挪站位到该点反而为 289.353 / 307.059px。该对有释放 A 的作用，但这批 B 位置没有把该损失点补至 112px 的能力。

但中左孔 `hole-0 → subordinate-13` 提供反例：首轮 96 档 B 站位 `(1136,1184)` 到两个已列损失点 `(964,1116)` / `(956,1116)` 为 **93.574 / 101.432px**，均小于保守 106.343px，且共同状态合法。该点已经被补回，收据中的 deep 代理仍是 1056px。故“所有 B 都太远，统一放大步长就能解决”不成立。

upper-clamp 的 96 档同样可以把这两个点降到 90.539 / 94.362px，但其完整支撑全部失败；这种位置不是可用补位。距离足够与共同合法是两个必须同时满足的条件。

### 3. 当前最大 loss 点并不等于新打开的深区连接口

原 cause 列表中四个不同 loss 点，在 A 移动**之前**到最近结构的距离分别为：

- `(964,1116)`：173.658px；
- `(956,1116)`：166.027px；
- `(948,1468)`：191.230px；
- `(844,708)`：172.070px。

它们原本全都已在 112px 深区之外。当前实现按“移动后距离最大、再看正增量”选 loss，因而选中的是本来就很空、移动后更空的点，**未专门寻找原先被 A 分隔、移走后才接通的边界**。这解释了为什么“成功补回 loss 单点”仍不足以证明 deep 连通被修复。

以上证据支持修复目标语义存在缺口；没有在本次审查中计算新增深区的连通口位置。因此不能断言具体哪个新坐标是正确补位，也不能从一个远处原 deep 见证点推断 B 必须覆盖它——截断长连通区可以发生在别的部位。

### 下一步的具体因果建议

**停止继续沿当前单一 max-loss 点机械加档位。下一操作轴应是“按失去的覆盖职责产生补位目标”，仍保持两个完整对象。** 候选数量、母体形体、计数、门和全局预算均不变。这是尚待 Director 安排的下一设计/实施点，不是本次已执行修复：

1. 对 A 的既有位移，先区分两个待修职责。最大空白职责使用超出 cover 边界且因 A 移动而恶化的见证点；deep 分隔职责使用原先在深区阈值内、移动后才越界的已有场点，并核对它们是否接通了原来分开的深区。**原本已深的最大 loss 点不能自动充当分隔连接口。** 若这一步没有证实新的连接口，明确保留未知，不编造一个中心点。
2. B 的选取先检查必要可达界：它到所选职责点的 footprint 距离、需要恢复的阈值、其完整支撑能否允许相应平移。最大空白和 deep 用各自的现行阈值，不把“所有 loss 必须到 112”变成新的准入门。像下孔那一对，四档最多 96px 明知连现行 cover 边界都触不到，就不应消耗四个完整精评去期待它补位。
3. 若要产生下一版 B 站位，用 **footprint 最近点到职责边界所需的平移** 构造有限候选，候选数仍至多 4；不再只按对象中心朝单点固定走 16/32/64/96px。平移长度来自明确的覆盖缺额，不能随失败无限加大；到位后仍核对 B 丢失的旧职责、共同支撑、间隔、全域 deep 和实际自由断缘门。
4. 先用已保存 c39 的既有场点说明“哪个职责因 A 移动才失去、为什么当前 B 目标没有补住”再实施，不重抽世界或同时引入旋转 / 尺寸交换 / 第三个对象。当前证据尚不能保证上述目标改正后存在合法双物件解，更不能保证完整地图能通过。

因此，均衡后的失败收据保留有效，但它反证的是**当前固定步长、单一最大 loss 指向的双移位候选产生器**，不反证批准合同允许的双物件联合求解本身。正式请求和完整地图验收状态未改变。

## 下一次有因候选合同：恢复失去的覆盖职责

本节收束 Director 已授权的新候选方向，替代旧的“最大 loss 单点＋B 固定四档”产生方式；由 Director 统一交 Code 实施。本节未运行新位置。**不引入最大流、最小割或保证拓扑修复的声明。**

### 输入、A 槽与职责目标

保留原来的 3 个主对象 A、每 A 四个既定站位、每 A 至多 16 个完整 tuple、总量至多 48；不增加 A 位移档或随机流。每个 A 试位都从同一个不可变 base 起算。

Context 显式接收由现有评估方计算的两个**规划距离限值**：`coverPlanningLimit = policy.maxEmptyRadiusPx−8`（当前152px）、`deepPlanningLimit = policy.deepEmptyThresholdPx−4√2`（当前约106.343px），以及基础格点数量/步长和 8px 坐标对齐步长；禁止在新模块另写 160 / 112 常量或再次扣距离误差。前者对应 `completePlanningScore` 的 cover 分母，后者对应 `createNativeDeepSpanProxy` 内部 `distance+4√2>threshold`。额外 actual assessment 点可参与最大空白见证，**不可作为连通格点**。连接关系复用现有 deep 规划图相邻规则。当前是 16px 规划图，以下称**预测新增深区**；实际重新断缘后的 8px 身体图继续独立验收，实际门自己的误差口径不改。

对每个 A 站位计算旧距离 `d0(p)` 与仅 A 移动后的 `dA(p)`。最多取两个职责目标：

1. **deep 目标优先。** 新增带严格为 `d0(p) ≤ deepPlanningLimit` 且 `dA(p) > deepPlanningLimit` 的基础格点。分别标记旧 deep 分量与新增带分量。新增带分量先按“接触至少两个不同旧 deep 标签”排前，再按其中最大正距离增量降序、最小格点 y/x 升序；只取第一分量。其代表集合 W 至多两点：距离增量最大点 p1，及同一分量内离 p1 最远的点 p2，平局均 y/x，重复去重。它们都必须来自新增带，禁止用原本已经 deep 的最深点替代。接触多标签仅为候选优先级；代表点被覆盖并不保证长深区被截断。
2. **max-cover 目标其次。** 在 `dA>d0` 且 `dA>coverPlanningLimit` 的已有场点中，按“超过 coverPlanningLimit 的违例增量”降序，再按 `dA` 降序、y/x 升序选一点组成 W。该职责使用现有最大空白160规则对应的规划152限值，deep职责使用现有112规则对应的约106.343限值；不把两者混成一条更严的新门。这里允许原本已空旷但被 A 移走后进一步恶化的点。

没有对应见证就没有该目标，不补造点，不把旧 loss 最深点回填为 deep 目标。新增带识别最多 12 份距离场和连通分量扫描，不查询 B 的全地图位置。

### B 解析站位与共同可行性

每个职责目标 W 用其包围盒中心 q 和 `ρ=max distance(q,p), p∈W` 表示；单点时 ρ=0。令该职责的**规划距离限值**为 T（上述两个限值之一），`R=T−ρ`，不再扣 E。若 R≤0，记“该代表集合无法由本圆包络生成器认证”，跳过该目标；不能据此宣布完整 footprint 无法覆盖或双物件无解。

对每个 B，求原 blocking footprint 到 q 的最近点 z、距离 D。若 D≤R，旧 B 已能认证该 W，不需要这份补位候选；跳过。否则沿单位向量 `(q−z)/D` 产生解析平移：

`t0 = D−R + snapStep/√2`；`t1 = t0 + snapStep`。

两项分别平移 B 的**整个物件组**并对齐既有坐标网格。对齐后再精确检查 W 中每点 `distance(Bnew,p)≤T`；不能因公式估算满足就省略这一检查。`snapStep/√2` 仅补偿新站位对齐误差，不是再次扣实际门的单元误差。t 的长度由欠缺的覆盖距离导出，不沿固定 16/32/64/96 盲试，也不额外增加长距离档。完整支撑、母体附属 relief、A/B 共同间距及其余对象仍走现有共同合法性。

每目标最多考虑 3 个 B：按解析必要位移 `D−R` 升序、稳定 ID 排序，从同一有限对象集取前三。**先对已定义解析站位做共同合法性，再选可行搭档**；最近 B 所有站位支撑失败不能据此称 A 已被充分检验。没有单一阻挡者时，每个完整 tuple 槽选择这三者中第一个同时满足目标覆盖与共同合法性的 B；没有可行者则该槽为空，不扩到第四个。

若 A 新位被恰好一个旧对象 B 阻挡，所有修复槽都强制使用该 B；移动别的对象不能释放它。仍保留 B 与 A 同平移向量的释放候选，该候选只需共同合法，不必假称覆盖了 deep / cover 目标。两个以上阻挡者仍不在双物件操作域内。海岸支撑失败不能被 B 释放。

### 精确预算与排序

每个 A 站位仅有四个固定槽，依次为：`deep(t0)`、`deep(t1)`、`max-cover(t0)`、`max-cover(t1)`。存在单一阻挡者时，第4槽替换为同向释放，不另外追加。不存在的目标留空，不回填。

- 每槽最多查看上述 3 个 B 的**一个已定义坐标**，优先取第一个目标覆盖及共同合法的 B；最多 3 A × 4 A站位 × 4槽 × 3 B = **144 次有限位置预检查**。单阻挡者槽实际只看一个 B。
- 每槽最多进行一次全场完整 tuple，故每 A 至多16、整次至多48；预检查不得偷偷调用完整 tuple / 宽域洪泛 / 地形编译。
- 完全相同的 A/B 新位置组合全局去重，来源目标/方向保留到诊断；重复槽不补抽。比较仍是原 `(maximum,sum,mean)`，进展仍要求前两项严格改善；实际门及72次/60秒不动。
- 记录每个 A 站位的新增带数量、选中分量接触的旧标签数、W/q/ρ、目标阈值、每个 B 的 D / 必要位移 / 解析站位、覆盖或支撑拒因、预检查数和完整 tuple 数。没有可行搭档与“评过但不改善”分开报告。

### 本轴的反证标准

先做确定性夹具：原本已 deep 的最大 loss 不得入选新增 deep 带；新增带代表必须回指已有格点；解析站位须达到所用职责阈值，160与112不混；最近 B 支撑失败时可检查同一前三集合的下一 B；144/48封顶、原子事务/母体完整/单阻挡释放保持。

再在已保存 c39 上做一次该有因轴的固定评价，保留此前两份失败收据。只有真实重新编译后的完整门才能证明地图改善；规划代表被覆盖、预测分量变化、解析必要距离达到，均不等于实际深区被断开或整图通过。无改善时报告具体目标覆盖/支撑/全场违例，不能在同一轴继续追加档位或见证。
