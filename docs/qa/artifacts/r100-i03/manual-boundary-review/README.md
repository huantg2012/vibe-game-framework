# 斜边通行独立复核

结论：有真实缺陷。8px 保守实体格将板体之外的空白边角也作为完整墙格处理，角色会比真实实体提前约 2–8px 停止。本次不是角色脚点偏移，不是 relief 被误登记为 solid，也不能解释为根任务完全看错了一堵宽墙。宽斜板本身仍是 solid，修复精度不会让整块板可以穿过。

## 实际结果

1. **007→008，W 2500ms**：中心从约 `(579.19,313.54)` 到 `(580.57,306)` 后停止。顶边 `y296` 碰到格 `(71,36)`；该格64像素中仅16像素属于可见solid。按真实三角形投影，完整20px身体还能向上 **4.96px** 才相交。
2. **012→013，A 2400ms**：中心完全停在 `(538,334)`。真实身体是 `[528,548]×[324,344]`，左上碰到墙格 `(65,40)`，其范围是 `[520,528]×[320,328]`。格内只有14/64像素为可见solid，全部落在 `y320–323`，没有任何可见solid处于身体的 `y324–344` 高度带。身体距最近可见solid为4.30px；沿左方向按真实三角形仍可移动 **7.66px**。这是玩家看到空地却原地停住的直接原因。
3. **016，W 3000ms**：中心约 `(341.60,354)`；实际身体与三角形之间仍有 **2.16px** 向上净空，却已被完整8px格阻挡。附近格 `(41,42)` 甚至没有采到可见solid像素，但实际三角形与格发生极小相交，整格仍为墙。
4. **017→018，W 3000ms**：中心从约 `(267.76,354)` 到 `(264.92,330)`。真实身体顶边 `y320`；视觉足沿约在 `y313–314`。按真实三角形还有 **4.99px** 向上净空，8px墙格先挡住。

所有上述接触对象都是 **solid #1**。该地图还有 solid #2 与 relief #3；#3在上方，未参与本次阻挡。身体中心与 sprite 原点一致，尺寸20×20、偏移6/6，没有临时扩大身体。角色靴底在图像中心下方是原有俯视模型，不是这7.66px提前阻挡的原因。暂停后 `body.blocked` 已清空，不能用这个标志否定实际碰撞；位置不变和独立支持检查均复现了阻挡。

## 因果链

`r100-master-world.ts / solidCoverage` 将任意 solid 三角形与8px格的相交都登记为整格 `WALL`。这是合理的生成准入保守近似，却同时被 `RiftScene` 不可见 TilemapLayer 的 Arcade 碰撞使用。因此，斜线、尖角和细曲边普遍存在最多接近一格的不可见扩展，不限当前一个种子或当前四个点。

渲染则按1px raster画真实三角形，未填满那一格。两个表示同源但精度不同；“同源”不能证明玩家看到的边界与运行碰撞一致。本次旧足缘抽核不足以覆盖这种沿角方向靠近的情况。

另有独立的视觉读法问题：007/018看得见完整板形，但母面面积很大、局部薄足缘与普通地床接近，容易误读为可以踏上的低起伏。这不等于 relief/solid 数据错乱。先修复不可见扩展，再用相同正常灯光复核残留读法，不能用把8px格涂出来掩盖差异。

## 最小修复边界（尚未实施）

### 保留生成与身份

- 保留现有8px保守生成准入、出生/搜取站位、20px身体、32px Host格、敌人巡逻配方、地图identity及所有旧v1/v2执行路径。
- 为v3实际身体查询提供精细实体占据。依据必须是**所有solid几何的投影并集**，与既有不可用地面/VOID相交约束。不能直接使用 `raster.matter`（包含relief），也不能直接使用最高可见面的 `fields.solid`（上层relief可能覆盖下层solid，但不应清除其碰撞）。
- 若用1px掩码，需保守覆盖真实三角形与每像素方格的相交，不能仅测像素中心导致细三角形漏挡；VOID仍继承原8px地面支持规则。细掩码只减去旧8px墙格中没有solid的空白部分，不移除真实solid，不放宽VOID，不缩身体。
- 生成8px可达路径必然仍被支持；可达空间只增不减。细碰撞数据可从原已冻结mesh/matter导出并预烤，避免改recipe/map签名；是否纳入worker准备由现有P01时间门实测。

### 普通移动与技能不能分叉

- 仅v3替换玩家与静态8px地图层的碰撞处理，保留现有Player输入、加速/减速、朝向、战斗和实体碰撞。按实际物理步对完整20×20身体做连续扫掠和沿边滑动，阻止高dt穿透；不要每帧缩半径，也不要先穿过再回弹。
- 不能只在Arcade tile process callback里忽略空格部分：如果真正接触时仍按整格分离，会被突然推回旧8px外沿，产生抖动。
- `sweepPlayerDash`目前仍传 `formFloorGrid`，其 `bodyFits` 会把新增合法贴边位置判为非法，导致冲刺原地失败。普通移动、冲刺起点/整段/终点必须共用精确身体支持检查，保持原有可见性、敌人身体与沿途伤害检查。
- `findSingleWallLanding`明确用 `grid.tileSize` 定义“一格墙”的相位穿越。**不能直接把tileSize从8换成1**，否则会把允许穿过的墙厚改成1px。保留8px墙层选择/穿越厚度语义，分离起点、落点及非目标墙的精确身体检查；避免贴边后无故无法发动，同时不能借修复穿过第二堵墙或VOID。
- 声诱投掷、缝线与近战目前也使用保守地图。它们不是玩家身体移动，不应未经设计决定全部换成1px玩法。需明确保留粗导航/机制网格与精细身体边界的职责，而不是把全局 `formFloorGrid` 替换成1px、牵连小地图、Host和AI路径规模。
- AI的32/8px导航仍可保留保守路线；若实现共用底层实际身体位移，必须保证敌人也不穿实体。不要把玩家更贴边的位置当新的巡逻点来重写生成结果。

### 存取与旧在途v3

- 当前 `validateProceduralRiftAdmission` 对玩家只做地图范围与**中心格**可走检查（`rift-recovery.ts`约250行），没有完整身体支持判定。20px身体大于8px格，正常精细合法中心原则上仍不会落进有实体的同格；但不能以此代替正式恢复校验。
- 新精细边界应同时用于当前运行与v3恢复的完整20px身体检查，且由该存档冻结的native数据重建，不从最新世界配置猜测。既有保守网格内合法的旧v3位置应继续合法，保持原identity、player/bodyPosition、音景时钟、Host和掉落状态，不挪回出生点。
- v1/v2准入和移动维持旧路径。存档schema无需因派生细掩码改变；新增贴边位置的保存→冷恢复→首帧连续性必须实测。
