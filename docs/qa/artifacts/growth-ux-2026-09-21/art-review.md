## 最短 HOW：本轮怎样改

### 1. 画面主次与可读性

唯一决策仍是下一次蜕变。列表负责定位，详情负责说明这一笔薪柴得到什么。详情依次安排能力名、目标等级、一次收益、当前至目标的真实数值、必要限制与费用。责任类别与风味降为辅助信息；不要用整句同色说明或增加大量小标题拉长右栏。

- 能力名使用已存在的 16px 标题档；主要收益正文 12px，关键数值复用 16px 读数档；责任类别、风味、等级上限为 11px 辅助档。
- 目标等级写 `Level N`，未拥有用“首次刻入”，最高级单独表达。能力等级不写 `n / 总级数`；全路线完成数量可以保留总数含义。不要把逐级信息画成可任意选择的按钮。
- 使用既有文字语义：收益 / 目标灰绿 `#b3baae`，薪柴消耗暖灰 `#b39b75`，类别 / 风味 `#7e8a7e`，必要代价 / 缺口沿既有 `#ab9676`。颜色之外必须有标签、位置及 `+` / `→` 等明确关系。
- 右栏可在原 584px 总宽内局部增宽至约 228px，减少主列表的冗余横宽；不扩大整块 UI，不加底板，不移培养藏。

### 2. 玩家动作与理解

箭头只能连接同一量纲的真实前后状态。`延缓覆盖` 不能被当作 `完整度 +15` 的旧状态；生命强化应明说完整度**上限**，风味单列。首次和后续购买都区分“本次得到”和“目前累计”；已刻入项目只描述当前能力。

连带检查：

- 生命强化：`完整度上限 +15`，避免暗示即时治疗；风味用完整的污染覆盖语义。
- 渗透抗性：明示“自然混乱”，不能扩大为所有污染效果；初始不写难读的 `-0%`。
- 薪柴亲和：本次增量、累计基础产出和储藏增益分清，不能暗示面板数字就是最终每堆实际整数收益。
- 预兆洞察：拆开长句箭头，将本次新获得的信息与当前已辨明的信息区别表达；不公开尚未解锁的后续项目。
- 供奉 / 出击扩容：容量是件数 / 工具位，等级是 `Level N`，两者不要混写；保留成熟速度、被动位及负重的真实限制。
- 加厚：写清三台装置的完整度上限；“加厚后”与“供奉扩容”分开。当前 HP 不增加、起始混乱、实际补满费用与三台前后值仍要在首屏可读。
- 成功反馈 / 已满级 / 已购详情与列表使用同一等级格式；缺经历就近表达一个短条件，缺薪柴显示实际缺口。

### 3. 与既有世界的关系

载体仍是培养藏这一世界内装置；真实对象在左侧，邻近暗处承接无框读数。屏幕文字挂既有 `#dom-ui-root`，不是把文字绑在随相机变形的世界层。保留现行进入 / 退出、装置聚焦、固定底栏及键鼠共用购买事务。

参考沿既有 Darkwood 的场景优先与暗处留白、Signalis 的克制工业读数，以及本作迭代 11 已认可的培养藏构图；只借信息关系，不移植其他游戏的界面外壳。全部样式限定蜕变作用域，避免改变其他五处交互和已锁 HUD。

## 实现后复核

本代理已亲自查看以下本轮生产页面原图；根代理在隔离浏览器 context 中采样，本代理没有另外操作用户存档或重复声称完成试玩。

- [新档零薪柴](runtime/fresh/01-growth.png)：`Level 1` 与 `最高 Level 4` 分开，`完整度上限 +15` 是详情第一收益；`自身完整度上限 100 → 115` 是可核对的真实变化。风味单列，既不借箭头表达也不充当机制标签。8 薪柴为暖灰，缺口明确为还差 8。
- [首档加厚](runtime/linear/step-07.png)：三台上限各 +15、每台 100 → 115、本次 12 薪柴、刻入后余量及另需补满费用分属收益／消费／后果。三台各自的 100/100 → 100/115、起始混乱 0 → 0 和底栏同屏，未见原 192px 窄栏的长文挤压。
- [第三主动位](runtime/linear/step-12.png)：等级 `Level 1` 与主动位 2 → 3 分开，单次多携带一件为主要收益，被动位与重量条件为辅助句。
- [晚期供奉扩容](runtime/linear/step-18.png)：`Level 2 → Level 3` 是能力成长，`3 件 → 4 件` 是容量；两种信息不再共用一个 n/4 读数。下一项与已购同类能力的两处记录分别承担购买与当前能力查看。
- [全部完成](runtime/linear/03-complete.png)：只读列表和当前能力详情，无购买费用或下一档诱导；全部完成数量、最高等级与当前自然混乱减缓 20% 同时可读。
- [缺经历](runtime/impact/01-growth.png)：只显示当前下一项的“尚待经历／承受冲击”，没有把未来其他条件一起展示。

### 主次判断

不建议继续增亮主收益。当前既有灰绿在真实暗场上已可辨，16px 增量、独立行与空隙提供了颜色之外的重点；再加亮会把阅读焦点从培养藏旁侧推成大面积亮文字。成本沿已有薪柴暖灰，类别／风味／当前值较弱，目标值较强。245px 右栏在既有 584px 总宽内腾挪，没有扩大整体界面或遮住培养藏。

新档“进入裂隙时生效”承担生效时机，“厌恶污染覆盖，身体逐渐变得坚韧”承担风味，两者目前不造成拥挤。`不改变装置完整度` 可选精简为 `仅作用于自身`，不列为此次阻塞项，避免为了删字损失身体与装置的区分。

### 本轮追加发现

首次复核 [退潮门槛](runtime/crest/01-growth.png) 与 [预兆第三级](runtime/linear/step-17.png) 时，发现非数值效果仍把全部现有信息复制到长箭头两边，导致“重点装置”跨行断词，且让新增信息被重复语句稀释。已要求把预兆独立为“本次新获得”与“刻入后可辨明”的目标信息；已购使用“现已辨明”。数值轴继续保留真实前后值。

根代理接受该反馈后更新了生产实现，并另行修复列表项目被 flex 压缩的问题。以下为最终修改后的有限复核；首次运行原图保留，用于区分发现与修复。

### 最终原图复核

本代理亲自查看以下五张 `runtime-final` 原图，并对照最终局部 CSS、预兆展示结构：

- [预兆第三级／未经历退潮](runtime-final/crest/01-growth.png)：收益行只讲本次读取的供奉前压力；“刻入后可辨明”下列累计可辨明范围。旧状态不再复制到箭头左边，`重点装置`、`供奉前压力` 未被拆词。条件、成本和固定底栏均完整。
- [预兆第三级／可购买](runtime-final/linear/step-17.png)：同一信息结构在条件满足时自动去掉条件段，不露后续路线；26 薪柴与余量位于下方独立消费段。
- [首档加厚](runtime-final/linear/step-07.png)：245px 详情宽及紧凑后果区保持，三台前后完整度、0 → 0、额外补满费用与底栏仍同屏，没有因新等级排字挤掉最末行。
- [晚期供奉扩容](runtime-final/linear/step-18.png)：列表各项保留完整固定行高，名称、Level 行及分隔不再被挤到一起。剩余已购项自然进入滚动区域；不要求为了让七种能力同时塞进首屏而压字。当前下一项与费用始终处于首屏。
- [全部完成](runtime-final/linear/03-complete.png)：完成计数、只读 Level 5 抗性及累计效果保留；最后的加厚条目处于列表下缘，其下一行要滚动查看，这是列表滚动边界，不是详情缺失。键盘选中时能否自动显露、滚轮驻留由专项交互检查确认，静帧不代签。

上述限定样本中，没有留下需要再次修改的文案层级、长句断词或新增遮挡问题。主收益维持当前亮度；无需继续加色、增加装饰或削去已有必要限制。最终两状态重跑记录见 [runtime-final/manifest.json](runtime-final/manifest.json)，`crest` 与 `linear` 均为 `ok: true`、`errors: []`；它支持根代理该两条受控路径的运行事实，不是本代理追加的一轮试玩。

## U1–U12 有范围核对

- **U1 载体：** 静态实现沿 `#dom-ui-root` 与原 `bindWorldInteraction`；以上原图均保留左侧培养藏及邻近暗场，未添加元界面或实体终端外壳。
- **U2 组件形态：** 新增样式限 `#growth-panel` 下的排字／间距／色义，没有新圆角卡片、阴影底板、通用图标或渐变按钮。原已锁列表选中微亮仍存在，不把旧组件重新包装成新成果。
- **U3 色彩：** 新规则复用本项目既有 `#b3baae`、`#b39b75`、`#7e8a7e`、`#ab9676` 等读数色。数值、薪柴、条件有不同文字和位置，非仅靠颜色；本代理未完成逐像素对比度机器测量。
- **U4 排版：** 名称 16/24、收益正文 12/24、关键数值 16/24、类别与等级 11/18，沿原字族和既有档位；没有新增响应式断点。实际查看为 1440×960 原图对应 960×640 逻辑画布的 1.5 倍显示。
- **U5 术语：** 玩家自身完整度上限与装置上限分清；加厚后果不再称供奉扩容；自然混乱范围、被动位／重量限制保留。`Level N` 依本轮用户明确要求使用。
- **U6 布局：** 所看图中装置可见、详情及底栏无重叠，加厚最末净化器行完整。最终列表取消项目压缩，保持字行间隔；晚期项目自然滚动，不以截图覆盖未查看的滚动行为。
- **U7 输入：** 静态检查依旧由同一个购买事务接鼠标与键盘，按住 Enter 的 repeat 保护保留。实际按键／点击结果引用根代理 [六状态记录](runtime/manifest.json)，本代理没有另行试玩。
- **U8 不可用原因：** 零资源给实际薪柴缺口，经历不足就近列唯一短条件；已购及已至上限是只读，不显示虚构可购状态。
- **U9 信息分离：** 能力名、类别、等级、上限、当次增量和真实前后值均分节点；数字轴的 +／→ 提供第二编码。预兆第三级的长句重复已在最终两张原图中消除，改为本次收益与累计可辨明内容，术语没有拆词。
- **U10 反馈：** 首档加厚、晚期供奉和完成图可见顶部 `名称 · Level N 已刻入`，静态代码在成功 render 后立即写反馈；本代理未测精确毫秒时序，不以静帧代签 400ms 全路径。
- **U11 一致性：** 保留现行世界对象、暗场、字族与固定底栏；改动以蜕变局部选择器保护其他交互与已锁 HUD。未对其他五处重新进行整批视觉验收。
- **U12 参考：** 延续上述 Darkwood／Signalis 信息与场景关系及本作已锁实景，不开启新的参考研究或引入其他作品皮肤。

这些记录支持所列状态的局部文案与层级核对，不判断完整净化点美术、成长获得感、自然长期经济或用户最终审美。
