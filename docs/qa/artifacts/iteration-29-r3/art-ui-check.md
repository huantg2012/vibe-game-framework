## 最短核三：具体变化与相关 U 项

### 入口强度

`src/ui/dom/purification-hud.ts` 当前差异只涉及 `buildPromptPreview('rift')`：

- 原来直接取 `tideSystem.getState().currentIntensity.toFixed(1)`，拼成 `x倍率`；现在取 `impactSystem.getForecastReading(当前洞察等级)`。
- 公开预告不确定时显示 `轻微／中等／剧烈／极端 + ？`；确定时去掉问号。无预告时不添强度，只留出击次数。
- 名称 `name()`、次数 `qty()`、强度 `grade()` 仍是分开的文字节点。`qty` 与 `grade` 同为 11px／16px 行高；强度从等宽数值切到与已有档位一致的常规文字，沿原 `COL.brightText`。字号、容器、间距、底栏位置与挂载根不变。
- [forecast-hud.json](forecast-hud.json) 提供隔离 DOM 检查：普通 L0 为“中等？”、L1–L3 为确定档位，未出现真倍率；旧已承诺预告仍保持其既有确定性。本文件引用其有限机器事实，不称为本代理实机操作。

相关 U1／U3／U4／U5／U8／U9／U11：保持载体、已有颜色和字级，使用强度与世界分档，问号与文字共同表达不确定性，名称／值分节点。U6 在本次两张入口原图中未见新增遮挡／裁切；U7 的按键绑定不在本次差异内；U10 的连续时序本代理未测。

### 首档加厚

- `growth-panel.ts` 继续在 `thickenConsequencesHtml` 显示 `preview.startingChaos → preview.nextStartingChaos`，没有用固定提示遮掉变化；三模块各自保留当前完整度与新上限。
- 本轮共享 `previewThickening` 仍依实际模块、每份修复值与单次修复余量计算费用。读取 [thicken-preview.json](thicken-preview.json)：三台原满额、无修复余量时，首档为 **起始混乱 0→0、补满另需至少 12 薪柴**；余量 8 时为 10，余量足够大也只抵一次、为 9。不能将费用统一写死成 12，也不能暗示购买自动补满。
- 原有加厚动作、费用、剩余薪柴与退出栏保持。R3 原图同时可读 `100/100→100/115`、`0→0`、补满费用和底栏，没有为了简化文字删掉真实后果。

相关 U5／U8／U9／U11：沿用当前完整度、起始混乱、薪柴和加厚语义，保留真实数量与独立行；U6 在本次首屏原图中未见裁切／重叠。机器预览与静帧各自只支持其可见事实。

## in-game-ux 三问

1. **画面主次：** 不提升入口预览分量，`[E] 踏入裂隙` 仍是第一行行为提示，强度为第二行辅助读数；加厚仍由 next 和真实一次投入为焦点。
2. **游戏动作与理解：** 入口与右上预告使用同一公开信息层，未获确定知识时保留问号；加厚用当前值／新上限说明容量变化，起始混乱以实际 0→0 表达，不承诺治疗。
3. **与既有世界的关系：** 字族、色值、边缘位置、无框排字和装置近景均复用原路径。净化点整体材料／模型／成长发生感的问题留待用户指定的独立美术审核，不借本次热修实施。
