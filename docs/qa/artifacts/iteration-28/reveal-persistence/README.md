# I28 鉴定持久化与固定掉落回归

2026-09-20。独立 QA 复核；**定向边界测试，不是自然流程、掉落概率或美术终审样本**。没有操作用户浏览器档案，没有修改生产 CSV 或场景实现。

## 结论

- 归返保存连续拒绝两次：真实身份不进入报告或提示，冲击揭晓音效不播放，原存档字节不变，入场动画结束后角色仍不能移动。
- 使用真实鼠标点击重试：第三次写入成功；三次写入使用相同字节的结算候选。报告、冲击音效、揭晓提示分别出现一次。
- 琥珀甲虫进度为 3、余次为 5，发现记录和揭晓回执各一条。刷新后库存、模块损伤、潮汐、稳定度不重复结算，不重播揭晓报告。
- 在入场动画结束前重试并立即合上报告，动画结束后移动正常。
- 首次揭晓按独立字段列出主动/被动、次数/趟数及重量；无能力物只显示重量，没有虚假余次或装配提示。主动、被动与无能力三类均已做浏览器断言。
- 最终截图不滚动报告。三类的真名、已加载真图标及余量/重量行完整位于首屏可视区内；测试记录了 bounding box 和 `scrollTop: 0`，没有调用 `scrollIntoView`。
- 恢复接受合法的已保存物品身份、来源片区和提示，不与当前算法重新抽取的结果比较；来源片区遗漏薪柴堆或与条目标签冲突时拒绝恢复。

## 本次发现并复核的修复

1. 原归返流程保存失败仍展示鉴定报告；现在只在结算候选持久化成功后发布。
2. 原恢复流程重新生成掉落计划再比较；现在以存档中的实际结果及来源片区为准。
3. 重试按钮最初继承 `pointer-events: none`，实际鼠标点击被游戏画布截走；现使用既有装置面板容器，真实点击已通过。
4. 入场回调最初以静态 `impactResult.skipped` 控制输入，快速合上报告后可能再次锁死；现检查报告实时状态，早关闭反例已通过。
5. 首次揭晓原先缺少装配类型、实际余量及重量；现由公开投影传入，主动显示“5 次”、被动显示“2 趟”、无能力不显示次数。
6. root 后续首屏复核把有转化时的同一揭晓块移到最大损伤摘要后，避免被模块明细压到首屏之外；最终三类未滚动首屏断言通过。无能力重复说明也已合并。
