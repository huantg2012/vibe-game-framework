## 已修复的问题记录

下面保留首次发现时的代码位置和复现，不能将这些旧行号对应的原始问题当作当前仍未修复。

### B-QA-01 / P1 / 已修复：刚放入供奉的返刻片不能立即兑现可信预告

CSV 明确承诺“供奉期间预告的冲击目标与强度可信，并提前显露下一轮的预告”。当前可信标记仅在 `impact-system.ts:398` 的 `generateForecast()` 读取供奉槽时建立；`contaminant-system.ts:202` 的放入操作只同步其他模块加成，没有刷新预告。生产 `purification-scene.ts:415` 在场景创建时生成一次预告，因此玩家进净化点后才放入返刻片，本轮仍走原来的随机目标路径（`impact-system.ts:255`）。

独立真实域复现 `/tmp/i20-qa-forecast.ts`：

1. 重置真实 GameState / ContaminantSystem / ImpactSystem；进入非零 cycle。
2. 尚未供奉返刻片时生成预告，固定随机数得到 CORE。
3. acquire + slotDefense 返刻片，返回 true；此时前瞻仍为 null。
4. 把随机数设为 0.99，调用真实 `impactSystem.run()`。
5. 得到实际目标 PURIFIER、`forecastCorrect=false`，与已经供奉期间的可信承诺冲突。

修复验收应覆盖：同轮放入立即得到可信当前预告和下一轮前瞻；移除物件不撤销已经展示的承诺；高/低潮成熟后，先前前瞻仍成为下一次实际目标。

### B-QA-02 / P1 / 已修复：同轮重新建立场景会推进预告队列，承诺也未保存

`impact-system.ts:400–401` 每次生成都会 shift 前瞻队列，未按实际冲击轮次辨认是否推进；`purification-scene.ts:415` 包括菜单重新进入也调用生成。相同世界 cycle 连续调用三次真实生成，固定输入可得到 CORE → CORE → PURIFIER；期间没有实际冲击发生。

此外，`impact-system.ts:186–198` 的当前目标、可信状态和前瞻只在模块内存，`save-manager.ts:74–87` 收集存档没有这部分状态。浏览器重新启动不能恢复先前已经显示的承诺。这不是建议改变退出/死亡政策；需要保存的是既有净化点预告事实。

验收要求：同轮重复生成幂等；菜单重新进入和真正读档保留当前/下一轮承诺；老存档缺字段兼容；保存失败不得留下已消费队列与存储中旧预告不一致的可见状态。

### B-QA-03 / P2 / 已修复：撤离结果仍显示族固定旧星数

`rift-result-panel.ts:102–104` 的“实际带回”读取 `c.rarity` 与旧 `RARITY_STARS`，没有读取实例 `quality`。RiftScene 真实出击结算使用该面板；例如卓越冷结块仍显示与普通冷结块相同的一星。应与库存/供奉的实例品质字段保持一致。此项已交根任务处理。

### B-QA-04 / P2 / 已修复：复声壳来源文字仍是旧燃烧能力

`data/contaminants.csv` 的 kindle 行已改为复声壳与听觉诱饵，但 `narrative_origin` 仍是“燃烧消耗时空——物质在此不断自焚又从灰烬重构”。`inspect-dock.ts:105` 的旧工具检视渲染器会将此字段作为物件“源起”显示，但当前统一库存主链没有直接显示该字段，因此分类为内容身份残留，不能据此声称当前主库存已显示错误文案。该文案与首批同一件异常物的当前身份/能力不一致；须跟随当前物件原理更新，而不是沿用旧火焰族含义。其余已改造七族亦需检查来源字段；不要求未改造十族提前换身份。
