## 接口合同

`CatalogIconRef` 仅有公开展示分支：`{kind:'shell',appearanceId}` 或 `{kind:'item',definitionId,appearanceId?}`。旧物件由调用端继续使用旧API；此模块不会猜测旧ID迁移。

- `catalogIconUrl(ref)`：24像素SVG data URL；`catalogIconPixels(ref)`：原生24 RGBA。
- `catalogWorldPixels(ref)`：原生32 RGBA，按中心锚点落地。32稿逐物件独立坐标与局部细节，不放大24位图。
- `catalogGroundPixels(ref)`，别名 `groundPixels`：上述8个已使用物件的原生16 RGBA；其余返回 `undefined`。绘制以中心定位，即 `x-8,y-8`；不必再采样或缩放。支持ID见 `CATALOG_GROUND_IDS`。
- `catalogRemnantPixels(appearanceId,size)`：可复用残片图层。`catalogArtCanvas` 提供检查用焦点掩码与共同接缝锚点。
- 绘制结果缓存供只读消费，调用端不得修改返回像素。未知目录ID抛出错误，不回退成同一个通用石块。

### 32像素真实地面背景诊断与修复

新增复现脚本：`node --import tsx tools/inventory/check-catalog-context.ts`。`--strict`在存在未达项时返回非零，但仍保留全部取证。源码/原图SHA、原帧、采样中心、屏幕到世界倍率、种子、具体三像素边段及比值均在[诊断JSON](../../public/assets/items/contaminant-catalog/context/report.json)。本人已查看六张输出板。

方法先固定背景位置，再调用公开`catalogWorldPixels`取原生32。只用最大4连通实体的外缘，横向与纵向各找一段8邻接连续3像素，每点与紧邻外部背景的相对亮度比均需达到2:1。深浅两种对比都有效，内部亮点、孔洞和残片不替代主轮廓。背景直接从实际打灯原帧按世界像素中心采样，不调色、不选背景替物件过线、不补轮廓或发光。

修复前结果共336例，**静态条件下204满足/132未达**：当前正式土色底33/56、吸光釉原48/56、晶化林床15/56、无彩层原39/56、猩釉层原22/56、钴蓝金脉47/56。不是玩家失败率，也不是正式引擎渲染失败率。

- 中明度晶化与猩釉底容易吞掉灰毡手套、围巾、花萼、陶胶囊等中明度外缘；这和暗库存底上主体可见不矛盾。
- 吸光浅底与钴金亮面反向削弱鱼眼、蜡纽扣、浅骨片、蜡封包和薄壳卵的部分外缘。仅提高整体亮度会把这组变差，因此不能用整图提亮作为统一修复。
- 少数项目离阈值很近，不能只报舍入后的2.00；JSON保留实际数值，以原值判断。

**关键局限**：这些板是明确标注的静态拼合，不是游戏截图。地面已受正式灯光和遮罩影响，插入的物件只用源RGB，尚未重放物件上方的ADD灯光/暗幕；I26五世界原帧也不是I28新物件实机。因此数字用于暴露背景适配风险，不能确认正式核心区/衰减区最终通过或失败。目前没有满足“全量56种世界物件经正式光照、两方向连续3像素2:1”的证据，保留为开放项。

后续补证优先：正式脚边陶封块确认接线，灰毡手套/花萼对中明度底、蜡包/鱼眼对浅底各一组，采集同步背景/物件原帧与visibility，以最终渲染边缘复核。若仍未达，优先调整材料受光面与背光面的分配及真实落地支撑，保持色彩自由，不锁低饱和，不添加整圈描边或整件发光。
