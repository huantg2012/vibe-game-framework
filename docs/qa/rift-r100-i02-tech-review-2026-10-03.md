## 发现、修复与复核

### P2：过期材质请求的失败会覆盖新场景状态 — 已关闭

原 `main.ts` 的 `build()` 在 `loadPaintedMaterial()` 成功后检查 `token !== serial`，但失败分支直接 `reportError()`。快速切换 A → B 后，A 的解码失败可在 B 已建立或正在准备巡查时设置错误界面，并通过 `reportError()` 清空当前 `queuedLightPatrol`。

主线程将失败分支改为只在 `token === serial` 时上报。已重新读取现代码，成功和失败两条异步完成路径都受同一代次约束。此处为静态控制流复核，未宣称进行了浏览器网络故障注入。

### P2：过滤发光接点后，粒子取错原构造方向 — 已关闭

`phaseSources` 会跳过没有可见发光面或落在侵蚀区域的构造；原 `drawStress()` 却用其下标读取未过滤的 `world.meshes[s]`。实际对九格当前作者数据创建世界并核对，固定种子的 `folded-slab-severe` 为：原实体 ID `[1,2,3]`，可见源 ID `[1,3]`。第二个源属于旋转 `2.95` 的实体 3，原代码却使用实体 2 的 `0.81`，偏差 `2.14` 弧度，约 `122.6°`。

主线程在成功加入每个真实光源时同步保存 `sourceAxes`，绘制改为读取对应轴。已复核两个数组在同一筛选分支中成对写入，`drawStress()` 不再索引原始实体数组。该复核证明关联错误已修，不代表粒子造型已经获得美术认可。

## 接入检查结论

1. `materialLighting` 和 `createCombatGrid` 均是 DEV 可选项；没有该 fixture 时，原生 Rift 继续使用既有视野配置和 `sightGrid` 作为近战默认输入。本轮关闭的是额外 ADD 灯图，不是有限视野或目标可见性查询。
2. 当前世界明确将普通实体设为物理障碍、普通浅浮雕设为可走地面；只有缺失地面/作者侵蚀阻断视野。材质投影阴影没有写回战术可见性。材质上传同样使用 `matterAt()`，不会由绘画填回 VOID。
3. 创建失败的局部 GPU 清理、presentation 回滚栈、原生场景 shutdown 的调用链有对应释放；音频控制器只管理自己的两个低优先级实例。销毁后的调用不继续播放或提交绘制。没有发现本轮变更会写入玩家正式存档的路径；训练运行仍使用内存存储。
4. 声音配方已排除 impact 结果与 player search 提示，使用现有环境摩擦/阻力文件。此为音源语义和执行逻辑检查，不能由文件名或音量指标推导“听起来合适”。
