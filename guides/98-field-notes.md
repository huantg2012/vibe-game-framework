- Slice 1 / 工具链缺口累积（2026-08-01, T8 收口）：**同一根因第三次浮现——缺一个能驱动真实引擎的正式 dev harness**。三处表现：(1) 仓库无 `lint` script / eslint 配置 / 依赖，T7、T8 两次只能退回 `build` + `ReadLints` 当静态门禁；(2) 无测试框架（T5 已记），战斗不变量 K1/K2/K3/K5 只能靠 dev-boot 断言（DEC-020）+ 一次性脚本验证；(3) 浏览器无法模拟"按住键 / 同帧 keydown+keyup"，键盘手感、移动、攻击手感在 T5/T7/T8 **三个 Slice 任务连续被阻塞**，每次都只能把"真人试玩"留成遗留项。是否引入 Vitest / 保留一个 `#rift-harness` 驱动入口 = 架构决策（Director 从 T5 起就挂着的未决项），建议在 Slice 1 整合或 retro 时拍板，勿再逐任务临时糊。
- Slice 2-3 交界 / 框架教训（2026-08-09）：**四条 high-level 经验**——(1) 区分"数值调参"与"经济结构设计"，后者必须回 design agent 而非直接改 constants；Director 的 playtest 反馈处理流程应增加此判断步骤。(2) Design agent 输出格式应为"方向+后果+待答问题"而非"完整方案+推荐选项"；角色是引导者不是决定者。(3) 复杂系统设计应结构化为多轮短迭代（each round: 已锁定+待确认），不应试图一轮完成。(4) 世界观约束是设计最强锚点——陷入"怎么设计"时回 world.md 比堆参考更有效；design agent 流程应把世界观检查放第一步而非最后。
- Slice 4.5 / 流程绕过（2026-08-12，Director 收尾时观察）：本 Slice 从头到尾没走 Step 1-3（无一致性检查、无 Slice 立项、无 `docs/tasks/slice-4.5.md`），完全由对话直接驱动 code/art 实现，`current-slice.md` 与 roadmap 是事后补记的。**代价**：七个 commit 里新增了两个系统（BoundaryShape / BoundaryBreath）却没有任何 spec 承接，architecture.md 也没登记——这正是"无机器闸门的产出静默漂移"那类问题，只是这次漂的是文档而非代码。**但也要如实记录另一面**：表现层工作的验证方式天然是"改一版→人当场看→指名下一版问题"，预先写 Task Brief 的收益确实比系统 Slice 低。retro 议题：打磨/表现类 Slice 是否该有一条轻量路径（免 Task Brief，但强制在收尾时登记新增系统 + 补 spec 判断），而不是像现在这样在正式流程与完全裸奔之间二选一。
- Slice 4.5 / **严重摩擦：框架在 in-game UX 上产出质量差**（2026-08-12，人原话："framework 在 in-game ux 方面的表现非常差，难以输出游戏风格的设计，这个必须想办法"）：表现层翻修花了**七轮**人工返工才收敛，起点产出被形容为"调试信息 + 后台管理系统 + 原型几何体"。**根因不是模型审美不行，是框架的 UI 词汇表本身是 web 应用词汇表**——三处物证：(1) `docs/specs/_template-ui.md` 原版含"响应式策略：桌面/平板/手机"与 `default/hover/active/disabled` 组件表，照着填必然填出后台表单，而本项目手机端明确 out-of-scope、面板是键盘驱动的；(2) art agent 的「UI 设计输出格式」原为"布局描述 + CSS + 响应式断点"，框死在"这是一张样式表"而非"这是世界里的一台设备"；(3) Director 的试玩反馈路由表把"UX/表现问题"全导向 design→code，**整条链路里没有 art agent**——而风格恰恰是视觉规格层的产出。另外真正让方向收敛的唯一输入是人给出的**具名游戏参考**（Rimworld / DF / Hades / Darkest Dungeon / FTL / Signalis / Darkwood），框架里此前没有任何地方要求写参考锚点。已落地对策见 `guides/99-review.md` FV-01。
- Slice 5 / Director Step 1 与 CLAUDE.md 结构对不上（2026-08-12）：director agent 定义要求"对比 CLAUDE.md 中的**系统全景**和**内容汇总**表格"，但 CLAUDE.md 里从来没有这两张表——状态记在"当前阶段"的散文段落里。这条指令跑了五个 Slice 都无法执行，属于典型的"规则引用了不存在的结构"。retro 议题：补表 vs 改 agent 定义为"读当前阶段段落 + Glob 验证"。
- Slice 5 / 部分补核的复利代价（2026-08-12，Step 1 实测）：4.5 收尾时 architecture.md 只补核了三块新系统并留下"其余待下次全量补核"，本次全量核对发现欠账远大于 backlog 记录——**约 14 个 Slice 2/3/4 模块从未登记过**，"规划中"标记过期只是表象。**框架启示**：注册表这类"每 Slice 增量维护"的文档，一旦允许"部分补核"就会持续复利；要么设为 Slice 收尾的强制闸门（架构登记已在 4.5 后写进 director Step 3 收尾四项），要么根本不要求它完整。另外，"数字型"陈述漂移得比散文快——roadmap 写"9 种 Fine/Rare 工具"，CSV 实际 11 种。
- Slice 5 / 范围名称掩盖工作形状（2026-08-12）：roadmap 里的「Fine/Rare 工具」读起来是"11 件同质工具"，代码核对后实际是三类性质不同的活（7 个主动工具效果 / 1 个被动 / 6~8 处需跨系统持久状态的防御接线，后者在 Slice 4 源码里以 `handled externally` 注释形式留下）。**框架启示**：roadmap 的方向条目在进入 Slice 规划时必须做一次"对着代码重估形状"，否则会照着标题估工期。同时 Slice 4 留下的 `future iteration` 注释没有进任何追踪列表——源码 TODO 与 backlog 之间缺连接。
- Slice 5 / 收尾时验证门禁被跳过，且这次跳得有道理（2026-08-12，DEC-043）：Slice 5 实现全交付、机器闸门全绿，但人**没有回签试玩清单也没有过 U1-U12**，直接指示收尾并开 Slice 5.5 做 UX 重构。框架当前的 Slice 生命周期假设"实现完成 → 人试玩 → 给结论 → 收尾"，而这次的真实情况是**界面状态会污染试玩信号**：玩家分不清 15 件工具做什么，"装配决策是否纠结"这个验证问题根本测不出有效信号，先试玩等于测噪声。所以收尾时只能记「实现完成、体验未验证」——这个状态框架里没有词，roadmap 的「验证结论」列此前只出现过 PASS。**retro 议题**：(1) Slice 收尾是否应显式允许第三种验证状态（实现完成/体验未验证 + 验证问题转下游 Slice），并要求写明"转到哪、若不成立回退到哪"；(2) 当一个系统 Slice 的验证问题依赖于表现层可读性时，是否该在规划阶段就把 UX 收敛排进同一 Slice，而不是事后补一个 x.5。
- Slice 3 / 临时任务追踪缺口（2026-08-10）：用户 playtest 反馈中产生的临时待办事项（如"薪柴显示看不到"/"冲击时机不对"/"面板语言混乱"）没有可靠的去处。当前这些要么在对话中即时修复要么靠 design-notes 文档记录——前者不留痕，后者不是正式追踪机制。长线开发中可能因跨 session/跨 conversation 而丢失。需要一个轻量的"临时 issue 收集"机制，既不增加流程负担，又保证不遗漏。

- Slice 5.5 / UX 防回退（2026-08-13）：FV-01 诊断成立——第一轮试玩错误类型从「后台管理系统」变成 HUD 看不见 / 滚动条 / 条读不懂 / Esc 甩标题。新回退面五条：(1) **术语收口 ≠ 句子能读**——「23 混乱 · 稳定」词对了仍读成复合名词，表名/数值/档位必须分开；(2) **HUD 技术默认值是坑**——Phaser `scrollFactor(0)` 在 camera zoom 下仍把角锚 HUD 甩出画面，屏幕空间读数必须挂 `#dom-ui-root`，载体 A 是视觉语言不是「必须 Phaser」；小地图仍挂 `document.body`，记约束不修游戏；(3) **Kit 会在同一 Slice 里过期**——HUD 迁 DOM 后「Phaser 字号 ×1.5」失效，打磨规格是活文档；(4) **试玩热修仍跳过 art**——混乱条/溢出蒙层是人点名后直接 code，即使人已给视觉处方仍须 art 最短合规核对；(5) **UX 不能制造机制里没有的犹豫**——界面讲清事实，纠结不成立则回 design 重审收益结构。另：轻量路径能开干，但 ALL 表面把单个 code agent 在 C0 中途耗尽、C1/C2 拆开重派——缺批次/上下文预算。DEC-043「实现完成、体验未验证」是合法收尾态；系统 Slice 验证若依赖界面可读，规划时要么把 UX 收进同一 Slice，要么明确把验证转下游并写回退路径。U1–U12 会不会变成无证据勾选，仍待人回签 5.5 后观察。
