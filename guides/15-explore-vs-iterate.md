# 探索策略：宽抽窄迭

> **TL;DR** — 用哪种探索形状，由「一次评估要多久」决定，不由任务重不重要决定。生成已经很便宜，评估没有变便宜，所以瓶颈在评估侧。抽卡（并行低保真候选 + 人一次性挑选）用来**破框**；迭代（改一版 → 过闸门 → 再改）用来**守住已选定的方向**。转折点只有一个判据：**能不能写出一句可否证的验收句。**

本文是设计原理文档（给人看）。执行标准在 `CLAUDE.md`「探索策略：宽抽窄迭」与 `.claude/agents/director.md` Step 3。冲突时以那两处为准。

---

## 一、真正的轴不是「抽 vs 迭」

两者都是在一个空间里搜索，各自需要的前提不同：

- **抽卡 = 采样。** 价值在于给出你没想到的选项。前提是**你能判断哪一发好**，而且判断比生成便宜。
- **迭代 = 下降。** 价值在于往已知目标收敛。前提是**你知道目标在哪**，而且每一步的距离可测。

本文里的「抽卡」指**并行低保真候选 + 人一次性挑选**，不是碰运气。低保真是刻意的：它把单次评估成本压到最低，这才是抽卡成立的条件。

### 决定一切的那个事实

生成成本已经塌了——并行开几个候选是分钟级的事。**评估成本一点没变。** 瓶颈从生成侧整体搬到了评估侧。

这直接判了抽卡的死刑区间。抽卡的全部前提是「生成便宜所以多采样」，可如果一小时只能评估三个候选，采样五十个毫无意义。**抽卡的吞吐上限是人的眼睛和手，不是模型。**

### 迭代无法逃出一个错的框

迭代只能在给定的框内下降。这不是效率问题，是能力边界问题。

实测证据（`guides/98-field-notes.md` A-G3 / DEC-018）：一道美术门禁默认了「表现力来自多做几种离散 tile」这个前提，在这个前提里做了**五轮**参数调优（亮度归一 / 随机旋转 / 降权），结果只是从一种瑕疵变成另一种瑕疵；换成另一条前提（按世界坐标程序化生成连续表面）之后**一次成型**。

五轮迭代不如一次换框。**换框只能靠重新采样得到——这就是抽卡不可替代的位置。** 它不是廉价内容生成器，它是跳出局部最优的工具。

那次复盘写下的原话是：门禁的验证方式本身也可能带错误前提。所以有一条实用推论：**当同一个循环连续几轮都在原地打转，先怀疑框架，不要继续调参数。**

### 失败代价是倒置的

直觉上抽卡显得草率、迭代显得严谨，实际正相反：

| | 失败长什么样 | 成本 | 什么时候付 |
| --- | --- | --- | --- |
| 抽卡 | 这一发不行，扔掉 | 有界 | 立刻 |
| 迭代 | 优雅地收敛到错的东西 | 无界 | 延迟——错前提先烙进代码，再烙进更多代码 |

这和「模型路由与 token 经济性」是同一条逻辑：错误能被机器抓住 → 便宜地错没关系；错误会被下游当作事实 → 代价远超省下的成本。

## 二、先验偏斜的维度上，抽卡不起作用

这是最容易被忽略的一条，而它决定了该在哪抽。

抽卡的隐含假设是**采样分布覆盖了目标**。如果模型的训练先验系统性地偏离你要的东西，抽一百次只是从同一个偏斜分布里取一百个样本——**你付的是采样的钱，买的是同一个错答案的一百份副本。**

实测证据（`guides/99-review.md` FV-01）：in-game UI 的表现层翻修花了**七轮**人工返工。复盘结论明确——根因不是模型审美不行，是没有参考锚点，而模型对「界面」的默认先验是 SaaS 后台。七轮里唯一让方向收敛的输入，是人从分布外部塞进来的**具名游戏参考**。

**这类维度上的正确动作是先条件化，再采样**：钉死具名参考 + 禁令，把分布掐到目标附近，然后才开始抽。顺序颠倒 = 白付采样成本。

判断一个维度是否先验偏斜，问一句：**这个领域在训练数据里的主流形态，和我要的东西是同一种东西吗？** 不是 → 必须先给锚点。in-game UI 是本框架实测中最严重的一例（默认先验 = 后台管理系统），但不是唯一一例。

## 三、按维度选策略

组织原则一句话：**抽卡的可行性正比于单次评估成本的倒数。**

| 维度 | 一次评估要多久 | 策略 |
| --- | --- | --- |
| 美术 / 色板 / 界面质感 | 一秒（看一眼） | **多抽**，但必须先条件化（第二节） |
| 核心循环 / 玩家动词 | 分钟（灰盒试玩） | 少量抽 → 人选定 → 转迭代 |
| 数值 / 经济 / 系统组合 | 小时，且组合失败隐形 | **纯迭代** + 不变量断言，禁止抽 |
| 实现 / 架构 / 重构 | 秒级且可自动（机器闸门） | 纯迭代，放开降档 |
| 好不好玩 / 手感 | 无自动判据 | 两者都不适用，只有真人试玩 |

这张表解释了一个看起来矛盾的结论：**在最容易翻车的表现层，恰恰应该抽得最多**——因为那里评估只要一秒。前提是先把参考钉死，否则抽的是同一口井。

而在感觉上「最该多试试」的数值平衡上，抽卡最没用。两个原因：一次评估要长时间游玩；更要紧的是**组合失败在验货那一刻看不见**——单看每个候选都没问题，坏的是它和其他系统凑在一起的结果。这类工作必须走单线迭代 + 启动期不变量断言。

最后一行是硬边界。实测证据（`guides/98-field-notes.md` Slice 1 / T5-T7-T8）：浏览器无法模拟「按住键」和「同帧 keydown+keyup」，键盘手感在**三个连续的 Slice 任务里被阻塞**，每次都只能把真人试玩留成遗留项。这不是会被工具进步便宜解决的缺口——缺的是判据本身。**手感不可 loop。**

## 四、转折点判据：能不能写出一句可否证的验收句

不用凭感觉。只有一个判据：

- **写不出来**（只能说「要有那种感觉」）→ 还在找方向 → **该抽**。这时候强行迭代，是在向一个自己都没定义的目标做梯度下降。
- **写出来了**（「玩家必须先看到敌人」「玩两分钟能感到不想开枪」）→ **该迭代**。这时候继续抽，是在丢掉已经付过钱的信息。

可否证的验收句还有第二个要求：**描述可观察的后果，不是「实现了 X」。**

实测证据（`guides/99-review.md` FV-04 / DEC-043）：一个系统 Slice 的机器闸门全绿、实现全交付，但验证问题依赖界面可读，玩家读不懂就测不出机制——先试玩等于测噪声，收尾只能记「实现完成、体验未验证」。闸门当时测的是「能不能编译」，不是「有没有可观察的后果」。

所以规划时要先问一句：**这条验收句依赖什么才能产生有效信号？** 依赖界面可读 → UX 必须进同一批；依赖手感 → 先做灰盒手感再做内容。搞错顺序，会花钱做出一批无法被验证的东西。

## 五、抽到的必须能留住，否则不算抽到

一发好的候选，如果说不出它好在哪、也没归档，等价于没抽到——下次还得重抽。**这是抽卡能复利而不是空转的前提条件。**

有效结果必须当场落成三类耐用件之一：

| 耐用件 | 形态 | 为什么耐用 |
| --- | --- | --- |
| 数值 + 推导理由 | 常量文件里的一个值，旁边写清它为什么是这个值 | 只写数值 = 照抄；上游一变就错。写了推导，下游才能跟着改 |
| 一条禁令 | 「不许出现 X」 | 最短、最难误读，编码了「什么被试出来是错的」这类最贵的信息 |
| 一个参考锚点 | 具名参考 + 学什么 / 明确不学什么 | 唯一能把审美意图无损传给下一轮的载体（FV-01 七轮换来的结论） |

正向形容词（「要有氛围」）不是耐用件——它传不过去，下一轮还会漂。**把每一次「不是这样」的否决当场记成一行禁令**，是成本最低、收益最高的归档动作。

## 六、实际形态与三条边界条件

**宽抽、窄迭。** 低保真度并行采样若干方向 → 人在一次坐下里挑出一个 → 只对这一个做有闸门的深度迭代 → 把这一轮的结论落成耐用件。

三条边界条件，都来自实测，别越：

**1. 禁止 agent 自评「抽中了 / 已收敛」。** 判据不存在时（好不好玩、好不好看），loop 无意义。更麻烦的是模型不会停在「我做不到」——它会宣布胜利，或者满足字面而腐蚀实质（削弱断言、把难分支 stub 掉、删掉挡路的测试）。这类错误不报错。所以要保留「实现完成、体验未验证」这种合法收尾态，否则它会被写成 PASS。

**2. 循环要有硬上限。** 见 `CLAUDE.md`「探索循环的成本闸门」与「逃逸兜底」：循环体降档跑，只有收敛判断上顶配；连续 2 次过不了机器闸门就停止重试、升档重做；到顶未收敛升级给人，不许无声续跑。

**3. 别打成一大批。** 实测证据（FV-04）：把 ALL 表面塞进一次 agent 会话，会在中途耗尽上下文，必须拆批重派。一批的尺度是：**一次会话能独立做完、能独立看、能独立过闸门。**

---

## 七、什么会改变这个结论

写清楚是因为这个结论是有时效的：

- 如果出现**可靠的自动化手感与可玩性判据**（能模拟按住键、能跑出「玩家在这里犹豫了」这类指标），评估成本会塌下来，天平会大幅倒向抽卡——抽卡唯一的瓶颈就是评估。这不是靠模型变强能解决的，缺的是判据本身。
- 如果模型的**界面先验**不再默认是软件后台，第二节那个陷阱会消失，表现层可以省掉条件化步骤。这个有可能靠训练数据分布变化自然发生。

在这两件事发生之前：**迭代做主干，抽卡专门用来破框和抽表现层，评估带宽是唯一真正需要优化的东西。**
