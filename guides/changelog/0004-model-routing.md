# 0004: 模型路由与 token 经济性

## 起因

"全程用高级模型太废 token"。排查时发现更严重的问题：6 个 agent 的 frontmatter 写的是 `model: opus` / `model: sonnet`，这是 Claude Code 的别名，**不在 Cursor 文档化的 model ID 词汇表里**。在 Cursor 下这些值识别不了会静默回退——也就是说这套路由配置一直没生效，实际全程跑的是 UI 里选中的模型。

## 核心原则

**按"错误能否被机器抓住"分配模型，而不是按"任务重不重要"。**

强模型的代价每次调用都要付；弱模型犯错的代价只在错误逃逸时才付。所以决策变量是逃逸概率——下游有没有自动闸门。有闸门（tsc/lint/测试/`art:verify`/运行时冒烟）就放心降档，因为"便宜模型跑两次"仍远比"强模型跑一次"便宜；没有闸门、且产出会被其他 agent 当作事实来源的（spec/决策/范围），错误不会报错只会静默传播，必须保持强模型。

## 落地

- **档位表**（写入 `CLAUDE.md`）：T1 ideation/director/design；T2 code/art；T3 qa。两个运行时各自映射到本地可用 ID。
- **code 从 T1 降到 T2**——省钱的最大一笔（token 消耗最大 + 验证最充分）。人选择了保守方案：先降到中档观察一个 Slice，而非直接到廉价档。这推翻了 `guides/99-review.md` AE-08 当年"code 升 opus"的结论。
- **逃逸兜底**：同一任务连续 2 次过不了机器闸门 → 停止重试，升档 T1 重做。让降档的失败成本有上界。
- **探索循环成本闸门**：多轮探索的循环体跑 T2/T3，只有收敛判断上 T1；循环次数必须有硬上限。依据是 Slice 1 的 A-G3 实测——约 14 轮迭代里只有 1 轮是真正的判断。
- **不用 Cursor Auto 做框架内路由**：Auto 用分类器猜复杂度，而框架的每份工作到达时已被结构化分类，信息量严格更多；且 Auto 不可观测、不可复现，会污染 dogfooding 的框架验证信号。Auto 留给框架外的自由对话。

## 一致性规则放宽

两个运行时的模型 ID 词汇表不重叠，"两份定义逐字一致"与"模型路由生效"无法同时满足。规则改为：**正文逐字一致，frontmatter 仅 `model` 允许 per-runtime 差异**。

新增 `tools/agent-parity/check.mjs`（无依赖）执行校验：正文逐字比对 + frontmatter 除 `model` 外全部一致 + 两侧都必须显式声明 `model`。原先的 `diff -r` 验收方式作废。

## 待验证

Cursor 侧 frontmatter 是否真的生效——派子 agent 时看侧栏显示的模型即可确认。这是本次改动唯一没有自动化手段兜住的假设。
