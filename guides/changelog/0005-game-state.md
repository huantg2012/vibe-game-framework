# 0005 — 游戏现状索引与证据维护

日期：2026-09-20

## 原问题

长期迭代时，CLAUDE.md 的累计状态、路线图、聊天记忆和局部搜索无法共同保证游戏全貌；目录存在、开发场景可用、正式入口可达和人审通过容易被压成同一个“完成”。人读全貌也缺少可从文本低成本刷新出的视图。

## 当前变更

- 可独立使用的 game-state 技能承载唯一协议、结构校验、文件漂移/依赖检查和离线视图生成。框架不硬编码某款游戏、引擎或美术风格。
- CLAUDE.md/AGENTS.md 改为约束与路由；游戏现状由 docs/game-state 文本源维护，INDEX.md 为 Agent 提供快捷全貌，atlas.html 按需供人阅读。
- 六角色接入 feature ID 与证据交接：Director 汇总，Design 维护规则指针，Code 维护实际入口，Art 维护视听依据，QA 登记有限范围验证，Ideation 不把构想提升为实现。
- 接入、工作安排和证据互相独立；指纹 baseline 不代表验收，旧证据不因重新生成视图而变新。
- 旧项目渐进补录，无索引时先建全分类骨架、保留未知，当前任务只核相关分支。

## 传播范围

CLAUDE.md、AGENTS.md、START-HERE.md；两份六角色定义；guides/01、03、08、09、10、12、14；99-review 增加历史结论被替代说明。旧 changelog 和 field-notes 保留历史。游戏分支的具体能力/证据由各游戏自己建立，不写入 master。

## 验证边界

Agent 正文及工具权限变更需运行 `node tools/agent-parity/check.mjs`。脚本与协议验证由技能自己的检查完成；框架接线或数据 schema 通过不能证明任意游戏已被全面验收。
