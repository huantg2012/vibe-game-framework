# 阶段5: Polish（打磨）

## 目标

将"功能完整但粗糙"的游戏变成"体验流畅、品质感达标"的可发布产品。

**输入**：Feature Complete 版本
**输出**：Release Candidate（发布候选）

---

## 打磨的三个维度

```
1. 体验打磨 — 手感、节奏、反馈、新手引导
2. 技术打磨 — 性能、兼容性、稳定性
3. 内容打磨 — 平衡、一致性、边缘case
```

---

## 工作方式：问题驱动而非功能驱动

Production 是"做功能"，Polish 是"解决问题"。工作方式从 Task Brief 变为 Issue Tracking：

```
试玩 → 发现问题 → 记录 Issue → 排优先级 → 逐个解决
```

---

## Step 1: 全面试玩 + Issue 收集

### 你做什么

- 完整玩 3-5 遍游戏，记录所有"不舒服"的瞬间
- 找 3-5 个人试玩，观察或收集反馈
- 不只记 Bug，也记"感觉不对"的地方

### AI Agent 做什么

**角色：QA Agent**

- 帮你整理试玩笔记为结构化 Issue
- 自动扫描代码找明显问题（类型错误、未处理异常、性能警告）
- 生成兼容性检查清单

### 产出：Issue List

```markdown
## Issue 列表

### 体验类
| ID | 描述 | 严重度 | 位置 | 状态 |
| -- | ---- | ------ | ---- | ---- |
| E01 | [反馈不够明确] | Medium | [战斗结算] | Open |
| E02 | [新手不知道该点哪] | High | [开局] | Open |

### 技术类
| ID | 描述 | 严重度 | 位置 | 状态 |
| -- | ---- | ------ | ---- | ---- |
| T01 | [某场景帧率低] | High | [xxx.ts] | Open |
| T02 | [Safari布局错乱] | Medium | [CSS] | Open |

### 内容类
| ID | 描述 | 严重度 | 位置 | 状态 |
| -- | ---- | ------ | ---- | ---- |
| C01 | [第3关难度断层] | High | [level-3] | Open |
| C02 | [某物品描述矛盾] | Low | [items.json] | Open |
```

## Step 2: 体验打磨

### 打磨清单（通用）

- [ ] **手感/操作反馈**：每个操作有即时视觉+音效反馈
- [ ] **过渡/流畅**：场景切换有过渡动画，不是硬切
- [ ] **节奏**：没有"空等"的时刻，也没有"太快跟不上"的瞬间
- [ ] **新手体验**：第一次玩的人能自然理解操作
- [ ] **结算/奖励感**：胜利/完成有明确的正反馈
- [ ] **失败体验**：失败后不觉得浪费时间，想再试一次
- [ ] **信息呈现**：所有关键信息在需要时可见，不需要时不干扰

### AI Agent 做什么（体验打磨）

**角色：Code Agent（打磨模式）**

- 实现 juice（屏幕震动、粒子、缓动动画、音效触发）
- 优化交互反馈（hover、click、状态变化的视觉反馈）
- 实现新手引导/教学流

### Prompt 策略

```
这个功能目前能工作但缺乏"手感"：[描述当前状态]
我想要的感觉是：[描述目标体验，可以参考其他游戏]

请添加 juice/polish：
- 适当的动画缓动
- 操作反馈（视觉+可选音效触发点）
- 状态变化的过渡

原则：微妙但有感知，不要过度花哨。
```

## Step 3: 技术打磨

### 性能优化

| 指标 | Web游戏目标 | 检测方式 |
| ---- | ----------- | -------- |
| FPS | 稳定60（至少30） | Chrome DevTools Performance |
| 首屏加载 | <3秒 | Lighthouse |
| 资产总大小 | <10MB（首屏<2MB） | Bundle analyzer |
| 内存泄漏 | 无 | 长时间运行观察 |

### AI Agent 做什么（技术打磨）

**角色：Code Agent（性能模式）**

- 分析并优化性能瓶颈
- 实现资产懒加载
- 修复内存泄漏
- 处理浏览器兼容性

### 兼容性检查清单

- [ ] Chrome (latest)
- [ ] Firefox (latest)
- [ ] Safari (latest)
- [ ] Mobile Chrome (Android)
- [ ] Mobile Safari (iOS)
- [ ] 不同屏幕尺寸（响应式或固定比例）

## Step 4: 内容打磨

### AI Agent 做什么

**角色：QA Agent（平衡模式）**

- 分析数值平衡（如果有数值系统）
- 检查文本一致性
- 验证所有关卡/内容可完成
- 找出边缘情况

### Prompt 策略（数值平衡）

```
这是我的 [系统] 的完整数值表：[粘贴数据]
设计目标：[比如：玩家从弱到强的感觉，但不能碾压]

请分析：
1. 有没有明显的数值断层或平衡点
2. 曲线是否平滑
3. 有没有"永远不会被选"的选项
4. 建议调整

输出调整建议和理由，我来决定是否采纳。
```

---

## Step 5: 最终验收

### 你做什么

- 再次完整试玩，确认 Issue 都已解决
- 做"发布决策"：这个版本够好了吗？

### 验收标准

- [ ] 所有 High/Critical Issue 已解决
- [ ] 新手能在无引导下上手（或引导已到位）
- [ ] 性能达标
- [ ] 主流浏览器兼容
- [ ] 你自己愿意把这个给陌生人玩

## 本阶段的 Agent 配置

| Agent | 用途 | 频率 |
| ----- | ---- | ---- |
| QA Agent | Issue 整理、代码扫描、平衡分析 | 开始和结束各一次 |
| Code Agent | 逐个解决 Issue | 高频（主力） |
| Art Agent | 补充缺失资产、优化视觉细节 | 按需 |

---

## 常见陷阱

| 陷阱 | 症状 | 解药 |
| ---- | ---- | ---- |
| 无底洞打磨 | "再优化一点点"无限循环 | 设定截止日期，到了就发 |
| 只修自己注意到的 | 有盲区 | 必须有外部试玩反馈 |
| 打磨变成新功能 | "顺便加个xxx" | 回看 MVP scope，新功能进 backlog |
| 忽略性能 | 开发机上流畅，用户设备卡 | 用节流模式测试 |

---

## 质量门禁：Polish → Launch

- [ ] 零 Critical/High Bug
- [ ] 性能达标（FPS + 加载时间）
- [ ] 至少 3 个外部试玩者反馈"可以发布"
- [ ] 你自己的判断："我愿意署名发布这个"
