# 阶段6: Launch（发布）

## 目标

让游戏被人玩到，建立持续运营的基础。

**输入**：Release Candidate
**输出**：线上可玩版本 + 运营/迭代体系

---

## 发布不是终点，是一个新循环的开始

```
发布前准备 → 发布 → 观察数据 → 迭代更新 → ...
```

---

## Step 1: 发布前准备

### 你做什么

- 确定发布渠道（itch.io、自有域名、社交媒体推广）
- 准备营销素材的方向和文案要点
- 设定发布日期

### AI Agent 做什么

**角色：Code Agent（部署模式）+ 内容 Agent**

技术侧：
- 配置生产环境构建
- 设置部署流水线（Vercel/Netlify 一键部署）
- 实现基础数据统计（简单的事件追踪）
- 确保资产压缩、CDN 配置

营销侧：
- 生成发布页面文案（游戏描述、特性列表）
- 生成社交媒体宣传文案变体
- 帮助设计发布页面 / itch.io 页面

### 产出

```markdown
## 发布清单

### 技术
- [ ] 生产环境构建通过（`npm run build` 无错误）
- [ ] 部署测试通过（线上地址可访问、可游玩）
- [ ] 数据统计代码就位（基础事件）
- [ ] 错误监控就位（如 Sentry，可选）
- [ ] 性能在生产环境达标

### 内容
- [ ] 游戏标题确定
- [ ] 一句话描述（用于分享）
- [ ] 详细描述/特性列表（用于发布页面）
- [ ] 截图/GIF 3-5 张
- [ ] 封面图（发布平台要求的尺寸）

### 渠道
- [ ] 发布平台账号就绪（itch.io / 自有域名）
- [ ] 社交媒体发布准备（帖子草稿）
- [ ] 反馈收集渠道（Discord/表单/评论区）
```

---

## Step 2: 发布

### 你做什么

- 最终检查线上版本
- 点击发布按钮
- 发布社交媒体公告
- 监控初期反馈

### AI Agent 做什么

此步骤 AI 参与有限 — **发布的时机和措辞是人的判断**。

AI 可以帮助：
- 快速修复发布后发现的紧急问题
- 回复社区反馈的措辞建议

---

## Step 3: 数据观察

### 你做什么

- 观察关键指标（通常发布后 48-72 小时）
- 收集并阅读玩家反馈
- 判断是否需要紧急修复

### AI Agent 做什么

**角色：分析助手**

- 帮你解读数据趋势
- 整理玩家反馈为结构化分类
- 建议优先修复/迭代的方向

### 关键指标（Web 游戏）

| 指标 | 说明 | 健康范围 |
| ---- | ---- | -------- |
| 访问量 | 有多少人看到了 | 取决于推广 |
| 转化率 | 看到→开始玩 | >50% |
| 完成率 | 开始→完成核心循环 | >30% |
| 留存 | 第二天回来 | >10% 不错 |
| 平均游玩时长 | 花了多少时间 | 取决于设计 |

---

## Step 4: 迭代更新

### 工作模式

发布后进入"小步快跑"的迭代模式：

```
收集反馈 → 排优先级 → 实现 → 热更新部署 → 观察效果
```

每次更新聚焦于：
1. 修复阻断性问题（玩家流失的原因）
2. 根据数据优化留存点
3. 小幅内容更新保持新鲜感

### AI Agent 配置（运营期）

进入轻量模式，不再需要全部 Agent：

| 需求 | Agent | 频率 |
| ---- | ----- | ---- |
| Bug修复 | Code Agent | 按需 |
| 内容更新 | Code + Content Agent | 每周 |
| 反馈分析 | 分析助手 | 有新数据时 |
| 大版本规划 | Director Agent | 每月 |

---

## 发布渠道选择指南（Web 游戏）

| 渠道 | 优势 | 劣势 | 适合场景 |
| ---- | ---- | ---- | -------- |
| itch.io | 独立游戏社区、内置曝光 | 分成、受众有限 | 第一个发布平台 |
| 自有域名 | 完全掌控、利于品牌 | 需要自行导流 | 有社媒影响力时 |
| Newgrounds | 游戏社区、反馈活跃 | 受众特定 | Flash/Web游戏风格 |
| Steam (Web) | 用户量大 | 审核周期、门槛 | 规模较大时 |
| 社交媒体嵌入 | 传播方便 | 体验受限 | 轻量级小游戏 |

---

## 常见陷阱

| 陷阱 | 症状 | 解药 |
| ---- | ---- | ---- |
| "再打磨一下再发" | 永远不发布 | 设死线，到了就发 |
| 忽略首印象 | 发布页面粗糙 | 花1天做好截图和描述 |
| 无反馈渠道 | 不知道玩家怎么想 | 至少有一个评论/反馈入口 |
| 对差评过度反应 | 一条差评就大改 | 看趋势不看个例 |
| 更新太频繁 | 玩家每次来都不一样 | 攒一批一起发布 |

---

## 质量门禁：Launch 之后

发布不是"完成"，但要有"停止积极开发"的标准：

- [ ] 核心体验已稳定，玩家反馈正面为主
- [ ] 无严重技术问题
- [ ] 你对这个项目的学习目标已达成
- [ ] 准备好进入维护模式或开始下一个项目
