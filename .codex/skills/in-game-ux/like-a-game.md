# 怎样读作游戏 UI

本文件服务 [SKILL.md](SKILL.md) **问 2**。色值、组件类住在 Kit。审查论述住在 `docs/art/review-2026-08-28/report-purification.html` §6。

## 先验

训练语料里「UI」的最大簇是 SaaS 后台。第二大簇是「AI 生成的暗色仪表盘」：左侧导航、卡片网格、全量平铺。本游戏已经选对磷光屏，仍会掉进第二簇——因为组织方式是网页。

## 游戏菜单 vs 网页

| 网页 / 后台 | 游戏菜单 |
| ----------- | -------- |
| 左侧分类导航 | 顶部 Tab（或键切的同级页） |
| 所有信息一次铺开，靠人扫描 | 主-从：先选中，再看详情 |
| 多处可点、权重相同 | 同时只有一个操作焦点 |
| 空 = 黑或「暂无数据」 | 空状态三件套：是什么 / 为什么空 / 现在做什么 |
| hover 才出身份 | 键鼠同一通道；选中即填 |
| 表名+数值+档位写成一句 | 三个独立节点 |
| 不可用只变灰 | 写出缺口（还差 N / 已至上限） |
| Debug 字贴画布 | 装置读数：有容器、有分组、有层级 |

心理模型从「阅读文档」改成「操作一台设备」。

## 本游戏已锁的参考动作

从 `docs/design-notes/ux-references.md` 选，学动作、不学皮。

| 游戏 | 学什么动作 | 不学什么 |
| ---- | ---------- | -------- |
| FTL | 一槽 = 表名 + 数值；贴边常驻；决策不必先点开商店 | 全息蓝、圆形供电格、升级树卡墙 |
| Signalis | 检视是设备打出来的字 | 曲面畸变当滤镜秀、把说明做成设置页 |
| Barotrauma | 走到装置前读灯/刻度；坏了是灯在说 | 拟真阀门轮（32px 会糊） |

每条参考只锚**一个可执行动作**。只写游戏名 = 停工。

本屏明确不像：Dashboard、设置页、电商确认链、引擎 debug overlay、左侧栏后台。

## 四条面板原则（审查锁定，不许再退回平铺）

1. **主-从。** 列表/Tab 是主，详情是从。选中项始终有且只有一个。
2. **渐进披露。** 第一眼只放决策必需；其余进详情或第二行。
3. **焦点驱动。** 分配屏焦点 = 投入量。状态屏焦点 = 当前模块的完整度与后果。
4. **状态优先。** 完整度、能否做、还差多少，压过氛围段。氛围句保留时，下面必须跟数值。

## 提示条是桥梁

底栏不是 HUD 的附录。它是世界里那台东西与磷光屏之间**唯一的句子**。无目标要弱、有目标要满、靠近要能预览状态——否则玩家必须先 E 再决定要不要走过去，那是网页的「先打开再看」。

## 出击预估不是新系统

把局部投入译成全局后果时，只许组合机制里已有的出击修正（混乱增速、薪柴价值、起始混乱）。禁止发明「生存 中」一类机制里没有的评分来制造犹豫。
