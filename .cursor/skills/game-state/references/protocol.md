# 游戏现状索引协议

## 1. 哪些事实由谁决定

- **设计意图**：有效决策、世界观、系统 spec。索引只链接并概述，不复制数值、完整规则或资产清单。
- **实现事实**：正式入口到功能处理/数据写入的调用链与注册数据。设计里出现不等于做了；代码里出现不等于正式可达。
- **验证事实**：有版本、条件、范围、结果、限制和持久化来源的实录/报告。静态阅读单独标 source。
- **进度**：任务/路线图是工作计划；本索引记录产物现状。暂停不等于下线，收口不等于验证通过。
- **未知/矛盾**：显式记录缺口和待确认问题。代码与设计不一致时保留双方证据，不能用代码反向修改设计使问题消失。

索引不是第二份 GDD、spec 或按时间堆叠的日志。规则放正文，版本历史归 Git，界面图是可丢弃的快照。

## 2. 首次盘点：先广度，后深度

默认覆盖 12 域：循环；控制/玩家能力；场景/地图；遭遇/挑战；物品/内容；成长/经济；菜单/信息界面；音画/反馈；叙事/世界规则；存档/恢复/交付；设置/可访问性；开发/挂起/退役。覆盖域不是游戏必须拥有的功能清单。无战斗的解谜游戏无需编造武器，缺少设置页可以记录明确缺失；不适用需有理由。其他品类可增加联机、社交、编辑器等域，并说明分类。

1. 收集项目版本与可用材料，读引擎/入口、注册表、场景路由、菜单、数据源、spec 索引及当前任务。
2. 以“玩家能做什么”建立条目，按生产/开发/设计/退役分开。通常一个独立能力、菜单或内容族一个 ID；不为每个贴图/控件立项，也不能用“UI”一项掩盖全部菜单。
3. 从正常启动路径追踪入口、前提、输入、结果、失败/恢复；必要时单独列跨系统循环。DEV hash/练习场不算正常可达。
4. 配置 inventory 发现漏登的场景、菜单、注册数据。纳入源码来源的文件用于追踪漂移，范围可渐增，不能声称“扫到文件=全功能覆盖”。
5. 登记现有证据原有版本与限制。本次只读源码则只写静态证据；旧报告的运行通过不能伪装为本次重跑。
6. 指出剩余未知，核对、建立基线并生成文本索引。按需生成 HTML 交人浏览。

## 3. 文本与证据的最低粒度

每项功能：稳定 ID、领域、玩家行为摘要、实际入口、接入状态、工作状态、权威来源、依赖、证据 ID、未知。ID 不随标题变动；拆分/退役需保留旧 ID 的去向。

证据分别记录静态 source、自动执行 automated、运行实录 runtime、人工认可 human。它们不是能互相升级的单一等级；一项功能可同时有视野自动通过和美术人工未通过。范围只覆盖实际检查对象，不能从三张地图推导所有种子都已验收。

证据版本优先使用实际 Git 提交。无法映射版本时如实写工作树/日期；工具将标为无法自动比较。输出由 `revision` 与关联实现文件对比给出“变化/未变/无法比较”；即使未变，也不扩张原证据的适用范围。

有效约束有来源与适用功能，可被另一条明确替代。用户决定优先；不得把猜测、临时探索、被否决方案写成长期硬约束。

## 4. 每轮维护

**开工**：读项目入口 → `check` → INDEX 全貌 → 当前功能及正向依赖；记录功能 ID。`impact --feature` 给出反向影响闭包和所需背景，`impact --since` 按版本差异定位。依赖是“该功能依赖哪些功能”，不是任意相关链接。

**实现**：维护自己的事实字段、入口、来源、依赖和未知；数值更新在 CSV/spec，不在索引重复；新增或退役入口同步登记。

盲测/首次接触评审是加载时机的例外：隔离评审者可先观察原始游戏材料，在形成初步判断后再读现状索引交叉核实；不把项目自述提前灌给盲测者。协调者仍可用索引安排覆盖。

**验证**：记录真实版本和范围；检查老证据是否受本次改动影响。发生漂移不删除历史通过事实，但不得继续声称它证明新实现。

**收尾**：合并各方登记，核对新文件和遗漏域 → 修正文本/写明未知 → `baseline --reviewed` → `check` → `render --index-only`。按需 `render` 刷新 HTML。基线允许有明确未知；不能绕过格式错误、未登记文件或偷偷将未知改成通过。

**复核触发**：菜单/场景/数据注册变化、共享代码/存档接口变化、有效决策变化、发现实机与文档矛盾。只复核受影响闭包；无根据的每轮全量审计会让机制不可持续。

## 5. 框架职责与独立使用

有 framework 时：director 维护全域覆盖/关系及收尾，design 管规则意图/决策映射，code 管实现/入口/数据与依赖，art 管音画来源和实际验收范围，qa 管证据及失效判断，ideation 初始化能力边界。各角色只修改责任字段，职责不允许替其他角色虚构通过。

没有 framework 时，同一人/Agent 可以按上述责任先后工作；只需完整 skill 与文本目录。没有 Git 仍可用文件 SHA-256 基线；版本证据自动比较将明确不可用。没有 Node 仍能读写文本，但不能声称机械检查或 HTML 已刷新。

## 6. 限度

机械检查能发现格式错误、失效路径、未知 ID、字段矛盾、文件漂移与扫描范围内未登记文件。不能证明功能语义、入口真的可达、审美/乐趣、全体内容完整性，也不能自动发现所有同文件内新增能力。不要把绿色检查或覆盖域 mapped 当作质量通过。

HTML 是离线快照，打开时不会自行检测仓库变化；页眉显示生成时刻/源指纹/生成时检查状态。想知道此刻状态必须重新运行 check/render，不能把“生成时新鲜”解读成实时监控。
