# 十一个典型组合与各自的技术栈

每一条是在商业作品里反复出现的稳定组合，不是穷举。六轴可组合的坐标远多于十一个，但多数组合在成本或可读性上不成立。

坐标写法：`轴一调色板 / 轴二笔法 / 轴三视角 / 轴四生产 / 轴五网格 / 轴六后处理`。轴的定义见 [SKILL.md](SKILL.md)。

---

## 1. 真硬件自限派

**代表** GB Studio 作品、NES homebrew · **坐标** 硬件封闭 / 硬边平涂 / 横版或正俯视 / 手绘逐帧 / 严格单一网格 / 无

- **引擎** GB Studio（底层 GBDK）、NESmaker，或直接汇编 / C。导出真 ROM，能在真机与准确模拟器上跑
- **分辨率** 硬件固定（GB 160×144 四阶灰、NES 256×240）
- **资产管线** 工具链本身强制约束：超板、超 sprite 数、超 bank 会直接编译失败
- **动画** 逐帧，帧数受 ROM 与 bank 切换预算限制
- **光照** 无。明暗全部烤进美术
- **要点** 这是唯一「自限是技术而非纪律」的一派——**约束由编译器执行，不靠人自觉**。选它就等于把设计空间交给硬件，反过来省掉了所有关于风格一致性的争论

## 2. Neo-retro 自限派

**代表** Shovel Knight · **坐标** 自设封闭（宽于真硬件）/ 硬边平涂加描边 / 正侧面横版 / 手绘逐帧 / 单一网格但**非整数缩放** / 无或轻

- **引擎** 自研 C++；同类现代做法可用 MonoGame、Godot、Unity 2D
- **分辨率** 400×240。垂直 240 与 NES 一致、背景 tile 16×16 也一致，**只加横向空间**以适配 16:9，避免黑边
- **缩放** **非 pixel-perfect**：1080p 下一个游戏像素约 4.5×4.5 输出像素。开发方明确权衡后选择了「任意窗口尺寸可玩」而非「整数倍最锐」
- **资产管线** Aseprite 或 GraphicsGale 手绘，关卡编辑器自研或 Tiled，手工排 tileset 与 spritesheet
- **动画** 逐帧四到八帧，帧数少本身是风格
- **光照** 无动态光照。运行时只做 palette swap（受击闪白、配色变体）
- **要点** 「自限」是**自设规则 + 按体验需要主动破例**，不是复刻硬件。Shovel Knight 公开破掉了每扫描线八 sprite 的闪烁、音效抢占音乐声道、单轴滚动限制、卡带容量。**破例清单必须写下来**，否则会不知不觉滑成完全开放

## 3. Fantasy console 极限约束派

**代表** Celeste Classic（Pico-8）· **坐标** 虚拟机封闭 / 硬边无抗锯齿 / 横版或正俯视 / 内置编辑器手绘 / 严格单一网格 / 平台内置

- **引擎** Pico-8 或 TIC-80 的内置 Lua 虚拟机
- **分辨率** Pico-8 固定 128×128，16 色硬编码调色板
- **资产管线** 全部内置：sprite、map、sfx、music 编辑器。8×8 单元
- **动画** 手动切 sprite index，没有动画系统
- **光照** 无。`pal()` 换色与 `fillp()` 抖动是唯一的明暗手段
- **要点** cart 32KB 与 8192 token 上限会**反向塑造设计**——机制必须简单到压得进去。这一派的产出速度是全部十一派里最快的，适合做核心循环的低保真候选

## 4. 街机手工抗锯齿高帧派

**代表** Metal Slug、KOF、Garou · **坐标** 硬件封闭高色深 / 手工抗锯齿 / 正侧面横版 / 手绘逐帧 / 严格单一网格 / 无

- **引擎** 街机基板（Neo Geo 320×224）；现代复刻走 MonoGame、Unity 或自研
- **资产管线** 纯手绘，无 shader 参与质感。质感完全来自逐像素放中间色
- **动画** 单个动作二十到数十帧，是全部十一派里帧数最高的
- **光照** 无
- **要点** **sprite ROM 预算是设计约束**：多一个角色就是一大块 ROM，所以角色数少、复用高。这一派的成本几乎全在美术人力上，工程量最小——它是「用钱换质感」的极端，不适合小团队照抄，但它的**帧安排**（预备、命中、恢复的帧分配）是最值得学的部分

## 5. 16-bit JRPG 与生活模拟派

**代表** Chrono Trigger、Stardew Valley · **坐标** 16-bit 或完全开放 / 描边加平涂 / 3⁄4 俯视 oblique / 手绘 tileset / 单一网格整数缩放 / 无或轻

- **引擎** SNES（历史，256×224）；现代走 XNA / MonoGame、Unity、Godot、RPG Maker
- **分辨率** 16×16 或 32×32 tile，逻辑分辨率随平台，整数缩放
- **资产管线** 手绘 tileset atlas 加多层地图（地面 / 建筑 / 前景 / 永远最前）。编辑器 Tiled、LDtk、xTile 或引擎原生
- **动画** 行走循环四帧乘四方向，加水流与火焰这类 tile 动画帧
- **光照** 简单 additive 光圈。时间与季节靠整套 palette 或 tileset 切换
- **要点** **Y-sort 遮挡与图层顺序是可读性命脉**。巨大内容体量靠 tile 复用摊薄，所以 tileset 的设计（哪些块可拼接）比单块的画质更决定产能

## 6. 现代 HD 像素横版

**代表** Celeste、Katana Zero、Hyper Light Drifter · **坐标** 完全开放或受控 / 半 painterly、常无描边 / 正侧面横版 / 手绘加 shader / 低分辨率 target 整数放大 / bloom 或 CRT

- **引擎** MonoGame / FNA（Celeste 用 Monocle）、GameMaker（Katana Zero、Hyper Light Drifter）、Godot 4、Unity
- **分辨率** Celeste 内部 320×180，pixel-perfect 整数缩放，相机位置每帧取整防抖
- **资产管线** Aseprite 手绘，构建期自动打包 atlas，多层视差背景
- **动画** 逐帧加**代码驱动的 squash and stretch**——形变由程序做，不画进帧里
- **光照** 轻量。additive sprite 加局部 distort shader，一般不做全局光照
- **要点** 手感优先于画面。coyote time、输入缓冲、corner correction 这类东西吃掉的工程量往往大于美术。轴六是这一派的主要辨识度来源（Katana Zero 的 CRT、Hyper Light Drifter 的 bloom）

## 7. 3D 渲染降采样派

**代表** Dead Cells · **坐标** 完全开放 / painterly（3D 光照生成）/ 正侧面或俯视 / 3D 渲染加手工修边 / pixel-styled / 动态光照

- **引擎** Heaps.io（Haxe）或 Unity。关卡编辑器 LDtk 出自同一作者
- **资产管线** Blender 或 3ds Max 建模与骨骼动画 → 正交相机批量渲染 → **手工像素修边** → 烘成巨型 atlas
- **动画** 3D 骨骼动画逐帧渲出，方向与帧数的边际成本极低
- **光照** 动态 2D 光照，部分资产带法线贴图
- **要点** 需要 3D 美术岗与一条自动化渲染流水线。**修边工序省不掉**——省了就露出 3D 味。这一派换来的是「动画量便宜」，代价是团队构成变了

## 8. HD-2D / 像素立在 3D 场景派

**代表** Octopath Traveler、Triangle Strategy、Songs of Conquest · **坐标** 受控开放 / 硬边或半 painterly / 3D 场景内 billboard 模拟俯视 / 手绘 sprite 加 3D 场景 / **放弃 pixel-perfect** / 重后处理

- **引擎** Unreal Engine 4（Square Enix 系）或 Unity URP（Songs of Conquest）
- **相机** 低 FOV（约 35°）模拟等距或俯视，而不是真正的正交投影
- **资产管线** 角色 sprite 在 Aseprite 手绘并导出为平面贴图；场景在 Photoshop 绘制或在引擎里搭 3D，贴像素化贴图
- **光照** 真 3D 光照：点光让 sprite 在场景上投影、方向光做日夜循环
- **后处理** 这一派的签名就在这里——景深与 bokeh、tilt-shift、bloom、体积光与雾、视差滚动，叠出「立体模型盒」的观感
- **要点** 拿到真光照与景深，永久放弃像素网格对齐，并接管一整套 3D 引擎的复杂度。**Songs of Conquest 的做法值得单独看**：Unity URP，地形网格用 marching squares 在代码里生成、UV 投影烘 splat map，billboard 用 shader 顶点位移近似旋转（把基座信息烘进第二 UV 通道），光照走顶视投影的实时 lightmap（由专门相机渲染 lighting sprite），法线做静态重建。他们是**从纯像素路线主动转出来的**，公开讲过这个决定
- **注** 这是近十年商业存在感最强的像素派系。它同时说明一件事：「像素」可以只是贴图的分辨率，而不是渲染管线的性质

## 9. 等距预渲染派

**代表** Diablo II、Transport Tycoon · **坐标** 256 色索引板 / 抖动加 cluster shading / 真等距 2:1 / 3D 预渲染 / 单一网格 / 无

- **引擎** 自研（历史）；现代同类走 Unity、Godot
- **分辨率** 640×480 到 800×600，256 色索引调色板
- **资产管线** 3ds Max 预渲染成 palette-indexed 帧格式（DC6 / DCC），八个方向全量烘焙
- **动画** 逐方向预渲染帧
- **光照** 用 palette index 查表实现光半径——索引色时代做「动态光照」的唯一办法
- **要点** 等距坐标与 depth sort 是**引擎级设计**而非渲染细节。方向数直接乘美术成本，所以这一派历史上几乎全部走预渲染。现代想手绘做真等距，得先接受八到十六个方向的绘制量

## 10. 1-bit 抖动派

**代表** Return of the Obra Dinn、Playdate 全平台 · **坐标** 1-bit / 有序抖动是唯一明暗手段 / 任意（常为 3D）/ 实时渲染加抖动 shader / 视情况 / 抖动本身就是后处理

- **引擎** Unity（Obra Dinn）；Playdate SDK 的 C 与 Lua
- **分辨率** Obra Dinn 高分辨率 1-bit 输出；Playdate 硬件固定 400×240 单色反射屏
- **资产管线** Obra Dinn **根本没有像素资产**——是低多边形 3D 加全屏抖动 shader；Playdate 侧是 1-bit PNG
- **光照** 3D 实时光照算出灰度，再按抖动阈值二值化
- **要点** 抖动图案的**锚定方式**是该作最著名的技术难题：锚屏幕空间会随镜头游动，锚世界空间会破坏图案规整。这一派最好的说明作用是——**轴六可以吃掉轴一到轴四**：当明暗只剩抖动，画风几乎完全由后处理决定

## 11. 程序化 lo-fi 恐怖俯视派

**代表** Teleglitch、Fear & Hunger · **坐标** 完全开放但常自设近单色 / painterly 无描边 / 3⁄4 俯视或正俯视 / 程序化纹理加离散 sprite / 低分辨率 target / 暗角、噪点、扫描线

- **引擎** 自研（历史）；现代走 Godot、Unity、Phaser 3；RPG Maker 也是这一派的一条低成本支线（Fear & Hunger）
- **资产管线** 程序化 noise 烘连续地表，离散 sprite 单独手绘或走量化后处理管线
- **动画** 常常没有动画系统：方向贴图切换加离散 step-fade，禁止连续渐变
- **光照** 自实现 raycast 加遮罩擦除，**光照是玩法不是装饰**——有限视野即恐怖来源
- **要点** 视野是最贵的每帧开销，必须做缓存、降级与预算监控。**近单色加无描边意味着形体只能靠明度分离**，所以动态光照不是氛围加分项而是可读性前提。程序化地表换来零接缝零重复，代价是地表无法承载手工叙事细节，只能靠离散 decal 与 sprite 补回
- **注** 这一派最有名的几作（Signalis、Puppet Combo 系）其实是**低多边形 3D 加后处理**，不是像素。抄错载体会得到完全不同的技术栈

## 与轴五 / 轴六无关的一条横切技术：骨骼驱动像素

Spine、DragonBones、引擎 2D IK 驱动像素贴图，可以叠在上面多数派系上。它不是独立派系，而是一条**锁定链**：旋转与非整数缩放进入渲染路径，像素网格纪律基本失效。

两条出路：接受「pixel-styled 而非 pixel-perfect」，或者把骨骼动画离线烘成帧再用。程序化 / 物理驱动的部件动画（Rain World 那类）是同一条链的更极端形态——动画便宜到近乎无限，但完全放弃逐帧的手工控制。

## 事实校订

以下说法流传较广但不准确。记在这里是为了不再重犯。

| 常见说法 | 实际情况 |
| --- | --- |
| Shovel Knight 是严格自限复古派 | 开发方公开文章题为 *Breaking the NES*，主动破了每扫描线八 sprite 的闪烁、音效抢占声道、单轴滚动、卡带容量。它是 **neo-retro**：自设规则 + 按体验破例。真正「严格」的是编译到真 ROM 的那一派 |
| 低逻辑分辨率必然配整数缩放 | Shovel Knight 用**非** pixel-perfect 缩放（1080p 下一像素约 4.5×4.5），换取任意窗口尺寸可玩。整数缩放是轴五的一个位置，不是低分辨率的必然结论 |
| Songs of Conquest 属等距预渲染派 | 它是 Unity URP 下的 **2.5D billboard**：像素 sprite 立在 3D 世界里，地形网格由 marching squares 生成，光照走顶视投影实时 lightmap，法线静态重建。团队明确从纯像素路线转了出去，属第 8 派 |
| Lone Survivor 是俯视 lo-fi 恐怖像素 | 它是**侧视**横版（原作 Flash / AS3）。视角轴上与俯视派不同，可读性与光照做法都不通用 |
| lo-fi horror 就是像素风 | 该美学里最有名的几作是低多边形 3D 加后处理。像素分支存在但小得多 |
