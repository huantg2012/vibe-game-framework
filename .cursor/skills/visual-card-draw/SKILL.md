# 抽卡决策循环：视觉/体验多方案怎么让人抽

口头描述方案 = 人没法判断（实测答复：「太抽象了，放 gym 里我看看」）。变量排列组合 = 几十张碎片人没法抽。机制与表现纠缠着抽 = 每一轮都在重抽机制（实测七轮才收敛）。本 skill 是三次实战（油膜三变体 → 视野渲染 → 拾取翻找）沉淀的 HOW。

自定义 agent **不会**自动加载 skill。Director 派抽卡任务时 Task Brief 必须写明「先 Read 本文件」。

## 适用 / 不适用

**适用**：视觉/体验方向有多个合理方案，对错只能由人眼拍板——表现层打磨、交互反馈、揭晓动效、识别面、外观身份。像素物体怎么画另读 `.cursor/skills/pixel-models/SKILL.md`（本文件只管抽卡流程）。

**不适用**：对错可机器验证（直接做 + 闸门，不用抽）；方案间有客观优劣指标（量化比较后给人看数字）；人已点名方案（走 in-game-ux 的最短合规核对，不重新抽）。

## 流程（六步，缺一步不许往下走）

### 0. 机制先锁（design，T1）

抽卡只抽表现，不抽机制。开抽前 design 必须交出**机制约束表**：时长 / 打断 / 数值 / 信息通道 / 数据契约全部锁死，所有卡共享同一份。机制没锁就开抽 = 每一轮都在重抽机制。

人没写清的机制细节（如「持续按键」是按住还是开关），design 在职责内拍定写进约束表——不含糊带过，不拿去问人。

### 1. 卡设计：完整组合 + 预先声明可分维度

每张卡 = 一个**完整组合**：本需求涉及的所有表现维度各取一个连贯取值，拼成可体验的完整答案。禁止变量排列组合（3 外观 × 3 进度 × 3 动效 = 27 张碎片，人没法抽）。

每张卡必须有：名字、一句话读法（制作人语言）、载体决策、2–3 个具名游戏参考（学什么动作 / 明确不学什么）。

同时**预先声明哪些维度可拆开重组**写进约束表。人完全可能选「卡 A 的容器 + 卡 B 的进度条」——只有声明过的可分维度，杂交时才拼得起来、不返工。

### 2. 对比课实现标准（code）

- **真实上下文**：用生产同一份布局 / 系统 / 玩家角色。禁止为练习场另做一套渲染或系统——假上下文产出假信号。确需例外，登记进合同。
- 数字键切卡 + 可换种子；**带动效，模拟实际帧率**（静帧抽卡抽不出手感）。
- 每张卡可交互演示**完整流程**（触发 → 进行 → 完成 → 反馈），不是只画结果。
- spike 分支住生产代码（开关 / 枚举），但**生产默认不动**；人拍板前禁止翻默认。

### 3. art 逐卡最短核

每卡核四件：载体 + 具名参考 + 相关 U 项 + 审美底线。只核不改。存疑项书面列出并标「阻断 / 不阻断」——不阻断项随拍板后的落地批修。不代勾好看。

### 4. 人抽（不替人选）

给人的材料：每卡一句话读法 + 对比课地址 + 操作说明 + 决策问题清单。可以给数据（对比度数值、性能实测、闸门状态），**禁止给结论**（「推荐卡 N」「我觉得」都是越权）。

### 5. 拍板落地（DEC 先行）

人拍板 → **先登记 DEC**（选中组合、落选分支、人点名的补强项）→ 再动手：

- 选中组合翻生产默认；杂交组合按约束表预先声明的可分维度拼接
- 落选分支**整支删除**——不留「以后可能有用」的死代码
- 人点名的补强项进合同批次；抽卡期登记的存疑项随落地修
- 色板外临时值清零（抽卡期允许探路，落地必须落锁定色板）

### 6. 结案

删对比课（侧栏 / 注册 / 文档同步）；spec 原地更新；收尾四项（架构登记 / spec 判断 / 交付范围 / UI 清单若适用）；闸门全绿。标 COMPLETE 必须有人终审 PASS，禁止无证据记 PASS。

## 贯穿纪律：人抓回的每个问题都要沉淀成机器闸门

人眼抓回一次视觉回归 = 欠一道机器闸门。修复时不止修本体，必须新增或扩展一道**定量闸门**（对比度 / 像素指纹 / 能量平价），让同类问题永远不用再靠人抓。没有闸门的「已修复」不算修复完成——逃逸路径还在。

推论：**新视觉元素类别在规格期就要声明对背景的定量可读下限**（对比度 / 明度差），不是等人抓回再补。规格只写「颜色从哪推导」而不写「与背景至少拉开多少」，逃逸就是必然的。

## 色板纪律（锁定色板项目）

新格 = art 提案 + 人拍板 + DEC 登记 + 全链路传播。提案必须附安全性分析：与最近既有格的差异、与语义冲突色族（如污染色）的差异、明度变化对既有选色池的影响。规则豁免（如「暖色稀缺」的材料色口径）由人拍板，agent 不自行解释规则。code 禁止私自发明色板外值。

## 反模式（出现任一条 = 不合格）

- 机制没锁就开抽；抽卡里夹带机制差异
- 变量排列组合当卡；口头描述让人抽，不做对比课
- 练习场另做一套渲染 / 系统（假信号）
- 人没拍板就翻生产默认；替人选默认；报告里给倾向性结论
- 落选分支留在代码里「以后可能有用」；结案不删课
- 人抓回的问题只修本体不补闸门
- 杂交组合时硬拼未声明可分的维度，拼不上就偷偷改机制

## 角色分工

| 角色 | 本 skill 里必须做的 |
| ---- | ------------------- |
| design | 步骤 0 机制约束表；机制细节职责内拍定 |
| art | 步骤 1 卡设计（读法 / 载体 / 参考）+ 步骤 3 逐卡最短核 + 色板提案与安全性分析 |
| code | 步骤 2 对比课 + 步骤 5 落地 + 闸门实现；不私自发明色板外值 |
| qa | 步骤 5/6 机械对照；验证「人抓回的问题已有闸门」 |
| director | 全流程编排；DEC 登记；不替人选；派发中止 / 异常后以仓库状态为准回报，不以代理回报为准 |
