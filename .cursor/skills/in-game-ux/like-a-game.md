# 交互组织与实现中需要保住的行为

补充 [SKILL.md](SKILL.md)。机制数据与规则仍归所属 spec/CSV，UI 只解释与操作真实状态。

## 结构服务动作

供奉/装配的横向槽位、库存与单件详情，蜕变的成长列表与效果/成本，报告的装置列表与当前读数，在迭代 11 获得认可。复用主从和比较关系，不照搬某一种网格或方向。

分配先读当前完整度，再输入投入，再看修复、出击效果和余额。无关装置耐久、无关成长价格不必挤入当前操作。结果先读所得或损伤，再读明细与返回。暂停用短选项列表与明确当前选择。

保留动作资格：普通 Enter 装填、Shift+Enter 出击是不同意图。空库仍能出击时，按钮/键提示仍可达。覆盖存档确认保留具体后果与返回路径，不能因视觉简化删掉。

## 滚动驻留不是隐藏滚动条

- 常规内容优先通过编排与适当密度容纳；超长库存自然滚动，底部关键动作保持可达。
- 选择变化保留列表 DOM，只更新详情、选中态与动作。完整数据变化保存/恢复每个滚动区位置；删除条目降低新最大值时允许自然夹紧。
- 键盘浏览才主动显露当前项。鼠标滚动或点击不应被旧焦点拉回顶部；切报告页可显式重置。
- `pointerover` 与 DOM 重建容易重入：新节点又到鼠标下，引起重新选择/重画。优先在真实 `pointermove` 且索引变化时处理，避免每帧、每次悬停重建。
- 本作已有 `src/ui/dom/panel-render-state.ts`，先了解现有策略，避免各面板另写冲突版本。用长库存滚到后段，再点击、装填、键盘移动验证；初始截图抓不到回顶。

## 坐标与场景生命周期

本项目固定960×640逻辑画布，屏幕空间DOM由`#dom-ui-root`随画布缩放；实体投影点用于定位邻近读数。不要混用屏幕角锚与世界坐标，也不要为此加入响应式断点。

镜头、输入锁、反馈和关闭是一段完整生命周期。确认期间防重复执行；返回镜头完成后恢复操作；关闭或切场景清理rAF、延迟回调和过渡DOM。先确认现有模块如何分担这些责任。

迭代11实测：Phaser相机在scene shutdown回调前已销毁，此时不能再用main相机恢复视角；转场延迟应绑定scene Clock并清理，避免旧回调把新界面带走。这些是本项目故障经验，不泛化成所有引擎的规则。

## 验证边界

按实际改动检查：动作不裁切、提示与绑定一致、键鼠同一选中状态、提交不重复、退出没有遮蔽或相机残留。共享CSS还需回归引用它的报告、暂停、结算。

开发页是隔离的生产组件入口，不替代机制真相、不读写正式存档。区分组件测试、真实场景入口测试与用户验收；输入自动化没有成功，不写成全链路通过。
