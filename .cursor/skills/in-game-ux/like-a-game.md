# 怎样做得像游戏 UX

本文件是**判断动作**，不是某款游戏的答案。色值、布局、组件类、已确认翻车录住在项目 UI Kit / 参考研究里。开工闸门在 [SKILL.md](SKILL.md)。

## 先验

训练语料里「UI」的最大概率簇是 SaaS 后台（圆角卡片、hover、居中弹窗、`hover/active/disabled`）。不先钉具名游戏参考与载体，模型会按这个先验填表。

## 如何选参考（机制同构 + 气质同构）

不要列「像素风灵感」。问：这一屏要解决的**信息问题**是什么，哪款**具名游戏**用可观察的动作解决过同类问题。

| 本屏的信息问题 | 去锚什么动作（例） |
| -------------- | ------------------ |
| 资源/子系统分配，战斗中不能停 | 名 + 条 + 状态同屏；贴边常驻；不靠 hover |
| 高密度词条，决策瞬间要筛 | 符号 / 边框 / 数字三层独立编码 |
| 检视物品或读日志 | 固定读出面，像设备输出，不是 OS tooltip |
| 预告必须可信 | 预告–发生–结算同一套符号 |
| 机械/有机体承压 | 装置自己报状态（灯、声、读数），不是「系统错误」对话框 |

每条参考只锚**一个可执行动作**。写清「不学什么」（配色、滤镜、玩法结构默认不抄）。抄错参考比不抄更贵。

项目若已有 `docs/design-notes/ux-references.md`（或等价），从那里选 2–3 个，不要另起一套。没有则走 SKILL.md Bootstrap，请人锁定后再画。

## 像游戏 vs 不像游戏（抽象反模式）

| 不像游戏 | 为什么 | 改成什么 |
| -------- | ------ | -------- |
| 外发光 / 卡片投影 / 按钮渐变 | 现代软件强调，世界里的设备通常没有这层物理 | 分离靠遮罩、边框亮度、留白；装饰须有物理原因 |
| 原生 `title` tooltip / 仅 hover 可得 | 系统字体、延迟、键盘零通道 | 固定检视区或选中即填的详情，键鼠同一通道 |
| 英文 debug 菜单、`Continue` / `OK` / `Prototype Build` | 第一眼是引擎启动页或网页 | 世界术语；元界面仍守术语与色板 |
| 连续多个「知道了」阻断确认 | 玩家在消系统对话框 | 阻断通道同时只 1 条；其余就地或事件条 |
| 无标签裸条、只有圆点没有名字 | 零操作截图读不出「这是什么」 | 条旁分开的表名 + 数字；槽位有身份 |
| 不可用只变灰 / 降透明 | 表单 disabled | 写出缺口（缺什么、还差多少） |
| 同一物件跨界面改名 | 同一台设备两种语言 | 术语单一数据源 |
| 调试 overlay 默认开、压 HUD | 开发工具冒充游戏 UI | 默认关；不占用玩家四角 |
| 进行中居中大弹窗 | 挡住要看的战场 | 贴边 / 侧栏；打开方式必须是玩家动作 |
| 表名+数值+档位粘成一句 | 术语对了仍读成复合名词 | 三个独立节点 |
| 浏览器默认滚动条、按钮随字长短不齐 | 网页表单草稿感 | 用项目 Kit 的滚动与底栏规则 |
| 角锚 HUD 绑在会随 camera zoom 漂移的实现上 | 读数飞出画面 = 没有 HUD | 按 architecture 的屏幕空间根挂载 |

状态名只用游戏语义：静默 / 可交互 / 已选中 / 缺 X / 临界。

## 信息节奏

- P0：决策瞬间必须已经知道，额外操作会断链。
- P1：一键或走近，不依赖 hover。
- P2：允许暂停阅读。

常驻信息（P0）走不打断视线的装置读数；唤出信息可以走终端。元界面是唯一允许「我知道这是软件」的地方，文案仍要服务世界观。
