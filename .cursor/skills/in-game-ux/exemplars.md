# 迭代 11：被否决与获认可的做法

用户2026-09-07明确结单；实现与证据提交`fd8c719`。本文件记录判断，不是第二份UI Kit。截图路径以含该提交的本作检出为准：`docs/art/iteration-11-evidence/`；测试详情在`docs/qa/iteration-11.md`，最终视觉定义在`docs/design-notes/ui-art-overhaul.md` A节。

## R0/R1：布局改善不等于风格成立

用户认可主从布局与主菜单左右布局，却否决美术与字体；大字、过强HUD、刻意的像素/设备皮肤仍失败。错误在于把游戏感理解成更凸显的UI，并用旧处方约束审美。

同时暴露：入口缺出击按钮/提示，三装置生命横线与投入选中竖线撞车。操作完整性和审美分别处理。`r1-*`是被否决的结果，不能作成品模板；更早的2026-08-28审查图也不能覆盖最新验收。

## R2：HUD95分PASS，交互布局80分

轻量边缘HUD、小字号、槽位与库存/详情主从让信息获得适当分量。用户认可HUD和布局，要求继续改面板颜色、标题字体。看`r2-purification-hud.png`、`r2-rift-hud.png`、`r2-defense.png`；复用注意力分配与决策顺序，不将当时皮肤视为最终认可。

## R3：材料调整仍像外来窗口

细噪点、微透景、同族标题落实后，用户仍说像从别处挪来的窗口。材料能改善纯色生硬感，不能替代与场景的关系。`r3-status.png`、`r3-growth.png`是诊断反例，不能反过来要求所有后续面板必须带颗粒。

## R4/R5：实体、读数与无框决策

核心样板让真实设备参与：靠近、读附近状态、在暗处投入、看到实际修复回应、退回场景。用户表示“惊艳到我了！接受这个设计，应用到游戏吧”，六点推广随后获“效果非常棒”。

看`r4-core-sample.png`、`r4-core-preview.png`、`r4-core-committed.png`、`r4-core-return.png`；推广看`r5-storage.png`、`r5-purifier.png`、`r5-defense.png`、`r5-growth.png`、`r5-loadout.png`。

净化器名称曾误指上方玩家，通过侧置与局部暗场修正。要看实际对象关系，不能机械复制核心的标签位置。镜头变化也需要输入恢复与转场清理。

## R6：别遗留第二套菜单

六点认可后，用户指出Tab报告、Esc等菜单格格不入。报告、暂停/覆盖确认、撤离/阵亡、冲击及失焦随后统一无框排字、同族小字与连续暗场。它们没有实体焦点，所以保留视角；主菜单保留本作宣传图和左右构图。

看`r6-report.png`、`r6-pause.png`、`r6-overwrite.png`、`r6-extraction.png`、`r6-death.png`、`r6-impact.png`、`r6-main-menu.png`。用户随后要求“这个问题结单，更新进度，提交”。

认可覆盖最终交付，不意味着未来所有界面必须无框或推镜头。保护已验收成果；新需求改变决策或场景关系时重新判断，不扩大旧结论的适用范围。
