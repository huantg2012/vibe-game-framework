# In-game UX：让界面从当前游戏里生长

本 skill 沉淀迭代 11 已获用户验收的经验，帮助判断，不替代审美判断。**当前用户指令与最新验收高于旧经验；成功样板也不能变成所有新界面的固定模板。**

适用 HUD、交互面板、报告、菜单和提示。角色阴影、实体遮挡、精灵绘制不归本 skill，不因出现“视觉问题”就套 UI 方案。

## 先确认哪些是真正认可的成果

区分布局认可、材质认可、样板认可、推广授权和整批验收。不能把其中一个当作其余全部通过，也不能在后续修改中重新推翻已锁定部分。

本作验收链：轻量 HUD 获 95 分 PASS → 交互布局获认可但仍有外来窗口感 → 核心场景样板被接受 → 六点推广获认可 → 报告、Esc 及结算统一后，2026-09-07 用户明确结单。历史失败与成功证据见 [exemplars.md](exemplars.md)。

旧版“HUD 必须有实体底板”“所有交互都是磷光终端”“留白必须填满”“左侧导航一定像后台”均已被此轮实际结果推翻。不要把它们从旧审查图或附件重新导入设计。

## 开工所需的上下文

- 看相关的**当前实景**：玩家、装置、光源、材质与空间关系。世界观用于判断气质与词语，不能仅转换成装饰符号。
- 明确玩家此刻要看什么、决定什么、执行什么；读取相关系统规则，保留真实成本、资格、效果与退出路径。
- 本项目现行视觉定义在 `docs/design-notes/ui-art-overhaul.md` A 节，机制在所属 spec，世界在 `docs/world.md` 与 `docs/art-direction.md`，挂载约定在 `docs/architecture.md`。旧文与新验收冲突时，更新归属文档，别沿过时规定继续画。
- 选最相关的一两张已认可实景参照。小修改无需重读整个历史，也不必强制另找几款游戏、另请一轮批准才开工。

## 先决定世界与界面如何共处

**常驻读数**：让行动与场景占据注意力。靠边缘位置、对齐、分组、有限的字号/明度差建立可找性，不靠整块底板和全面放大制造存在感。无底板不等于 debug；缺少层级、上下文和稳定锚点才是问题。危险反馈仍须在实景中辨认。

**有实体的交互**：当操作对象值得看，考虑让真实对象成为主体，读数贴近它，选择在邻近暗处展开。核心成功在于实体、镜头、读数和修复反馈形成连续行为；仅给旧窗口增加噪点和透明度未解决外来感。是否推镜头、推多远，按对象与阅读负担判断，不照抄每台装置。

**无对应实体的报告/暂停/结果**：保留当前场景视角，以留白和连续渐暗承接文字。不要为统一风格虚构一台终端或强行聚焦无关对象。报告、Esc、覆盖确认、结算和失焦层要与主要交互一起检查；主菜单可保留自己的构图，但字体与图像气质须相容。

审看方法见 [aesthetics.md](aesthetics.md)。

## 布局由决策决定

- 保留一个当前决策中心：投入量、当前物品或选项。列表与详情建立主从，避免每项都获得同样的亮度、边框和面积。
- 同级分类可用 Tab，装置列表可用左侧导航。位置本身没有“游戏/后台”属性，要看是否服务浏览和比较。保留用户认可的布局，除非新证据表明它失效。
- 有效留白用于保留场景、隔开行为或让重点安静呈现。不要为了填满空间补说明、数值或装饰，也不能把必要内容挤进滚动区来制造留白。
- 字体服务本作气质和实际阅读尺寸。像素世界不自动要求像素中文；标题不必使用宋体或刻意特殊化。精确值查 Kit，不在 skill 复制第二套色板/尺寸表。
- 可执行提示要有真实绑定；空库仍可出击时保留入口。不可用说明实际缺口或原因，不制造机制里不存在的收益评分和犹豫。

行为与技术要点见 [like-a-game.md](like-a-game.md)。

## 修改与验证

视觉不确定时，先在真实、高代表性的交互上做完整样板，包含进入、操作、反馈、退出。用户已授权推广后继续覆盖相关表面，不反复要求批准同一方向。修已锁样式的小问题不必重走样板。

共享样式变更先列出受影响表面，必要时用局部类保护已认可的 HUD 或其他交互；验证范围按实际影响确定。不要一边修菜单一边改机制或世界模型。

验证使用实际生产组件与内容长度：典型状态、零资源/空库、足够长的内容；检查主要动作可达、滚动驻留、键鼠选中一致、退出恢复与重复输入。截图不能冒充交互测试，构建通过不能冒充体验通过。开发示例应隔离正式存档。

交付说明画面主次、操作完整性、与当前世界的关系，附实景和实际验证结果，明确未实测项。已有用户 PASS 可如实记录；新表面最终审美由用户判断，不能拿书面三问或 U1–U12 勾选替代。只更新相关规格与进度，不建立平行视觉规范。
