# 审美判断：看完整体验，不只看窗口皮肤

补充 [SKILL.md](SKILL.md)。精确样式由当前 UI Kit 维护；以下是本作迭代 11 得到验证的方法，不是所有恐怖游戏的通则。

## 从实景中提取关系

看真实场景怎样建立注意力：暗环境中的局部灯光、低饱和器具、人物与装置尺度。界面沿这些关系安排主次，不把“克苏鲁”翻译成符文、金属框、衬线大字或满屏青绿。

打开后依次看世界主体、当前决策、辅助信息。若最先看到一块整齐的大矩形，检查构图与遮蔽范围；继续加纹理未必有用。界面移走后，场景是否仍是刚才的场景，操作是否像发生在这个对象上？

## 本轮有效的做法

- **世界参与构图。** 核心使用真实实体与镜头靠近，身份和完整度围绕实体，投入与后果在右侧。修复后实体回应，再退回原视角。它不是背景贴图加另一个窗口。
- **暗场连续。** 需要压住阅读区域的世界噪声时，渐暗跨越内容边界，避免形成独立矩形。报告和暂停没有实体焦点，因此保留视角。不要一律加黑，让世界完全消失。
- **小而可读。** 正文和标题同族，层级靠位置、间距、有限字号差与明度。HUD 更轻，操作时主数值稍突出，不把整屏变成大字模式。以实际显示比例审看，放大截图不能证明可读。
- **克制分隔。** 淡线帮助分组，选择标记只标当前对象。生命横条与投入左竖线曾拼成冲突折角；需要分离状态与操作，而非继续加框。
- **材质不替代构图。** R3 的细噪点、微透景和同族标题回应了反馈，仍未获得原生感认可；后续场景无框构图才解决它。不要自动给每个表面或文字加噪点/透明度。

## 看过程，也看其他菜单

进入与退出时检查：镜头是否抢走控制，邻近对象是否误导归属，读数是否跟得上对象，确认反馈是否对应实际结算，退出是否还给玩家原来的场景。

并看代表表面：HUD、实体交互、报告、Esc、结果。只优化最常见面板会遗留第二套菜单。主菜单宣传图要与实际环境、主体和光色一致，不以泛用暗黑插画凑版面。

用户说看不清时检查字号、干扰与层级，不以气氛作借口。用户说像移植窗口时优先检查场景关系，不默认纹理不够重。
