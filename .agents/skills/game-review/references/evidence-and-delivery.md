# 证据、裁决与交付

## 记录环境与覆盖

记录构建/提交及未提交差异、入口、相关配置、运行环境、存档起点、审查角色及已知先验。可用哈希或版本标签标识；不为一次小专项强制生成庞大资产清单。

覆盖台账每项包括：模块或循环节点、状态、正式/开发入口、操作事件、证据路径、结论上限、缺口。确实不存在标不适用，存在但材料不足标未覆盖。变更版本时单开记录，不把边审边改的结果混为同一版；没有明确实施授权时不改被审内容。

在项目已有QA目录存报告和证据，长任务另保留轻量运行台账：已完成阶段、封存观察、待复核假设、阻断、下一步。复用已有记录结构，不为每个细节建一套平行文档。

## 证据种类与能支持的结论

这些是不同来源，不是能自动互换的排名：

- **真实目标玩家研究**：记录招募、经验、任务、样本及条件，才讨论相应玩家反应；小样本不泛化成留存/满意度数字。
- **专家实际操作**：可支持当次理解、策略和艺术判断。AI的离散操作、暂停、工具限制和全图知识会改变体验，要披露。
- **受控浏览器/实机复现**：支持具体条件下的状态与表现。预置装备、传送、锁种子、暂停或故障注入逐项注明；不写成自然获得或首玩。
- **静帧/素材/文档**：支持所见范围的表达或规则分析，不能证明完整动态循环。
- **代码、数据、模拟和自动检查**：支持实现事实、约束、推断和覆盖；不能单独证明好玩、好看、音色好听或长期经济合理。

记录片段宜包含前提→线索→选择→行动→结果→下一次理解。时间类缺陷用连续录制或实际帧事件；最终截图无法排除中间闪帧。图像必须看过才作视觉判断；音频必须实际审听才作听感判断。

## 抽样与因果

- 覆盖常见、风险/失败、未调优和必要的深层状态；解释等价类和抽样理由，不以固定地图数/截图数当充分性。
- 固定回归、新样本、失败样本各有作用；公开筛选、拒绝、重抽、回退及缺失样本。新局通过不能自动排除旧局、旧档和另一入口的问题。
- 先排实现失效，再评价数值或设计收益。例如显示承诺未进入实际效果时，不先把无感归因于成长曲线。
- 写一个竞争解释，并说明什么观察能推翻当前结论。出现相反样本就缩小断言，而不是藏掉它。
- 机制触发、统计收益和玩家实际价值分开验证。概率推算附假设，CPU微基准不当作整帧表现；完整输入链也不自动等于自然新手体验。
- 在预算内完成有决定价值的复核；重复证据不再增加把握时停止，保留未知，不凑“全部通过”。

## 发现记录

使用稳定ID。篇幅按影响缩放，重要发现至少包含以下内容：

- **标题与类别**：症状/后果；实现、设计、表达、艺术品质或待调查。
- **情境**：版本、入口、起点、状态及操作序列。
- **预期依据**：游戏已教规则、实际承诺、品类假设或作者意图，注明来源。
- **实际观察与证据**：图片/片段/时间点/数据/代码位置；区分事实与推论。
- **后果与范围**：影响哪项决定、情绪、循环或交付能力，哪些场景未覆盖。
- **严重度／频率／把握**：分别注明。
- **竞争解释与反证**：何种结果会削弱结论，下一步怎样区分。
- **建议与验收**：期望收益、代价、依赖、工作量级别、最小实验和通过条件。

严重度沿用项目约定；没有约定时可用P0核心流程/数据阻断、P1持续破坏关键体验或作品身份、P2有范围的明显摩擦、P3局部轻微瑕疵。频率未知不等于低影响，艺术品质也可为P1。调查优先级可高于根因把握。不要用严重度代替置信度。

## 优化决策与计划

按根因归并跨组发现，每项保留证据来源及未解决的分歧。既列问题，也列应保护的优势；一个改动可能同时有玩法收益和艺术损失，要显式裁决。

用户要求整体处置时，逐项说明：接受、部分接受、不接受或待验证，理由及证据是什么。不能因报告写了“建议”就假定作者同意。若用户已经授权按结论修复，遵守既有范围继续，不人为加批准环节。

计划围绕可验收的成果组织：

- 先消除使体验判断失真的可靠性/因果断点。
- 再以最小样本验证设计或表达假设，同时检查跨系统代价。
- 假设成立后改共享能力、数据或制作流程，补对应产物与状态的回归。
- 扩充内容、长期采样或人审单列条件与范围，不自动解除既有挂起。

每批标目标、影响模块、依赖、预期成本档、验收场景、需要保留的特性和证据。成本不能估则先给调查任务。不要用“增加细节/提升体验/加强打磨”作无检验标准的计划。

## 报告的最小结构

1. 结论与制作建议：值得保护什么，最大瓶颈是什么，下一步做什么。
2. 实际范围与限制：版本、入口、材料、角色先验、覆盖/缺口，证据类型。
3. 按适用质量轴的判断：成立/脆弱/不成立/未验证，附依据；不算虚假总分。
4. 独立美术归类与品质结论；音频和手感另列实测范围。
5. 重要发现及因果链，优点与反证，按收益和依赖排序。
6. 可执行的候选方案、最小实验、验收标准；长期或用户验证的缺口。

小专项可合并成短报告，不要求凑齐多份附件。只有有限材料时，标题与总结都限定范围。分清审查完成、实施完成、内部验证与用户验收；同一人被教会后不能再次被记为首玩。
